Debian Particionar e Formatar

Um disco novo chega "cru": o Debian enxerga o aparelho, mas não consegue guardar arquivos nele. Para usar, você faz três coisas: cria uma tabela de partições, cria uma ou mais partições e formata cada uma com um sistema de arquivos. Nesta aula você faz tudo isso num laboratório que não põe nada em risco.

Esta aula apaga dados

Particionar e formatar destroem o que estiver no disco, sem lixeira e sem "desfazer". Pratique primeiro no laboratório mostrado abaixo. Num disco real, confira o nome do dispositivo duas vezes antes de apertar Enter.

Você vai aprender
  • A diferença entre disco, tabela de partições, partição e sistema de arquivos.
  • Como montar um laboratório sem risco com um arquivo-imagem e o losetup.
  • Como identificar o disco certo com lsblk.
  • Particionar com fdisk (interativo) e com parted (numa linha só).
  • Formatar com mkfs.ext4 e outros formatos, e criar swap.

Os exemplos acontecem na máquina fictícia servidor. Como no Debian a usuária ana não tem sudo (veja root, su e sudo), os comandos de disco são rodados como root: o prompt muda para root@servidor:~#.

Conceito: o terreno, os lotes e a casa

Pense num disco como um terreno. Antes de construir, é preciso registrar o mapa dos lotes, depois dividir o terreno em lotes e, por fim, construir em cada lote.

PeçaAnalogiaNo Linux
DiscoO terreno inteiro/dev/sdb, /dev/nvme1n1
Tabela de partiçõesO mapa que diz onde começa e termina cada loteGPT (moderna) ou MBR/DOS (antiga)

Sistema de arquivosA casa construída no loteext4 (padrão do Debian), xfs, vfat, exfat

GPT ou MBR?

GPTMBR (DOS)
Tamanho máximo do discoPraticamente ilimitado2 TiB
Quantidade de partições128 por padrão4 primárias (ou 3 + estendida)
Quando usarSempre, em disco novoMáquinas antigas sem UEFI e pendrives para aparelhos velhos
Curiosidade: a própria instalação do Debian

Quando o Debian é instalado numa máquina sem UEFI, o instalador costuma usar MBR, com uma partição estendida guardando a swap. Na VM de teste deste guia, o lsblk mostra exatamente isso: sda1 é o sistema, sda2 (1K) é a partição estendida e sda5 é a swap.

Nomes dos dispositivos

  • /dev/sda, /dev/sdb…: discos SATA, USB e discos de VM. As partições ganham um número: /dev/sdb1.
  • /dev/nvme0n1…: SSDs NVMe. As partições ganham p + número: /dev/nvme0n1p1.
  • /dev/vda: disco virtual em VMs KVM.
  • /dev/loop0…: "discos" que na verdade são arquivos. É o que você vai usar no laboratório.

Laboratório seguro: um disco que é só um arquivo

Você vai criar um arquivo de 2 GB e pedir ao kernel para tratá-lo como um disco de verdade. A partir daí, fdisk, parted e mkfs funcionam nele igualzinho funcionariam num HD.

Outra opção: uma VM com disco extra

No VirtualBox, em Configurações → Armazenamento, adicione um segundo disco virtual. Dentro da VM ele aparece como /dev/sdb, igual a um disco de verdade.

Passo 1: identificar o disco certo

O erro mais grave desta aula é formatar o disco do sistema por engano. Antes de tudo, descubra o nome do disco novo.

lsblk
"list block devices": lista discos e partições.
-o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS
Escolhe as colunas: nome, tamanho, tipo, formato e onde está montado.
#> lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS
NAME     SIZE TYPE FSTYPE MOUNTPOINTS
sda       25G disk
├─sda1  23,7G part ext4   /                           « disco do sistema: NÃO mexa
├─sda2     1K part
└─sda5   1,3G part swap   [SWAP]
sdb      100G disk                                    « o novo: sem partições, sem montagem
sr0     1024M rom

Como reconhecer o disco novo:

  • Tem o tamanho que você comprou ou criou.
  • Não tem linhas de partição (├─) embaixo dele.
  • A coluna MOUNTPOINTS está vazia.

Outra forma de olhar é o fdisk -l, que mostra os detalhes de um disco sem mudar nada:

#> fdisk -l /dev/loop0
Disco /dev/loop0: 2 GiB, 2147483648 bytes, 4194304 setores
Unidades: setor de 1 * 512 = 512 bytes
Tamanho de setor (lógico/físico): 512 bytes / 512 bytes
Tamanho E/S (mínimo/ótimo): 512 bytes / 512 bytes          « sem "Tipo de rótulo": ainda não tem tabela
Por que "comando não encontrado"?

Se você rodar fdisk como ana, o Debian responde bash: fdisk: comando não encontrado. O programa existe, mas fica em /usr/sbin, que não está no PATH dos usuários comuns. Vire root com su - (o hífen importa: ele carrega o PATH do root).

Passo 2: particionar com fdisk

fdisk (de fixed disk) é interativo: você digita uma letra por vez, e ele pergunta o resto. Nada é gravado até você digitar w. Se errar, digite q para sair sem salvar.

fdisk
O programa de particionamento (rodando como root).
/dev/loop0
O disco inteiro, sem número de partição no fim.

Entendendo a pergunta do "último setor": o disco é dividido em setores de 512 bytes. Em vez de calcular setores, você escreve o tamanho com +: +1G significa "1 GB a partir do início". Deixar em branco usa todo o espaço livre.

O que o comando devolve

O fdisk não altera o disco até o w. Se você sair com q, nada mudou. Se ele não conseguir reler a tabela (o disco está em uso), avisa que a releitura falhou; nesse caso, rode partprobe /dev/sdb (do pacote parted) ou reinicie.

Forma alternativa: parted numa linha só

O parted faz o mesmo trabalho, mas aceita tudo como argumentos. É a forma preferida em scripts. No Debian ele não vem instalado:

#> parted

#> apt install parted

#> parted -s /dev/loop0 mklabel gpt mkpart dados ext4 0% 100% print

O parted do Debian responde em inglês: o pacote não traz tradução para o português. Number é o número da partição, Start/End são o início e o fim, e Name é o nome que você deu.

O "ext4" do mkpart não formata

No mkpart, o tipo é só uma etiqueta na tabela. A partição continua vazia até você rodar o mkfs. Usar 0% e 100% faz o parted alinhar a partição corretamente, sem você calcular setores.

Passo 3: formatar com mkfs

mkfs vem de make filesystem, "criar sistema de arquivos". Existe uma versão para cada formato: mkfs.ext4, mkfs.xfs, mkfs.vfat…

mkfs.ext4
Cria um sistema de arquivos ext4, o padrão do Debian.
-L dados
-L (label) dá um nome à partição. Aparece no lsblk -f e no gerenciador de arquivos.
/dev/loop0p1
A partição (com número no fim), não o disco.
#> mkfs.ext4 -L dados /dev/loop0p1

  • Filesystem UUID: o "RG" da partição. É ele que você usa no /etc/fstab (veja mount e fstab).

Apagar assinaturas antigas: wipefs

Um disco reaproveitado pode ter restos de formatos antigos (RAID, LVM, ZFS) que confundem o sistema. wipefs (de wipe filesystem signatures) lista e apaga essas "assinaturas".

#> wipefs /dev/loop0p2                              « só lista, não apaga
DEVICE  OFFSET TYPE UUID                                 LABEL
loop0p2 0x0    xfs  7e6911df-13af-474f-a47d-f8411f43511f backup
#> wipefs -a /dev/loop0p2                           « -a (all) apaga todas
/dev/loop0p2: 4 bytes foram apagados na posição 0x00000000 (xfs): 58 46 53 42
#> wipefs /dev/loop0                                « no disco inteiro: a tabela GPT e o MBR protetor
DEVICE OFFSET     TYPE UUID LABEL
loop0  0x200      gpt
loop0  0x7ffffe00 gpt
loop0  0x1fe      PMBR
Atenção

wipefs -a faz o disco ou a partição "esquecer" o formato na hora. Os dados ainda estão lá fisicamente, mas o sistema deixa de enxergá-los.

Swap: memória extra no disco

Swap é um espaço no disco que o Linux usa quando a memória RAM enche. É bem mais lento que a RAM, mas evita que programas sejam encerrados à força. Diferente do Ubuntu (que cria um arquivo /swap.img), o instalador do Debian cria uma partição de swap:

#> swapon --show
NAME      TYPE      SIZE USED PRIO
/dev/sda5 partition 1,3G   0B   -2                 « partição de swap criada na instalação

Criar um arquivo de swap extra

  1. Reserve o espaço. fallocate -l 2G cria um arquivo de 2 GB de uma vez. 
    #> fallocate -l 2G /swapfile
  2. Proteja o arquivo. Só o root pode ler: a swap pode conter senhas que estavam na memória. Se esquecer, o mkswap avisa: mkswap: /swapfile: permissões inseguras 0644, corrija com: chmod 0600 /swapfile. 
    #> chmod 600 /swapfile
  3. Formate como swap e ative. 
    #> mkswap /swapfile
Configurando espaço de swap versão 1, tamanho = 2 GiB (2147479552 bytes)
nenhum rótulo, UUID=2ec0cb1f-ea96-4672-9f59-b78091f66bf6
#> swapon /swapfile
#> swapon --show
NAME      TYPE      SIZE USED PRIO
/dev/sda5 partition 1,3G 268K   -2
/swapfile file        2G   0B   -3                 « a nova swap, com prioridade menor
  4. Torne permanente. Adicione a linha no /etc/fstab para ela voltar depois de reiniciar: 
    #> echo '/swapfile none swap sw 0 0' >> /etc/fstab

Quanto o sistema usa a swap: vm.swappiness

Um número de 0 a 200. O padrão é 60. Valores menores fazem o Linux preferir a RAM. No Debian, o sysctl também fica em /usr/sbin: rode como root.

#> cat /proc/sys/vm/swappiness
60
#> echo 'vm.swappiness=10' > /etc/sysctl.d/99-swappiness.conf
#> sysctl --system | tail -1
vm.swappiness = 10

Quando não funciona

"fdisk: comando não encontrado" 
$ fdisk -l
bash: fdisk: comando não encontrado

O que aconteceu: você está como usuário comum. No Debian, o PATH de quem não é root não inclui /usr/sbin, onde moram fdisk, mkfs e companhia.

Como resolver: su - e rode de novo. Usar su sem o hífen mantém o PATH antigo, e o erro continua.

"is mounted; will not make a filesystem here!" 
#> mkfs.ext4 /dev/sdb1
mke2fs 1.47.2 (1-Jan-2025)
/dev/sdb1 is mounted; will not make a filesystem here!

O que aconteceu: a partição está montada (em uso). O mkfs se recusa a formatar, para proteger seus dados.

Como resolver: confira com findmnt /dev/sdb1. Se for mesmo a partição certa, desmonte com umount /dev/sdb1 e rode de novo.

"contains a ext4 file system … Proceed anyway?" 
#> mkfs.ext4 /dev/loop0p1
mke2fs 1.47.2 (1-Jan-2025)
/dev/loop0p1 contains a ext4 file system labelled 'dados'
	created on Thu Oct 15 22:48:05 2026
Proceed anyway? (y,N) n

O que aconteceu: já existe um sistema de arquivos ali, possivelmente com dados. O padrão (N) cancela.

Como resolver: responda y só se tiver certeza de que pode apagar tudo.

"The file … does not exist and no size was specified." 
#> mkfs.ext4 /dev/loop0p3
mke2fs 1.47.2 (1-Jan-2025)
The file /dev/loop0p3 does not exist and no size was specified.

O que aconteceu: a partição não existe. Ou você errou o número, ou o kernel ainda não releu a tabela.

Como resolver: confira com lsblk. Se as partições acabaram de ser criadas e não aparecem, rode partprobe /dev/sdb. No laboratório, lembre do -P no losetup.

Formatou o disco inteiro em vez da partição

O que aconteceu: rodou mkfs.ext4 /dev/sdb (sem número). Funciona, mas apaga a tabela de partições: o disco vira um sistema de arquivos só.

Como resolver: se não há dados ainda, recomece com wipefs -a /dev/sdb e particione de novo. Regra prática: fdisk e parted recebem o disco (/dev/sdb); mkfs recebe a partição (/dev/sdb1).

Resumo

  • Ordem: tabela (GPT) → partição → formato (mkfs) → montagem.
  • No Debian, ferramentas de disco ficam em /usr/sbin: use su -.
  • fdisk já vem instalado; parted, xfsprogs, dosfstools e exfatprogs são instalados à parte.
  • fdisk/parted recebem o disco (/dev/sdb); mkfs recebe a partição (/dev/sdb1).
  • Treine com truncate + losetup -fP: as mesmas ferramentas funcionam num arquivo, sem risco.
