Debian Podman

O Podman roda containers como o Docker, com quase os mesmos comandos, mas com duas diferenças importantes: não tem um serviço central rodando como root (o "daemon") e funciona muito bem como usuário comum. Num Debian em que a sua usuária não tem sudo, isso cai como uma luva: ela roda containers sem nunca ganhar poder de root.

Você vai aprender
  • O que muda entre Podman e Docker, e quando usar cada um.
  • Rodar containers como a ana, sem root (modo rootless).
  • Por que o Podman do Debian transforma hello-world em outra imagem, e como usar nomes completos.
  • Como o "root de dentro" vira a ana de fora.
  • Transformar um container num serviço do systemd com um quadlet.

As saídas vêm do Debian 13 de laboratório, com Podman 5.4.2. Pré-requisito: Docker, para os conceitos de imagem e container.

Instalar

Instalar exige root (no Debian, su -; veja root, su e sudo). Depois disso, a ana usa sem root.

$ su -
Senha:
#> apt install podman
#> exit
$ podman --version
podman version 5.4.2

O pacote já traz o que o modo rootless precisa (uidmap, slirp4netns/passt). Confira com podman info:

$ podman info --format "rootless={{.Host.Security.Rootless}} driver={{.Store.GraphDriverName}} rede={{.Host.NetworkBackend}} cgroup={{.Host.CgroupsVersion}}"
rootless=true driver=overlay rede=netavark cgroup=v2

Nomes curtos: de onde vem a imagem?

No Docker, nginx significa sempre "a imagem nginx do Docker Hub". O Podman é mais desconfiado: um nome curto poderia vir de qualquer registro, e um atacante poderia publicar uma imagem com o mesmo nome. Por isso o Debian traz uma lista de apelidos conhecidos, em /etc/containers/registries.conf.d/shortnames.conf:

$ grep -E '"(alpine|debian|ubuntu)"' /etc/containers/registries.conf.d/shortnames.conf
  "alpine" = "docker.io/library/alpine"
  "debian" = "docker.io/library/debian"
  "ubuntu" = "docker.io/library/ubuntu"

O hello-world está nessa lista apontando para a versão do próprio Podman, no quay.io. Um nome que não está na lista dá erro:

$ podman run --rm meuapp-xyz
Error: short-name "meuapp-xyz" did not resolve to an alias and no unqualified-search registries are defined in "/etc/containers/registries.conf"
Use sempre o nome completo

docker.io/library/nginx em vez de nginx. Fica claro de onde vem a imagem e o comando funciona igual em qualquer máquina.

Quem é o "root" lá dentro?

Aqui está a mágica do rootless. Dentro do container, o nginx principal roda como root. Fora dele, o Debian vê... a ana:

$ podman top web user huser pid args
USER        HUSER       PID         COMMAND
root        1000        1           nginx: master process nginx -g daemon off;    « root lá dentro = UID 1000 (ana) aqui fora
nginx       100100      28          nginx: worker process
nginx       100100      29          nginx: worker process
$ ps -o user,pid,cmd -C nginx
USER         PID CMD
ana       127943 nginx: master process nginx -g daemon off;
100100    127975 nginx: worker process
USER
O usuário dentro do container.
HUSER
O usuário no Debian (host user). O root de dentro vira a ana (1000); os outros usuários de dentro viram números de uma faixa reservada para ela.

Essa faixa é definida em /etc/subuid e /etc/subgid, que o Debian 13 preenche ao criar o usuário:

$ grep ana /etc/subuid /etc/subgid
/etc/subuid:ana:100000:65536
/etc/subgid:ana:100000:65536

Ou seja: a ana pode usar 65.536 identidades, de 100000 em diante. Mesmo que algo escape do container, cai num usuário sem poder nenhum no sistema.

Container como serviço: quadlets

Como não há daemon, quem cuida de iniciar e reiniciar containers é o systemd. O jeito atual é o quadlet: um arquivo .container que o systemd transforma num serviço.

[Unit]
Description=Site da Ana (nginx num container)

[Container]
Image=docker.io/library/nginx:latest
PublishPort=8080:80

[Service]
Restart=always

[Install]
WantedBy=default.target
$ mkdir -p ~/.config/containers/systemd
$ nano ~/.config/containers/systemd/web.container
$ systemctl --user daemon-reload
$ systemctl --user start web.service
$ systemctl --user status web.service --no-pager
● web.service - Site da Ana (nginx num container)
     Loaded: loaded (/home/ana/.config/containers/systemd/web.container; generated)   « gerado a partir do .container
     Active: active (running) since Thu 2026-10-15 22:43:42 -03; 3s ago
 Invocation: 6b134406f6d5441082d90a513bd7c01b
   Main PID: 128219 (conmon)
      Tasks: 5 (limit: 4638)
     Memory: 31.7M (peak: 59.5M)
        CPU: 423ms
$ podman ps --format "{{.Names}} {{.Status}}"
systemd-web Up 3 seconds                               « o container ganhou o nome systemd-web
--user
Fala com o systemd da ana, não com o do sistema. Nada de root.
daemon-reload
Faz o systemd ler o arquivo .container novo e gerar o web.service.
O serviço para quando a ana sai

Por padrão, o systemd de um usuário só roda enquanto ele está logado:

$ loginctl show-user ana -p Linger
Linger=no

Para o container continuar depois do logout e subir no boot, o root precisa ligar o linger: loginctl enable-linger ana.

Quando não funciona

"Failed to bind port 80 (Permission denied)" 
$ podman run -d --name w80 -p 80:80 docker.io/library/nginx
Failed to bind port 80 (Permission denied) for option '-t 80-80:80-80'

O que aconteceu: portas abaixo de 1024 são reservadas ao root, e a ana roda sem root.

Como resolver: use uma porta alta (-p 8080:80) e, se precisar da 80, coloque um proxy na frente (veja nginx). Outra saída, feita pelo root, é baixar o limite: sysctl net.ipv4.ip_unprivileged_port_start=80.

"short-name … did not resolve to an alias"

O que aconteceu: o nome curto não está na lista de apelidos do Debian.

Como resolver: use o nome completo: docker.io/library/redis, quay.io/organizacao/imagem.

"cannot find newuidmap" ou erros de "subuid"

O que aconteceu: falta o pacote uidmap, ou o usuário foi criado sem faixa em /etc/subuid (usuários antigos ou criados à mão).

Como confirmar: grep $USER /etc/subuid não mostra nada. Como resolver: como root, apt install uidmap e usermod --add-subuids 100000-165535 --add-subgids 100000-165535 ana; depois, como a ana, podman system migrate.

O container some quando eu fecho o SSH

O que aconteceu: o linger está desligado e o systemd da usuária terminou junto com a sessão.

Como resolver: como root, loginctl enable-linger ana.

Resumo

  • O Podman usa os mesmos comandos do Docker, sem daemon e sem root.
  • No Debian, nomes curtos passam por shortnames.conf; prefira nomes completos.
  • O root de dentro do container é a sua usuária do lado de fora.
  • Portas abaixo de 1024 exigem root; use portas altas.
  • Serviços: arquivo .container em ~/.config/containers/systemd + systemctl --user + enable-linger.
