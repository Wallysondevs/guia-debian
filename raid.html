Debian RAID (mdadm)

Discos quebram. RAID (Redundant Array of Independent Disks, "conjunto redundante de discos independentes") junta vários discos para que a falha de um não leve seus dados junto. No Debian, o RAID por software é feito pelo próprio kernel e controlado pelo programa mdadm.

Você vai aprender
  • Os níveis de RAID mais usados e quanto espaço cada um entrega.
  • Criar um espelho (RAID 1) e responder às perguntas do mdadm.
  • Ler o /proc/mdstat e o mdadm --detail.
  • Salvar a configuração no lugar certo do Debian.
  • Simular um disco com defeito, removê-lo e reconstruir com um disco novo.
RAID não é backup

RAID protege contra a falha de um disco. Ele não protege contra arquivo apagado por engano, vírus, incêndio ou erro de comando: o que você apaga num disco é apagado no outro na mesma hora. Continue fazendo backup.

Os comandos rodam como root (su -) na máquina fictícia servidor. As saídas vêm de um Debian 13 real com mdadm 4.4. O mdadm responde em inglês.

Conceito: os níveis de RAID

NívelComo funcionaDiscos mínimosEspaço útil (4 discos de 1 TB)Aguenta perder
RAID 0Divide os dados entre os discos (mais rápido)24 TBNenhum disco
RAID 1Cópia idêntica em todos os discos (espelho)21 TBTodos menos um

RAID 6Dados + paridade dupla42 TB2 discos
RAID 10Espelhos combinados (1 + 0)42 TB1 disco de cada espelho

Para um servidor pequeno com dois discos, o RAID 1 é a escolha mais comum: simples e seguro.

Laboratório seguro

Instale o mdadm e crie três "discos" de 512 MB com arquivos (dois para o espelho, um para ser o disco de troca):

#> apt install mdadm
#> truncate -s 512M m1.img m2.img m3.img
#> losetup -f --show m1.img
/dev/loop0
#> losetup -f --show m2.img
/dev/loop1
#> losetup -f --show m3.img
/dev/loop2

O pacote mdadm do Debian também traz timers do systemd (mdcheck_start.timer e mdcheck_continue.timer) que fazem verificações periódicas dos arrays, e cria o /etc/mdadm/mdadm.conf com MAILADDR root: os avisos de falha vão para o e-mail do root.

Criar um espelho (RAID 1)

mdadm --create /dev/md0
Cria um array novo chamado /dev/md0 (md = multiple devices).
--level=1
RAID 1, espelho.
--raid-devices=2
Quantos discos fazem parte do array.
/dev/loop0 /dev/loop1
Os discos (num servidor real: /dev/sdb /dev/sdc).

O mdadm 4.4 faz duas perguntas antes de criar:

#> mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/loop0 /dev/loop1
To optimalize recovery speed, it is recommended to enable write-indent bitmap, do you want to enable it now? [y/N]? y
mdadm: Note: this array has metadata at the start and
    may not be suitable as a boot device.  If you plan to
    store '/boot' on this device please ensure that
    your boot-loader understands md/v1.x metadata, or use
    --metadata=0.90
Continue creating array [y/N]? y
mdadm: Defaulting to version 1.2 metadata
mdadm: array /dev/md0 started.
  1. Bitmap: um pequeno mapa que registra quais áreas mudaram. Se um disco cair e voltar, o array só ressincroniza o que mudou, em vez de copiar tudo. Responda y.
  2. Metadados no início do disco: só importa se você for colocar o /boot no array. Para dados, responda y.

Em scripts, evite as perguntas passando as respostas como opções: --bitmap=internal --run.

Você pode usar o array enquanto ele sincroniza; só fica um pouco mais lento.

Usar o RAID

Para o resto do sistema, /dev/md0 é um disco comum: formate e monte.

#> mkfs.ext4 -q /dev/md0
#> mkdir -p /mnt/raid
#> mount /dev/md0 /mnt/raid
#> echo teste > /mnt/raid/a.txt

Salvar a configuração (essencial)

Para o array voltar com o mesmo nome depois de reiniciar, registre-o no arquivo de configuração. No Debian ele fica em /etc/mdadm/mdadm.conf:

#> mdadm --detail --scan
ARRAY /dev/md0 metadata=1.2 UUID=032d52dd:a7737174:c586c48f:26832879
#> mdadm --detail --scan >> /etc/mdadm/mdadm.conf
#> update-initramfs -u
update-initramfs: Generating /boot/initrd.img-6.12.111+deb13-amd64

O update-initramfs -u copia a configuração para a imagem de inicialização, que é quem monta os arrays bem no começo do boot. Para o array ser montado automaticamente, adicione-o ao /etc/fstab pelo UUID do sistema de arquivos (veja mount e fstab).

Sem esse passo

Depois de reiniciar, o array pode voltar com outro nome, como /dev/md127, e o fstab que usava /dev/md0 deixa de funcionar.

Simular um disco com defeito e trocá-lo

O treino mais importante: o que fazer quando um disco quebra. Primeiro, marque um disco como falho:

  1. Marque a falha (num servidor real, o kernel faz isso sozinho quando o disco dá erro): 
    #> mdadm /dev/md0 --fail /dev/loop1
#> cat /proc/mdstat
Personalities : [raid6] [raid5] [raid4] [raid1]
md0 : active raid1 loop1[1](F) loop0[0]                        « (F) = falhou
      523264 blocks super 1.2 [2/1] [U_]                       « só 1 de 2 funcionando
      bitmap: 1/1 pages [4KB], 65536KB chunk

unused devices: <none>
#> cat /mnt/raid/a.txt
teste                                                          « os dados continuam acessíveis
  2. Remova o disco quebrado do array: 
    #> mdadm /dev/md0 --remove /dev/loop1
mdadm: hot removed /dev/loop1 from /dev/md0
  3. Troque o disco fisicamente (no laboratório, o "disco novo" é o /dev/loop2) e adicione: 
    #> mdadm /dev/md0 --add /dev/loop2
mdadm: added /dev/loop2
#> cat /proc/mdstat
Personalities : [raid6] [raid5] [raid4] [raid1]
md0 : active raid1 loop2[2] loop0[0]
      523264 blocks super 1.2 [2/1] [U_]
      [======>..............]  recovery = 32.0% (167936/523264) finish=0.4min speed=13994K/sec   « copiando
      bitmap: 1/1 pages [4KB], 65536KB chunk

unused devices: <none>
  4. Acompanhe até o [UU] voltar. Enquanto isso, o --detail mostra o disco novo como spare rebuilding: 
    #> mdadm --detail /dev/md0 | tail -3
    Number   Major   Minor   RaidDevice State
       0       7        0        0      active sync   /dev/loop0
       2       7        2        1      spare rebuilding   /dev/loop2
Acompanhar ao vivo

watch -n 2 cat /proc/mdstat atualiza a tela a cada 2 segundos. Saia com Ctrl+C.

Outros níveis

O comando é o mesmo; mudam o --level e a quantidade de discos. Um RAID 5 com três discos, sem perguntas:

#> mdadm --create /dev/md1 --level=5 --raid-devices=3 /dev/loop0 /dev/loop1 /dev/loop2 --run
mdadm: Defaulting to version 1.2 metadata
mdadm: array /dev/md1 started.
#> cat /proc/mdstat
Personalities : [raid6] [raid5] [raid4] [raid1]
md1 : active raid5 loop2[3](S) loop1[1] loop0[0]
      1044480 blocks super 1.2 level 5, 512k chunk, algorithm 2 [3/2] [UU_]

unused devices: <none>

Repare no detalhe: logo depois de criar, o RAID 5 monta a paridade tratando o terceiro disco como reserva (S) e reconstruindo para ele. Quando terminar, o estado vira [3/3] [UUU]. O espaço útil é de dois discos (1044480 blocos ≈ 1 GB), porque um disco inteiro de espaço vai para a paridade.

Desmontar o laboratório

#> umount /mnt/raid
#> mdadm --stop /dev/md0
mdadm: stopped /dev/md0
#> mdadm --zero-superblock /dev/loop0 /dev/loop1 /dev/loop2     « apaga a marca de RAID dos discos
#> losetup -d /dev/loop0 /dev/loop1 /dev/loop2
#> rm m1.img m2.img m3.img

Quando não funciona

"mdadm: create aborted." 
Continue creating array [y/N]? n
mdadm: create aborted.

O que aconteceu: você respondeu n (ou só apertou Enter, que vale N) na pergunta final.

Como resolver: rode de novo e responda y, ou use --run para não perguntar.

O array voltou como /dev/md127 depois de reiniciar

O que aconteceu: a configuração não foi salva no /etc/mdadm/mdadm.conf ou o initramfs não foi atualizado.

Como resolver: confira com cat /proc/mdstat, salve com mdadm --detail --scan >> /etc/mdadm/mdadm.conf (apague linhas repetidas), rode update-initramfs -u e reinicie.

"[2/1] [U_]" e ninguém percebeu

O que aconteceu: um disco falhou e o array seguiu funcionando, degradado. Se o segundo disco falhar, os dados se perdem.

Como resolver: troque o disco o quanto antes. Para ser avisado, configure o e-mail do administrador: a linha MAILADDR do /etc/mdadm/mdadm.conf (o Debian já vem com MAILADDR root) e um servidor de e-mail funcionando.

"Unrecognised md component device" 
#> mdadm --zero-superblock /dev/loop2
mdadm: Unrecognised md component device - /dev/loop2

O que aconteceu: o disco não tem marca de RAID. Não é um erro grave: não havia nada para apagar.

Exercícios

1. Espelho

Complete para criar um RAID 1 com dois discos:

mdadm --create /dev/md0 --level= --raid-devices= /dev/sdb /dev/sdc

2. Onde salvar

No Debian, qual é o caminho do arquivo de configuração do mdadm?

3. O /proc/mdstat mostra [2/1] [U_]. O que significa?

4. Quatro discos de 2 TB em RAID 5 entregam quanto espaço útil?

Resumo

  • RAID 1 espelha, RAID 5/6 usam paridade, RAID 0 só ganha velocidade (sem proteção).
  • mdadm --create cria; o mdadm 4.4 pergunta sobre o bitmap e sobre os metadados.
  • /proc/mdstat: [UU] é saudável, [U_] é degradado, (F) é disco falho.
  • Salve em /etc/mdadm/mdadm.conf e rode update-initramfs -u.
  • Troca de disco: --fail → --remove → trocar → --add → esperar o [UU].
  • RAID não substitui backup.
