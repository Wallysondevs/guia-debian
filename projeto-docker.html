Projeto App com Docker

Você vai colocar no ar um aplicativo de verdade, o Uptime Kuma (um painel que avisa quando seus sites caem), sem instalar nada dele no Debian: tudo roda dentro de um container. Os dados ficam num volume que sobrevive a atualizações. No fim, você faz backup desse volume e atualiza o app com dois comandos.

Ao terminar você terá
  • O Docker e o Docker Compose instalados do repositório do Debian (docker.io e docker-compose).
  • Um arquivo compose.yaml que descreve o app inteiro.
  • O Uptime Kuma respondendo na porta 3001, com os dados num volume.
  • Um backup do volume em .tar.gz e a rotina de atualização.

Docker do Debian ou da Docker Inc.?

O Debian empacota o Docker como docker.io, com versões estáveis e atualizações de segurança do próprio Debian. A empresa Docker oferece o docker-ce num repositório separado, com versões mais novas. Para aprender e para a maioria dos servidores, o do Debian basta. Veja Docker.

As etapas

  1. Instalar o Docker e o Compose

    $ sudo apt install docker.io docker-compose
$ docker --version
Docker version 26.1.5+dfsg1, build a72d7cd
$ docker compose version
Docker Compose version 2.26.1-4
$ systemctl is-active docker
active

    Repare que o comando é docker compose (com espaço). O pacote docker-compose do Debian 13 instala a versão 2, que funciona como um "subcomando" do docker.

  2. Decidir quem pode usar o Docker

    Sem permissão, a ana recebe:

    $ docker ps
permission denied while trying to connect to the Docker daemon socket at unix:///var/run/docker.sock: Get "http://%2Fvar%2Frun%2Fdocker.sock/v1.45/containers/json": dial unix /var/run/docker.sock: connect: permission denied

    Há dois caminhos: usar sudo docker … sempre, ou colocar a ana no grupo docker:

    $ sudo usermod -aG docker ana
    O grupo docker vale tanto quanto ser root

    Quem pode rodar containers pode montar o / do servidor dentro de um container e mexer em qualquer arquivo. Só coloque no grupo quem você colocaria no sudo. Neste projeto, por clareza, usamos sudo docker.

  3. Escrever o compose.yaml

    O que vamos fazer e por quê: em vez de um docker run enorme, descrevemos o app num arquivo. Ele vira a documentação e pode ir para o Git.

    $ sudo mkdir -p /srv/monitor
$ cd /srv/monitor
$ sudo nano compose.yaml
    services:
  kuma:
    image: louislam/uptime-kuma:1      # imagem e versão (tag "1")
    container_name: kuma
    restart: unless-stopped            # volta sozinho após reboot ou falha
    ports:
      - "3001:3001"                    # porta do Debian : porta do container
    volumes:
      - kuma-dados:/app/data           # volume com nome : pasta dentro do container

volumes:
  kuma-dados:
    $ sudo docker compose config --quiet && echo "config ok"
config ok

    O config --quiet confere o YAML sem subir nada. Um erro de indentação aparece aqui, com a linha.

  4. Subir o app

    $ sudo docker compose up -d
[+] Running 6/6
 ✔ kuma Pulled
 ✔ Network monitor_default    Created      « uma rede só para este projeto
 ✔ Volume "monitor_kuma-dados" Created     « o volume, com o nome da pasta na frente
 ✔ Container kuma             Started

    Na primeira vez, o Docker baixa a imagem (várias camadas, alguns minutos). O -d (de detached) devolve o terminal; o app continua rodando em segundo plano. O prefixo monitor_ vem do nome da pasta, que vira o nome do projeto.

    Confira:

    $ sudo docker compose ps
NAME      IMAGE                    COMMAND                  SERVICE   CREATED          STATUS                             PORTS
kuma      louislam/uptime-kuma:1   "/usr/bin/dumb-init …"   kuma      55 seconds ago   Up 40 seconds (health: starting)   0.0.0.0:3001->3001/tcp, :::3001->3001/tcp
$ sudo docker compose logs --tail 3 kuma
kuma  | 2026-10-16T02:01:36Z [SERVER] INFO: Init the server
kuma  | 2026-10-16T02:01:36Z [SERVER] INFO: Listening on 3001       « pronto
kuma  | 2026-10-16T02:01:36Z [SERVICES] INFO: Starting nscd
$ wget -S -qO /dev/null http://127.0.0.1:3001 2>&1 | head -3
  HTTP/1.1 302 Found
  X-Frame-Options: SAMEORIGIN
  Location: /dashboard

    O health: starting some depois de um minuto e vira healthy. A resposta 302 é o app redirecionando para o painel: está vivo. Para abrir no navegador do seu computador, redirecione a porta da VM (desligada): VBoxManage modifyvm lab --natpf1 "kuma,tcp,127.0.0.1,3001,,3001" e acesse http://localhost:3001.

    Se deu errado: "port is already allocated" 
    docker: Error response from daemon: driver failed programming external connectivity on endpoint kuma-dup (106acad3…): Bind for 0.0.0.0:3001 failed: port is already allocated.

    Outro container (ou programa) já usa a porta 3001. Veja quem com sudo ss -tlnp | grep 3001 ou sudo docker ps, e troque o lado esquerdo do ports (por exemplo, "3002:3001").

  5. Onde os dados moram

    $ sudo docker volume ls
DRIVER    VOLUME NAME
local     monitor_kuma-dados
$ sudo docker volume inspect monitor_kuma-dados --format '{{ .Mountpoint }}'
/var/lib/docker/volumes/monitor_kuma-dados/_data
$ sudo docker exec kuma ls /app/data
docker-tls
kuma.db
kuma.db-shm
kuma.db-wal
screenshots
upload

    O banco do app (kuma.db) está no volume, que fica em /var/lib/docker/volumes no Debian. Apagar o container não apaga o volume: é isso que permite atualizar sem perder nada.

  6. Backup do volume

    O que vamos fazer e por quê: um container descartável, com o volume montado só para leitura, empacota os dados num .tar.gz na pasta do projeto.

    docker run --rm
    Roda um container e apaga ele no fim.
    -v monitor_kuma-dados:/dados:ro
    Monta o volume em /dados, somente leitura (read-only).
    -v /srv/monitor:/destino
    Monta a pasta do Debian onde o arquivo vai ficar.
    debian:trixie
    A imagem usada só para ter o tar.
    tar czf /destino/kuma-backup.tar.gz -C /dados .
    O comando que roda lá dentro.
    $ sudo docker run --rm -v monitor_kuma-dados:/dados:ro -v /srv/monitor:/destino debian:trixie tar czf /destino/kuma-backup.tar.gz -C /dados .
$ ls -lh /srv/monitor/kuma-backup.tar.gz
-rw-r--r-- 1 root root 29K out 15 23:02 /srv/monitor/kuma-backup.tar.gz

    Leve esse arquivo para o seu Backup Automático. Para restaurar, use o mesmo truque ao contrário: tar xzf com o volume montado sem :ro.

  7. Atualizar o app

    $ sudo docker compose pull
 kuma Pulling
 kuma Pulled
$ sudo docker compose up -d
 Container kuma  Running              « já estava na versão mais nova: nada a fazer
$ sudo docker images louislam/uptime-kuma
REPOSITORY             TAG       IMAGE ID       CREATED       SIZE
louislam/uptime-kuma   1         ded82109b2b8   4 weeks ago   448MB

    Quando há versão nova, o up -d recria o container com a imagem nova e o mesmo volume. Imagens antigas ficam ocupando espaço até você rodar sudo docker image prune.

  8. Parar sem perder os dados

    $ sudo docker compose down
 Container kuma  Removing
 Container kuma  Removed
 Network monitor_default  Removing
 Network monitor_default  Removed
$ sudo docker volume ls
DRIVER    VOLUME NAME
local     monitor_kuma-dados          « o volume continua lá

    Um docker compose up -d depois disso traz o app de volta com todos os monitores cadastrados.

    Cuidado com o down -v

    O -v apaga também os volumes, ou seja, os dados do app. Use só quando quiser começar do zero, e com backup.

E com Podman?

O Debian também empacota o Podman, que roda containers sem um serviço central e sem precisar de root. O mesmo compose.yaml funciona com sudo apt install podman podman-compose e podman-compose up -d (troque a imagem por docker.io/louislam/uptime-kuma:1, com o endereço completo). Veja Podman.

Checklist do que você aprendeu

  • No Debian: apt install docker.io docker-compose, e o comando é docker compose.
  • O grupo docker equivale a root.
  • compose.yaml descreve imagem, portas, volumes e reinício; config --quiet confere.
  • Os dados ficam em volumes (/var/lib/docker/volumes) e sobrevivem ao down.
  • Backup de volume com um container --rm e tar; atualização com pull + up -d.

Desafios extras

  • Coloque o Uptime Kuma atrás do Apache do Servidor Web como proxy reverso (a2enmod proxy proxy_http proxy_wstunnel), com HTTPS.
  • Agende o backup do volume num systemd timer, como no Backup Automático.
  • Restaure o backup num volume novo e suba uma segunda cópia do app na porta 3002.

Limpeza

$ sudo docker compose down -v
 Volume monitor_kuma-dados  Removing
 Volume monitor_kuma-dados  Removed
$ sudo docker rmi louislam/uptime-kuma:1
$ sudo rm -rf /srv/monitor

Resumo

  • Docker do Debian: docker.io + docker-compose, comando docker compose.
  • App = compose.yaml; dados = volume; atualizar = pull + up -d.
  • Proteja o volume com backup e o servidor com cuidado no grupo docker.
