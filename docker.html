Debian Docker

O Docker roda programas dentro de containers: caixas isoladas que já trazem tudo o que o programa precisa. Com ele você sobe um servidor web, um banco de dados ou um app inteiro com um comando, sem bagunçar o seu Debian, e apaga tudo com outro comando.

Você vai aprender
  • A diferença entre container, imagem e máquina virtual.
  • As duas formas de instalar o Docker no Debian (docker.io e docker-ce), e qual escolher.
  • Como liberar o Docker para a sua usuária sem sudo, do jeito Debian.
  • O que cada parte de docker run -d -p 8080:80 --name web nginx faz.
  • Volumes, Dockerfile, Compose e os erros mais comuns.

As saídas desta página vêm do Debian 13 de laboratório (usuária ana, máquina notebook). IDs, tamanhos e horários mudam a cada execução.

Prefere sem daemon e sem root?

O Debian também empacota o Podman, que usa os mesmos comandos do Docker e roda como usuário comum. Vale ler as duas aulas.

Forma 2: repositório oficial da Docker

O passo a passo atual fica em docs.docker.com/engine/install/debian. A ideia, como root: baixar a chave da Docker para /etc/apt/keyrings, criar o arquivo do repositório apontando para ela com signed-by e instalar.

#> nano /etc/apt/sources.list.d/docker.sources

Usar sem root: o grupo docker

O comando docker conversa com o serviço por um arquivo especial, o socket /var/run/docker.sock. Só o root e quem está no grupo docker podem usá-lo. A ana, logo depois da instalação:

$ docker ps
permission denied while trying to connect to the Docker daemon socket at unix:///var/run/docker.sock: Get "http://%2Fvar%2Frun%2Fdocker.sock/v1.45/containers/json": dial unix /var/run/docker.sock: connect: permission denied
$ echo $?
1
$ groups
ana cdrom floppy audio dip video plugdev users netdev     « nada de docker

Para liberar, o root coloca a ana no grupo. Repare que o usermod está em /usr/sbin, fora do PATH da ana; por isso ele roda na sessão de root:

usermod
Altera uma conta (veja Usuários e Grupos).
-aG docker
-a = acrescentar, -G docker = ao grupo docker. Sem o -a, a ana sairia de todos os outros grupos.
ana
A usuária.
#> usermod -aG docker ana
#> groups ana
ana : ana cdrom floppy audio dip video plugdev users netdev docker

Depois de sair e entrar de novo, na sessão da ana:

$ groups
ana cdrom floppy audio dip video plugdev users netdev docker
$ docker ps
CONTAINER ID   IMAGE     COMMAND   CREATED   STATUS    PORTS     NAMES     « funcionou (lista vazia)

O grupo novo só vale em sessões novas: saia e entre de novo (ou use newgrp docker no terminal atual).

Atenção: grupo docker = poder de root

Quem está no grupo docker consegue montar o disco inteiro dentro de um container e mexer em qualquer arquivo do sistema. É o mesmo que dar a senha de root. Num Debian em que a ana propositalmente não tem sudo, pense duas vezes; o Podman sem root é a alternativa segura.

Guardar dados: volumes

Tudo o que um programa grava dentro do container some quando o container é apagado. Para guardar dados, ligue uma pasta de fora a uma de dentro:

-v ~/site:/usr/share/nginx/html
pasta-do-debian:pasta-do-container. O que você muda em ~/site aparece na hora no container.
:ro
read-only: o container só lê.
$ mkdir ~/site
$ echo "<h1>Site da Ana</h1>" > ~/site/index.html
$ docker run -d -p 8080:80 --name web -v ~/site:/usr/share/nginx/html:ro nginx
$ curl -s localhost:8080
<h1>Site da Ana</h1>                         « o nginx serve o arquivo da sua pasta
$ docker volume create dados-db
dados-db
$ docker volume ls
DRIVER    VOLUME NAME
local     dados-db
$ docker volume inspect dados-db --format "{{.Mountpoint}}"
/var/lib/docker/volumes/dados-db/_data
FormaExemploMelhor quando…
Pasta do Debian (bind mount)-v ~/site:/dadosVocê edita os arquivos (código, site, configurações).
Volume nomeado-v dados-db:/dadosOs dados são do programa (banco de dados). Ficam em /var/lib/docker/volumes.
Sem volume(nada)Os dados podem sumir (testes).

Vários containers: Compose

Com o pacote docker-compose do Debian, você descreve vários containers num arquivo compose.yaml e sobe tudo com docker compose up -d:

services:
  web:
    image: nginx
    ports:
      - "8080:80"
    volumes:
      - ./site:/usr/share/nginx/html:ro
    restart: unless-stopped
$ docker compose up -d
[+] Running 2/2
 ✔ Network projeto_default  Created                « uma rede só para este projeto
 ✔ Container projeto-web-1  Started
$ docker compose ps
NAME            IMAGE     COMMAND                  SERVICE   CREATED          STATUS         PORTS
projeto-web-1   nginx     "/docker-entrypoint.…"   web       14 seconds ago   Up 2 seconds   0.0.0.0:8080->80/tcp, :::8080->80/tcp
$ docker compose down
[+] Running 2/2
 ✔ Container projeto-web-1  Removed
 ✔ Network projeto_default  Removed

O pacote do Debian instala o Compose versão 2 (Docker Compose version 2.26.1-4), que funciona tanto como docker compose quanto como docker-compose.

Quando não funciona

"permission denied while trying to connect to the Docker daemon socket"

O que aconteceu: a usuária não está no grupo docker, ou entrou nele e ainda não abriu sessão nova.

Como confirmar: groups não mostra docker.

Como resolver: como root, usermod -aG docker ana; depois saia e entre de novo.

"sudo: comando não encontrado" ao seguir um tutorial

O que aconteceu: a maioria dos tutoriais da internet supõe Ubuntu, com sudo docker …. No Debian instalado com senha de root, não há sudo.

Como resolver: rode o comando numa sessão de root (su -), sem o sudo na frente; ou instale e configure o sudo (veja root, su e sudo).

"Cannot connect to the Docker daemon … Is the docker daemon running?"

Como confirmar: systemctl is-active docker mostra inactive ou failed.

Como resolver: como root, systemctl enable --now docker; se não subir, journalctl -u docker -n 30 mostra o motivo (veja Logs).

"port is already allocated"

O que aconteceu: outra coisa já usa a porta do Debian (outro container ou um nginx instalado pelo apt).

Como confirmar: ss -tlnp | grep 8080 como root (veja ip, ping, ss). Como resolver: use outra porta (-p 8081:80) ou pare o que está ocupando.

"TLS handshake timeout" ao baixar uma imagem 
$ docker build -t vaca:1.0 .
…
ERROR: failed to solve: debian:trixie-slim: failed to resolve source metadata for docker.io/library/debian:trixie-slim: failed to authorize: failed to fetch anonymous token: Get "https://auth.docker.io/token?scope=repository%3Alibrary%2Fdebian%3Apull&service=registry.docker.io": net/http: TLS handshake timeout

O que aconteceu: a conexão com o Docker Hub demorou demais. É um problema de rede, não do seu Dockerfile.

Como resolver: tente de novo. Se repetir, teste a rede com curl -I https://registry-1.docker.io e veja Conceitos de Rede.

O container sai logo depois de subir

O que aconteceu: o programa de dentro terminou ou deu erro. Um container só vive enquanto o programa principal vive.

Como confirmar: docker ps -a mostra Exited (1) e docker logs nome mostra o erro.

As regras de firewall "sumiram" ou o container ignora o firewall

O que aconteceu: o Docker cria regras próprias de iptables (no Debian 13, traduzidas para o nftables) para publicar portas. Uma porta com -p fica acessível mesmo que o seu firewall pareça bloqueá-la.

Como resolver: publique só para a máquina local quando não precisar de acesso de fora: -p 127.0.0.1:8080:80. Veja nftables.

Resumo

  • Imagem é a receita; container é a imagem rodando.
  • docker.io vem do Debian; docker-ce vem da Docker, com repositório e Signed-By.
  • Sem sudo no Debian: instale com su - e, se quiser, coloque a usuária no grupo docker (que equivale a root).
  • docker run -d -p 8080:80 --name web nginx: segundo plano, porta, nome, imagem.
  • Dados que importam vão em volumes; vários containers, em Compose.
