Debian Instalação Automática (preseed)

O instalador do Debian faz umas trinta perguntas: idioma, teclado, rede, senha, partições, programas. Para uma máquina, tudo bem. Para dez servidores iguais, ou para uma VM que você recria toda semana, é trabalho repetido e sujeito a erro. O preseed ("pré-semear") é um arquivo de texto com todas as respostas prontas: você dá o arquivo ao instalador e ele termina sozinho.

Você vai aprender
  • Como cada linha de um preseed é montada (dono, pergunta, tipo, valor).
  • As três formas de entregar o arquivo ao instalador: file=, url= e dentro do initrd.
  • Um preseed completo, comentado linha a linha: o mesmo que instalou a VM usada neste guia.
  • Como escolher partições (partman), programas (tasksel) e rodar comandos no fim (late_command).
  • Como descobrir o nome de uma pergunta e testar o arquivo numa VM antes de usar de verdade.
Feito de verdade

A máquina de laboratório deste guia (Debian 13.7, usuária ana, máquina notebook) foi instalada com o preseed desta página, sem nenhum clique. As saídas abaixo vêm dela.

Conceito: o instalador é um questionário

Por baixo dos panos, cada pergunta do instalador é uma pergunta do debconf, o sistema de configuração do Debian (o mesmo que faz perguntas quando você instala alguns pacotes). Cada pergunta tem um nome único, como passwd/username. O preseed só diz ao debconf: "para a pergunta tal, a resposta já é esta".

Uma linha de preseed tem sempre quatro partes:

d-i
Dono da pergunta. d-i = debian-installer, o próprio instalador. Perguntas de pacotes usam o nome do pacote (tasksel, popularity-contest).
passwd/username
Nome da pergunta: "qual o login do primeiro usuário?".
string
Tipo da resposta: string (texto), boolean (true/false), select (uma opção), multiselect (várias, separadas por vírgula), password, note.
ana
Valor: a resposta. Tudo até o fim da linha.

Linhas que começam com # são comentários. Uma linha muito longa pode continuar na seguinte terminando com \.

Como o instalador encontra o arquivo

O preseed é passado na linha de boot do instalador: os parâmetros que você digita (ou que já vêm prontos) antes de ele começar. Há três formas:

FormaParâmetro de bootMelhor quando…
Arquivo no pendrive/ISOauto=true preseed/file=/cdrom/preseed.cfgVocê monta sua própria mídia de instalação.
Pela redeauto=true url=http://192.168.0.10/preseed.cfgVárias máquinas na mesma rede: o arquivo fica num servidor web e você muda num lugar só.
Dentro do initrd(nenhum: o arquivo /preseed.cfg dentro do initrd.gz é lido sozinho)Quando a rede ainda não existe no começo da instalação (perguntas de idioma e rede também ficam respondidas).

A VM deste guia usou a primeira forma. O próprio instalador deixa a linha de boot registrada no log:

#> grep -m1 "Command line" /var/log/installer/syslog
Oct 15 23:10:25 kernel: [    0.000000] Command line: BOOT_IMAGE=/install.amd/vmlinuz vga=788 initrd=/install.amd/initrd.gz --- quiet  auto=true preseed/file=/cdrom/preseed.cfg priority=critical quiet splash noprompt noshell automatic-ubiquity debian-installer/locale=pt_BR keyboard-configuration/layoutcode=us languagechooser/language-name=English localechooser/supported-locales=pt_BR.UTF-8 countrychooser/shortlist=BR --

As partes que importam:

auto=true
Modo automático: adia as perguntas de idioma e rede até o preseed ser carregado, para que ele possa respondê-las.
preseed/file=/cdrom/preseed.cfg
Onde está o arquivo. /cdrom é a mídia de instalação. A forma curta é file=.
priority=critical
Só pergunta o que for crítico. Qualquer pergunta que o preseed esquecer e tiver resposta padrão usa o padrão em vez de parar.
debian-installer/locale=pt_BR
Respostas também podem ir direto na linha de boot, no formato pergunta=valor.
Linha de boot também conta

Repare que essa linha diz keyboard-configuration/layoutcode=us, mas o preseed pede teclado br. Quando os dois respondem a mesma pergunta, vale o que for lido por último, e o arquivo é lido depois da linha de boot. Por isso a VM ficou com teclado ABNT2.

Um preseed completo, comentado

Este é o arquivo que instalou a VM do guia, só com as senhas e a chave SSH trocadas por marcadores. Ele faz uma instalação "típica" do Debian: português do Brasil, teclado ABNT2, root com senha e a usuária comum sem sudo, sistema padrão e servidor SSH.

### Idioma, país e teclado
d-i debian-installer/locale string pt_BR.UTF-8
d-i debian-installer/language string pt_BR
d-i debian-installer/country string BR
# idiomas extras a gerar (o en_US ajuda a ler erros em inglês)
d-i localechooser/supported-locales multiselect pt_BR.UTF-8, en_US.UTF-8
d-i console-setup/ask_detect boolean false
d-i keyboard-configuration/xkb-keymap select br
d-i keyboard-configuration/layoutcode string br
d-i keyboard-configuration/modelcode string abnt2

### Rede
# escolhe sozinho a primeira placa com cabo/sinal
d-i netcfg/choose_interface select auto
d-i netcfg/get_hostname string notebook
d-i netcfg/get_domain string lan
# força o nome mesmo que o DHCP sugira outro
d-i netcfg/hostname string notebook

### Espelho (de onde vêm os pacotes)
d-i mirror/country string manual
d-i mirror/http/hostname string deb.debian.org
d-i mirror/http/directory string /debian
d-i mirror/http/proxy string

### Relógio e fuso horário
d-i clock-setup/utc boolean true
d-i time/zone string America/Sao_Paulo
d-i clock-setup/ntp boolean true

### Disco (CUIDADO: apaga o disco inteiro)
d-i partman-auto/disk string /dev/sda
d-i partman-auto/method string regular
# atomic = tudo numa partição só (+ swap)
d-i partman-auto/choose_recipe select atomic
d-i partman-partitioning/confirm_write_new_label boolean true
d-i partman/choose_partition select finish
d-i partman/confirm boolean true
d-i partman/confirm_nooverwrite boolean true

### Contas
# root com senha => o primeiro usuário NÃO entra no grupo sudo
d-i passwd/root-login boolean true
d-i passwd/root-password-crypted password $6$SAL$HASH-DA-SENHA-DO-ROOT
d-i passwd/user-fullname string Ana
d-i passwd/username string ana
d-i passwd/user-password-crypted password $6$SAL$HASH-DA-SENHA-DA-ANA

### Repositórios e programas
d-i apt-setup/non-free-firmware boolean true
d-i apt-setup/services-select multiselect security, updates
tasksel tasksel/first multiselect standard, ssh-server
d-i pkgsel/include string openssh-server locales
# instala as atualizações já durante a instalação
d-i pkgsel/upgrade select safe-upgrade
popularity-contest popularity-contest/participate boolean false

### Carregador de boot e fim
d-i grub-installer/only_debian boolean true
d-i grub-installer/bootdev string default
d-i finish-install/reboot_in_progress note

### Comando final: roda no sistema recém-instalado
d-i preseed/late_command string \
  in-target sh -c 'mkdir -p /home/ana/.ssh && echo "ssh-ed25519 AAAA...SUA-CHAVE" > /home/ana/.ssh/authorized_keys && chmod 700 /home/ana/.ssh && chmod 600 /home/ana/.ssh/authorized_keys && chown -R ana:ana /home/ana/.ssh'

Nas próximas seções, cada bloco é explicado com mais calma.

Senhas: nunca em texto puro

O preseed aceita a senha "limpa" (passwd/root-password password segredo), mas qualquer pessoa que veja o arquivo descobre a senha. Use a versão -crypted com um hash: uma versão embaralhada da senha que não dá para desembaralhar.

mkpasswd
Gera o hash de uma senha (pacote whois).
-m sha-512
O método. O hash começa com $6$, que o instalador entende.
$ mkpasswd -m sha-512
Senha:                                      « digite a senha (nada aparece)
$6$U4txSsGiZZKYCDsB$h2S6CGmUOUKFSNIiqInG…   « o hash: copie a linha inteira

O mkpasswd vem no pacote whois e fica em /usr/bin, então a ana consegue usar sem root.

Cole a linha inteira que começa com $6$ depois de password. Mesmo com hash, trate o arquivo como confidencial: um hash fraco ainda pode ser quebrado por força bruta.

root com senha ou sudo? Uma linha decide

Esta é a diferença que mais surpreende quem vem do Ubuntu, e ela nasce no instalador:

PreseedResultado
d-i passwd/root-login boolean true + senha de rootroot tem senha; o primeiro usuário não tem sudo (o pacote nem é instalado). Para administrar: su -. É o caso da VM deste guia.
d-i passwd/root-login boolean falseroot fica sem senha (bloqueado); o sudo é instalado e o primeiro usuário entra no grupo sudo. Fica igual ao Ubuntu.

Veja na VM: a ana não tem o grupo sudo, e o comando nem existe.

$ groups
ana cdrom floppy audio dip video plugdev users netdev
$ sudo ls
bash: sudo: comando não encontrado

Detalhes em root, su e sudo.

Partições: partman

O particionador do instalador se chama partman. O jeito mais simples é usar uma das três "receitas" prontas, as mesmas da instalação manual:

ReceitaO que criaPara quem
atomicUma partição / com tudo + swapIniciantes, VMs, a maioria dos usos
home/ e /home separados + swapQuem quer reinstalar o sistema sem perder os arquivos pessoais
multi/, /home, /var e /tmp separados + swapServidores
d-i partman-auto/method string regular
Partições comuns. Outras opções: lvm (veja LVM) e crypto (LVM criptografado).
d-i partman-auto/choose_recipe select atomic
A receita.
partman/confirm… true
As quatro linhas de confirmação respondem "sim, pode gravar no disco".
Atenção: o preseed apaga o disco sem perguntar

Com essas linhas, o instalador formata /dev/sda sem nenhuma confirmação. Nunca deixe um pendrive com preseed automático conectado a um computador com dados, e confira o nome do disco (/dev/sda, /dev/nvme0n1, /dev/vda).

Na VM, o instalador registrou a receita escolhida:

#> grep -A1 "Name: partman-auto/choose_recipe" /var/log/installer/cdebconf/questions.dat
Name: partman-auto/choose_recipe
Value: /lib/partman/recipes-amd64/30atomic

Programas: tasksel e pkgsel

O tasksel instala grupos prontos de programas, as "tarefas". São as caixinhas da tela "Seleção de software" do instalador. A lista real, tirada da VM:

#> tasksel --list-tasks
u desktop	ambiente de área de trabalho no Debian
u gnome-desktop	GNOME
u xfce-desktop	Xfce
u gnome-flashback-desktop	GNOME Flashback
u kde-desktop	KDE Plasma
u cinnamon-desktop	Cinnamon
u mate-desktop	MATE
u lxde-desktop	LXDE
u lxqt-desktop	LXQt
u web-server	servidor web
i ssh-server	servidor SSH                       « i = instalada, u = não instalada
u laptop	laptop
u blendsel	Choose a Debian Blend for installation

No preseed, você usa os nomes da segunda coluna. A tarefa standard (utilitários básicos) não aparece na lista, mas existe e quase sempre vai junto:

LinhaResultado

tasksel tasksel/first multiselect standard, desktop, gnome-desktopDesktop com GNOME
tasksel tasksel/first multiselect standard, desktop, xfce-desktopDesktop leve com Xfce

Comandos no fim: late_command

O preseed/late_command roda depois que tudo foi instalado, antes do reinício. Detalhe importante: nesse momento o sistema novo está montado em /target, e o instalador ainda está rodando por cima dele.

d-i preseed/late_command string
A pergunta e o tipo.
in-target
Roda o comando dentro do sistema novo (como um chroot /target). Sem ele, o comando roda no instalador e os caminhos precisam do prefixo /target.
sh -c '…'
Um shell para juntar vários comandos com &&.

Usos comuns: copiar uma chave SSH (como na VM do guia), instalar o sudo e colocar alguém no grupo, baixar um script de configuração.

### exemplo: root com senha, mas a ana também ganha sudo
d-i pkgsel/include string sudo
d-i preseed/late_command string in-target usermod -aG sudo ana

Descobrir o nome de uma pergunta

Ninguém decora os nomes. Há três jeitos de descobri-los:

  1. O exemplo oficial. O Debian publica um preseed de exemplo com quase tudo comentado: procure "example-preseed.txt" no site do Debian e no apêndice B do Guia de Instalação.
  2. O que o instalador respondeu. Depois de uma instalação manual, as perguntas e respostas ficam em /var/log/installer/cdebconf/questions.dat, e o debconf-get-selections --installer (pacote debconf-utils) as mostra já no formato de preseed.
  3. Perguntas de pacotes. debconf-get-selections | grep pacote mostra as respostas dos pacotes instalados.
#> apt install debconf-utils
#> debconf-get-selections --installer | grep -E "passwd/username|tasksel/first"
d-i	passwd/username	string	ana
user-setup-udeb	passwd/username	string	ana
user-setup-udeb	passwd/username-bad	error
user-setup-udeb	passwd/username-reserved	error
d-i	tasksel/first	string	standard, ssh-server

A saída vem separada por tabulações e traz algumas linhas internas (como as do tipo error), que você pode ignorar. Copie só as que interessam para o seu arquivo.

Esse é o caminho mais seguro para montar um preseed: instale uma vez à mão, do jeito que você quer, e copie as respostas.

Testar antes de usar

1. Conferir a sintaxe

O debconf-set-selections -c (de check) lê o arquivo e reclama de linhas mal formadas, sem aplicar nada:

#> debconf-set-selections -c preseed.cfg
#> echo $?
0                                           « nenhuma reclamação: sintaxe certa
#> debconf-set-selections -c ruim.cfg
warning: Unknown type ana, skipping line 1           « faltou o tipo (string)
warning: Unknown type booleano, skipping line 3      « o tipo é "boolean", em inglês
#> echo $?
0
Atenção: o código de saída é 0 mesmo com avisos

Leia a saída. Um script que confia só no $? deixaria passar um preseed com linhas ignoradas. E o teste confere só a forma das linhas, não se os nomes das perguntas existem: isso só uma instalação de teste mostra.

2. Instalar numa VM

  1. Crie uma VM com um disco vazio (VirtualBox, KVM).
  2. Sirva o arquivo pela rede com um servidor web de teste: python3 -m http.server 8000 na pasta do preseed.cfg.
  3. No menu do instalador, escolha Advanced options → Automated install, ou aperte Esc e digite auto url=http://IP-DO-SEU-PC:8000/preseed.cfg.
  4. Acompanhe. Se ele parar numa pergunta, é uma resposta que faltou: anote o nome da tela e acrescente a linha.
Atalho do VirtualBox

O VBoxManage unattended install --script-template=preseed.cfg monta a mídia e passa o arquivo sozinho. Foi assim que a VM deste guia nasceu.

Quando não funciona

O instalador parou numa pergunta

O que aconteceu: o preseed não respondeu aquela pergunta, ou respondeu com um valor que não existe na lista.

Como confirmar: aperte Alt+F4 no instalador para ver o log (no fim aparece o nome da pergunta). Depois da instalação, o mesmo log fica em /var/log/installer/syslog.

Como resolver: acrescente a linha que falta. Use priority=critical na linha de boot para que perguntas não críticas usem o valor padrão.

Perguntou idioma e teclado antes de ler o arquivo

O que aconteceu: faltou auto=true. Sem ele, o arquivo só é lido depois das primeiras perguntas (idioma, país, teclado, rede).

Como resolver: use auto=true na linha de boot, ou coloque o preseed dentro do initrd.

O late_command "não fez nada"

O que aconteceu: quase sempre falta o in-target, e o comando rodou no instalador em vez do sistema novo. Ou um erro no meio interrompeu a corrente de &&.

Como resolver: use in-target, ou o prefixo /target nos caminhos. Procure "late_command" em /var/log/installer/syslog para ver a saída.

Não consigo usar sudo depois da instalação

O que aconteceu: o preseed tinha passwd/root-login boolean true. Esse é o comportamento esperado do Debian.

Como resolver: entre como root com su -, instale o sudo e adicione o usuário ao grupo (veja root, su e sudo). Na próxima vez, use root-login false ou o late_command mostrado acima.

Exercícios

1. O tipo certo

Complete a linha que responde "sim" à pergunta "habilitar o login do root?":

d-i passwd/root-login

2. Desktop com Xfce

Complete para instalar o sistema padrão com o ambiente Xfce:

tasksel tasksel/first multiselect standard, desktop,

3. Rodar no sistema novo

Que palavra faz o late_command rodar dentro do sistema instalado?

d-i preseed/late_command string apt-get install -y vim

4. Você quer que o primeiro usuário tenha sudo, como no Ubuntu. Qual linha resolve?

5. O instalador perguntou o idioma antes de usar o seu preseed servido por url=. O que faltou na linha de boot?

Resumo

  • Cada linha é dono pergunta tipo valor, por exemplo d-i passwd/username string ana.
  • O instalador recebe o arquivo por file=, url= ou dentro do initrd; use auto=true priority=critical.
  • passwd/root-login decide entre "root com senha" (sem sudo) e "sudo como no Ubuntu".
  • partman apaga o disco sem perguntar: teste sempre numa VM.
  • Monte o arquivo a partir de uma instalação manual com debconf-get-selections --installer.
