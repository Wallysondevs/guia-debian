Debian Incus (containers de sistema)

O Docker e o Podman empacotam um programa por container. O Incus roda um sistema inteiro por container: um Debian, um Ubuntu ou um Alpine com systemd, usuários, SSH e apt, que sobe em segundos e gasta quase nada. É como ter dezenas de VMs leves para testar, estudar ou separar serviços.

Você vai aprender
  • A diferença entre container de aplicação e container de sistema.
  • Incus, LXD e LXC: quem é quem, e o que o Debian 13 oferece.
  • Instalar, inicializar e lançar um Debian 13 dentro do seu Debian.
  • Entrar, tirar snapshots e voltar no tempo.
  • Usar como usuário comum e resolver o conflito com o Docker.

Testado no Debian 13 de laboratório, com Incus 6.0.4. A VM de laboratório já tinha o Docker instalado, e isso rendeu o cenário mais importante desta aula.

Incus, LXD e LXC

NomeO que éNo Debian 13
LXCA tecnologia de baixo nível de containers do LinuxPacote lxc
LXDO gerenciador criado pela Canonical (empresa do Ubuntu), usado pelo comando lxcPacote lxd na versão 5.0.2, uma linha antiga mantida pelo Debian
IncusContinuação comunitária do LXD (2023), mantida pela antiga equipe do projetoPacotes incus 6.0.4 (versão de suporte longo), a opção recomendada

Os comandos do Incus são quase iguais aos do LXD, trocando lxc por incus. Quem aprender um aprende o outro.

Instalar

PacoteO que traz
incus-baseO serviço só com containers. Leve.
incusContainers e máquinas virtuais (puxa o QEMU, bem maior)
incus-clientO comando incus (para gerenciar um servidor remoto, por exemplo)
$ su -
Senha:
#> apt install incus-base incus-client
#> incus --version
6.0.4
#> getent group incus incus-admin
incus:x:987:
incus-admin:x:986:

O pacote cria dois grupos. Eles decidem quem pode usar o Incus sem ser root:

GrupoAcesso
incus-adminControle total, inclusive do sistema. Equivale a root, como o grupo docker.
incusCada usuário ganha um "projeto" restrito só dele, com limites. Seguro para usuários comuns.

Inicializar: incus admin init

Antes do primeiro container, o Incus precisa de um lugar para guardar os sistemas (storage pool) e de uma rede. O init pergunta tudo; com --minimal, ele usa os padrões:

incus admin init
Configuração inicial, uma vez só.
--minimal
Sem perguntas: armazenamento numa pasta (dir) e uma ponte de rede incusbr0 com NAT.
#> incus admin init --minimal
#> incus network list
+----------+----------+---------+----------------+---------------------------+-------------+---------+---------+
|   NAME   |   TYPE   | MANAGED |      IPV4      |           IPV6            | DESCRIPTION | USED BY |  STATE  |
+----------+----------+---------+----------------+---------------------------+-------------+---------+---------+
| docker0  | bridge   | NO      |                |                           |             | 0       |         |
| enp1s0   | physical | NO      |                |                           |             | 0       |         |
| incusbr0 | bridge   | YES     | 10.12.235.1/24 | fd42:15ad:ed7b:3a08::1/64 |             | 2       | CREATED |   « a rede dos containers

bash

Snapshots: voltar no tempo

Antes de um teste arriscado, tire uma foto do container. Se der errado, restaure em segundos.

#> incus snapshot create c1 antes
#> incus snapshot list c1
+-------+----------------------+------------+----------+
| NAME  |       TAKEN AT       | EXPIRES AT | STATEFUL |
+-------+----------------------+------------+----------+
| antes | 2026/10/15 23:32 -03 |            | NO       |
+-------+----------------------+------------+----------+
#> incus exec c1 -- touch /root/arquivo-novo
#> incus exec c1 -- ls /root
arquivo-novo
#> incus snapshot restore c1 antes
#> incus exec c1 -- ls /root
#>                                   « vazio: o container voltou ao momento da foto

Parar e apagar

#> incus stop c1
#> incus list c1 -c ns
+------+---------+
| NAME |  STATE  |
+------+---------+
| c1   | STOPPED |
+------+---------+
#> incus delete c1

Usuários comuns: o grupo incus

Colocando um usuário no grupo incus (como root: usermod -aG incus ana, e a ana sai e entra de novo), ele ganha um projeto próprio, isolado dos outros:

$ incus list

Or for a virtual machine: incus launch images:ubuntu/22.04 --vm

Quando não funciona

O container tem IP, mas não acessa a internet (com Docker instalado) 
#> incus exec c1 -- ping -c1 -W3 deb.debian.org
1 packets transmitted, 0 received, 100% packet loss, time 0ms
#> iptables -S FORWARD | head -3
-P FORWARD DROP                         « o Docker mudou a política de encaminhamento
-A FORWARD -j DOCKER-USER
-A FORWARD -j DOCKER-ISOLATION-STAGE-1

O que aconteceu: ao instalar, o Docker muda a política de encaminhamento (FORWARD) do firewall para DROP. O tráfego dos containers do Incus passa por ali e é descartado.

Como resolver: libere a ponte do Incus na cadeia que o Docker reserva para você, a DOCKER-USER:

#> iptables -I DOCKER-USER -i incusbr0 -j ACCEPT
#> iptables -I DOCKER-USER -o incusbr0 -m conntrack --ctstate RELATED,ESTABLISHED -j ACCEPT
#> incus exec c1 -- ping -c2 -W3 deb.debian.org
2 packets transmitted, 2 received, 0% packet loss, time 1007ms

Essas regras somem no reboot; para mantê-las, guarde-as no seu firewall (veja nftables). Se não precisar do Docker, não instale os dois na mesma máquina.

O incus launch num script "leu" o resto do script 
#> bash meu-script.sh
Error: yaml: unmarshal errors:
  line 1: cannot unmarshal !!str `incus list` into api.InstancePut

O que aconteceu: o incus launch lê configuração em YAML pela entrada padrão. Num script com here-document ou pipe, ele consome as linhas seguintes.

Como resolver: nos scripts, use incus launch images:debian/13 c1 < /dev/null.

"Error: Only empty projects can be removed."

O que aconteceu: o projeto ainda tem containers ou imagens. Como resolver: apague o que houver dentro (incus delete -f --project NOME …, incus image delete --project NOME …) e tente de novo.

"--vm" não funciona

O que aconteceu: o incus-base só tem containers, ou o processador não tem virtualização disponível (veja KVM). Como resolver: instale o pacote incus e confira o suporte com kvm-ok.

Resumo

  • Incus = sistemas inteiros em containers leves; no Debian 13, versão 6.0.4 (o LXD 5.0.2 também existe, mas o Incus é a opção recomendada).
  • incus-base para containers, incus para containers e VMs.
  • incus admin init --minimal uma vez; depois launch, exec, snapshot, delete.
  • Grupo incus = projeto restrito; incus-admin = poder de root.
  • Com Docker na mesma máquina, libere a incusbr0 na cadeia DOCKER-USER.
