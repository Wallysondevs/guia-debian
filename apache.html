Debian Servidor Web (Apache)

O Apache HTTP Server é o servidor web mais antigo ainda em uso em larga escala. No Debian ele se chama apache2 e vem organizado de um jeito próprio: cada site e cada módulo é um arquivo que você liga e desliga com comandos a2en… e a2dis…. Esse "jeito Debian" é o assunto desta aula.

Você vai aprender
  • Instalar o Apache e reconhecer a página padrão do Debian.
  • Onde fica cada arquivo em /etc/apache2.
  • Publicar um site com um VirtualHost e ativá-lo com a2ensite.
  • Ligar módulos e configurações com a2enmod e a2enconf.
  • Testar a configuração antes de recarregar, ler os logs e entender os erros mais comuns.

Os comandos rodam como root (su -) na máquina fictícia servidor. As saídas vêm de um Debian 13 real com Apache 2.4.68. Os comandos a2en… e as mensagens do Apache são em inglês.

Conceito: um prédio com vários apartamentos

Pense no servidor como um prédio com um único endereço (o IP e a porta 80). O Apache é o porteiro: quando chega um visitante, ele olha para qual nome o visitante perguntou (loja.com.br, blog.com.br) e o leva ao apartamento certo. Cada apartamento é um VirtualHost, com sua própria pasta de arquivos e seus próprios logs.

Onde fica cada coisa

#> ls /etc/apache2
apache2.conf  conf-available  conf-enabled  envvars  magic  mods-available  mods-enabled  ports.conf  sites-available  sites-enabled
CaminhoO que guarda

sites-available/Todos os sites configurados (ligados ou não)
sites-enabled/Atalhos para os sites ligados
mods-available/ / mods-enabled/Módulos existentes / ligados
conf-available/ / conf-enabled/Trechos de configuração extra / ligados

/var/log/apache2/access.log (visitas) e error.log (erros)

A regra do "available/enabled": o arquivo de verdade fica em …-available; ligar é criar um atalho (link simbólico) em …-enabled. Você não cria esses atalhos à mão: usa os comandos abaixo.

Para…LigarDesligar
Sitesa2ensite NOMEa2dissite NOME
Módulosa2enmod NOMEa2dismod NOME
Configurações extrasa2enconf NOMEa2disconf NOME

O nome vem de "apache2 enable site" e "apache2 disable site". Já vem ligado o site 000-default, o padrão:

<VirtualHost *:80>
	ServerAdmin webmaster@localhost
	DocumentRoot /var/www/html
	ErrorLog ${APACHE_LOG_DIR}/error.log
	CustomLog ${APACHE_LOG_DIR}/access.log combined
</VirtualHost>

Publicar o seu primeiro site

  1. Crie a pasta e a página. 
    #> mkdir -p /var/www/meusite
#> echo '<h1>Olá do meu site</h1>' > /var/www/meusite/index.html
  2. Escreva o VirtualHost em sites-available. O nome do arquivo precisa terminar em .conf: 
    <VirtualHost *:80>                       # vale para qualquer IP, porta 80
    ServerName meusite.local                # o nome que o visitante digita
    DocumentRoot /var/www/meusite           # a pasta com os arquivos do site
    ErrorLog ${APACHE_LOG_DIR}/meusite-error.log
    CustomLog ${APACHE_LOG_DIR}/meusite-access.log combined
</VirtualHost>
    ${APACHE_LOG_DIR} é uma variável definida em /etc/apache2/envvars; vale /var/log/apache2. Os comentários com # no fim da linha estão aqui só para explicar: no arquivo real, deixe cada comentário numa linha própria.
  3. Ligue o site:
    a2ensite
    Liga um site (cria o atalho em sites-enabled).
    meusite
    O nome do arquivo, sem o .conf.
    #> a2ensite meusite
Enabling site meusite.
To activate the new configuration, you need to run:
  systemctl reload apache2                                « ele mesmo diz o próximo passo
  4. Teste a configuração antes de aplicar: 
    #> apache2ctl configtest
Syntax OK
  5. Recarregue e teste. O -H "Host: …" finge que o visitante digitou meusite.local, sem precisar de DNS: 
    #> systemctl reload apache2
#> curl -H "Host: meusite.local" http://localhost
<h1>Olá do meu site</h1>

Módulos e configurações extras

Módulos acrescentam recursos ao Apache. Um dos mais pedidos é o rewrite, que muitos sistemas (como o WordPress) usam para "URLs amigáveis":

#> a2enmod rewrite
Enabling module rewrite.
To activate the new configuration, you need to run:
  systemctl restart apache2                               « módulo pede restart, não reload
#> systemctl restart apache2
#> a2dismod rewrite
Module rewrite disabled.
To activate the new configuration, you need to run:
  systemctl restart apache2

Os módulos ligados ficam em /etc/apache2/mods-enabled; para ver os disponíveis, ls /etc/apache2/mods-available. Com as configurações extras é igual:

#> ls /etc/apache2/conf-available
charset.conf  javascript-common.conf  localized-error-pages.conf  other-vhosts-access-log.conf  security.conf  serve-cgi-bin.conf
#> a2disconf serve-cgi-bin
Conf serve-cgi-bin disabled.
To activate the new configuration, you need to run:
  systemctl reload apache2

Ler os logs

Cada visita vira uma linha em access.log; cada problema, uma linha em error.log. Os logs são do grupo adm: a ana, que não está nesse grupo, não consegue ler (cat: /var/log/apache2/access.log: Permissão negada).

#> tail -2 /var/log/apache2/access.log
::1 - - [15/Oct/2026:22:59:10 -0300] "HEAD / HTTP/1.1" 200 255 "-" "curl/8.14.1"
::1 - - [15/Oct/2026:22:59:10 -0300] "GET / HTTP/1.1" 200 10958 "-" "curl/8.14.1"

Acompanhar ao vivo: tail -f /var/log/apache2/access.log (saia com Ctrl+C).

Quando não funciona

"AH00526: Syntax error … Invalid command" 
#> apache2ctl configtest
AH00526: Syntax error on line 3 of /etc/apache2/sites-enabled/meusite.conf:
Invalid command 'DocumentRot', perhaps misspelled or defined by a module not included in the server configuration
#> systemctl reload apache2
Job for apache2.service failed.
See "systemctl status apache2.service" and "journalctl -xeu apache2.service" for details.

O que aconteceu: uma palavra errada na configuração (DocumentRot). O erro diz o arquivo e a linha.

O detalhe que salva você: o reload falhou, mas o Apache continuou no ar com a configuração antiga. Já um restart com erro derrubaria o servidor. Por isso: sempre apache2ctl configtest antes.

Como resolver: corrija a linha indicada e teste de novo até aparecer Syntax OK.

"AH00112: Warning: DocumentRoot … does not exist" 
#> apache2ctl configtest
AH00112: Warning: DocumentRoot [/var/www/naoexiste] does not exist
Syntax OK

O que aconteceu: a sintaxe está certa (Syntax OK), mas a pasta do site não existe. O site vai responder com erro.

Como resolver: crie a pasta ou corrija o caminho no DocumentRoot.

403 Forbidden 
#> curl -I -H "Host: meusite.local" http://localhost
HTTP/1.1 403 Forbidden
#> tail -1 /var/log/apache2/meusite-error.log
[Thu Oct 15 22:59:27.108412 2026] [core:error] [pid 134044:tid 134049] (13)Permission denied: [client ::1:57680] AH00132: file permissions deny server access: /var/www/meusite/index.html

O que aconteceu: o Apache roda como o usuário www-data, que não tem permissão de ler o arquivo.

Como resolver: dê permissão de leitura: chmod 644 nos arquivos e 755 nas pastas (veja chmod). O error.log sempre diz o motivo exato.

"ERROR: Module … does not exist!" 
#> a2enmod naoexiste
ERROR: Module naoexiste does not exist!

Como resolver: confira o nome em ls /etc/apache2/mods-available. Alguns módulos vêm em pacotes separados, como o PHP (libapache2-mod-php).

A ana não consegue recarregar o Apache 
$ systemctl reload apache2
Failed to reload apache2.service: Access denied
See system logs and 'systemctl status apache2.service' for details.

Como resolver: no Debian sem sudo, use su - antes. Veja root, su e sudo.

"Address already in use" ao iniciar

O que aconteceu: outro programa (geralmente o nginx) já ocupa a porta 80.

Como resolver: descubra quem com ss -tlnp | grep :80 e pare o outro serviço, ou mude a porta em /etc/apache2/ports.conf. Veja também Servidor Web (nginx).

Resumo

  • No Debian o pacote é apache2, a configuração fica em /etc/apache2 e os sites padrão em /var/www/html.
  • Cada site é um .conf em sites-available; a2ensite/a2dissite ligam e desligam.
  • Módulos: a2enmod/a2dismod + restart. Sites e configurações: reload.
  • apache2ctl configtest antes de qualquer reload; o error.log sempre diz o motivo do erro.
