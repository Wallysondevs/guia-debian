Debian Conceitos de Rede

Antes de usar comandos de rede, vale entender as peças: IP, máscara, gateway, DNS e porta. Com elas na cabeça, as saídas do ip, do ping e do ssh deixam de ser sopa de números. No fim, você terá um roteiro para descobrir por que "a internet não funciona".

Você vai aprender
  • O que são IP, máscara, gateway, DNS e porta, comparando com endereços de correio.
  • A diferença entre IP privado (da sua casa) e IP público (da internet).
  • Onde o Debian guarda e mostra cada uma dessas informações.
  • Um roteiro de 6 passos para achar onde a conexão quebrou.

Os exemplos usam a máquina notebook, da usuária ana, com um Debian 13 instalado como servidor e ligado por cabo. As saídas foram tiradas de um Debian real; só os endereços foram trocados pelos de uma rede de casa típica. No seu computador, os números e os nomes das placas serão outros.

A rede como um sistema de correio

Uma rede de computadores funciona como o correio de uma cidade. Cada peça técnica tem um equivalente do dia a dia:

TermoAnalogiaExemplo
Endereço IPO endereço da casa. Sem ele, ninguém sabe para onde mandar a carta.192.168.0.15
Máscara de redeDiz qual parte do endereço é o "bairro". Quem está no mesmo bairro se fala direto./24 ou 255.255.255.0
GatewayA agência do correio do bairro. Tudo que vai para fora do bairro passa por ela.192.168.0.1 (o roteador)
DNSA agenda de contatos: troca o nome pelo endereço.debian.org → 151.101.2.132
PortaO número do apartamento dentro do prédio. Cada serviço mora num número.22 (SSH), 443 (sites com HTTPS)

De onde vêm nomes como enp1s0?

O Linux dá nomes que descrevem onde a placa está ligada: en = ethernet (cabo), wl = wireless (Wi-Fi), p1s0 = barramento PCI 1, slot 0. O lo é a placa "de mentira" do próprio computador (loopback).

Endereço IP

IP vem de Internet Protocol, "protocolo de internet". O endereço IPv4 tem 4 números de 0 a 255, separados por pontos. O jeito mais rápido de ver o seu é o hostname -I:

hostname
O programa que mostra o nome da máquina.
-I
Com i maiúsculo: em vez do nome, mostra todos os endereços IP.
$ hostname -I
192.168.0.15 2804:14c:5b80:8a1f:a00:27ff:fe90:fbde       « o primeiro é o IPv4; o segundo, IPv6

IP privado e IP público

O 192.168.0.15 é um IP privado: só vale dentro da sua casa, como "apartamento 15" só faz sentido dentro do prédio. Para a internet, toda a sua casa aparece com um único IP público, o do roteador. Para descobri-lo, é preciso perguntar a um site de fora. O wget já vem no Debian (o curl, não):

$ wget -qO- -4 ifconfig.me
177.92.48.203                                « ilustrativo: o endereço da sua casa vista de fora

Três faixas são reservadas para redes privadas. Se o seu IP começa assim, ele é privado:

FaixaOnde costuma aparecer
192.168.x.xRoteadores de casa e de pequenos escritórios
10.x.x.xEmpresas, VPNs, nuvem e máquinas virtuais (o VirtualBox usa 10.0.2.x)
172.16.x.x a 172.31.x.xEmpresas e o Docker
127.0.0.1Não é rede: é o próprio computador (localhost)
localhost: o computador falando com ele mesmo

127.0.0.1, ou o nome localhost, sempre aponta para a própria máquina. Funciona até sem internet:

$ ping -c 2 127.0.0.1
PING 127.0.0.1 (127.0.0.1) 56(84) bytes of data.
64 bytes from 127.0.0.1: icmp_seq=1 ttl=64 time=0.029 ms
64 bytes from 127.0.0.1: icmp_seq=2 ttl=64 time=0.040 ms

2 packets transmitted, 2 received, 0% packet loss, time 1042ms
rtt min/avg/max/mdev = 0.029/0.034/0.040/0.005 ms

Máscara de rede: qual é o seu "bairro"

A máscara diz quantos números do começo do IP formam o endereço da rede (o bairro). Ela aparece depois de uma barra, no formato chamado CIDR: 192.168.0.15/24.

O /24 quer dizer que os 24 primeiros bits, ou seja, os três primeiros números (192.168.0), são o bairro. O último número muda de casa para casa. Por isso 192.168.0.15 e 192.168.0.30 se falam direto, mas 192.168.1.7 já está em outro bairro.

CIDRMáscara por extensoParte fixaEndereços para máquinas
/8255.0.0.010.x.x.xcerca de 16 milhões
/16255.255.0.0172.16.x.x65.534
/24255.255.255.0192.168.0.x254
/32255.255.255.255o endereço inteiro1 (uma máquina só)

Para o dia a dia, basta lembrar: em casa, quase sempre é /24.

Gateway: a porta de saída

Para falar com algo fora do bairro (um site, por exemplo), o computador entrega o pacote ao gateway, quase sempre o roteador. O comando ip r mostra as rotas:

ip
A ferramenta de rede do Linux (pacote iproute2, sempre instalado).
r
Abreviação de route: a tabela de rotas, ou seja, por onde cada destino sai.
$ ip r
default via 192.168.0.1 dev enp1s0 proto dhcp src 192.168.0.15 metric 1002      « para qualquer outro lugar, vá pelo roteador
192.168.0.0/24 dev enp1s0 proto dhcp scope link src 192.168.0.15 metric 1002    « o "bairro": entrega direto
PedaçoSignificado
default"Qualquer destino que não esteja nas outras linhas."
via 192.168.0.1Mande pelo gateway, o roteador.
dev enp1s0Pela placa de cabo.
proto dhcpEssa rota veio do DHCP: o roteador entregou IP e gateway automaticamente.
src 192.168.0.15Usando o seu IP como remetente.
metric 1002Prioridade: com duas rotas iguais, vence a de número menor. O cliente DHCP do Debian (dhcpcd) usa 1000 + o número da placa.

DNS: a agenda de nomes

Computadores só entendem números, mas pessoas lembram nomes. O DNS (Domain Name System, "sistema de nomes de domínio") traduz debian.org para um IP. No Debian com o "sistema padrão" instalado, o dig e o host já vêm prontos:

dig
Pergunta ao DNS (de domain information groper).
+short
Mostra só a resposta, sem os detalhes técnicos.
debian.org
O nome a traduzir.
$ dig +short debian.org
151.101.130.132
151.101.66.132
151.101.2.132
151.101.194.132                              « um nome pode ter vários IPs
$ host debian.org
debian.org has address 151.101.194.132
debian.org has address 151.101.130.132
debian.org has address 151.101.2.132

Quem responde as perguntas de DNS?

No Debian, a resposta está num arquivo de texto simples, o /etc/resolv.conf:

$ cat /etc/resolv.conf
# Generated by dhcpcd from enp1s0.dhcp, enp1s0.ra       « escrito automaticamente pelo DHCP
# /etc/resolv.conf.head can replace this line
domain lan
nameserver 192.168.0.1                                   « o servidor DNS: o próprio roteador
# /etc/resolv.conf.tail can replace this line
Diferença para o Ubuntu

No Ubuntu, quem responde é um serviço local, o systemd-resolved, e o comando é resolvectl status. Num Debian servidor ele não vem instalado (resolvectl dá "comando não encontrado"): o dhcpcd escreve o servidor de DNS direto no /etc/resolv.conf. No Debian com GNOME, quem cuida disso é o NetworkManager. Os detalhes de configuração estão em Configurar a Rede.

Quando "a internet caiu", muitas vezes é só o DNS

Se você alcança um IP mas não abre nenhum nome, a internet está funcionando: quem falhou foi a agenda. O roteiro abaixo mostra como distinguir os dois casos.

Portas, TCP e UDP

Um computador roda vários serviços ao mesmo tempo. A porta é o número que diz para qual deles o pacote vai, como o número do apartamento num prédio. O IP leva até o prédio, a porta leva até o apartamento.

PortaProtocoloServiço
22TCPSSH: acesso remoto pelo terminal (SSH)
53UDP e TCPDNS
80TCPHTTP: sites sem criptografia
443TCP (e UDP no HTTP/3)HTTPS: sites com cadeado
25TCPEnvio de e-mail entre servidores (SMTP)
123UDPNTP: acerto do relógio
67, 68UDPDHCP: entrega de IP automático

O próprio Debian tem uma lista oficial de portas e nomes, em /etc/services:

$ grep -w ssh /etc/services
ssh		22/tcp				# SSH Remote Login Protocol

Existem dois "tipos de entrega":

  • TCP: como uma carta registrada. Confirma o recebimento e reenvia o que se perder. Usado por sites, SSH e e-mail.
  • UDP: como um panfleto. Mais rápido, sem confirmação. Usado por DNS, chamadas de vídeo e jogos.

Para ver quais portas a máquina escuta, use o ss. Num Debian servidor recém-instalado, só o SSH (porta 22) espera conexões:

$ ss -tln
State  Recv-Q Send-Q Local Address:Port Peer Address:Port
LISTEN 0      128          0.0.0.0:22        0.0.0.0:*      « SSH em todos os endereços IPv4
LISTEN 0      128             [::]:22           [::]:*      « e em todos os IPv6

Os detalhes do ss estão em ip, ping, ss.

IPv4 e IPv6

Os endereços IPv4 (4 números) estão acabando: são só cerca de 4 bilhões. O IPv6 resolve isso com endereços enormes, em hexadecimal e separados por dois-pontos, como 2804:14c:5b80:8a1f:a00:27ff:fe90:fbde. Os dois convivem, e o Debian configura os dois automaticamente.

  • :: é uma abreviação para "um monte de zeros".
  • Endereços que começam com fe80: são locais e só valem dentro da rede.
  • Endereços que começam com fd são privados, como o 192.168 do IPv4.
  • ::1 é o localhost do IPv6.

Roteiro: "a internet não funciona"

Siga os passos em ordem. Cada passo testa uma peça do correio; o primeiro que falhar mostra onde está o problema.

  1. A placa de rede está ligada e tem IP? Use ip -br a (-br = brief, "resumido"):

    $ ip -br a
lo               UNKNOWN        127.0.0.1/8 ::1/128
enp1s0           UP             192.168.0.15/24 2804:14c:5b80:8a1f:a00:27ff:fe90:fbde/64 fe80::ae13:e729:e153:39c/64   « ligada, com IP

    Se a placa está DOWN, ou UP mas sem endereço IPv4, o problema é a conexão física (cabo solto, Wi-Fi desligado) ou o DHCP. Veja Configurar a Rede; no Wi-Fi, Wi-Fi e Wi-Fi que Não Funciona.

  2. Existe um gateway?

    $ ip r
default via 192.168.0.1 dev enp1s0 proto dhcp src 192.168.0.15 metric 1002
192.168.0.0/24 dev enp1s0 proto dhcp scope link src 192.168.0.15 metric 1002

    Sem a linha default, o computador não sabe sair do bairro.

  3. O roteador responde? O ping manda um "você está aí?" e espera a resposta. -c 3 limita a 3 tentativas; sem isso, ele só para com Ctrl+C.

    $ ping -c 3 192.168.0.1
PING 192.168.0.1 (192.168.0.1) 56(84) bytes of data.
64 bytes from 192.168.0.1: icmp_seq=1 ttl=64 time=3.12 ms
64 bytes from 192.168.0.1: icmp_seq=2 ttl=64 time=2.87 ms
64 bytes from 192.168.0.1: icmp_seq=3 ttl=64 time=4.05 ms

--- 192.168.0.1 ping statistics ---
3 packets transmitted, 3 received, 0% packet loss, time 2003ms     « 0% de perda: o roteador está ok

    Se aparecer 100% packet loss, o problema está entre você e o roteador.

  4. A internet responde por IP? Teste um IP conhecido, como o DNS público 8.8.8.8. Assim você testa a saída para a internet sem depender do DNS:

    $ ping -c 3 8.8.8.8

    Se o roteador responde mas o 8.8.8.8 não, a internet do provedor caiu.

  5. A internet responde por nome?

    $ ping -c 3 debian.org
PING debian.org (151.101.66.132) 56(84) bytes of data.        « o nome virou IP: DNS funcionando
64 bytes from 151.101.66.132: icmp_seq=1 ttl=64 time=365 ms

    Se o ping 8.8.8.8 funcionou mas o nome deu "Nome ou serviço desconhecido", o problema é o DNS.

  6. Qual DNS está em uso?

    $ cat /etc/resolv.conf
nameserver 192.168.0.1
$ dig +short debian.org @1.1.1.1            « pergunte a outro servidor de DNS, direto
151.101.2.132

    Se o DNS público (@1.1.1.1) responde e o do roteador não, configure outro DNS na conexão (veja Configurar a Rede).

Resumo do roteiro

Placa com IP → gateway → ping no roteador → ping num IP da internet → ping num nome → DNS. O primeiro passo que falha diz onde está o defeito.

Quando não funciona

"Nome ou serviço desconhecido" 
$ ping -c 1 nao-existe.invalid
ping: nao-existe.invalid: Nome ou serviço desconhecido

O que aconteceu: o DNS não conseguiu traduzir o nome. Ou o nome está errado (confira a digitação), ou o DNS não está respondendo.

Como confirmar: ping -c 3 8.8.8.8. Se esse funcionar, a internet está ok e o problema é só o DNS.

"A rede está fora de alcance" 
$ ping -c 1 8.8.8.8
ping: connect: A rede está fora de alcance

O que aconteceu: o computador nem tentou enviar, porque não tem rota para fora: não há gateway, ou a placa está sem IP.

Como resolver: volte aos passos 1 e 2 do roteiro.

"100% packet loss" 
$ ping -c 2 -W 1 192.168.0.250
...
2 packets transmitted, 0 received, 100% packet loss, time 1012ms

O que aconteceu: o pacote saiu, mas ninguém respondeu. O endereço pode não existir, a máquina pode estar desligada, ou um firewall bloqueia o ping.

Como resolver: confira o IP. Lembre que muitos servidores bloqueiam o ping de propósito: não responder ao ping não prova que a máquina está fora do ar.

"curl: comando não encontrado" / "resolvectl: comando não encontrado"

O que aconteceu: esses comandos, comuns em tutoriais de Ubuntu, não vêm num Debian servidor.

Como resolver: use os que já vêm (wget, cat /etc/resolv.conf, dig) ou instale o curl como root: apt install curl.

Resumo

  • IP é o endereço; a máscara (/24) diz qual parte é a rede; o gateway é a saída; o DNS traduz nomes; a porta escolhe o serviço.
  • hostname -I e ip -br a mostram o IP; ip r mostra o gateway.
  • No Debian servidor, o DNS está em /etc/resolv.conf (gerado pelo dhcpcd); não há resolvectl nem curl, mas há dig, host e wget.
  • Roteiro: placa → gateway → roteador → IP da internet → nome → DNS.
