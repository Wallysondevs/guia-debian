Debian lsblk, df e du

Três comandos respondem às perguntas mais comuns sobre armazenamento. lsblk diz quais discos existem, df diz quanto espaço livre sobrou e du diz quem está ocupando o espaço. Nenhum deles altera nada, então você pode usá-los à vontade, mesmo como usuário comum.

Você vai aprender
  • Como o Linux dá nome aos discos e às partições (sda1, nvme0n1p2…).
  • A ler cada coluna do lsblk, do df e do du.
  • Por que o Debian mostra uma partição de 1K e um /tmp que mora na memória.
  • Três formas de descobrir o que está enchendo o disco.
  • O que fazer quando aparece "Não há espaço disponível no dispositivo".

As saídas desta aula vêm de um Debian 13 de verdade, instalado com as opções padrão do instalador. No seu computador, os tamanhos e os nomes podem ser outros.

Antes dos comandos: disco, partição e sistema de arquivos

Pense num armário. O disco é o armário inteiro (SSD, HD ou pendrive). As partições são as prateleiras: o disco é dividido em pedaços independentes. O sistema de arquivos é a forma como cada prateleira é organizada por dentro (ext4, FAT32, NTFS…).

No Linux, cada disco aparece como um arquivo especial dentro de /dev (de devices, "dispositivos"):

NomeO que é
/dev/sdaO primeiro disco SATA ou USB (HD, SSD SATA, pendrive, disco de máquina virtual). O segundo é sdb, depois sdc…
/dev/sda1A partição 1 do disco sda.
/dev/nvme0n1O primeiro SSD NVMe (comum em notebooks novos).
/dev/nvme0n1p1A partição 1 desse SSD (p de partition).
/dev/sr0O leitor de CD/DVD (ou o drive virtual de uma VM).
/dev/loop0…"Discos virtuais" feitos a partir de arquivos. Um Debian recém-instalado não tem nenhum, porque não usa Snap.

Para usar uma partição, o Linux a monta numa pasta, chamada ponto de montagem. A partição principal fica montada em /, e um pendrive costuma aparecer em /media/ana/NOME no desktop. Você vai aprender a montar em mount e fstab.

lsblk: quais discos existem

lsblk vem de list block devices, "listar dispositivos de bloco". Dispositivo de bloco é qualquer coisa que guarda dados em blocos: discos, partições, pendrives.

lsblk
O programa. Sem opções, mostra todos os discos e partições em forma de árvore.
$ lsblk
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sda      8:0    0   25G  0 disk                  « o disco inteiro
├─sda1   8:1    0 23,7G  0 part /                « a partição do sistema
├─sda2   8:2    0    1K  0 part                  « partição estendida (só um "envelope")
└─sda5   8:5    0  1,3G  0 part [SWAP]           « a área de troca (swap)
sr0     11:0    1 1024M  1 rom                   « o leitor de DVD
ColunaSignificado
NAMENome do dispositivo. Os traços ├─ e └─ mostram que a partição pertence ao disco de cima.
MAJ:MINNúmeros internos do kernel. O 8 identifica discos SCSI/SATA; você raramente vai precisar disso.
RMRemovable: 1 se é removível (pendrive, cartão, DVD).
SIZETamanho total.
RORead-only: 1 se for somente leitura (o DVD é).
TYPEdisk (disco), part (partição), rom (CD/DVD), loop (virtual).
MOUNTPOINTSOnde está montado. [SWAP] é a área de troca. Vazio = não montado.
Por que existe uma partição de 1K e a numeração pula do 2 para o 5?

Na instalação padrão em computadores com BIOS antiga (ou máquinas virtuais), o instalador do Debian usa a tabela de partições MBR, que só aceita 4 partições "principais". Para criar mais, ele faz uma partição estendida (sda2, que aparece com 1K) e coloca dentro dela as partições lógicas, numeradas a partir de 5. Em computadores com UEFI, o instalador usa GPT: você verá uma partição /boot/efi e numeração seguida (1, 2, 3).

Ver o sistema de arquivos e o UUID: -f

Com -f (de filesystems), o lsblk mostra o tipo de cada partição, o rótulo (LABEL) e o UUID, um código único que identifica a partição. O UUID é o que o Debian usa no /etc/fstab.

$ lsblk -f
NAME   FSTYPE FSVER LABEL UUID                                 FSAVAIL FSUSE% MOUNTPOINTS
sda
├─sda1 ext4   1.0         50185294-cee5-49de-a27c-2cf995361c67   20,8G     5% /
├─sda2
└─sda5 swap   1           889d958f-02ec-4d04-9252-01fabc01bb17                [SWAP]
sr0

FSAVAIL é o espaço livre e FSUSE% é quanto já foi usado. Só aparecem nas partições montadas.

Escolher as colunas: -o

Com -o (de output, "saída") você escolhe só as colunas que quer, na ordem que quiser:

$ lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINTS
NAME    SIZE FSTYPE MOUNTPOINTS
sda      25G
├─sda1 23,7G ext4   /
├─sda2    1K
└─sda5  1,3G swap   [SWAP]
sr0    1024M

Só os discos: -d

$ lsblk -d
NAME MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sda    8:0    0   25G  0 disk
sr0   11:0    1 1024M  1 rom
Descobrir qual é o pendrive

Rode lsblk, conecte o pendrive e rode de novo. O dispositivo que apareceu é ele (geralmente sdb, com RM = 1). Faça isso sempre antes de formatar ou gravar uma ISO: errar o nome apaga o disco errado.

E o blkid?

O blkid mostra só os UUIDs e tipos. No Debian ele fica em /usr/sbin, que não está no PATH da usuária comum. Por isso, como ana, ele "não existe":

$ blkid
bash: blkid: comando não encontrado
$ su -
Senha:
#> blkid
/dev/sda5: UUID="889d958f-02ec-4d04-9252-01fabc01bb17" TYPE="swap" PARTUUID="b4c43cbc-05"
/dev/sda1: UUID="50185294-cee5-49de-a27c-2cf995361c67" BLOCK_SIZE="4096" TYPE="ext4" PARTUUID="b4c43cbc-01"

Como root, o PATH inclui /usr/sbin e o comando aparece. Para a usuária comum, lsblk -f resolve quase sempre. Entenda o PATH do Debian em .bashrc, alias, PATH e o su em root, su e sudo.

df: quanto espaço livre sobrou

df vem de disk free, "disco livre". Ele mostra, para cada sistema de arquivos montado, o tamanho, quanto foi usado e quanto sobra.

df
O programa.
-h
Human-readable: tamanhos em K, M, G em vez de blocos de 1 KB.
$ df -h
Sist. Arq.      Tam. Usado Disp. Uso% Montado em
udev            1,9G     0  1,9G   0% /dev
tmpfs           393M  508K  392M   1% /run
/dev/sda1        24G  1,2G   21G   6% /                     « o que importa
tmpfs           2,0G     0  2,0G   0% /dev/shm
tmpfs           1,0M     0  1,0M   0% /run/credentials/systemd-journald.service
tmpfs           5,0M     0  5,0M   0% /run/lock
tmpfs           2,0G  8,0K  2,0G   1% /tmp                  « o /tmp está na memória
tmpfs           1,0M     0  1,0M   0% /run/credentials/getty@tty1.service
tmpfs           393M  4,0K  393M   1% /run/user/1000
ColunaSignificado
Sist. Arq.Qual partição (ou sistema virtual, como tmpfs e udev).
Tam.Tamanho total.
Usado / Disp.Usado e disponível.
Uso%Porcentagem usada. Acima de 90%, comece a limpar.
Montado emA pasta onde a partição aparece.

tmpfs e udev são "discos" que moram na memória RAM e somem ao desligar. Você pode ignorá-los quando a pergunta for "meu disco está cheio?".

No Debian 13, o /tmp some ao reiniciar

A partir do Debian 13, a pasta /tmp é um tmpfs: fica na memória e é apagada a cada reinicialização. Nunca guarde em /tmp algo que você queira manter. Se precisar de uma pasta temporária que sobreviva ao reinício, use /var/tmp.

Por que Usado + Disp. não dá o Tam.?

Na linha do /, 1,2G + 21G = 22,2G, e não 24G. O ext4 reserva cerca de 5% do espaço para o administrador. Assim o sistema ainda consegue funcionar quando um usuário enche o disco.

Missão: rode df -h e descubra quanto espaço livre a partição / da máquina fictícia tem. Depois rode free -h e compare: o free fala da memória RAM, não do disco.

du: quem está ocupando espaço

df diz que o disco está cheio; du (de disk usage, "uso de disco") diz onde. Ele soma o tamanho dos arquivos de uma pasta.

du
O programa.
-s
Summarize: mostra só o total, em vez de cada subpasta.
-h
Tamanhos legíveis.
/usr
A pasta a medir.
$ du -sh /usr
737M	/usr

Sem o -s, o du lista todas as subpastas, uma por linha, o que pode ser muito longo. Veja com uma pasta pequena de exemplo:

$ du -h d
1,0M	d/b
5,0M	d/a
6,0M	d                                « o total vem por último
$ du -sh d/*
5,0M	d/a
1,0M	d/b

Um nível de cada vez: -d 1

A opção -d (de depth, "profundidade") limita quantos níveis de pastas o du mostra. Com -d 1, ele mostra só as pastas de primeiro nível e o total.

Ordenar pelo tamanho: | sort -h

A saída do du vem fora de ordem. Mandando-a para o sort -h (que entende K, M e G), o maior fica por último:

du -h -d 1 ~
Tamanho de cada pasta de primeiro nível da sua pasta pessoal.
|
O pipe: entrega a saída para o próximo comando (veja Pipes).
sort -h
Ordena tamanhos legíveis, do menor para o maior.
| tail -5
Mostra só as 5 últimas linhas: as maiores.
$ du -h -d 1 d | sort -h
1,0M	d/b
5,0M	d/a
6,0M	d

Num notebook de verdade, troque d por ~. O culpado costuma ser Downloads, .cache ou .local/share/Trash (a lixeira). Depois, repita o comando dentro da pasta maior para descer mais um nível.

Três formas de achar o que enche o disco

Forma 1: du + sort, descendo pasta por pasta

É o método acima. Funciona em qualquer Debian, inclusive em servidor sem interface gráfica e sem instalar nada.

Forma 2: ncdu, interativo

O ncdu (NCurses Disk Usage) mostra as pastas ordenadas e deixa você navegar com as setas. Ele não vem instalado:

$ ncdu ~
bash: ncdu: comando não encontrado
$ su -c "apt install ncdu"
Senha:

Depois de instalado, use ↑ ↓ para escolher, Enter para entrar na pasta, d para apagar (pede confirmação) e q para sair.

Forma 3: arquivos grandes com find

Às vezes o problema é um arquivo enorme escondido. O find procura por tamanho:

$ find ~ -type f -size +1G
/home/ana/Downloads/debian-13.5.0-amd64-DVD-1.iso

A saída acima é ilustrativa. Veja mais em find e locate.

FormaMelhor quando…
du -h -d 1 | sort -hVocê quer saber qual pasta cresceu. Funciona em qualquer lugar.
ncduVocê vai investigar e limpar várias pastas.
find -size +1GVocê suspeita de poucos arquivos gigantes.
Analisador de uso de discoVocê está no desktop e prefere gráficos.

Quando não funciona

"Não há espaço disponível no dispositivo" 
$ cp video.mp4 ~/Vídeos/
cp: erro de escrita de '/home/ana/Vídeos/video.mp4': Não há espaço disponível no dispositivo

O que aconteceu: a partição encheu. Programas podem travar e o sistema pode não conseguir salvar configurações. Em inglês, a mensagem é No space left on device.

Como confirmar: df -h / mostra Uso% perto de 100%.

Como resolver: ache o culpado com du -h -d 1 ~ | sort -h. Lugares que costumam crescer: ~/Downloads, ~/.cache, a lixeira (~/.local/share/Trash), os logs (como root: journalctl --vacuum-size=200M) e o cache do apt (como root: apt clean). Veja Manutenção.

df diz que há espaço, mas nada pode ser criado 
$ df -i /
Sist. Arq.        Inós IUsado  ILivre IUso% Montado em
/dev/sda1      1553440  38465 1514975    3% /

O que aconteceu: cada arquivo gasta um inode (uma "ficha" que guarda suas informações; o Debian em português chama de "inó"). Milhões de arquivos pequenos, como caches e sessões, esgotam as fichas antes do espaço. Quando isso acontece, a coluna IUso% chega a 100% e ILivre fica em 0.

Como resolver: ache a pasta com mais arquivos (find /var -xdev -type f | cut -d/ -f2-3 | sort | uniq -c | sort -n | tail) e apague o que não serve.

du mostra "Permissão negada" 
$ du -sh /etc
du: não foi possível ler diretório '/etc/credstore': Permissão negada
du: não foi possível ler diretório '/etc/credstore.encrypted': Permissão negada
4,2M	/etc

O que aconteceu: algumas pastas só o root pode ler. O total mostrado fica menor que o real (como root, o mesmo comando mostra 4,3M).

Como resolver: para medir pastas do sistema, entre como root (su -) e rode de novo. Para só esconder os avisos: du -sh /etc 2>/dev/null.

Apaguei um arquivo grande e o espaço não voltou

O que aconteceu: se um programa ainda está com o arquivo aberto (por exemplo, um log que um serviço continua escrevendo), o espaço só é liberado quando o programa fecha o arquivo. Outra possibilidade: o arquivo foi para a lixeira do desktop.

Como resolver: esvazie a lixeira ou reinicie o serviço que usava o arquivo. Para listar arquivos apagados que ainda estão abertos, como root: lsof +L1 (o lsof vem instalado no Debian).

Resumo

  • lsblk lista discos e partições; -f mostra tipo e UUID.
  • Na instalação MBR do Debian, a partição de 1K é a estendida e as lógicas começam no 5.
  • df -h mostra o espaço livre; ignore tmpfs e udev.
  • du -sh pasta mede uma pasta; du -h -d 1 | sort -h acha a maior.
  • No Debian 13, /tmp fica na memória e é apagado ao reiniciar.
  • blkid e outros programas de /usr/sbin só aparecem para o root.
