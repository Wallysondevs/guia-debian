Debian Servidor Web (nginx)

O nginx (pronuncia-se "engine-x") é um servidor web leve e rápido, muito usado também como proxy reverso: ele fica na frente de uma aplicação (Node, Python, PHP) e repassa os visitantes para ela. No Debian, ele segue a mesma ideia de pastas sites-available e sites-enabled do Apache.

Você vai aprender
  • Instalar o nginx e conferir se ele respondeu.
  • Onde fica cada arquivo em /etc/nginx.
  • Publicar um site com um bloco server.
  • Ler os logs e entender os códigos 200, 403, 404 e 502.
  • Colocar o nginx na frente de uma aplicação (proxy reverso).

Comandos como root (su -) na máquina fictícia servidor. As saídas vêm de um Debian 13 real com nginx 1.26.3. O nginx responde em inglês.

Conceito: o caminho de um pedido

  1. O navegador pede http://meusite.local/ para o IP do servidor, porta 80.
  2. O nginx olha o cabeçalho Host e escolhe o bloco server cujo server_name combina.
  3. Esse bloco diz o que fazer: entregar um arquivo de uma pasta (root) ou repassar para uma aplicação (proxy_pass).
  4. Se nenhum server_name combinar, quem responde é o bloco marcado como default_server.

Diferença para o Apache

O nginx do Debian também usa sites-available e sites-enabled, mas não tem um comando como o a2ensite. Você liga um site criando o atalho com ln -s e desliga apagando o atalho com rm.

O site padrão, sem os comentários:

server {
	listen 80 default_server;
	listen [::]:80 default_server;
	root /var/www/html;
	index index.html index.htm index.nginx-debian.html;
	server_name _;
	location / {
		try_files $uri $uri/ =404;
	}
}

Publicar o seu primeiro site

  1. Crie a pasta e a página. 
    #> mkdir -p /var/www/meusite
#> echo '<h1>Olá do nginx</h1>' > /var/www/meusite/index.html
  2. Escreva o bloco server. Cada linha de configuração termina com ;, e cada bloco fica entre { }: 
    server {
    listen 80;                       # escuta no IPv4
    listen [::]:80;                  # escuta no IPv6 (não esqueça!)
    server_name meusite.local;       # o nome que o visitante digita
    root /var/www/meusite;           # a pasta com os arquivos
    index index.html;                # o arquivo aberto quando pedem só "/"
    location / {
        try_files $uri $uri/ =404;   # o arquivo, a pasta, ou erro 404
    }
}
  3. Ligue o site criando o atalho:
    ln -s
    Cria um link simbólico (atalho). Veja Links.
    /etc/nginx/sites-available/meusite
    O arquivo de verdade.
    /etc/nginx/sites-enabled/
    Onde o atalho é criado.
    #> ln -s /etc/nginx/sites-available/meusite /etc/nginx/sites-enabled/
  4. Teste a configuração: 
    #> nginx -t
nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful
  5. Recarregue e teste fingindo o nome com -H "Host: …": 
    #> systemctl reload nginx
#> curl -H "Host: meusite.local" http://localhost
<h1>Olá do nginx</h1>

Proxy reverso: nginx na frente de uma aplicação

Muitas aplicações (Node, Python, Go) escutam numa porta alta, como a 3000, só no próprio servidor. O nginx recebe o visitante na porta 80 e repassa. Para testar, suba um "aplicativo" de mentira com o servidor embutido do Python:

#> echo "resposta da aplicacao" > index.html
#> python3 -m http.server 3000 --bind 127.0.0.1 &
server {
    listen 80;
    listen [::]:80;
    server_name app.local;
    location / {
        proxy_pass http://127.0.0.1:3000;   # para onde repassar
        include proxy_params;               # cabeçalhos padrão do Debian
    }
}
proxy_pass http://127.0.0.1:3000
Repassa o pedido para a aplicação na porta 3000 da própria máquina.
include proxy_params
Inclui o arquivo /etc/nginx/proxy_params, que envia à aplicação o nome pedido e o IP real do visitante.
#> ln -s /etc/nginx/sites-available/app /etc/nginx/sites-enabled/
#> nginx -t && systemctl reload nginx
nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful
#> curl -H "Host: app.local" http://localhost
resposta da aplicacao                                      « veio da aplicação, através do nginx

O proxy_params do Debian 13 termina com estas linhas (antes delas há um comentário explicando por que o Debian passou a usar $host em vez de $http_host, por segurança):

proxy_set_header Host $host;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;

Desligar um site e o nginx

#> rm /etc/nginx/sites-enabled/app                    « apaga só o atalho; o arquivo continua em sites-available
#> nginx -t && systemctl reload nginx
#> systemctl disable --now nginx                       « para e não liga mais no boot

Quando não funciona

Instalei o nginx e aparece "Apache2 Debian Default Page" 
#> curl -sI http://localhost | grep Server
Server: nginx
#> curl -s http://localhost | grep -i "<title>"
    <title>Apache2 Debian Default Page: It works</title>
#> ls /var/www/html
index.html  index.nginx-debian.html

O que aconteceu: o Apache já tinha sido instalado e deixou o seu index.html na pasta padrão. Quem responde é o nginx (Server: nginx), mas ele procura primeiro o index.html.

Como resolver: é só o arquivo de boas-vindas; troque pelo seu site ou apague o /var/www/html/index.html.

O site novo não aparece, só o padrão

O que aconteceu: o bloco tinha só listen 80;. O curl http://localhost (e muitos navegadores) conecta pelo IPv6 (::1); como o seu site não escuta em IPv6, quem responde é o default_server.

Como resolver: adicione listen [::]:80; ao bloco, rode nginx -t e recarregue. Confira também se o atalho existe em sites-enabled e se o server_name está certo.

502 Bad Gateway 
#> curl -I -H "Host: app.local" http://localhost
HTTP/1.1 502 Bad Gateway
#> tail -1 /var/log/nginx/error.log
2026/10/15 23:12:49 [error] 140499#140499: *7 connect() failed (111: Connection refused) while connecting to upstream, client: ::1, server: app.local, request: "HEAD / HTTP/1.1", upstream: "http://127.0.0.1:3000/", host: "app.local"

O que aconteceu: o nginx está bem; quem caiu foi a aplicação (Connection refused na porta 3000).

Como resolver: confira se a aplicação está rodando (ss -tlnp | grep 3000, systemctl status app) e se a porta do proxy_pass é a mesma da aplicação.

403 Forbidden: "directory index … is forbidden" 
#> tail -1 /var/log/nginx/error.log
2026/10/15 23:12:44 [error] 140436#140436: *4 directory index of "/var/www/meusite/" is forbidden, client: ::1, server: meusite.local, request: "HEAD / HTTP/1.1", host: "meusite.local"

O que aconteceu: a pasta não tem o arquivo citado no index (aqui, o index.html sumiu).

Como resolver: crie o index.html ou ajuste a linha index. Se o arquivo existir, confira as permissões: o nginx roda como www-data.

"nginx: comando não encontrado" como ana

O que aconteceu: o nginx fica em /usr/sbin, fora do PATH dos usuários comuns no Debian.

Como resolver: su - e rode de novo.

Resumo

  • O nginx do Debian usa sites-available + sites-enabled, ligados com ln -s.
  • Cada site é um bloco server; toda linha termina em ;. Inclua listen 80; e listen [::]:80;.
  • nginx -t sempre antes do systemctl reload nginx.
  • proxy_pass + include proxy_params colocam o nginx na frente de uma aplicação; 502 = aplicação fora do ar.
  • Apache e nginx não podem usar a mesma porta ao mesmo tempo.
