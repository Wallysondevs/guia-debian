Debian Solução de Problemas

Os 33 problemas mais comuns no Debian 13, cada um com a mensagem que aparece de verdade, o que causou e como resolver, e o link para a aula completa. Muitos deles pegam justamente quem vem do Ubuntu.

Método em 3 passos
  1. Leia a mensagem até o fim. A causa costuma estar na última parte ("Permissão negada", "comando não encontrado").
  2. Confirme a hipótese com um comando que só observa: ls -l, id, systemctl status, journalctl.
  3. Mude uma coisa por vez e teste de novo.

sudo: comando não encontrado 
$ sudo apt update
bash: sudo: comando não encontrado

O que aconteceu: Na instalação você definiu uma senha de root. Nesse caso, o Debian não instala o sudo.

Como resolver: Use su - (senha do root) ou su -c "apt update". Se quiser o sudo, instale como root e coloque o usuário no grupo: su -c "apt install sudo && usermod -aG sudo ana", depois saia e entre de novo na sessão.

Aula: root, su e sudo.

ana is not in the sudoers file 
$ sudo apt update
[sudo] senha para ana:
ana is not in the sudoers file.
This incident has been reported to the administrator.

O que aconteceu: O sudo está instalado, mas a ana não está no grupo sudo. A recusa sai em inglês mesmo com o sistema em português.

Como resolver: Como root: usermod -aG sudo ana. A mudança só vale numa sessão nova: saia e entre de novo (ou abra outro login no TTY).

Aula: root, su e sudo.

Coloquei no grupo sudo e continua recusando 
$ su -c "usermod -aG sudo ana"
Senha:
$ id
uid=1000(ana) gid=1000(ana) grupos=1000(ana),24(cdrom),25(floppy),29(audio),30(dip),44(video),46(plugdev),100(users),101(netdev)

O que aconteceu: Os grupos são lidos no login. A sessão aberta ainda tem a lista antiga (repare que sudo não aparece no id).

Como resolver: Saia da sessão e entre de novo. Depois confira com id: o grupo 27(sudo) precisa aparecer.

Aula: root, su e sudo.

reboot: comando não encontrado 
$ reboot
bash: reboot: comando não encontrado

O que aconteceu: O reboot existe, mas fica em /usr/sbin, que não está no PATH de um usuário comum no Debian. O mesmo acontece com adduser, usermod e blkid.

Como resolver: Rode como root: su -c reboot, ou abra um shell com su - (o hífen carrega o PATH do root, com /sbin). Com su sem hífen, o PATH continua o da ana.

Aula: root, su e sudo.

su: Falha de autenticação 
$ su -
Senha:
su: Falha de autenticação

O que aconteceu: A senha digitada não é a do root. O su pede a senha do usuário de destino, não a sua.

Como resolver: Digite a senha que você definiu para o root na instalação. Nada aparece enquanto você digita; isso é normal. Se esqueceu, veja "Esqueci a senha de root" abaixo.

Aula: root, su e sudo.

su falha dentro de um pipe 
$ echo oi | su -c "tee /etc/teste"
Senha: su: Falha de autenticação

O que aconteceu: O su tenta ler a senha da entrada padrão, que agora é o pipe. Ele recebe "oi" como senha.

Como resolver: Coloque o pipe inteiro dentro do su -c: su -c 'echo oi | tee /etc/teste'.

Aula: Pipes e xargs.

apt: você é root? 
$ apt install htop
Erro: Não foi possível abrir arquivo de trava /var/lib/dpkg/lock-frontend - open (13: Permissão negada)
Erro: Não é possível adquirir a trava da interface do dpkg (/var/lib/dpkg/lock-frontend), você é root?

O que aconteceu: Instalar programas mexe no sistema e exige root.

Como resolver: su -c "apt install htop" ou, num shell de root (su -), apt install htop.

Aula: apt.

dpkg was interrupted 
#> apt install htop
Erro: dpkg was interrupted, you must manually run 'dpkg --configure -a' to correct the problem.

O que aconteceu: Uma instalação anterior parou no meio (o computador desligou, ou alguém fechou o terminal).

Como resolver: Como root: dpkg --configure -a e depois apt -f install.

Aula: dpkg e .deb.

Comando não encontrado e nenhuma sugestão 
$ htop
bash: htop: comando não encontrado

O que aconteceu: O programa não está instalado. Ao contrário do Ubuntu, o Debian não vem com o command-not-found, que sugere o pacote.

Como resolver: Procure o pacote: apt search htop e instale como root. Para descobrir qual pacote tem um comando, apt-file search bin/htop (pacote apt-file).

Aula: apt.

ll: comando não encontrado 
$ ll
bash: ll: comando não encontrado

O que aconteceu: No Debian, o apelido ll vem comentado no ~/.bashrc.

Como resolver: Use ls -l, ou tire o # da linha #alias ll='ls -l' no ~/.bashrc e rode source ~/.bashrc.

Aula: .bashrc, alias, PATH.

Não existe /var/log/syslog 
$ tail /var/log/syslog
tail: não foi possível abrir '/var/log/syslog' para leitura: Arquivo ou diretório inexistente

O que aconteceu: O Debian 13 não instala o rsyslog. Os logs ficam no journal do systemd.

Como resolver: Use journalctl: journalctl -b (desde o boot), journalctl -u ssh (um serviço), journalctl -f (acompanhar).

Aula: Logs (journalctl).

journalctl só mostra meus logs (Hint) 
$ journalctl -n 2
Hint: You are currently not seeing messages from other users and the system.
      Users in groups 'adm', 'systemd-journal' can see all messages.
      Pass -q to turn off this notice.

O que aconteceu: Um usuário comum só vê os próprios logs.

Como resolver: Rode como root, ou adicione a ana ao grupo adm (usermod -aG adm ana) e entre de novo na sessão.

Aula: Logs (journalctl).

pgrep não acha as abas do Firefox 
$ pgrep -l firefox
2210 firefox-esr
$ pgrep -l Isolated
2251 Isolated Web Co

O que aconteceu: O navegador é o firefox-esr, mas cada aba roda num processo chamado Isolated Web Content, cortado para 15 caracteres (Isolated Web Co).

Como resolver: Para achar tudo do Firefox, procure na linha de comando inteira: pgrep -af firefox.

Aula: ps, pgrep, top.

killall: comando não encontrado 
$ killall firefox-esr
bash: killall: comando não encontrado

O que aconteceu: O killall vem no pacote psmisc, que não está numa instalação de servidor.

Como resolver: Use pkill firefox-esr, que já vem instalado, ou instale o psmisc.

Aula: Encerrar Programas (kill).

A interface travou

O que aconteceu: A sessão gráfica parou de responder, mas o sistema por baixo geralmente continua vivo.

Como resolver: Aperte Ctrl+Alt+F3, entre com usuário e senha, encontre o culpado com top e encerre com kill. Se nada responder, Alt+SysRq+R S U B (no Debian, E e I estão bloqueadas).

Aula: Quando o Sistema Trava.

Ctrl+Alt+T não abre o terminal

O que aconteceu: Esse atalho é do Ubuntu. O GNOME do Debian não tem atalho para o terminal.

Como resolver: Aperte Super e digite "terminal", ou crie o atalho em Configurações → Teclado → Atalhos personalizados com o comando gnome-terminal.

Aula: Atalhos de Teclado.

Não há espaço disponível no dispositivo 
$ cp /etc/services ~/teste
cp: erro de escrita de '/home/ana/teste': Não há espaço disponível no dispositivo
$ df -h /
Sist. Arq.      Tam. Usado Disp. Uso% Montado em
/dev/sda1        19G   18G     0 100% /

O que aconteceu: O disco encheu.

Como resolver: Ache o que ocupa espaço com du -h -d 1 ~ | sort -h (e, como root, em /var). Limpe o cache do apt com apt clean e os logs antigos com journalctl --vacuum-time=7d.

Aula: lsblk, df, du.

Meus arquivos de /tmp sumiram 
$ mount | grep " /tmp "
tmpfs on /tmp type tmpfs (rw,nosuid,nodev,nr_inodes=1048576,inode64)

O que aconteceu: No Debian 13, o /tmp fica na memória (tmpfs) e é esvaziado a cada reinício.

Como resolver: Guarde o que importa na sua pasta pessoal. Para temporários que sobrevivem ao reinício, use /var/tmp.

Aula: Estrutura de Diretórios.

Sem rede depois de mexer na configuração

O que aconteceu: No Debian servidor, a rede é do ifupdown (/etc/network/interfaces). Um erro nesse arquivo deixa a interface desligada (DOWN no ip -br link).

Como resolver: No console da máquina, como root: confira o arquivo, teste com ifup --no-act enp1s0 e suba com ifup enp1s0. Tenha sempre uma cópia do arquivo que funcionava.

Aula: Configurar a Rede.

O NetworkManager diz que a placa é "não gerenciada"

O que aconteceu: Uma interface declarada em /etc/network/interfaces fica com o ifupdown, e o NetworkManager a ignora.

Como resolver: Escolha um dos dois: ou tire a interface do interfaces (deixando só o lo) para o NetworkManager assumir, ou continue com o ifupdown.

Aula: Configurar a Rede.

O Wi-Fi não conecta ou não aparece 
$ nmcli device wifi connect CasaDaAna password 'senhaerrada1'
…
Error: Connection activation failed: Segredos foram requisitados, mas não fornecidos.

O que aconteceu: senha errada (a mensagem acima), conexão salva com a senha errada (key-mgmt: propriedade está faltando), Wi-Fi bloqueado (placa não disponível) ou a placa nem aparece (driver ou firmware).

Como resolver: senha e conexões salvas: Wi-Fi: quando não funciona. Placa bloqueada ou ausente: Wi-Fi que Não Funciona. Sem Wi-Fi nenhum: celular por USB.

Wi-Fi ou vídeo não funcionam (firmware)

O que aconteceu: Muitas placas precisam de um firmware fechado, que fica no componente non-free-firmware.

Como resolver: Confira se o sources.list tem non-free-firmware. Veja no dmesg qual firmware falhou (Direct firmware load … failed with error -2) e instale o pacote (por exemplo, firmware-iwlwifi para Wi-Fi Intel, firmware-realtek para Realtek).

Aulas: Wi-Fi que Não Funciona e Repositórios (sources).

O repositório não está assinado 
#> apt update
Erro:1 https://download.docker.com/linux/debian trixie InRelease
  Sub-process /usr/bin/sqv returned an error code (1), error message is: Missing key 7EA0A9C3F273FCD8, which is needed to verify signature.
E: O repositório 'http://download.docker.com/linux/debian trixie InRelease' não está assinado.

O que aconteceu: Você adicionou um repositório de terceiros sem a chave que prova a origem dos pacotes.

Como resolver: Baixe a chave oficial para /etc/apt/keyrings/ e aponte para ela com signed-by= na linha do repositório. O apt-key não existe mais no Debian 13.

Aula: Repositórios (sources).

Dependências quebradas depois de misturar versões

O que aconteceu: Pacotes da testing ou do Ubuntu instalados numa stable criam um "FrankenDebian": versões incompatíveis que travam as atualizações.

Como resolver: Volte a usar só os repositórios da sua versão. Para um programa mais novo, prefira o trixie-backports ou o Flatpak.

Aula: Backports e Pinning.

add-apt-repository não existe 
$ add-apt-repository ppa:exemplo/ppa
bash: add-apt-repository: comando não encontrado

O que aconteceu: PPAs são do Ubuntu, e o comando não existe no Debian 13.

Como resolver: Não use PPAs no Debian. Para repositórios de terceiros, siga as instruções do fornecedor para Debian, com signed-by.

Aula: Repositórios (sources).

O boot parou pedindo a senha de root 
You are in rescue mode. After logging in, type "journalctl -xb" to view
system logs, "systemctl reboot" to reboot, or "exit"
to continue bootup.
Give root password for maintenance
(ou pressione Contrl-D para continuar):

O que aconteceu: O sistema entrou em modo de emergência, quase sempre por um erro no /etc/fstab ou num disco que sumiu.

Como resolver: Digite a senha do root, rode journalctl -xb para ver o erro, corrija o /etc/fstab com nano e reinicie com systemctl reboot.

Aula: Recuperar um Sistema.

Esqueci a senha de root

O que aconteceu: Sem a senha de root (e sem sudo), você não administra a máquina.

Como resolver: Reinicie, aperte e no menu do GRUB, acrescente init=/bin/bash à linha do linux, inicie com Ctrl+X, rode mount -o remount,rw / e passwd. Detalhes e cuidados na aula.

Aula: Recuperar um Sistema.

findmnt --verify avisa sobre /media/cdrom0 
#> findmnt --verify
/media/cdrom0
   [W] não foi possível detectar o tipo de sistema de arquivos em disco (Mídia não encontrada)
0 erro de análise, 0 erro, 1 aviso

O que aconteceu: O instalador deixa no fstab uma linha para o leitor de DVD usado na instalação. Sem mídia, o findmnt só avisa.

Como resolver: É inofensivo. Se a máquina não tem leitor, comente a linha do /dev/sr0 no /etc/fstab.

Aula: mount e fstab.

ssh: Connection refused 
$ ssh ana@192.168.0.50
ssh: connect to host 192.168.0.50 port 22: Connection refused

O que aconteceu: A máquina respondeu, mas não há servidor SSH escutando na porta 22.

Como resolver: Na máquina de destino: apt install openssh-server e systemctl status ssh.

Aula: SSH.

Permission denied (publickey,password) 
$ ssh root@192.168.0.50
root@192.168.0.50: Permission denied (publickey,password).

O que aconteceu: No Debian, o root não entra por SSH com senha (PermitRootLogin prohibit-password). Ou a senha/chave está errada.

Como resolver: Entre com um usuário comum e use su - lá dentro, ou instale sua chave para o root.

Aula: SSH.

O firewall não está protegendo nada 
#> systemctl status nftables
○ nftables.service - nftables
     Loaded: loaded (/usr/lib/systemd/system/nftables.service; disabled; preset: enabled)
     Active: inactive (dead)

O que aconteceu: O serviço nftables vem desligado, e o arquivo padrão aceita tudo.

Como resolver: Escreva as regras em /etc/nftables.conf, teste com nft -c -f /etc/nftables.conf e ative com systemctl enable --now nftables, liberando a porta 22 antes se a máquina for remota.

Aula: Firewall (nftables).

As atualizações automáticas não acontecem

O que aconteceu: O unattended-upgrades não vem instalado no Debian e, mesmo instalado, não roda até existir o arquivo /etc/apt/apt.conf.d/20auto-upgrades.

Como resolver: Como root: apt install unattended-upgrades e dpkg-reconfigure -plow unattended-upgrades (responda Sim).

Aula: Atualizações.

Containers do Incus sem internet depois de instalar o Docker 
#> incus exec c1 -- ping -c1 -W3 deb.debian.org
1 packets transmitted, 0 received, 100% packet loss, time 0ms
#> iptables -S FORWARD | head -1
-P FORWARD DROP

O que aconteceu: O Docker muda a política de encaminhamento para DROP, e o tráfego da ponte do Incus deixa de passar.

Como resolver: Libere a ponte do Incus na cadeia DOCKER-USER, como mostra a aula, ou evite os dois na mesma máquina.

Aula: Incus (containers de sistema).

Mensagem metade em inglês: cannot create directory 
$ mkdir fotos
mkdir: cannot create directory ‘fotos’: Arquivo existe

O que aconteceu: Não é erro de instalação: a tradução do GNU coreutils no Debian deixa o começo da frase em inglês.

Como resolver: Leia o fim da mensagem, que é a causa: "Arquivo existe". Use mkdir -p se a ideia era só garantir que a pasta exista.

Aula: touch e mkdir.

Exercícios

1. Você rodou usermod -aG sudo ana como root, mas o sudo continua recusando. O que falta?

2. Por que echo oi | su -c "tee /etc/teste" falha?

Missão: treine o passo 2 do método: confirme quem é o dono do arquivo /etc/hostname antes de tentar mudá-lo. Use ls -l /etc/hostname.
