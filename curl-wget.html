Debian curl, wget, dig

Três ferramentas conversam com a internet pelo terminal. O wget baixa arquivos. O curl faz requisições de todo tipo e mostra o que o servidor respondeu, por isso é o favorito para testar sites e APIs. O dig pergunta ao DNS qual é o IP de um nome. No Debian, nem todas vêm instaladas.

Você vai aprender
  • Quais dessas ferramentas o Debian já traz e como instalar as que faltam.
  • Baixar arquivos com wget e retomar um download interrompido.
  • Ver o cabeçalho e o código HTTP de um site com curl -I.
  • Usar o código de saída do curl em scripts.
  • Descobrir o IP de um nome com dig e o caminho até ele com traceroute.

Retomar um download grande

Caiu a conexão no meio de uma ISO de 4 GB? Rode o mesmo comando com -c (de continue) na mesma pasta: o wget pede ao servidor só o pedaço que falta. Se o arquivo já estiver completo, ele avisa:

$ wget -c -O debian.html https://www.debian.org/
…
A requisição HTTP foi enviada, aguardando resposta... 416 Requested Range Not Satisfiable

    O arquivo já foi completamente obtido; não há nada a ser feito.

curl: conversar com servidores

O curl (de client URL) mostra o conteúdo na tela por padrão, em vez de salvar. A opção mais usada para diagnóstico é a -I, que busca só o cabeçalho da resposta:

curl
O programa.
-I
Só o cabeçalho (head), sem o conteúdo da página.
https://www.debian.org/
O endereço.
$ curl -I https://www.debian.org/
HTTP/2 200                                          « protocolo e código: deu certo
content-location: index.en.html
vary: negotiate,accept-language,Accept-Encoding,cookie
x-content-type-options: nosniff
strict-transport-security: max-age=15552000
last-modified: Tue, 13 Oct 2026 03:28:16 GMT        « quando a página mudou pela última vez
content-length: 15864                               « tamanho, em bytes
cache-control: max-age=86400
content-type: text/html                             « o tipo do conteúdo
date: Fri, 16 Oct 2026 00:28:47 GMT
server: Apache                                      « o programa servidor

O curl e as respostas HTTP ficam em inglês, independentemente do idioma do sistema.

Seguir redirecionamentos: -L

Sem -L, o curl para no primeiro redirecionamento e só mostra para onde ele aponta:

$ curl -I http://debian.org
HTTP/1.1 302 Found                     « "está em outro lugar"
Content-Length: 0
Server: Varnish
location: https://www.debian.org/      « o endereço novo
…

Com -L (de location), ele segue até o destino final: curl -IL http://debian.org mostra os dois cabeçalhos, o 302 e o 200.

Salvar em arquivo: -o e -O

$ curl -o pagina.html https://www.debian.org/                 « -o minúsculo: você escolhe o nome
$ curl -O https://www.debian.org/Pics/openlogo-50.png          « -O maiúsculo: usa o nome do link
  % Total    % Received % Xferd  Average Speed   Time    Time     Time  Current
                                 Dload  Upload   Total   Spent    Left  Speed
100  2006  100  2006    0     0   1490      0  0:00:01  0:00:01 --:--:--  1491

Quando salva em arquivo, o curl mostra uma tabela de progresso. Para escondê-la em scripts, use -s (de silent).

Só o código, em uma linha: -w

O -w (de write-out) escreve informações no fim. Junto com -s -o /dev/null (descartar o conteúdo), sobra só o que você pediu:

$ curl -s -o /dev/null -w "%{http_code}\n" https://www.debian.org/
200
$ curl -s -o /dev/null -w "%{http_code} %{time_total}s\n" https://deb.debian.org/naoexiste
404 1.160527s

curl em scripts: -f e o código de saída

Por padrão, o curl considera "sucesso" qualquer resposta, até um 404: o código de saída é 0. Com -f (de fail), um código 400 ou mais vira erro 22. Com -sS, ele fica silencioso mas ainda mostra a mensagem de erro:

$ curl -fsS https://deb.debian.org/naoexiste
curl: (22) The requested URL returned error: 404
$ echo $?
22

Assim dá para escrever: curl -fsS https://meusite.com.br/ > /dev/null || echo "site fora do ar".

Seu IP público

O IP que aparece no ip a é o da rede local. Para saber com qual IP você aparece na internet, pergunte a um site: curl -s https://ifconfig.me/ip ou wget -qO- https://ifconfig.me/ip. A resposta é um único endereço, como 203.0.113.45 (pode vir em IPv6).

dig: perguntar ao DNS

O dig (de domain information groper) mostra a resposta do DNS em detalhes. Comece pela forma curta, com +short:

$ dig +short deb.debian.org
debian.map.fastlydns.net.          « deb.debian.org é um apelido (CNAME) deste nome
151.101.66.132                     « que aponta para estes IPs
151.101.130.132
151.101.194.132
151.101.2.132

Sem o +short, a saída é longa, mas tem partes úteis:

$ dig deb.debian.org

;; global options: +cmd
;; Got answer:
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 54883       « NOERROR: o nome existe
;; flags: qr rd ra; QUERY: 1, ANSWER: 2, AUTHORITY: 0, ADDITIONAL: 1

;; QUESTION SECTION:

Tipos de registro e outro servidor

ComandoPergunta
dig +short debian.orgIPv4 (registro A)
dig +short AAAA debian.orgIPv6
dig +short MX debian.orgServidores de e-mail
dig +short NS debian.orgServidores DNS do domínio
dig +short -x 1.1.1.1DNS reverso: nome de um IP (one.one.one.one.)
dig +short @8.8.8.8 debian.orgPergunta a um servidor específico (aqui, o do Google)

Perguntar a outro servidor com @ é o teste clássico: se dig @8.8.8.8 responde e o dig normal não, o problema está no DNS configurado na sua máquina.

traceroute: o caminho até o destino

O traceroute mostra cada roteador (cada "salto") entre você e o destino. Útil para ver onde a conexão para.

$ traceroute -n -m 5 deb.debian.org
traceroute to deb.debian.org (151.101.250.132), 5 hops max, 60 byte packets
 1  192.168.0.1  0.337 ms  0.289 ms  0.432 ms          « o seu roteador
 2  10.15.255.250  12.518 ms  13.750 ms  12.003 ms     « o provedor de internet
 3  203.0.113.85  14.921 ms  15.985 ms  14.798 ms
 4  * * *                                              « este salto não respondeu

O -n mostra só números (mais rápido) e -m 5 limita a 5 saltos. Estrelas (* * *) são comuns: muitos roteadores não respondem ao traceroute, e isso não é erro. Saídas ilustrativas: os saltos dependem da sua rede.

Quando não funciona

curl: (6) Could not resolve host 
$ curl https://nada.invalid/
curl: (6) Could not resolve host: nada.invalid

O que aconteceu: o DNS não achou o nome. Erro de digitação ou DNS sem resposta.

Como confirmar: dig +short nada.invalid volta vazio; teste o mesmo nome com @8.8.8.8. No wget, o mesmo erro aparece como não foi possível resolver endereço de máquina “nada.invalid” (código 4).

curl: (7) Could not connect to server 
$ curl http://127.0.0.1:8080/
curl: (7) Failed to connect to 127.0.0.1 port 8080 after 1 ms: Could not connect to server

O que aconteceu: a máquina existe, mas nada escuta naquela porta (no wget: falha: Conexão recusada.). O serviço está parado ou usa outra porta: confira com ss -tln.

curl: (28) Connection timed out 
$ curl -m 2 http://192.0.2.1/
curl: (28) Connection timed out after 2011 milliseconds

O que aconteceu: ninguém respondeu dentro do tempo. Máquina desligada, IP errado ou firewall descartando.

O 404 "passou" no script

O que aconteceu: sem -f, o curl devolve 0 mesmo quando o site responde 404 ou 500.

Como resolver: use curl -fsS; aí o código vira 22 e o || do script funciona.

"curl: comando não encontrado"

O que aconteceu: o Debian não instala o curl por padrão. Como root: apt install curl. Enquanto isso, o wget resolve a maioria dos casos: wget -qO- URL faz o mesmo que curl -s URL.

Resumo dos códigos de erro do curl

CódigoSignificado
0Sucesso (inclusive 404, se não usar -f)
6Não resolveu o nome (DNS)
7Não conectou (porta fechada, serviço parado)
22Resposta HTTP 400 ou mais, com -f
28Tempo esgotado
60Certificado SSL não confiável

Resumo

  • O Debian traz wget, dig, host e traceroute; o curl se instala com apt install curl.
  • wget -O nome URL baixa; -c retoma; as mensagens saem em português.
  • curl -I mostra o cabeçalho; -L segue redirecionamentos; -o/-O salvam.
  • Em scripts: curl -fsS e o código de saída (6 DNS, 7 conexão, 22 erro HTTP, 28 tempo).
  • dig +short nome resolve; @8.8.8.8 testa outro servidor de DNS.
