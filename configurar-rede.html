Debian Configurar a Rede

No Debian não existe Netplan. Quem cuida da rede depende de como o sistema foi instalado: num servidor (sem desktop) é o ifupdown, configurado pelo arquivo /etc/network/interfaces; num desktop é o NetworkManager. Nesta aula você aprende os dois e, principalmente, a mudar a rede sem perder o acesso à máquina.

Você vai aprender
  • Descobrir quem gerencia a rede do seu Debian.
  • Ler o /etc/network/interfaces linha por linha.
  • Trocar DHCP por IP fixo, testando antes com ifup --no-act.
  • Entender de onde vem o /etc/resolv.conf (o DNS) no Debian 13.
  • Usar o nmcli no desktop e evitar o conflito entre NetworkManager e ifupdown.
  • Trocar o nome da máquina corretamente.
Antes de mexer na rede

Mudar a rede de uma máquina que você acessa por SSH pode derrubar a sua conexão, e você fica do lado de fora. Faça essas mudanças pelo console (tela e teclado na máquina, ou a janela da VM). Se não tiver jeito, use o "plano B" com tempo de volta, mostrado mais abaixo.

Quem cuida da rede neste Debian?

Tipo de instalaçãoGerenciadorOnde se configura
Servidor ou instalação mínima (sem desktop)ifupdown (serviço networking) + dhcpcd/etc/network/interfaces
Desktop (GNOME, KDE, Xfce…)NetworkManagerConfigurações → Rede, ou nmcli
Configuração avançada (opcional)systemd-networkd/etc/systemd/network/ (vem desativado)

Para descobrir qual está em uso, pergunte ao systemd:

$ systemctl is-active networking NetworkManager
active                          « o ifupdown está cuidando da rede
inactive                        « o NetworkManager não está rodando (ou não está instalado)

No servidor de exemplo deste guia, só o networking está ativo. O NetworkManager nem vem instalado numa instalação sem desktop.

O arquivo /etc/network/interfaces

Este é o arquivo que o instalador do Debian cria num servidor. A leitura não precisa de root:

# This file describes the network interfaces available on your system
# and how to activate them. For more information, see interfaces(5).

source /etc/network/interfaces.d/*

# The loopback network interface
auto lo
iface lo inet loopback

# The primary network interface
allow-hotplug enp1s0
iface enp1s0 inet dhcp
# This is an autoconfigured IPv6 interface
iface enp1s0 inet6 auto

Linha por linha:

LinhaSignificado
# …Comentários (os do instalador ficam em inglês).
source /etc/network/interfaces.d/*Lê também todos os arquivos da pasta interfaces.d. Útil para separar a configuração de cada placa.
auto loLiga a placa lo automaticamente no boot.
iface lo inet loopback"A placa lo, em IPv4 (inet), é do tipo loopback."
allow-hotplug enp1s0Liga a placa quando o sistema a detectar (no boot ou se ela for conectada depois).
iface enp1s0 inet dhcpA placa enp1s0 pega o IPv4 por DHCP, do roteador.
iface enp1s0 inet6 autoO IPv6 é configurado automaticamente pelo roteador.

Cada placa é descrita por um bloco que começa com iface <placa> <família> <método>:

iface
Começa a descrição de uma placa.
enp1s0
O nome da placa, igual ao do ip a.
inet
A família: inet = IPv4, inet6 = IPv6.
dhcp
O método: dhcp (automático), static (IP fixo), loopback, manual…

auto ou allow-hotplug?

As duas ligam a placa sozinhas. auto liga sempre no boot, e o sistema espera por ela. allow-hotplug liga quando a placa aparece. O instalador usa allow-hotplug; para um servidor com IP fixo, prefira auto.

ifquery, ifup e ifdown

O ifupdown tem três comandos, todos em /usr/sbin (só funcionam como root; para a usuária comum, eles dão "comando não encontrado"):

ComandoFaz
ifquery <placa>Mostra como a placa está configurada no arquivo.
ifquery --stateLista as placas que o ifupdown ligou.
ifup <placa>Liga a placa conforme o arquivo.
ifdown <placa>Desliga a placa. Por SSH, isso derruba a sua conexão.
systemctl restart networkingDesliga e liga todas as placas com auto/allow-hotplug.
$ su -
Senha:
#> ifquery --state
lo=lo
enp1s0=enp1s0
#> ifup enp1s0
ifup: interface enp1s0 already configured          « já está ligada: nada a fazer

Trocar DHCP por IP fixo

Um servidor precisa de um endereço que não mude. Escolha um IP fora da faixa que o roteador distribui (por exemplo, 192.168.0.50) e anote o gateway e o DNS da rede (ip r e cat /etc/resolv.conf).

  1. Faça uma cópia do arquivo, para poder voltar: 
    #> cp /etc/network/interfaces /etc/network/interfaces.bak
  2. Edite o bloco da placa com nano /etc/network/interfaces. Troque as linhas da enp1s0 por: 
    auto enp1s0
iface enp1s0 inet static
    address 192.168.0.50/24
    gateway 192.168.0.1
    As linhas de dentro do bloco ficam com recuo (o recuo é só para leitura; o que conta é a ordem).
  3. Teste sem aplicar com --no-act (não faça nada) e -v (detalhado). O ifup mostra os comandos que rodaria: 
    #> ifup --no-act -v enp1s0

ifup: configuring interface enp1s0=enp1s0 (inet)
run-parts --exit-on-error --verbose /etc/network/if-pre-up.d
ip addr add 192.168.0.50/255.255.255.0 broadcast 192.168.0.255 	  dev enp1s0 label enp1s0   « o IP novo
ip link set dev enp1s0   up
 ip route add default via 192.168.0.1  dev enp1s0 onlink                                      « o gateway
run-parts --exit-on-error --verbose /etc/network/if-up.d
    Se houver erro de digitação, ele aparece aqui, antes de qualquer estrago (veja "Quando não funciona").
  4. Ajuste o DNS: com IP fixo, ninguém escreve o /etc/resolv.conf por você (veja a próxima seção). Deixe-o assim: 
    nameserver 192.168.0.1
nameserver 1.1.1.1
  5. Aplique, de preferência pelo console. Desligar e ligar na mesma linha garante que a placa volte mesmo se a conexão cair no meio: 
    #> ifdown enp1s0 && ifup enp1s0
  6. Confira: 
    #> ip -br a show enp1s0
enp1s0           UP             192.168.0.50/24 fe80::ae13:e729:e153:39c/64
#> ping -c 2 debian.org
E a opção dns-nameservers?

Muitos tutoriais colocam dns-nameservers 1.1.1.1 dentro do bloco da placa. No Debian, essa linha só tem efeito se o pacote resolvconf (ou o systemd-resolved) estiver instalado. Numa instalação padrão do Debian 13 ela é ignorada, por isso o passo 4 edita o /etc/resolv.conf direto.

Plano B: voltar sozinho se você perder o acesso

O Debian não tem um "teste com tempo para confirmar" como o netplan try do Ubuntu. Mas dá para montar um com o systemd-run: agende a volta do arquivo antigo para daqui a 5 minutos, aplique a mudança e, se tudo der certo, cancele o agendamento.

#> systemd-run --on-active=5min /bin/sh -c 'cp /etc/network/interfaces.bak /etc/network/interfaces && systemctl restart networking'
Running timer as unit: run-p10090-i10390.timer          « o "despertador" de 5 minutos
Will run service as unit: run-p10090-i10390.service
#> ifdown enp1s0 && ifup enp1s0
# … reconecte pelo IP novo. Deu certo? Cancele a volta:
#> systemctl stop run-p10090-i10390.timer

Se a conexão cair e você não conseguir voltar, em 5 minutos o arquivo antigo é restaurado e a rede reinicia sozinha.

DNS: quem escreve o /etc/resolv.conf

O arquivo /etc/resolv.conf diz quais servidores de DNS usar. No Debian 13, quem pega o IP por DHCP é o dhcpcd, e é ele que escreve esse arquivo. A primeira linha conta isso:

$ cat /etc/resolv.conf
# Generated by dhcpcd from enp1s0.dhcp, enp1s0.ra       « escrito pelo dhcpcd
# /etc/resolv.conf.head can replace this line
domain lan
nameserver 192.168.0.1                                 « o DNS que o roteador informou
# /etc/resolv.conf.tail can replace this line
SituaçãoQuem controla o resolv.conf
Servidor com DHCP (padrão)O dhcpcd: ele reescreve o arquivo a cada renovação. Edições à mão se perdem.
Servidor com IP fixoNinguém: você edita o arquivo e ele fica como está.
Desktop com NetworkManagerO NetworkManager.

Diferente do Ubuntu, o Debian não usa o systemd-resolved por padrão, então o comando resolvectl não existe. Para testar o DNS, use getent hosts debian.org ou dig (veja curl, wget, dig).

Para fixar um DNS mesmo usando DHCP, acrescente ao /etc/dhcpcd.conf a linha static domain_name_servers=1.1.1.1 9.9.9.9 e reinicie a rede.

No desktop: NetworkManager e nmcli

Num Debian com desktop, use o ícone de rede no canto da tela ou Configurações → Rede. No terminal, a ferramenta é o nmcli (de NetworkManager command line). Os comandos são os mesmos de qualquer distribuição:

ComandoFaz
nmcli device statusLista as placas e o estado de cada uma
nmcli device wifi listRedes Wi-Fi ao alcance
nmcli device wifi connect "MinhaRede" password "senha"Conecta num Wi-Fi
nmcli connection showConexões salvas
nmcli connection modify "Conexão" ipv4.method manual ipv4.addresses 192.168.0.50/24 ipv4.gateway 192.168.0.1 ipv4.dns "1.1.1.1"IP fixo numa conexão
nmcli connection up "Conexão"Aplica as mudanças

O conflito clássico do Debian: placa "não gerenciada"

O NetworkManager do Debian ignora toda placa que estiver descrita no /etc/network/interfaces (opção managed=false em /etc/NetworkManager/NetworkManager.conf). Se você instalou o desktop depois de um servidor, a placa aparece como não gerenciado (unmanaged) e o ícone de rede não a controla.

Solução: deixe no /etc/network/interfaces só o bloco do lo, comente o da placa e reinicie: systemctl restart networking NetworkManager. A partir daí, o NetworkManager assume.

Escolha um só

Não configure a mesma placa no interfaces e no NetworkManager ao mesmo tempo. Servidor: ifupdown. Desktop: NetworkManager.

O nome da máquina

O nome aparece no prompt (ana@notebook) e na rede. Para ver:

$ hostnamectl hostname
notebook

Para trocar, são dois passos como root. O primeiro troca o nome; o segundo atualiza o /etc/hosts, onde o Debian coloca o nome da própria máquina:

#> hostnamectl set-hostname servidor
#> cat /etc/hosts
127.0.0.1	localhost
127.0.1.1	notebook.lan	notebook          « ainda com o nome antigo
…

Edite a linha 127.0.1.1 para 127.0.1.1 servidor.lan servidor. Sem isso, a máquina não consegue resolver o próprio nome, e alguns programas reclamam ou demoram (o sudo, se você o instalou, avisa unable to resolve host servidor). O prompt muda no próximo login.

Quando não funciona

"ifup: unknown interface eth0" 
#> ifup eth0
ifup: unknown interface eth0

O que aconteceu: o nome da placa está errado ou ela não está no arquivo. O nome antigo eth0 não existe mais na maioria das máquinas.

Como resolver: veja o nome real com ip -br a e use o mesmo nome no arquivo.

Erro de digitação no método 
#> ifup --no-act enp1s0
ifup: /etc/network/interfaces:5: unknown or no method and no inherits keyword specified   « linha 5
ifup: couldn't read interfaces file "/etc/network/interfaces"

O que aconteceu: na linha 5 há um método inválido, como statik no lugar de static.

Como resolver: corrija a linha indicada e teste de novo com --no-act.

Faltou o endereço 
#> ifup --no-act enp1s0

ifup: missing required variable: address
ifup: missing required configuration variables for interface enp1s0/inet
ifup: failed to bring up enp1s0

O que aconteceu: o método static exige a linha address, e ela está faltando ou com o nome errado (por exemplo, endereco).

IP fixo funciona, mas os nomes não resolvem

O que aconteceu: sem DHCP, ninguém atualiza o /etc/resolv.conf; ele pode estar vazio ou com um DNS que não existe nessa rede.

Como resolver: coloque um nameserver válido no arquivo e teste com getent hosts debian.org.

Rodei ifdown pelo SSH e perdi o acesso

O que aconteceu: o ifdown desligou a placa por onde a sua conexão passava.

Como resolver: vá até o console da máquina (ou a janela da VM) e rode ifup enp1s0. Da próxima vez, use ifdown enp1s0 && ifup enp1s0 na mesma linha, ou o plano B com systemd-run.

Resumo

  • Servidor Debian: ifupdown com /etc/network/interfaces; desktop: NetworkManager. Não há Netplan.
  • Cada placa tem um bloco iface <placa> inet dhcp|static.
  • Teste com ifup --no-act -v antes de aplicar; aplique com ifdown placa && ifup placa.
  • No Debian 13, o dhcpcd escreve o /etc/resolv.conf; com IP fixo, edite-o à mão.
  • O NetworkManager ignora placas do interfaces: escolha um gerenciador só.
  • Trocar o nome: hostnamectl set-hostname e a linha 127.0.1.1 do /etc/hosts.
