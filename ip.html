Debian ip, ping, ss

Três ferramentas respondem quase todas as perguntas sobre a rede: ip mostra as placas, os endereços e as rotas; ping testa se um destino responde; ss lista as conexões e as portas abertas. As três já vêm instaladas em qualquer Debian, até na instalação mínima.

Você vai aprender
  • Ler a saída completa do ip a e a versão resumida ip -br a.
  • Ver o gateway, as rotas e os vizinhos com ip r e ip neigh.
  • Usar o ping com limite de tentativas e entender o código de saída dele.
  • Descobrir quais portas estão abertas e qual programa usa cada uma com ss.
  • Por que, no Debian, o ss não mostra os processos para a usuária comum.

Se ainda não leu Conceitos de Rede, comece por lá: esta aula usa IP, máscara, gateway e porta o tempo todo. Os exemplos são da máquina fictícia notebook, ligada no cabo de rede (placa enp1s0), com IP 192.168.0.15. As saídas foram tiradas de um Debian 13 real; só os endereços foram trocados.

O comando ip

O ip faz parte do pacote iproute2, a ferramenta oficial de rede do Linux. Ele tem subcomandos, e cada um cuida de uma parte da rede:

SubcomandoAbreviaçãoMostra
ip addressip aEndereços IP de cada placa
ip routeip rRotas: por onde sai cada destino
ip linkip lAs placas em si: ligadas ou não, endereço físico (MAC)
ip neighbourip nVizinhos: aparelhos da rede local que o computador já conhece

Qualquer abreviação sem ambiguidade funciona: ip a, ip addr e ip address são o mesmo comando. Ler informações com o ip não precisa de root; só mudar a rede precisa.

E o ifconfig?

Tutoriais antigos usam ifconfig e netstat, do pacote net-tools. Eles não vêm no Debian 13 e estão parados há anos. No Debian, digitar ifconfig como usuária comum dá bash: ifconfig: comando não encontrado. Use ip e ss.

Ver os endereços: ip -br a

Comece pela versão resumida. Ela mostra uma linha por placa:

ip
A ferramenta de rede.
-br
Opção brief, "resumido": uma linha por placa.
a
Subcomando address: os endereços.
$ ip -br a
lo               UNKNOWN        127.0.0.1/8 ::1/128
enp1s0           UP             192.168.0.15/24 fd17:625c:f037:2:a00:27ff:fe90:fbde/64 fe80::ae13:e729:e153:39c/64

Cada linha tem três colunas: o nome da placa, o estado e os endereços.

NomeO que é
loLoopback: a placa virtual que o computador usa para falar consigo mesmo. Sempre existe.
enp1s0, eno1, ens3Placa de cabo (Ethernet). O "en" vem de Ethernet; o resto indica onde a placa está ligada na máquina.
wlp2s0Placa Wi-Fi. O "wl" vem de wireless, "sem fio". Veja Wi-Fi.
docker0, virbr0, wg0Placas virtuais criadas pelo Docker, por máquinas virtuais ou por VPN.

Na coluna de estado, UP quer dizer ligada e com conexão, e DOWN, desligada ou sem cabo. O lo aparece como UNKNOWN, o que é normal. O endereço que interessa quase sempre é o primeiro IPv4 da placa ativa: 192.168.0.15/24.

Com cores

Acrescente -c (de color): ip -br -c a pinta o estado de verde ou vermelho e os endereços IPv4 e IPv6 em cores diferentes. Fica bem mais fácil de ler.

Os endereços IPv6

Ao lado do IPv4 aparecem endereços longos com :. Os que começam com fe80:: são de enlace local: existem em toda placa e só valem dentro da rede local. Os outros são IPv6 dados pelo roteador. Para o dia a dia, você pode ignorá-los.

A saída completa: ip a

Sem o -br, o ip mostra todos os detalhes de cada placa. Veja a placa de cabo, com cada linha explicada:

$ ip a show enp1s0
2: enp1s0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP group default qlen 1000   « número, nome e situação da placa
    link/ether 08:00:27:90:fb:de brd ff:ff:ff:ff:ff:ff                                                      « endereço físico (MAC)
    altname enx08002790fbde                                                                                 « nome alternativo
    inet 192.168.0.15/24 brd 192.168.0.255 scope global dynamic noprefixroute enp1s0                       « o IPv4
       valid_lft 85782sec preferred_lft 74982sec                                                           « tempo até renovar
    inet6 fe80::ae13:e729:e153:39c/64 scope link                                                            « IPv6 local
       valid_lft forever preferred_lft forever
ParteSignificado
2: enp1s0:Número interno da placa e o nome dela.
<…UP,LOWER_UP>UP: a placa foi ligada. LOWER_UP: há sinal físico (o cabo está conectado). Sem o LOWER_UP, o cabo está solto.
mtu 1500Tamanho máximo de cada pacote, em bytes. 1500 é o padrão.
link/ether 08:00:27:…O endereço físico (MAC) da placa, gravado de fábrica.
inet 192.168.0.15/24O endereço IPv4 e a máscara em notação CIDR (/24 = 255.255.255.0).
brd 192.168.0.255Endereço de broadcast: falar com todos da rede local de uma vez.
dynamicO endereço veio por DHCP (do roteador). Um IP fixo não tem essa palavra.
valid_lft 85782secPor quanto tempo o endereço emprestado pelo DHCP ainda vale (cerca de 24 horas).

Para ver só uma placa, use ip a show <placa>. Sem nome, o ip a lista todas, começando pelo lo.

Rotas e gateway: ip r

A tabela de rotas diz por onde cada destino sai. A linha mais importante é a rota padrão (default): tudo o que não é da rede local vai para o gateway, normalmente o roteador.

$ ip r
default via 192.168.0.1 dev enp1s0 proto dhcp src 192.168.0.15 metric 1002    « gateway: 192.168.0.1
192.168.0.0/24 dev enp1s0 proto dhcp scope link src 192.168.0.15 metric 1002   « a rede local
default
Qualquer destino que não tenha uma rota mais específica.
via 192.168.0.1
Mande para este endereço: o gateway (roteador).
dev enp1s0
Saindo por esta placa.
proto dhcp
A rota foi criada pelo cliente DHCP. No Debian 13, quem faz isso é o dhcpcd.
metric 1002
Prioridade: com duas rotas iguais, vence a de número menor.

Quer saber por qual caminho um endereço específico vai sair? Pergunte direto:

$ ip route get 8.8.8.8
8.8.8.8 via 192.168.0.1 dev enp1s0 src 192.168.0.15 uid 1000
    cache
Sem linha default, sem internet

Se o ip r não mostra nenhuma linha começando com default, o computador não sabe como sair da rede local: os sites não abrem, mesmo com IP. Veja o roteiro em Conceitos de Rede e Configurar a Rede.

Vizinhos e placas: ip neigh e ip link

O ip neigh mostra quais aparelhos da rede local o computador já encontrou, com o endereço físico de cada um:

$ ip neigh
192.168.0.1 dev enp1s0 lladdr 52:54:00:12:35:00 REACHABLE    « o roteador respondeu há pouco
192.168.0.20 dev enp1s0 lladdr 02:ab:cd:00:00:20 STALE        « visto antes, não confirmado agora

REACHABLE quer dizer "respondeu recentemente"; STALE, "conheço, mas faz tempo"; FAILED, "tentei e não respondeu".

O ip -s link (-s de statistics) conta os pacotes que passaram pela placa, incluindo erros:

$ ip -s link show enp1s0
2: enp1s0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP mode DEFAULT group default qlen 1000
    link/ether 08:00:27:90:fb:de brd ff:ff:ff:ff:ff:ff
    RX:  bytes packets errors dropped  missed   mcast
      17075134   15955      0       0       0       4    « recebidos
    TX:  bytes packets errors dropped carrier collsns
       1260981    9207      0       0       0       0    « enviados
    altname enx08002790fbde

RX (de receive) é o que chegou e TX (de transmit), o que saiu. Números crescendo em errors ou dropped indicam cabo ruim ou placa com problema.

ping: o destino responde?

O ping manda pequenos pacotes de teste e mede quanto tempo a resposta demora. No Linux ele não para sozinho: sem limite, fica rodando até você apertar Ctrl+C. Por isso, quase sempre se usa -c.

ping
O programa de teste.
-c 3
De count: envia 3 pacotes e para.
deb.debian.org
O destino: um nome ou um IP.
$ ping -c 3 deb.debian.org
PING debian.map.fastlydns.net (151.101.66.132) 56(84) bytes of data.            « o nome virou este IP
64 bytes from 151.101.66.132: icmp_seq=1 ttl=58 time=39.8 ms                     « resposta 1, em 39,8 ms
64 bytes from 151.101.66.132: icmp_seq=2 ttl=58 time=41.2 ms
64 bytes from 151.101.66.132: icmp_seq=3 ttl=58 time=40.5 ms

--- debian.map.fastlydns.net ping statistics ---
3 packets transmitted, 3 received, 0% packet loss, time 2003ms                   « nenhum pacote perdido
rtt min/avg/max/mdev = 39.815/40.503/41.200/0.565 ms                              « tempo mínimo/médio/máximo
ParteSignificado
icmp_seq=1Número do pacote. Se aparecer 1, 2, 4, o 3 se perdeu.
ttl=58"Tempo de vida": quantos roteadores o pacote ainda poderia atravessar.
time=39.8 msIda e volta, em milissegundos. Até uns 50 ms é rápido; acima de 200 ms dá para sentir.
0% packet lossPorcentagem de pacotes sem resposta. O ideal é 0%.

O ping mostra as mensagens em inglês mesmo com o sistema em português, exceto os erros de nome, que vêm do sistema e saem traduzidos.

O que o ping devolve

Em scripts, o que importa é o código de saída. O ping usa três valores:

$ ping -c 1 127.0.0.1 > /dev/null; echo $?
0                                                   « respondeu
$ ping -c 1 -W 1 192.0.2.1 > /dev/null; echo $?
1                                                   « não houve resposta
$ ping -c 1 nada.invalid; echo $?
ping: nada.invalid: Nome ou serviço desconhecido
2                                                   « erro antes de enviar: nome inexistente

O -W 1 (de wait) espera no máximo 1 segundo pela resposta. Com isso dá para escrever, por exemplo, ping -c 1 -W 2 192.168.0.1 > /dev/null && echo "roteador ok".

Outras opções úteis

OpçãoFazExemplo
-c NEnvia N pacotes e paraping -c 4 debian.org
-i NIntervalo entre pacotes, em segundosping -i 0.5 -c 10 192.168.0.1
-W NEspera no máximo N segundos por cada respostaping -c 1 -W 1 192.168.0.1

-qSilencioso: só a estatística finalping -q -c 20 debian.org
Ping que não responde nem sempre é problema

Muitos servidores e firewalls bloqueiam o ping de propósito. Se o site abre no navegador mas o ping dá 100% de perda, está tudo certo com a sua rede.

ss: conexões e portas abertas

O ss (de socket statistics) lista as conexões de rede. A combinação mais usada é ss -tulpn, que responde "quais portas estão esperando conexões nesta máquina?".

ss
O programa.
-t
Conexões TCP.
-u
Conexões UDP.
-l
Só as que estão listening, "escutando", à espera de alguém.
-p
Mostra o programa (process) dono de cada porta.
-n
Números em vez de nomes: 22 em vez de ssh.

Rodando como usuária comum, a coluna do processo fica vazia. Isso não é erro: o Debian não deixa um usuário ver os processos dos outros.

$ ss -tulpn
Netid State  Recv-Q Send-Q   Local Address:Port  Peer Address:PortProcess
udp   UNCONN 0      0         192.168.0.15:68         0.0.0.0:*
tcp   LISTEN 0      128            0.0.0.0:22         0.0.0.0:*                 « alguém escuta na porta 22
tcp   LISTEN 0      128               [::]:22            [::]:*

Como root (veja root, su e sudo), aparece o nome do programa:

$ su -
Senha:
#> ss -tulpn
Netid State  Recv-Q Send-Q   Local Address:Port  Peer Address:PortProcess
udp   UNCONN 0      0         192.168.0.15:68         0.0.0.0:*    users:(("dhcpcd",pid=858,fd=3))   « cliente DHCP
tcp   LISTEN 0      128            0.0.0.0:22         0.0.0.0:*    users:(("sshd",pid=778,fd=6))     « servidor SSH
tcp   LISTEN 0      128               [::]:22            [::]:*    users:(("sshd",pid=778,fd=7))
ColunaSignificado
NetidProtocolo: tcp ou udp.
StateLISTEN: esperando conexões. UNCONN: UDP aberto (UDP não tem "conexão").
Local Address:PortEm qual endereço e porta o programa escuta. 0.0.0.0 = todas as placas IPv4; [::] = todas IPv6; 127.0.0.1 = só a própria máquina.
Peer Address:PortO outro lado. * quando ainda não há ninguém.
ProcessPrograma, PID e descritor do arquivo. Só aparece para root.

Essa lista curta é típica de um Debian recém-instalado: só o SSH (porta 22) e o cliente DHCP (porta 68). Um Debian com desktop terá mais linhas, como impressora (631) e descoberta de rede (5353).

Conexões ativas

Sem o -l, o ss mostra as conexões já estabelecidas. ss -tn lista as TCP:

$ ss -tn
State Recv-Q Send-Q Local Address:Port  Peer Address:Port
ESTAB 0      0       192.168.0.15:22    192.168.0.20:58430    « alguém do 192.168.0.20 conectado por SSH

192.168.0.15 fd17:625c:f037:2:a00:27ff:fe90:fbde

Repare: esse é o IP da rede local. O IP com que você aparece na internet (o do roteador) só se descobre perguntando a um site, por exemplo wget -qO- https://ifconfig.me/ip. Veja curl, wget, dig.

Quando não funciona

"Nome ou serviço desconhecido" 
$ ping -c 2 debian.org
ping: debian.org: Nome ou serviço desconhecido

O que aconteceu: o computador não conseguiu transformar o nome em IP. É um problema de DNS, ou falta de rede por completo.

Como confirmar: teste um IP direto, sem nome: ping -c 2 1.1.1.1. Se o IP responde e o nome não, o problema é o DNS. Confira os servidores em cat /etc/resolv.conf.

Como resolver: veja Configurar a Rede.

100% de perda de pacotes 
$ ping -c 3 -W 1 192.168.0.50
PING 192.168.0.50 (192.168.0.50) 56(84) bytes of data.

--- 192.168.0.50 ping statistics ---
3 packets transmitted, 0 received, 100% packet loss, time 2050ms

O que aconteceu: o destino não respondeu. Ele pode estar desligado, num IP diferente ou bloqueando ping.

Como confirmar: faça ping no seu gateway (o via do ip r). Se nem o gateway responde, o problema é a sua própria conexão.

A placa aparece DOWN ou sem IP 
$ ip -br a
lo               UNKNOWN        127.0.0.1/8 ::1/128
enp1s0           DOWN

O que aconteceu: a placa está desligada ou o cabo está solto (falta o LOWER_UP no ip a).

Como resolver: confira o cabo. Num servidor Debian com ifupdown, suba a placa como root com ifup enp1s0. Detalhes em Configurar a Rede.

"ifconfig: comando não encontrado" 
$ ifconfig
bash: ifconfig: comando não encontrado

O que aconteceu: o ifconfig é do pacote antigo net-tools, que não vem no Debian. Além disso, ele fica em /usr/sbin, que não está no PATH da usuária comum.

Como resolver: use ip a. Não há necessidade de instalar o net-tools.

O ss não mostra o programa

O que aconteceu: sem root, a coluna Process fica vazia para portas de outros usuários.

Como resolver: rode como root: su - e depois ss -tulpn, ou su -c 'ss -tulpn'.

Complete para listar as portas TCP e UDP escutando, com números e o programa:

Resumo

  • ip -br a mostra o IP de cada placa; ip a, todos os detalhes.
  • ip r mostra o gateway na linha default via; sem ela não há internet.
  • ping -c N testa resposta; código 0 = respondeu, 1 = sem resposta, 2 = erro (como nome inexistente).
  • ss -tulpn lista as portas abertas; o nome do programa só aparece como root.
  • No Debian, ifconfig e netstat não existem: use ip e ss.
