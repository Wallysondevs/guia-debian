Debian scp e rsync

Copiar arquivos entre máquinas é a segunda coisa que todo mundo faz depois de aprender SSH. O scp (de secure copy) é o jeito rápido para uma cópia avulsa. O rsync (de remote sync) é o jeito inteligente: só manda o que mudou, retoma cópias interrompidas e sincroniza pastas inteiras. Os dois usam o SSH por baixo, então tudo viaja criptografado.

Você vai aprender
  • Escrever um caminho remoto (usuario@maquina:/pasta) sem errar.
  • Copiar arquivos e pastas com scp, nos dois sentidos.
  • Instalar o rsync (ele não vem no Debian mínimo) e sincronizar pastas.
  • A diferença que mais confunde: a barra no final da origem.
  • Usar --dry-run antes de qualquer --delete.

Esta aula supõe que você já entra no servidor por SSH (veja SSH). Nos exemplos, a Ana copia arquivos do notebook para a máquina servidor (192.168.0.50).

O caminho remoto

Os dois comandos usam o mesmo formato para dizer "um arquivo em outra máquina":

ana
O usuário na máquina remota. Pode ser omitido se for o mesmo nome que você usa aqui.
@servidor
A máquina: nome, IP (192.168.0.50) ou um apelido do ~/.ssh/config.
:
Os dois-pontos marcam que é remoto. Sem eles, vira uma cópia local para um arquivo chamado "ana@servidor".
/home/ana/docs/
O caminho lá dentro. Caminho relativo (sem / no começo) parte da pasta pessoal remota.

Então ana@servidor:relatorio.pdf é o arquivo /home/ana/relatorio.pdf no servidor, e ana@servidor: (nada depois dos dois-pontos) é a própria pasta pessoal.

scp: cópia rápida

O scp vem junto com o cliente SSH (pacote openssh-client), então já está instalado. A ordem é sempre origem, depois destino, como no cp.

Do notebook para o servidor

$ scp relatorio.pdf ana@192.168.0.50:docs/
relatorio.pdf                                  100%  238KB   8.9MB/s   00:00

A linha mostra o arquivo, a porcentagem, o tamanho, a velocidade e o tempo. Se o servidor pedir senha (ou a frase da chave), o scp pergunta antes de começar.

Do servidor para o notebook

Basta inverter: a origem remota vem primeiro. O . no fim quer dizer "aqui, na pasta atual".

$ scp ana@192.168.0.50:/var/log/meuapp.log .
meuapp.log                                     100%   12KB   1.4MB/s   00:00

-P 2222Porta do SSH (P maiúsculo; no ssh é -p)scp -P 2222 a.txt ana@servidor:

O scp sobrescreve sem perguntar

Se o destino já tiver um arquivo com o mesmo nome, ele é substituído sem aviso. Para pastas grandes ou cópias que se repetem, prefira o rsync.

rsync: instalar primeiro

Diferente do Ubuntu, a instalação padrão do Debian não traz o rsync. E ele precisa estar instalado nas duas máquinas, porque um rsync conversa com o outro.

$ rsync -av fotos/ ana@servidor:fotos/
bash: rsync: comando não encontrado
$ su -
Senha:
#> apt install rsync

Se faltar só no servidor, a mensagem é outra, vinda do lado de lá:

$ rsync -av fotos/ ana@servidor:fotos/
bash: linha 1: rsync: comando não encontrado                     « esta linha vem do servidor
rsync: connection unexpectedly closed (0 bytes received so far) [sender]
rsync error: error in rsync protocol data stream (code 12) at io.c(285) [sender=3.5.0]

rsync: o básico

rsync
O programa.
-a
Modo archive: recursivo e mantém permissões, datas, links e donos. Use quase sempre.
-v
Detalhado (verbose): lista cada arquivo.
fotos/
A origem.
backup/
O destino. Pode ser local ou remoto (ana@servidor:backup/).

O rsync funciona igual entre duas pastas da mesma máquina, o que é ótimo para treinar. Os exemplos a seguir foram rodados num Debian 13:

$ rsync -av fotos/ backup/
sending incremental file list           « calcula a lista enquanto envia
praia.jpg
serra.jpg
viagem/
viagem/mapa.png

sent 301 bytes  received 85 bytes  772,00 bytes/sec
total size is 7  speedup is 0,02

Rode o mesmo comando de novo e a lista vem vazia: nada mudou, então nada é copiado. Essa é a grande vantagem sobre o scp.

As mensagens do rsync ficam em inglês, mas os números usam vírgula porque o sistema está em português (772,00).

A barra no final da origem

Esta é a pegadinha mais famosa do rsync. Com barra (fotos/), ele copia o conteúdo da pasta. Sem barra (fotos), ele copia a pasta em si, criando uma subpasta no destino.

Sem barra: rsync -av fotos backup/Com barra: rsync -av fotos/ backup/
backup
└── fotos
    ├── praia.jpg
    ├── serra.jpg
    └── viagem
        └── mapa.png
backup
├── praia.jpg
├── serra.jpg
└── viagem
    └── mapa.png

Uma forma de lembrar: a barra significa "o que está dentro de". A barra no destino não muda nada; só a da origem importa.

Espelhar com --delete (e por que testar antes)

Por padrão, o rsync só acrescenta e atualiza: se você apagar um arquivo da origem, ele continua no destino. Para um espelho exato, existe o --delete, que apaga no destino o que não existe mais na origem.

--delete apaga de verdade

Uma barra trocada ou uma pasta errada, junto com --delete, pode apagar o destino inteiro. Rode sempre antes com -n (--dry-run, "ensaio"), que só mostra o que seria feito.

A Ana apagou serra.jpg e criou nova.jpg na origem. Primeiro, o ensaio:

$ rsync -avn --delete fotos/ backup/
sending incremental file list
deleting serra.jpg                     « seria apagado no destino
nova.jpg                               « seria copiado

sent 156 bytes  received 36 bytes  384,00 bytes/sec
total size is 9  speedup is 0,05 (DRY RUN)     « nada foi feito de verdade

O (DRY RUN) no fim confirma que foi só um ensaio. Conferido, rode sem o n:

$ rsync -avh --delete fotos/ backup/
sending incremental file list
deleting serra.jpg
nova.jpg

sent 205 bytes  received 56 bytes  522,00 bytes/sec
total size is 9  speedup is 0,03

Pela rede, numa porta diferente

$ rsync -avz -e "ssh -p 2222" ~/projeto/ ana@192.168.0.50:projeto/

Quando não funciona

"stat local … No such file or directory" 
$ scp nada.txt ana@192.168.0.50:
scp: stat local "nada.txt": No such file or directory

O que aconteceu: o arquivo de origem não existe na pasta atual. Confira com ls ou use o caminho completo.

rsync com código 23 
$ rsync -av nada/ backup/
sending incremental file list
rsync: [sender] change_dir "/home/ana/rs/nada" failed: No such file or directory (2)

sent 19 bytes  received 12 bytes  62,00 bytes/sec
total size is 0  speedup is 0,00
rsync error: some files/attrs were not transferred (see previous errors) (code 23) at main.c(1394) [sender=3.5.0]

O que aconteceu: o código 23 quer dizer "transferência parcial". A causa está na linha rsync: … mais acima: aqui, a origem nada/ não existe. Em outros casos são arquivos sem permissão de leitura.

Apareceu uma pasta a mais no destino

O que aconteceu: faltou a barra no final da origem, e o rsync criou backup/fotos/.

Como resolver: apague a pasta extra e repita com fotos/.

"connection unexpectedly closed" / código 12

O que aconteceu: o rsync não está instalado na máquina remota. A pista é a primeira linha, bash: linha 1: rsync: comando não encontrado, que vem do servidor. Instale lá com apt install rsync (como root).

"is not a regular file" 
$ scp fotos ana@192.168.0.50:
scp: local "/home/ana/fotos" is not a regular file
scp: failed to upload file /home/ana/fotos to .

O que aconteceu: fotos é uma pasta, e o scp só copia pastas com -r: scp -r fotos ana@192.168.0.50:.

Arquivo remoto inexistente 
$ scp ana@192.168.0.50:nada.txt .
scp: nada.txt: No such file or directory

O que aconteceu: o caminho depois dos dois-pontos não existe no servidor. Lembre que caminho relativo parte da pasta pessoal remota; confira com ssh ana@192.168.0.50 ls.

Connection refused ou timed out

O que aconteceu: o problema é a conexão SSH, não a cópia. Teste antes com ssh ana@servidor e veja os erros em SSH.

Resumo

  • Caminho remoto: usuario@maquina:caminho; os dois-pontos são obrigatórios.
  • scp origem destino para cópias rápidas; -r para pastas, -P para a porta.
  • O rsync não vem no Debian mínimo: apt install rsync nas duas pontas.
  • fotos/ copia o conteúdo; fotos copia a pasta.
  • Antes de --delete, sempre -n e confira o (DRY RUN).
