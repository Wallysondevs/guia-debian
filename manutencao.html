Debian Manutenção

O Debian estável é famoso por "funcionar sozinho por anos". Mas ele funciona sozinho porque alguém faz uma manutenção pequena e regular: atualizar, reiniciar o que precisa, limpar o que sobra e olhar se algo falhou. Nesta aula você monta essa rotina e descobre o que o Debian já faz por você.

Você vai aprender
  • Quais tarefas o Debian 13 já roda sozinho (os timers do systemd).
  • Atualizar com apt e ler as notícias do apt-listchanges.
  • Saber o que precisa reiniciar com o needrestart.
  • Limpar o cache do apt, pacotes órfãos e o journal.
  • Encontrar serviços com falha e arquivos de pacote alterados.

Os comandos de manutenção rodam como root (su -). As saídas são de um Debian 13 real.

Antes do comando: o que já é automático

O que não é automático numa instalação padrão: instalar as atualizações (sem unattended-upgrades), reiniciar serviços, limpar o cache do apt e conferir backups.

1. Atualizar o sistema

#> apt update
Atingido:1 http://deb.debian.org/debian trixie InRelease
Atingido:2 http://security.debian.org/debian-security trixie-security InRelease
Atingido:3 http://deb.debian.org/debian trixie-updates InRelease
Lendo listas de pacotes...
Construindo árvore de dependências...
Lendo informação de estado...
Todos os pacotes estão atualizados.                 « nada para atualizar

Quando há atualizações, a última linha diz quantas, e apt list --upgradable mostra quais. Para instalar:

ComandoO que fazQuando usar
apt upgradeAtualiza, mas nunca remove pacotesA rotina do dia a dia
apt full-upgradeAtualiza e pode remover/trocar pacotesKernels novos, revisões (13.7 → 13.8), quando o upgrade diz que "segurou" pacotes

No Debian estável os dois quase sempre fazem o mesmo, porque as atualizações só corrigem falhas. Veja apt e, para trocar de versão (13 → 14), Atualizar a Versão do Debian.

apt-listchanges: as notícias antes de instalar

O Debian vem com o apt-listchanges. Quando um pacote traz uma mudança importante (arquivo NEWS), ele mostra o texto antes de instalar, num leitor de páginas. Leia e aperte q para continuar. A configuração real do Debian 13:

[apt]
frontend=pager        # mostra num leitor de páginas (como o less)
which=news            # só as notícias importantes, não todo o changelog
email_address=root
email_format=text
confirm=false         # não pergunta se quer continuar
headers=false
reverse=false
save_seen=/var/lib/apt/listchanges

2. Precisa reiniciar?

Uma atualização troca os arquivos no disco, mas os programas que já estavam rodando continuam com a versão antiga na memória. O kernel novo só vale depois de reiniciar a máquina. O needrestart descobre isso. Ele não vem instalado:

#> apt install needrestart
#> needrestart -r l
…
Running kernel seems to be up-to-date.                 « o kernel em uso é o mais novo

No services need to be restarted.                      « nenhum serviço com biblioteca antiga

No containers need to be restarted.

No user sessions are running outdated binaries.

No VM guests are running outdated hypervisor (qemu) binaries on this host.
needrestart
O programa.
-r l
restart mode list: só lista o que precisa reiniciar, sem reiniciar nada.

Depois de instalado, o needrestart roda sozinho no fim de cada apt upgrade e oferece reiniciar os serviços afetados. Para scripts e monitoramento há o formato curto needrestart -b:

#> needrestart -b
NEEDRESTART-VER: 3.11
NEEDRESTART-KCUR: 6.12.111+deb13-amd64      « kernel em uso
NEEDRESTART-KEXP: 6.12.111+deb13-amd64      « kernel esperado (o mais novo instalado)
NEEDRESTART-KSTA: 1                         « 1 = em dia; 3 = precisa reiniciar a máquina

O needrestart é em inglês. No Ubuntu é comum olhar o arquivo /var/run/reboot-required; no Debian ele só aparece em alguns casos: quando o unattended-upgrades está instalado e chega um kernel novo (ele traz o gancho /etc/kernel/postinst.d/unattended-upgrades), ou quando o dbus é atualizado. Numa instalação mínima, um kernel novo não cria esse arquivo, por isso o needrestart é a resposta mais confiável.

3. Limpar o que sobrou

Pacotes órfãos

Dependências que nenhum pacote usa mais (e kernels antigos) saem com:

#> apt autoremove
…
0 pacotes atualizados, 0 pacotes novos instalados, 0 a serem removidos e 0 não atualizados.

Cache do apt

Todo pacote baixado fica guardado em /var/cache/apt/archives. Com o tempo isso cresce:

#> du -sh /var/cache/apt/archives
392M	/var/cache/apt/archives
#> apt clean                         « apaga todos os pacotes baixados
#> du -sh /var/cache/apt/archives
36K	/var/cache/apt/archives

O apt autoclean é mais suave: apaga só os pacotes que nem estão mais disponíveis nos repositórios. (O tamanho depois do clean é o típico: sobram só as pastas vazias.)

O journal

#> journalctl --disk-usage
Archived and active journals take up 16M in the file system.
#> journalctl --vacuum-time=4weeks
Vacuuming done, freed 0B of archived journals from /run/log/journal.
Vacuuming done, freed 0B of archived journals from /var/log/journal/03c89c72dc504632b46ffa5cf5f2879b.
Vacuuming done, freed 0B of archived journals from /var/log/journal.

O journal já se limita sozinho (no máximo 10% do sistema de arquivos, por padrão). O --vacuum-time apaga registros mais velhos que o tempo dado; aqui não havia nada tão antigo. Veja Logs (journalctl).

4. O que está enchendo o disco?

#> df -h /
Sist. Arq.      Tam. Usado Disp. Uso% Montado em
/dev/sda1        24G  1,3G   21G   6% /
#> du -xh / --max-depth=1 2>/dev/null | sort -h | tail -4

Os culpados mais comuns são /var/cache/apt, /var/log, imagens de containers (/var/lib/docker) e a pasta pessoal. Mais em lsblk, df, du.

5. Serviços com falha e erros

#> systemctl --failed
  UNIT LOAD ACTIVE SUB DESCRIPTION

0 loaded units listed.                                 « nenhum serviço falhou
#> journalctl -p err -b --no-pager | tail

Se algum serviço aparecer, investigue com systemctl status nome e journalctl -u nome (veja systemctl).

debsums: algum arquivo de pacote foi alterado?

O pacote debsums compara cada arquivo instalado com a "impressão digital" (checksum) registrada no pacote. Serve para achar arquivos corrompidos ou modificados:

#> apt install debsums
#> debsums -s                       « -s: só mostra problemas; silêncio = tudo íntegro

Ele não substitui um sistema de detecção de invasão (um invasor pode alterar os registros também), mas acha disco com defeito e arquivos editados por engano.

6. Backups

O Debian guarda sozinho uma cópia da lista de pacotes em /var/backups (timer dpkg-db-backup). Mas os seus dados você precisa copiar: veja Backup e o projeto Backup Automático. Pelo menos uma vez por mês, restaure um arquivo para provar que o backup funciona.

Automatizando: relatório de saúde

Um script curto junta tudo e pode rodar pelo cron toda segunda-feira:

#!/usr/bin/env bash
# Relatório de saúde do servidor
echo "== $(hostname) — $(date '+%F %H:%M')"
echo "== Carga:";        uptime
echo "== Disco:";        df -h / | tail -1
echo "== Atualizações:"; apt list --upgradable 2>/dev/null | tail -n +2 | wc -l
echo "== Reiniciar?";    needrestart -b | grep KSTA
echo "== Serviços com falha:"; systemctl --failed --no-legend | wc -l

Quando não funciona

"Não foi possível obter a trava /var/lib/dpkg/lock-frontend" 
#> apt upgrade
Aguardando por trava de cache: Não foi possível obter a trava /var/lib/dpkg/lock-frontend. Ela está sendo mantida pelo processo 9748 (apt-get)...

O que aconteceu: outro apt está rodando (seu, ou o automático). Espere: ele continua sozinho quando a trava for liberada. Não apague os arquivos de trava.

"needrestart: comando não encontrado"

O que aconteceu: ele não vem no Debian. apt install needrestart.

"Os seguintes pacotes foram mantidos"

O que aconteceu: a atualização precisa instalar ou remover outro pacote, e o apt upgrade não faz isso. Rode apt full-upgrade e leia com atenção o que ele vai remover antes de confirmar.

Resumo

  • Timers do Debian já fazem logrotate, fstrim, backup do dpkg e índice do man.
  • Atualizar: apt update && apt upgrade; o apt-listchanges mostra as notícias importantes.
  • needrestart (instale) diz o que precisa reiniciar; o reboot-required nem sempre é criado no Debian.
  • Limpeza: apt autoremove, apt clean, journalctl --vacuum-time.
  • Saúde: systemctl --failed, journalctl -p err -b, debsums -s.
