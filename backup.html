Debian Backup

Backup é uma cópia dos seus arquivos guardada em outro lugar, para quando o disco queimar, o notebook for roubado ou você apagar algo sem querer. Nesta aula você vai copiar a pasta pessoal para um HD externo com rsync, empacotar com tar, guardar versões com restic e, o mais importante, testar se dá para restaurar.

Você vai aprender
  • A regra 3-2-1 e o que vale a pena copiar.
  • O rsync parte por parte, incluindo a "barra final" que confunde todo mundo.
  • Fazer backups com data no nome usando tar e $(date +%F).
  • Guardar várias versões com o restic, dos repositórios do Debian.
  • Restaurar um arquivo e conferir se a cópia está completa.

Antes dos comandos: o que é um bom backup

Um backup só existe de verdade quando você já conseguiu restaurar algo dele. Uma regra simples, usada por profissionais, é a 3-2-1:

NúmeroRegraExemplo da Ana
3Tenha 3 cópias dos dados (o original + 2 backups).Notebook + HD externo + nuvem.
2Em 2 tipos de mídia diferentes.SSD do notebook e HD externo.
11 cópia fora de casa.Um serviço de nuvem ou um HD na casa de um parente.

O que copiar

O quêOnde ficaPrecisa?
Seus arquivos/home/anaSim, é o mais importante.
Configurações do sistema que você mudou/etcEm servidores, sim (como root).

O próprio Debian/usr, /bin…Não; é mais rápido reinstalar.
A pasta /tmpMemória (tmpfs)Não; no Debian 13 ela é apagada a cada boot.

rsync: copiar só o que mudou

rsync vem de remote sync, "sincronização remota". Ele copia arquivos de um lugar para outro, local ou por rede. A grande vantagem sobre o cp: na segunda vez, ele copia só o que mudou. Um backup de 50 GB que levou uma hora passa a levar segundos.

Instalar o rsync

Diferente do Ubuntu, uma instalação padrão do Debian não traz o rsync:

$ rsync -avh ~/Documentos/ /media/ana/BACKUP/Documentos/
bash: rsync: comando não encontrado
$ su -c "apt install rsync"
Senha:

Depois de instalado, ele funciona como usuária comum para copiar os seus próprios arquivos.

-a

-v
Verbose: lista cada arquivo copiado.

~/Documentos/
A origem. A barra final importa (veja abaixo).
/media/ana/BACKUP/Documentos/

$ rsync -avh ~/Documentos/ /media/ana/BACKUP/Documentos/

Agora a Ana cria um arquivo novo e roda o mesmo comando de novo:

$ echo "reunião às 15h" > ~/Documentos/lembrete.txt
$ rsync -avh ~/Documentos/ /media/ana/BACKUP/Documentos/

sent 305 bytes  received 40 bytes  690,00 bytes/sec
total size is 8,53K  speedup is 24,73

A barra final na origem

Este é o detalhe que mais confunde no rsync. Uma barra no fim da origem muda o resultado:

ComandoResultado no destino
rsync -a ~/Documentos/ /backup/Copia o conteúdo: /backup/notas.txt
rsync -a ~/Documentos /backup/Copia a pasta: /backup/Documentos/notas.txt

Leia a barra como "o que está dentro de". No destino, a barra não faz diferença.

Ver antes de fazer: -n

A opção -n (de dry run, "ensaio") mostra o que seria feito, sem copiar nada. Use sempre que mudar o comando:

$ rsync -avhn ~/Documentos/ /media/ana/BACKUP/Documentos/
sending incremental file list

sent 238 bytes  received 14 bytes  504,00 bytes/sec
total size is 8,53K  speedup is 33,86 (DRY RUN)              « (DRY RUN): nada foi copiado

Espelho exato: --delete

Por padrão, se você apaga um arquivo no notebook, ele continua no backup. Com --delete, o rsync apaga do destino o que não existe mais na origem, deixando um espelho exato.

$ rm ~/Documentos/lembrete.txt
$ rsync -avh --delete ~/Documentos/ /media/ana/BACKUP/Documentos/
sending incremental file list
deleting lembrete.txt                                    « apagado também do backup

sent 216 bytes  received 37 bytes  506,00 bytes/sec
total size is 8,52K  speedup is 33,66
Cuidado com --delete

Se você trocar origem e destino de lugar, o --delete apaga os seus arquivos originais. Se você apagar algo sem querer e rodar o backup em seguida, a cópia também some. Rode antes com -n e mantenha mais de um backup (o restic, mais abaixo, guarda versões).

Deixar pastas de fora: --exclude

$ rsync -avh --delete --exclude='.cache' --exclude='Downloads' ~/ /media/ana/BACKUP/home/

Cada --exclude recebe um nome ou padrão. As aspas evitam que o shell expanda curingas antes da hora.

Ver o progresso: --progress

Em arquivos grandes, --progress (ou -P) mostra a porcentagem e a velocidade de cada arquivo:

$ rsync -avh --progress ~/Imagens/ /media/ana/BACKUP/Imagens/
sending incremental file list
created directory /media/ana/BACKUP/Imagens
./
ferias.jpg
          2,20M 100%  206,68MB/s    0:00:00 (xfr#1, to-chk=1/3)
perfil.png
        102,40K 100%    8,88MB/s    0:00:00 (xfr#2, to-chk=0/3)

xfr#1 é o número da transferência; to-chk=1/3 quer dizer "falta conferir 1 de 3 itens".

tar: um pacote com data no nome

O rsync mantém um espelho atualizado. Às vezes você quer fotografias de cada dia, para poder voltar a uma versão antiga. Para isso, empacote com tar (que vem instalado) e coloque a data no nome.

Primeiro, entenda o $(date +%F). O date +%F imprime a data no formato ano-mês-dia, e o $( ) coloca essa saída dentro de outro comando:

$ date +%F
2026-10-15
$ echo "backup-$(date +%F).tar.gz"
backup-2026-10-15.tar.gz
tar
O programa que empacota (veja tar, zip, gzip).
-czf
c = criar, z = compactar com gzip, f = o próximo nome é o arquivo.
/media/ana/BACKUP/documentos-$(date +%F).tar.gz
O arquivo a criar, com a data de hoje no nome.
-C ~
Entra na pasta pessoal antes de empacotar, para os caminhos ficarem curtos.
Documentos
O que empacotar.
$ tar -czf /media/ana/BACKUP/documentos-$(date +%F).tar.gz -C ~ Documentos
$ ls -lh /media/ana/BACKUP/*.tar.gz
-rw-rw-r-- 1 ana ana 8,8K out 13 22:00 /media/ana/BACKUP/documentos-2026-10-13.tar.gz
-rw-rw-r-- 1 ana ana 8,8K out 14 22:00 /media/ana/BACKUP/documentos-2026-10-14.tar.gz
-rw-rw-r-- 1 ana ana 8,8K out 15 21:17 /media/ana/BACKUP/documentos-2026-10-15.tar.gz

Para ver o que tem dentro sem extrair, use -t (de list):

$ tar -tzf /media/ana/BACKUP/documentos-2026-10-15.tar.gz
Documentos/
Documentos/relatorio.odt
Documentos/notas.txt
Documentos/projetos/
Documentos/projetos/backup.sh
Documentos/projetos/site/
Documentos/projetos/site/index.html

Missão: o simulador não tem tar, mas tem cp e $( ). Copie a pasta Documentos para dentro de backups, numa pasta com o nome da data de hoje. Dica: cp -r Documentos backups/$(date +%F). Depois confira com ls backups/*.

restic: várias versões, criptografadas

O rsync guarda só a última versão; o tar guarda versões, mas repete tudo a cada dia. O restic junta o melhor dos dois: guarda fotografias (snapshots) de cada backup, copia só o que mudou e protege tudo com senha. Ele está nos repositórios do Debian: su -c "apt install restic".

  1. Crie o repositório (a pasta onde ficam as cópias) e escolha uma senha: 
    $ restic init --repo /media/ana/BACKUP/restic
enter password for new repository:
enter password again:
created restic repository c66477b938 at /media/ana/BACKUP/restic

Please note that knowledge of your password is required to access
the repository. Losing your password means that your data is
irrecoverably lost.

    Guarde a senha num gerenciador de senhas: sem ela, o backup é inútil.

  2. Faça o backup: 
    $ restic --repo /media/ana/BACKUP/restic backup ~/Documentos
enter password for repository:
…
Added to the repository: 10.826 KiB (10.053 KiB stored)

processed 4 files, 8.322 KiB in 0:00
snapshot f4e72fbc saved                                   « o código desta fotografia
  3. Liste as fotografias: 
    $ restic --repo /media/ana/BACKUP/restic snapshots
enter password for repository:
ID        Time                 Host        Tags        Paths                    Size
-----------------------------------------------------------------------------------------
f4e72fbc  2026-10-15 21:17:44  notebook                /home/ana/Documentos     8.322 KiB
-----------------------------------------------------------------------------------------
1 snapshots
  4. Restaure numa pasta de teste: 
    $ restic --repo /media/ana/BACKUP/restic restore latest --target ~/teste-restauracao
enter password for repository:
…
Summary: Restored 7 files/dirs (8.322 KiB) in 0:00

Se a senha estiver errada, o restic responde Fatal: wrong password or no key found. As mensagens do restic são todas em inglês.

Testar a restauração

Um backup que nunca foi restaurado é só uma esperança. Faça o teste uma vez por mês.

  1. Restaure um arquivo do espelho do rsync para uma pasta de teste, sem sobrescrever o original: 
    $ mkdir -p ~/teste-restauracao
$ rsync -avh /media/ana/BACKUP/Documentos/notas.txt ~/teste-restauracao/
sending incremental file list
notas.txt

sent 177 bytes  received 35 bytes  424,00 bytes/sec
total size is 71  speedup is 0,33
$ cat ~/teste-restauracao/notas.txt
Comprar café
Ligar para o João
Estudar Debian
Fazer backup das fotos
  2. Compare a pasta inteira com o original. O diff -r compara pastas recursivamente; se não mostrar nada, são idênticas: 
    $ diff -r ~/Documentos /media/ana/BACKUP/Documentos
$ echo $?
0                                                        « 0 = idênticas

    Se algo mudou depois do último backup, o diff mostra o quê:

    $ diff -r ~/Documentos /media/ana/BACKUP/Documentos
diff -r /home/ana/Documentos/notas.txt /media/ana/BACKUP/Documentos/notas.txt
5d4
< extra                                                  « linha que só existe no original
$ echo $?
1
  3. Extraia um pacote tar numa pasta separada, com -x (extrair) e -C (onde): 
    $ tar -xzf /media/ana/BACKUP/documentos-2026-10-15.tar.gz -C ~/teste-restauracao
$ ls ~/teste-restauracao
Documentos  notas.txt

Apague a pasta de teste quando terminar: rm -r ~/teste-restauracao.

A lista de programas instalados

Em vez de copiar os programas, guarde a lista deles. O apt-mark showmanual mostra os pacotes que foram instalados de propósito (e não como dependência). Funciona como usuária comum:

$ apt-mark showmanual > /media/ana/BACKUP/pacotes.txt
$ wc -l /media/ana/BACKUP/pacotes.txt
206 /media/ana/BACKUP/pacotes.txt

Num Debian novo, reinstale tudo de uma vez, como root:

$ su -
Senha:
#> xargs apt install -y < /media/ana/BACKUP/pacotes.txt

Quando não funciona

"rsync: comando não encontrado" 
$ rsync -avh ~/Documentos/ /media/ana/BACKUP/
bash: rsync: comando não encontrado

O que aconteceu: o rsync não vem na instalação padrão do Debian.

Como resolver: su -c "apt install rsync".

"mkdir … failed: No such file or directory": o HD não está montado 
$ rsync -avh ~/Documentos/ /media/ana/BACKUP/
sending incremental file list
rsync: [Receiver] mkdir "/media/ana/BACKUP" failed: No such file or directory (2)
rsync error: error in file IO (code 11) at main.c(808) [Receiver=3.5.0]

O que aconteceu: o HD externo não está conectado ou não foi montado, então a pasta de destino não existe.

Como resolver: conecte o HD, confira com findmnt /media/ana/BACKUP e rode de novo. Num script, teste antes se a pasta existe (veja Condicionais).

O perigo de copiar para um HD que não está montado

Se a pasta de destino existir, mas o HD não estiver montado nela, o rsync copia para o disco do notebook, enchendo-o sem você perceber. Use destinos em /media (que somem quando o HD sai) ou confira com findmnt antes.

"code 23": alguns arquivos não foram copiados 
$ rsync -avh /etc/ssh/ ~/backup-ssh/
sending incremental file list
rsync: [sender] send_files failed to open "/etc/ssh/ssh_host_ecdsa_key": Permission denied (13)
…
rsync error: some files/attrs were not transferred (see previous errors) (code 23) at main.c(1394) [sender=3.5.0]

O que aconteceu: a usuária comum não pode ler alguns arquivos do sistema. O backup ficou incompleto, e o rsync avisa com o código 23.

Como resolver: para copiar arquivos do sistema, rode o rsync como root (su -). Num script, confira o código de saída ($?) para saber se o backup foi completo.

Resumo

  • Regra 3-2-1: 3 cópias, 2 mídias, 1 fora de casa.
  • rsync -avh origem/ destino/ copia só o que mudou; no Debian, instale-o antes.
  • A barra final na origem significa "o conteúdo de". Teste com -n antes do --delete.
  • tar -czf nome-$(date +%F).tar.gz guarda uma versão por dia; o restic guarda versões criptografadas.
  • Teste a restauração com diff -r e guarde a lista de pacotes com apt-mark showmanual.
