Debian .bashrc, alias e PATH

Toda vez que você abre um terminal, o bash (o programa que lê o que você digita) executa um arquivo de configuração chamado ~/.bashrc. É ali que você cria atalhos (alias), define variáveis e diz onde o sistema deve procurar programas (o PATH). O Debian vem com uma configuração bem enxuta, e entender isso explica vários "comando não encontrado".

Você vai aprender
  • O que são variáveis de ambiente e como ver o valor delas.
  • Por que a usuária comum não acha reboot e adduser: o PATH do Debian.
  • A diferença entre su e su -.
  • Por que o ll não funciona no Debian e como ativá-lo.
  • A diferença entre .bashrc, .bash_aliases, .profile e /etc/skel.

Antes dos comandos: variáveis

Uma variável é um nome que guarda um valor. O bash já começa com várias delas, chamadas variáveis de ambiente, que os programas consultam para saber quem você é, qual é sua pasta pessoal e assim por diante. Para ler uma variável, coloque $ antes do nome:

echo
Mostra na tela o que recebeu.
$HOME
O $ pede ao bash para trocar o nome pelo valor da variável antes de rodar o echo.
$ echo $HOME
/home/ana
$ echo "Eu sou $USER e uso o editor [$EDITOR]"
Eu sou ana e uso o editor []                « no Debian, EDITOR vem vazia
VariávelGuardaValor no Debian da Ana
HOMESua pasta pessoal/home/ana
USERSeu nome de usuárioana
PATHOnde procurar programas/usr/local/bin:/usr/bin:/bin:…
PWDA pasta atual/home/ana/Documentos
SHELLO seu shell/bin/bash
LANGIdioma e formato regionalpt_BR.UTF-8
EDITOREditor padrão de alguns comandosvazia (o Debian usa o "editor do sistema", veja abaixo)
E quem escolhe o editor, então?

Quando EDITOR está vazia, programas como o crontab -e usam o comando sensible-editor, que pergunta qual editor você prefere na primeira vez (veja cron). O padrão do sistema é o nano. Para fixar o seu, coloque export EDITOR=nano (ou vim) no ~/.bashrc.

PATH: onde o bash procura programas

Quando você digita ls, o bash não sabe de cara onde está o programa ls. Ele procura numa lista de pastas, na ordem, e usa o primeiro que encontrar. Essa lista é a variável PATH (em inglês, "caminho"). As pastas são separadas por dois-pontos. O tr troca cada : por uma quebra de linha, para ficar legível:

echo $PATH
Imprime o PATH.
|
Entrega a saída ao próximo comando.
tr ':' '\n'
Translate: troca cada : por \n, a quebra de linha.
$ echo $PATH | tr ':' '\n'
/usr/local/bin
/usr/bin                                 « a maioria dos programas está aqui
/bin
/usr/local/games
/usr/games

Agora compare com o PATH do root, depois de su -:

#> echo $PATH | tr ':' '\n'
/usr/local/sbin                          « as pastas "sbin" só aparecem para o root
/usr/local/bin
/usr/sbin
/usr/bin
/sbin
/bin

As pastas sbin (de system binaries, "programas do sistema") guardam ferramentas de administração: reboot, adduser, usermod, blkid, fdisk… O Debian define o PATH em /etc/profile, de acordo com quem você é:

if [ "$(id -u)" -eq 0 ]; then
  PATH="/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin"
else
  PATH="/usr/local/bin:/usr/bin:/bin:/usr/local/games:/usr/games"
fi
export PATH

É por isso que, como usuária comum, esses programas "não existem":

$ reboot
bash: reboot: comando não encontrado
$ /usr/sbin/reboot                       « com o caminho completo, o bash acha o programa…
Call to Reboot failed: Access denied     « …mas a usuária comum não tem permissão

which e type: qual arquivo vai rodar

$ which python3
/usr/bin/python3
$ type -a ls
ls está apelidada para `ls --color=auto'          « primeiro vem o alias
ls é /usr/bin/ls
ls é /bin/ls

O ls aparece duas vezes porque, no Debian 13, /bin é só um atalho para /usr/bin. Se o programa não está em nenhuma pasta do PATH, o bash responde "comando não encontrado", mesmo que o arquivo exista em outro lugar.

Missão: veja o valor de $HOME e $USER com echo. Depois mostre o PATH com uma pasta por linha. Repare que não há nenhuma pasta sbin.

su e su -: o hífen muda o PATH

Esse é um tropeço clássico de quem chega ao Debian. Os dois comandos pedem a senha do root e abrem um shell de root, mas só um deles carrega o ambiente do root:

$ su
Senha:
#> adduser teste
bash: adduser: comando não encontrado    « continua com o PATH da ana!
#> echo $PATH
/usr/local/bin:/usr/bin:/bin:/usr/local/games:/usr/games
#> exit
$ su -
Senha:
#> echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
#> pwd
/root
ComandoO que acontece
suVira root, mas mantém o PATH e a pasta atual da usuária. Programas de /sbin não são encontrados.
su -Entra como se fosse um login novo do root: PATH completo, pasta /root, configuração do root. Use sempre este.
su -c "comando"Roda um comando só como root e volta.

Veja mais em root, su e sudo.

Acrescentar uma pasta ao PATH

Imagine que a Ana guarda seus scripts em ~/scripts e quer rodá-los pelo nome, de qualquer pasta. Ela acrescenta essa pasta no começo do PATH, sem apagar o resto:

export
Torna a variável visível para os programas que o bash abrir.
PATH=
Atribui um novo valor ao PATH. Sem espaços em volta do =.
"$HOME/scripts
A pasta nova…
:$PATH"
…seguida de dois-pontos e do PATH antigo. Nunca esqueça o $PATH.
$ export PATH="$HOME/scripts:$PATH"
$ echo $PATH | tr ':' '\n' | head -3
/home/ana/scripts
/usr/local/bin
/usr/bin

Isso vale só para este terminal. Para ficar permanente, coloque a mesma linha no fim do ~/.bashrc (veja abaixo).

As pastas ~/bin e ~/.local/bin já estão previstas

O ~/.profile do Debian já põe ~/bin e ~/.local/bin no PATH, se essas pastas existirem. Num Debian novo elas não existem. Basta criar uma delas (mkdir -p ~/.local/bin), guardar os scripts lá e sair e entrar de novo na sessão.

# set PATH so it includes user's private bin if it exists
if [ -d "$HOME/bin" ] ; then
    PATH="$HOME/bin:$PATH"
fi

# set PATH so it includes user's private bin if it exists
if [ -d "$HOME/.local/bin" ] ; then
    PATH="$HOME/.local/bin:$PATH"
fi

export: variáveis para os outros programas

Uma variável criada sem export existe só dentro do bash atual. Os programas que ele abre não a enxergam. Veja a diferença (o bash -c abre um bash "filho" que roda um comando):

$ CIDADE=Recife
$ echo $CIDADE
Recife
$ bash -c 'echo "o filho vê: [$CIDADE]"'
o filho vê: []                           « sem export, o filho não enxerga
$ export CIDADE
$ bash -c 'echo "o filho vê: [$CIDADE]"'
o filho vê: [Recife]

Regra prática: use export para tudo que um programa precisa ler (PATH, EDITOR, chaves de API…).

alias: atalhos para comandos

Um alias ("apelido") é um nome curto que o bash troca por um comando maior. Para ver todos, digite alias. No Debian, a lista é curtíssima:

$ alias
alias ls='ls --color=auto'               « é por isso que o ls tem cores
$ ll
bash: ll: comando não encontrado          « no Ubuntu existe; no Debian, não

Por que o ll não existe: o .bashrc do Debian

O ll que você vê em tutoriais não é um programa: é um alias. O Debian deixa esses atalhos prontos no ~/.bashrc, mas comentados (com # na frente, o bash ignora a linha):

# some more ls aliases
#alias ll='ls -l'
#alias la='ls -A'
#alias l='ls -CF'

Para ativá-los, tire o # do começo das três linhas. Você pode fazer isso no nano ~/.bashrc ou com um comando só:

sed -i
Edita o arquivo no lugar (veja sed).
's/^#alias \(ll\|la\|l\)=/alias \1=/'
Nas linhas que começam com #alias ll=, #alias la= ou #alias l=, tira o #.
~/.bashrc
O arquivo.
$ sed -i 's/^#alias \(ll\|la\|l\)=/alias \1=/' ~/.bashrc
$ source ~/.bashrc
$ alias
alias l='ls -CF'
alias la='ls -A'
alias ll='ls -l'
alias ls='ls --color=auto'
O ll do Debian não é igual ao do Ubuntu

No Ubuntu, ll é ls -alF (mostra também os ocultos). No Debian, a versão comentada é ls -l. Se você prefere o do Ubuntu, escreva o seu: alias ll='ls -alF'.

Criar um alias

alias
O comando que cria apelidos.
atualizar=
O nome do atalho. Sem espaço antes nem depois do =.
'su -c "apt update && apt upgrade"'
O comando completo, entre aspas simples. Como não há sudo, usamos su -c.
$ alias atualizar='su -c "apt update && apt upgrade"'
$ type atualizar
atualizar está apelidada para `su -c "apt update && apt upgrade"'
$ atualizar
Senha:
Atingido:1 http://deb.debian.org/debian trixie InRelease
…

Para remover: unalias atualizar. Assim como as variáveis, esse alias some quando você fecha o terminal.

Um alias com o mesmo nome de um comando "ganha" dele. Para rodar o comando original uma vez, coloque uma barra antes: \rm arquivo.

Missão: no simulador (que é um Debian), ll não existe. Crie o alias ll para ls -l e rode ll. Depois confira com type ll.

Tornar permanente: os arquivos de configuração

Para que alias, variáveis e PATH sobrevivam ao fechar o terminal, eles precisam estar num arquivo que o bash lê sozinho. Qual arquivo depende de quando você quer que a configuração valha:

ArquivoQuando é lidoColoque aqui
~/.bashrcCada terminal interativo que você abreAlias, funções, aparência do prompt, PATH para o terminal.
~/.bash_aliasesLido pelo .bashrc do Debian, se existirSó os seus alias, separados e organizados.
~/.profileUma vez, ao entrar na sessão (gráfica, TTY ou SSH)Variáveis que programas gráficos também precisam ver. Ele também lê o .bashrc.
/etc/profile e /etc/bash.bashrcPara todos os usuáriosConfiguração do sistema todo (só o root edita).
/etc/skel/Copiada para a pasta de cada usuário novoO modelo de .bashrc, .profile e .bash_logout.

O .bashrc do Debian já tem estas linhas, que leem o ~/.bash_aliases:

if [ -f ~/.bash_aliases ]; then
    . ~/.bash_aliases
fi

Passo a passo: alias permanente

  1. Acrescente o alias no fim do ~/.bash_aliases. O >> acrescenta sem apagar o que já existe (e cria o arquivo se ele não existir): 
    $ echo "alias ll='ls -alF'" >> ~/.bash_aliases

    Para editar com mais calma, use nano ~/.bash_aliases.

  2. Recarregue a configuração no terminal atual. O source lê o arquivo de novo sem fechar o terminal:
    source
    Executa um arquivo dentro do shell atual. Também pode ser escrito só como .
    ~/.bashrc
    O arquivo a reler (ele também lê o .bash_aliases).
    $ source ~/.bashrc
$ type ll
ll está apelidada para `ls -alF'
  3. Teste num terminal novo. O alias deve continuar lá.

O prompt: cores e o root sem cor

O ~/.bashrc do Debian monta o prompt ana@notebook:~$ na variável PS1. Ele só usa cores quando o terminal avisa que suporta (o terminal do GNOME avisa). No console de texto (TTY), o prompt fica sem cor. Para forçar cores sempre, tire o # desta linha:

# uncomment for a colored prompt, if the terminal has the capability; turned
# off by default to not distract the user: the focus in a terminal window
# should be on the output of commands, not on the prompt
#force_color_prompt=yes

Já o root tem outro .bashrc, em /root/.bashrc, quase todo comentado. Por isso, depois de su -, o prompt fica sem cor e o ls também. Isso é proposital: é um lembrete visual de que você está como administrador.

# You may uncomment the following lines if you want `ls' to be colorized:
# export LS_OPTIONS='--color=auto'
# eval "$(dircolors)"
# alias ls='ls $LS_OPTIONS'
# alias ll='ls $LS_OPTIONS -l'
# alias l='ls $LS_OPTIONS -lA'
#
# Some more alias to avoid making mistakes:
# alias rm='rm -i'
# alias cp='cp -i'
# alias mv='mv -i'

Quando não funciona

"erro de sintaxe: fim prematuro do arquivo" ao abrir o terminal 
bash: /home/ana/.bashrc: linha 116: erro de sintaxe: fim prematuro do arquivo
ana@notebook:~$

O que aconteceu: você abriu um if, uma aspa ou um { no .bashrc e não fechou. O bash leu até o fim e parou. O terminal abre, mas sem a sua configuração.

Como resolver: abra com nano ~/.bashrc, vá até a linha indicada (Ctrl+_ no nano) e feche o bloco (fi, aspa ou }). Antes de editar, faça uma cópia: cp ~/.bashrc ~/.bashrc.bak. Se precisar, recupere o original do Debian em /etc/skel/.bashrc.

"alias: x: não encontrado" 
$ alias x = 'ls'
bash: alias: x: não encontrado
bash: alias: =: não encontrado
bash: alias: ls: não encontrado

O que aconteceu: há espaços em volta do =. O bash entendeu três palavras separadas e tentou mostrar três alias que não existem.

Como resolver: escreva tudo junto: alias x='ls'.

Virei root com su e o comando não existe 
$ su
Senha:
#> usermod -aG cdrom ana
bash: usermod: comando não encontrado

O que aconteceu: sem o hífen, o su mantém o PATH da usuária, que não tem /usr/sbin.

Como resolver: saia com exit e entre com su -.

Criei ~/.local/bin, mas o script continua "não encontrado"

O que aconteceu: o .profile só confere se a pasta existe no momento do login. Como ela foi criada depois, o PATH atual não a inclui.

Como resolver: saia e entre de novo na sessão (ou, só neste terminal, source ~/.profile). Confira com echo $PATH | tr ':' '\n'.

Resumo

  • Variáveis guardam valores: $HOME, $USER, $PATH. Use export para os programas enxergarem.
  • O PATH da usuária comum no Debian não tem /sbin; o do root tem.
  • Use su -, com hífen, para ter o ambiente completo do root.
  • O Debian só ativa o alias ls; ll, la e l estão comentados no ~/.bashrc.
  • Alias permanentes vão no ~/.bash_aliases; recarregue com source ~/.bashrc.
