Debian LVM

Com partições comuns, o tamanho de cada pedaço do disco fica fixo: se /home encher, você precisa reparticionar. O LVM (Logical Volume Manager, "gerenciador de volumes lógicos") junta discos numa "piscina" de espaço e tira dela volumes que podem crescer depois, com o sistema ligado.

Você vai aprender
  • As três camadas do LVM: PV, VG e LV.
  • Montar um laboratório com dois "discos" que são arquivos.
  • Criar, formatar e montar um volume lógico.
  • Aumentar um volume montado com lvextend -r.
  • Entender o LVM que o instalador do Debian cria na opção "LVM guiado".
  • Tirar um snapshot antes de uma mudança arriscada.

Todos os comandos rodam como root (su -), na máquina fictícia servidor. As saídas foram geradas num Debian 13 real, com o lvm2 2.03.31. O LVM do Debian responde em inglês: o pacote não tem tradução.

Conceito: caixas d'água e torneiras

Pense em várias caixas d'água (os discos) ligadas num reservatório único. Do reservatório saem torneiras de tamanhos diferentes. Se uma torneira precisar de mais água, é só puxar mais do reservatório.

CamadaSiglaAnalogiaExemplo
Volume físicoPV (Physical Volume)Cada caixa d'água/dev/sdb, /dev/sdc1
Grupo de volumesVG (Volume Group)O reservatório que junta as caixasdados
Volume lógicoLV (Logical Volume)Uma torneira: é ele que você formata e monta/dev/dados/fotos

O espaço do VG é dividido em blocos de 4 MiB chamados extents. Quando você cria um LV de 500 MiB, o LVM separa 125 extents para ele.

Instalar o LVM

Numa instalação "Disco inteiro" sem LVM, o Debian não instala as ferramentas. Se você tentar usar, recebe:

#> pvs
-bash: pvs: comando não encontrado
#> apt install lvm2

Se você escolheu "LVM guiado" na instalação, o lvm2 já está lá.

Laboratório seguro com losetup

Dois arquivos de 1 GB vão fazer o papel de dois discos. Veja a aula Particionar e Formatar para os detalhes do losetup.

#> truncate -s 1G d1.img
#> truncate -s 1G d2.img
#> losetup -f --show d1.img
/dev/loop0
#> losetup -f --show d2.img
/dev/loop1

Num servidor de verdade, troque /dev/loop0 e /dev/loop1 pelos discos novos (/dev/sdb, /dev/sdc), sempre conferindo com lsblk antes.

Passo 1: criar os volumes físicos (PV)

pvcreate
"physical volume create": marca um disco ou partição para uso do LVM.
/dev/loop0 /dev/loop1
Os discos. Pode passar vários de uma vez.
#> pvcreate /dev/loop0 /dev/loop1
  Physical volume "/dev/loop0" successfully created.
  Physical volume "/dev/loop1" successfully created.
#> pvs
  PV         VG Fmt  Attr PSize PFree
  /dev/loop0    lvm2 ---  1,00g 1,00g              « ainda sem grupo (coluna VG vazia)
  /dev/loop1    lvm2 ---  1,00g 1,00g

Repare que os tamanhos usam vírgula (1,00g): o LVM segue o idioma do sistema para números, mesmo com as mensagens em inglês.

Passo 2: criar o grupo (VG)

vgcreate
"volume group create": cria o reservatório.
dados
O nome do grupo. Ele vira parte do caminho: /dev/dados/….
/dev/loop0 /dev/loop1
Os PVs que entram no grupo.
#> vgcreate dados /dev/loop0 /dev/loop1
  Volume group "dados" successfully created
#> vgs
  VG    #PV #LV #SN Attr   VSize VFree
  dados   2   0   0 wz--n- 1,99g 1,99g             « 2 discos, nenhum volume ainda
ColunaSignificado
#PVQuantos volumes físicos o grupo tem
#LVQuantos volumes lógicos foram criados
#SNQuantos snapshots
VSize / VFreeTamanho total e espaço ainda livre

Passo 3: criar o volume lógico (LV)

lvcreate
"logical volume create": tira uma "torneira" do grupo.
-n fotos
-n (name): o nome do volume.
-L 500M
-L maiúsculo: tamanho exato (500 MiB).
dados
De qual grupo tirar o espaço.
#> lvcreate -n fotos -L 500M dados
  Logical volume "fotos" created.

Para usar tudo o que sobrou, use -l minúsculo com porcentagem:

-l 100%FREE
-l minúsculo conta em extents ou porcentagem: "100% do espaço livre".
#> lvcreate -n docs -l 100%FREE dados
  Logical volume "docs" created.
#> lvs
  LV    VG    Attr       LSize   Pool Origin Data%  Meta%  Move Log Cpy%Sync Convert
  docs  dados -wi-a-----   1,50g
  fotos dados -wi-a----- 500,00m
#> lsblk /dev/loop0 /dev/loop1
NAME          MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
loop0           7:0    0    1G  0 loop
├─dados-fotos 254:0    0  500M  0 lvm
└─dados-docs  254:1    0  1,5G  0 lvm                « o "docs" usa pedaços dos dois discos
loop1           7:1    0    1G  0 loop
└─dados-docs  254:1    0  1,5G  0 lvm

O lsblk mostra a mágica: o volume docs tem 1,5 GB, mais do que cabe num disco só. Ele usa o espaço que sobrou no loop0 e o loop1 inteiro.

Passo 4: formatar e montar

Cada LV aparece em dois caminhos que apontam para o mesmo lugar:

#> ls -l /dev/dados/
total 0
lrwxrwxrwx 1 root root 22 out 15 22:49 docs -> /dev/mapper/dados-docs
lrwxrwxrwx 1 root root 23 out 15 22:49 fotos -> /dev/mapper/dados-fotos
#> mkfs.ext4 -q /dev/dados/fotos
#> mkdir -p /mnt/fotos
#> mount /dev/dados/fotos /mnt/fotos
#> df -h /mnt/fotos
Sist. Arq.               Tam. Usado Disp. Uso% Montado em
/dev/mapper/dados-fotos  459M  139K  430M   1% /mnt/fotos

Para montar sempre no boot, use o /etc/fstab com o caminho /dev/dados/fotos ou o UUID (veja mount e fstab).

Aumentar um volume com o sistema ligado

É aqui que o LVM brilha. Primeiro, libere espaço no grupo (vamos apagar o docs, que estava vazio):

#> lvremove -y dados/docs
  Logical volume "docs" successfully removed.

Agora aumente o fotos em 200 MiB, montado, sem desligar nada:

lvextend
"logical volume extend": aumenta um LV.
-r
resizefs: depois de aumentar o volume, aumenta também o sistema de arquivos dentro dele. Sem isso, o espaço novo fica invisível.
-L +200M
O + significa "a mais". Sem o +, seria o tamanho final.
dados/fotos
Grupo/volume.
#> lvextend -r -L +200M dados/fotos
  File system ext4 found on dados/fotos mounted at /mnt/fotos.
  Size of logical volume dados/fotos changed from 500,00 MiB (125 extents) to 700,00 MiB (175 extents).
  Extending file system ext4 to 700,00 MiB (734003200 bytes) on dados/fotos...
resize2fs /dev/dados/fotos
resize2fs 1.47.2 (1-Jan-2025)
Filesystem at /dev/dados/fotos is mounted on /mnt/fotos; on-line resizing required   « aumenta "ao vivo"
old_desc_blocks = 4, new_desc_blocks = 6
The filesystem on /dev/dados/fotos is now 716800 (1k) blocks long.
resize2fs done
  Extended file system ext4 on dados/fotos.
  Logical volume dados/fotos successfully resized.
#> df -h /mnt/fotos
Sist. Arq.               Tam. Usado Disp. Uso% Montado em
/dev/mapper/dados-fotos  646M  139K  609M   1% /mnt/fotos                            « de 459M para 646M

Formas diferentes de aumentar

ComandoO que fazQuando usar
lvextend -r -L +200M dados/fotosAumenta 200 MiBVocê sabe quanto quer a mais.
lvextend -r -L 2G dados/fotosDeixa com 2 GiB no totalVocê sabe o tamanho final.
lvextend -r -l +100%FREE dados/fotosUsa todo o espaço livre do grupoO volume é o único que vai crescer.
lvextend -L +200M … e depois resize2fsEm duas etapasSistemas antigos; o -r faz as duas sozinho.

Acabou o espaço no grupo? Adicione um disco

#> pvcreate /dev/sdd
#> vgextend dados /dev/sdd                            « o grupo cresce com o disco novo
#> lvextend -r -l +100%FREE dados/fotos

Cenário real: o LVM do instalador do Debian

Na instalação, o particionamento assistido com LVM (usar o disco inteiro e configurar o LVM) cria um grupo com o nome da máquina terminado em -vg e dois volumes: root e swap_1. Numa máquina chamada servidor fica assim (saída típica):

#> lvs
  LV     VG           Attr       LSize   Pool Origin Data%  Meta%  Move Log Cpy%Sync Convert
  root   servidor-vg  -wi-ao---- <98,09g
  swap_1 servidor-vg  -wi-ao----  <1,00g
#> df -h /
Sist. Arq.                       Tam. Usado Disp. Uso% Montado em
/dev/mapper/servidor--vg-root     97G  1,9G   90G   3% /                        « o "-" do nome vira "--"

Ao contrário do instalador do Ubuntu Server, o do Debian usa todo o espaço do grupo nos volumes, então não sobra espaço livre "escondido". Para crescer, você adiciona um disco ao grupo (seção anterior) ou aumenta o disco virtual e o PV.

Snapshots: uma foto antes da mudança

Um snapshot congela o estado de um volume. Útil antes de uma atualização arriscada: se der errado, você volta.

lvcreate -s
-s (snapshot): cria uma "foto" em vez de um volume novo.
-n fotos-snap
Nome da foto.
-L 100M
Espaço para guardar as diferenças que acontecerem depois da foto.
dados/fotos
O volume fotografado.
#> lvcreate -s -n fotos-snap -L 100M dados/fotos
  Logical volume "fotos-snap" created.
#> lvs
  LV         VG    Attr       LSize   Pool Origin Data%  Meta%  Move Log Cpy%Sync Convert
  fotos      dados owi-aos--- 700,00m                                « "o" = tem snapshot (origin)
  fotos-snap dados swi-a-s--- 100,00m      fotos  0,51               « 0,51% do espaço da foto usado

A coluna Data% mostra quanto do espaço do snapshot já foi gasto com diferenças. Se chegar a 100%, o snapshot fica inválido. Para voltar ao estado da foto: desmonte o volume e rode lvconvert --merge dados/fotos-snap. Para descartar a foto: lvremove dados/fotos-snap.

Remover volumes e grupos

A ordem é a inversa da criação: LV → VG → PV.

#> umount /mnt/fotos
#> lvremove dados/fotos
Do you really want to remove active logical volume dados/fotos? [y/n]: y
  Logical volume "fotos" successfully removed.
#> vgremove dados
  Volume group "dados" successfully removed
#> pvremove /dev/loop0 /dev/loop1
  Labels on physical volume "/dev/loop0" successfully wiped.
  Labels on physical volume "/dev/loop1" successfully wiped.
#> losetup -d /dev/loop0 /dev/loop1
#> rm d1.img d2.img
Atenção

lvremove apaga o volume e tudo dentro dele. Ele pergunta antes (responda n se tiver dúvida); com -y, não pergunta.

Quando não funciona

"Insufficient free space" 
#> lvextend -L +5G dados/fotos
  Insufficient free space: 1280 extents needed, but only 335 available

O que aconteceu: o grupo não tem espaço livre suficiente. 5 GiB são 1280 extents de 4 MiB; só há 335 livres (1,3 GiB).

Como resolver: confira o livre com vgs (coluna VFree), peça menos (-l +100%FREE) ou adicione um disco com vgextend.

"Volume group … not found" 
#> lvs dados
  Volume group "dados" not found
  Cannot process volume group dados

O que aconteceu: o nome está errado ou o grupo não existe (ou os discos dele não estão conectados).

Como resolver: liste os grupos com vgs e os discos com pvs. Se os discos acabaram de ser conectados, rode vgscan e vgchange -ay.

Aumentei o volume e o df não mudou

O que aconteceu: você usou lvextend sem o -r. O volume cresceu, mas o sistema de arquivos dentro dele continua do tamanho antigo.

Como resolver: rode resize2fs /dev/dados/fotos (ext4) ou xfs_growfs /mnt/fotos (xfs). Da próxima vez, use -r.

"pvs: comando não encontrado"

O que aconteceu: ou você não é root (as ferramentas ficam em /usr/sbin), ou o pacote lvm2 não está instalado.

Como resolver: su - e, se ainda faltar, apt install lvm2.

Resumo

  • LVM tem três camadas: PV (disco) → VG (reservatório) → LV (volume que você formata).
  • pvcreate, vgcreate, lvcreate criam; pvs, vgs, lvs mostram.
  • lvextend -r aumenta volume e sistema de arquivos com tudo montado.
  • O instalador do Debian chama o grupo de MÁQUINA-vg, com volumes root e swap_1.
  • No Debian: rode como root (su -) e instale o lvm2 se não usou LVM na instalação.
