Projeto Servidor de Arquivos

Uma pasta no servidor que todo mundo da equipe abre como se fosse do próprio computador, seja Windows, Linux ou Mac. É para isso que existe o Samba: ele fala o protocolo de compartilhamento do Windows (SMB) a partir de um Debian. Neste laboratório você cria a pasta, o grupo da equipe, os usuários e a regra de firewall.

Ao terminar você terá
  • Uma pasta /srv/compartilhado onde só o grupo equipe lê e grava.
  • O compartilhamento \\lab\compartilhado configurado no /etc/samba/smb.conf e conferido com testparm.
  • Um usuário do Samba com senha própria.
  • A porta 445 liberada no nftables, e o acesso testado com smbclient e pelo gerenciador de arquivos.

Rede da VM para este projeto

Para outros computadores da casa enxergarem a VM, troque a placa de rede dela de NAT para Placa em modo Bridge (VirtualBox, Configurações > Rede). Assim ela ganha um IP da sua rede, como 192.168.0.50. Os testes com smbclient dentro da própria VM funcionam em qualquer modo.

As etapas

  1. Instalar o Samba

    $ sudo apt install samba smbclient
$ samba --version
-bash: samba: comando não encontrado
$ sudo samba --version
Version 4.22.11-Debian-4.22.11+dfsg-0+deb13u1
$ systemctl is-active smbd nmbd
active
active

    Dois serviços sobem: smbd (os arquivos e as impressoras) e nmbd (o nome da máquina na rede Windows antiga). O smbclient é o cliente de linha de comando, para testar. Como no Apache, o binário mora em /usr/sbin e só roda com sudo.

  2. Criar o grupo, o usuário e a pasta

    O que vamos fazer e por quê: o Samba respeita as permissões do Linux. Então a regra "só a equipe mexe" começa num grupo do sistema e nas permissões da pasta.

    $ sudo groupadd equipe
$ sudo adduser --disabled-password --comment "Bruno" bruno
$ sudo usermod -aG equipe bruno
$ sudo usermod -aG equipe ana
$ sudo mkdir -p /srv/compartilhado
$ sudo chown root:equipe /srv/compartilhado
$ sudo chmod 2775 /srv/compartilhado
$ ls -ld /srv/compartilhado
drwxrwsr-x 2 root equipe 4096 out 15 21:48 /srv/compartilhado
    2
    O bit setgid numa pasta: tudo criado dentro dela herda o grupo equipe. Aparece como s no lugar do x do grupo (rws).
    7
    Dono (root): ler, gravar, entrar.
    7
    Grupo (equipe): ler, gravar, entrar.
    5
    Outros: só ler e entrar.

    O --disabled-password cria o bruno sem senha de login no Linux: ele só vai usar o Samba, que tem senha própria. Veja Entendendo Permissões.

  3. Conhecer o smb.conf do Debian

    O arquivo vem cheio de comentários. Para ver só o que vale, filtre:

    $ grep -v -E '^\s*(#|;|$)' /etc/samba/smb.conf | head -8
[global]
   workgroup = WORKGROUP
   log file = /var/log/samba/log.%m
   max log size = 1000
   logging = file
   panic action = /usr/share/samba/panic-action %d
   server role = standalone server
   obey pam restrictions = yes

    Cada [nome] é uma seção. [global] vale para o servidor; as outras são compartilhamentos. O Debian já traz [homes] (a pasta pessoal de cada usuário, só leitura por padrão) e [printers].

  4. Criar o compartilhamento

    Faça uma cópia e acrescente no fim do arquivo (com sudo nano /etc/samba/smb.conf):

    $ sudo cp /etc/samba/smb.conf /etc/samba/smb.conf.bak
    [compartilhado]
   comment = Pasta da equipe
   path = /srv/compartilhado
   valid users = @equipe
   read only = no
   create mask = 0664
   directory mask = 2775
    LinhaO que faz
    [compartilhado]O nome que aparece na rede: \\lab\compartilhado.
    pathA pasta de verdade no Debian.
    valid users = @equipeSó membros do grupo equipe entram. O @ quer dizer "grupo".
    read only = noPermite gravar.
    create mask / directory maskPermissões dos arquivos e pastas criados pela rede: o grupo também pode editar.

    Confira com o testparm, que lê o arquivo e mostra como o Samba entendeu:

    $ testparm -s 2>/dev/null | tail -8
[compartilhado]
	comment = Pasta da equipe
	create mask = 0664
	directory mask = 02775
	path = /srv/compartilhado
	read only = No
	valid users = @equipe

    Se você errar o nome de uma opção, o testparm avisa com Unknown parameter encountered e a linha. Depois de conferir:

    $ sudo systemctl restart smbd

  5. Senhas do Samba

    O que vamos fazer e por quê: o Samba guarda as senhas num banco próprio, separado do /etc/shadow. Todo usuário que vai acessar precisa ser cadastrado nele.

    $ sudo smbpasswd -a bruno
New SMB password:
Retype new SMB password:
Added user bruno.
$ sudo smbpasswd -a ana
$ sudo pdbedit -L
ana:1000:
bruno:1001:

    O pdbedit -L lista quem está no banco do Samba, com o número de usuário (UID) do Linux.

  6. Liberar a porta no firewall

    O Samba escuta nas portas 445 (SMB moderno) e 139 (o antigo NetBIOS):

    $ sudo ss -tlnp | grep smbd
LISTEN 0      50           0.0.0.0:139       0.0.0.0:*    users:(("smbd",pid=112815,fd=31))
LISTEN 0      50           0.0.0.0:445       0.0.0.0:*    users:(("smbd",pid=112815,fd=30))
LISTEN 0      50              [::]:139          [::]:*    users:(("smbd",pid=112815,fd=29))
LISTEN 0      50              [::]:445          [::]:*    users:(("smbd",pid=112815,fd=28))

    Se o firewall do projeto Servidor Web estiver ativo, acrescente a 445 na regra do /etc/nftables.conf. Libere só a rede de casa, nunca a internet:

            ip saddr 192.168.0.0/24 tcp dport 445 accept    # Samba só para a rede local
    $ sudo nft -c -f /etc/nftables.conf
$ sudo systemctl reload nftables
    Nunca exponha o Samba na internet

    A porta 445 é das mais atacadas do mundo. Para acesso de fora de casa, use uma VPN (veja VPN (WireGuard)) e acesse o Samba por dentro dela.

  7. Testar de dentro do servidor

    O smbclient conversa com o Samba como um cliente da rede faria. Vamos enviar um arquivo como o bruno:

    //localhost/compartilhado
    Máquina e compartilhamento, no formato do Samba (barras normais).
    -U bruno
    O usuário do Samba. Ele pede a senha.
    -c 'put …; ls'
    Comandos a executar: enviar um arquivo e listar a pasta.
    $ echo "ola" > /tmp/oi.txt
$ smbclient //localhost/compartilhado -U bruno -c 'put /tmp/oi.txt oi.txt; ls'
Password for [WORKGROUP\bruno]:
putting file /tmp/oi.txt as \oi.txt (1,0 kb/s) (average 1,0 kb/s)
  .                                   D        0  Thu Oct 15 21:48:40 2026
  ..                                  D        0  Thu Oct 15 21:48:40 2026
  oi.txt                              A        4  Thu Oct 15 21:48:40 2026

		24253528 blocks of size 1024. 20668596 blocks available
$ ls -l /srv/compartilhado
total 4
-rw-rw-r-- 1 bruno equipe 4 out 15 21:48 oi.txt

    Repare no ls -l: o arquivo pertence ao bruno e ao grupo equipe (herdado pelo setgid), com permissão rw-rw-r-- (o create mask). A ana também consegue editá-lo.

    Confira a recusa: com a senha errada, o Samba responde:

    $ smbclient //localhost/compartilhado -U bruno%senhaerrada -c ls
session setup failed: NT_STATUS_LOGON_FAILURE

  8. Acessar de outro computador

    SistemaComo abrir
    WindowsNo Explorador de Arquivos, digite \\192.168.0.50\compartilhado na barra de endereço. Para fixar como letra (Z:), use "Mapear unidade de rede".
    Linux (GNOME)No Arquivos, "Outros locais" > "Conectar ao servidor": smb://192.168.0.50/compartilhado
    macOSFinder > Ir > Conectar ao Servidor (Cmd+K): smb://192.168.0.50/compartilhado
    Linux (terminal, montando)sudo mount -t cifs //192.168.0.50/compartilhado /mnt/equipe -o username=bruno,uid=$(id -u) (pacote cifs-utils)

    Troque 192.168.0.50 pelo IP da VM, que aparece em ip -br a.

    Se deu errado: "NT_STATUS_ACCESS_DENIED" ao gravar

    O Samba deixou entrar, mas o Linux não deixou gravar. Confira se o usuário está no grupo (id bruno), se a pasta é do grupo equipe com 2775 e se o read only = no está na seção certa. Reinicie o smbd depois de mexer em grupos.

    Se deu errado: o Windows não acha o servidor

    Confirme a placa da VM em modo Bridge, o IP certo e a regra da porta 445 no nftables. Teste do próprio Windows com Test-NetConnection 192.168.0.50 -Port 445 no PowerShell.

E o NFS?

Entre máquinas Linux, o NFS é a alternativa nativa: mais simples, sem senhas próprias, baseado em IPs e números de usuário. No Debian: sudo apt install nfs-kernel-server, uma linha no /etc/exports como /srv/compartilhado 192.168.0.0/24(rw,sync,no_subtree_check) e sudo exportfs -ra. Se a rede tem Windows ou Mac, prefira o Samba.

Checklist do que você aprendeu

  • O Samba usa as permissões do Linux: grupo + pasta com 2775 (setgid) primeiro.
  • Cada compartilhamento é uma seção no smb.conf; o testparm confere antes de reiniciar.
  • Usuários do Samba têm senha própria: smbpasswd -a, listados com pdbedit -L.
  • Porta 445 só para a rede local; para acesso remoto, VPN.
  • smbclient testa tudo sem sair do servidor.

Desafios extras

  • Crie um segundo compartilhamento [publico] só leitura e sem senha (guest ok = yes, read only = yes).
  • Ative a "lixeira" do Samba com vfs objects = recycle, para arquivos apagados pela rede irem para .recycle.
  • Inclua /srv/compartilhado no seu Backup Automático.

Limpeza

$ sudo cp /etc/samba/smb.conf.bak /etc/samba/smb.conf
$ sudo smbpasswd -x bruno
Deleted user bruno.
$ sudo deluser --remove-home bruno
$ sudo groupdel equipe
$ sudo rm -rf /srv/compartilhado
$ sudo apt purge samba smbclient

Exercícios

1. Herdar o grupo

Complete as permissões da pasta para o grupo gravar e os arquivos novos herdarem o grupo:

2. Só o grupo

Complete a linha do smb.conf que deixa entrar só quem é do grupo financeiro:

3. O bruno existe no Linux, está no grupo certo, mas o smbclient dá NT_STATUS_LOGON_FAILURE com a senha dele. O que falta?

4. Qual é a forma segura de acessar o Samba de casa quando você está viajando?

Resumo

  • Samba = pasta do Linux visível como compartilhamento do Windows, para qualquer sistema.
  • Permissões do Linux + valid users + senha do Samba formam as três travas de acesso.
  • Teste com testparm e smbclient; abra a porta 445 só para a rede local.
