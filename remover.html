Debian rm e rmdir

O rm apaga arquivos e o rmdir apaga pastas vazias. Eles são rápidos e não pedem confirmação. Por isso esta aula ensina, junto com os comandos, os hábitos que evitam apagar o que não devia.

O rm não usa lixeira

O que o rm apaga não vai para a lixeira do desktop e não volta com "desfazer". Antes de qualquer rm, confira o que vai sair. Se quiser uma segunda chance, use gio trash, mostrado nesta aula.

Você vai aprender
  • Apagar arquivos com rm e pastas com rmdir e rm -r.
  • Pedir confirmação com -i e -I.
  • Mandar para a lixeira pelo terminal, com gio trash.
  • Por que o rm -rf merece respeito, e a proteção que o Debian tem.

A ideia: apagar é tirar o nome da lista

Uma pasta é uma lista de nomes que apontam para os dados no disco. O rm tira o nome da lista. Sem nenhum nome apontando para eles, os dados viram espaço livre e serão sobrescritos. Na prática: o arquivo some na hora.

rm: apagar arquivos

rm vem de remove, "remover".

rm
O programa que apaga.
a.txt
O arquivo a apagar. Pode haver vários: rm a.txt b.txt.
$ ls
a.txt  b.txt  c.log  vazia  velho
$ rm a.txt
$ rm -v b.txt
removido 'b.txt'                  « com -v, o rm conta o que fez

O que o comando devolve

Silêncio é sucesso, e o código de saída confirma:

$ rm nada
rm: não foi possível remover 'nada': Arquivo ou diretório inexistente
$ echo $?
1

Pedir confirmação: -i e -I

-i: pergunta a cada arquivo

O -i (de interactive) pergunta antes de cada arquivo. Responda s para apagar ou n para manter:

$ rm -i aula1
rm: remover regular empty file 'aula1'? n

A pergunta mistura inglês e português no Debian 13: "regular empty file" quer dizer "arquivo comum vazio". O começo e o fim da frase são traduzidos; o tipo do arquivo ainda não. Com um arquivo com conteúdo, a pergunta vira "remover regular file 'x'?".

-I: pergunta uma vez só

O -I (maiúsculo) pergunta uma vez quando há mais de três arquivos, ou quando o apagamento é recursivo. É menos chato que o -i e ainda protege contra um curinga errado:

$ rm -I *.log
rm: remover 4 argumentos? n
$ rm -rI velho
rm: remover 1 argumento recursivamente? n

Arquivos protegidos contra escrita

Se o arquivo não tem permissão de escrita, o rm pergunta mesmo sem -i:

$ rm r1
rm: remover regular file 'r1' protegido contra escrita? n
Sempre perguntar

Para que o rm sempre pergunte, crie o apelido alias rm='rm -I' no ~/.bashrc (veja .bashrc, alias, PATH).

Apagar pastas

rmdir: só pastas vazias

rmdir vem de remove directory. Ele só apaga pastas vazias, o que é uma proteção:

$ rmdir vazia
$ rmdir velho
rmdir: falhou em remover 'velho': Diretório não vazio

Com -p, ele apaga também as pastas de cima que ficarem vazias:

$ rmdir -pv p1/p2/p3
rmdir: removendo o diretório 'p1/p2/p3'
rmdir: removendo o diretório 'p1/p2'
rmdir: removendo o diretório 'p1'

rm -r: a pasta e tudo o que há dentro

Sem opção, o rm recusa pastas:

$ rm velho
rm: não foi possível remover 'velho': É um diretório

O -r (de recursive) entra na pasta e apaga tudo, de dentro para fora:

rm
O programa.
-rv
-r apaga pastas e o conteúdo; -v mostra cada item.
velho
A pasta.
$ rm -rv velho
removido 'velho/x.txt'
removido 'velho/y.txt'
foi removido o diretório: 'velho'

Com -r e -i juntos, o rm pergunta até antes de entrar na pasta: rm: entrar no diretório 'velho'?.

Confira antes de apagar com curingas

Antes de um rm com curinga, troque rm por echo para ver a lista. Se estiver certa, rode o rm (veja Curingas):

$ echo *.log
c.log d.log
$ rm *.log

Usar a lixeira pelo terminal: gio trash

O Debian com desktop GNOME instala o comando gio (do pacote libglib2.0-bin). O gio trash manda arquivos para a mesma lixeira do app Arquivos, de onde dá para recuperar:

gio
Ferramenta do GNOME para mexer com arquivos.
trash
O subcomando: "mandar para a lixeira".
relatorio-velho.odt
O que mandar.
$ gio trash relatorio-velho.odt
$ ls relatorio-velho.odt
ls: não foi possível acessar 'relatorio-velho.odt': Arquivo ou diretório inexistente      « saiu da pasta, mas está na lixeira

Para ver, devolver ou esvaziar, use o app Arquivos (item Lixeira) ou estes comandos, que funcionam dentro da sessão gráfica do GNOME:

ComandoFaz
gio trash arqManda para a lixeira
gio trash --listLista o que está na lixeira
gio trash --restore trash:///arqDevolve ao lugar original
gio trash --emptyEsvazia a lixeira (aí não volta mais)

Fora da sessão gráfica (por SSH, por exemplo), só o primeiro funciona. Os outros dependem de um serviço do GNOME (o gvfs) e respondem assim:

$ gio trash --list
gio: trash:: Operação sem suporte

No servidor: trash-cli

Numa instalação sem desktop, o root pode instalar o pacote trash-cli. Ele usa a mesma lixeira do GNOME e funciona em qualquer terminal:

$ trash-put t2.txt
$ trash-list
2026-10-15 21:49:05 /home/ana/t2.txt
2026-10-15 21:49:05 /home/ana/relatorio-velho.odt
$ trash-restore      « pergunta qual item devolver
$ trash-empty        « esvazia

Repare que o trash-list mostrou também o arquivo mandado com gio trash: os dois usam a pasta ~/.local/share/Trash.

rm -rf: o comando que merece respeito

O -f (de force, "forçar") não pergunta nada e não reclama de arquivos que não existem. Junto com -r, apaga uma pasta inteira em silêncio. É útil em scripts e perigoso digitado à mão.

Atenção redobrada
  • rm -rf pasta /, com um espaço sem querer antes da barra, tentaria apagar a raiz do sistema.
  • rm -rf $PASTA/* com a variável vazia vira rm -rf /*.
  • Como root, nada impede o estrago dentro de /etc, /usr ou /home.

O Debian tem uma proteção para o pior caso, apagar a própria raiz:

$ rm -rf /
rm: é perigoso operar recursivamente em '/'
rm: use --no-preserve-root para contornar esta segurança

Essa trava só protege o / exato. Ela não protege /*, /home nem nenhuma outra pasta. A proteção de verdade é o hábito: confira com ls ou echo antes, prefira -I e tenha backup.

Quando não funciona

"É um diretório"

O que aconteceu: o rm sem opções não apaga pastas.

Como resolver: rmdir pasta se ela estiver vazia, ou rm -r pasta para apagar com o conteúdo.

"Diretório não vazio"

O que aconteceu: o rmdir só apaga pastas vazias. Às vezes há arquivos ocultos lá dentro.

Como resolver: veja o que há com ls -A pasta. Se pode mesmo sair tudo, use rm -r pasta.

"Permissão negada" 
$ rm /etc/hostname
rm: não foi possível remover '/etc/hostname': Permissão negada

O que aconteceu: para apagar, você precisa poder escrever na pasta que contém o arquivo, e /etc é do root.

Como resolver: pare e pense se é mesmo para apagar um arquivo do sistema. Se for, faça como root com su -.

Um arquivo com nome começando por hífen 
$ rm -arquivo
rm: opção inválida -- “a”
Tente "rm ./-arquivo" para remover o arquivo '-arquivo'.
Tente "rm --help" para mais informações.

O que aconteceu: o rm achou que -arquivo era uma opção.

Como resolver: faça como a própria mensagem sugere: rm ./-arquivo, ou rm -- -arquivo.

Apaguei sem querer

O que aconteceu: o rm não usa lixeira.

Como resolver: pare de gravar no disco e recupere de um backup. Ferramentas de recuperação existem, mas raramente devolvem tudo.

Resumo

  • rm apaga arquivos de verdade, sem lixeira.
  • rmdir apaga pastas vazias; rm -r apaga pastas com conteúdo.
  • -i pergunta a cada arquivo, -I pergunta uma vez.
  • gio trash (desktop) e trash-put (servidor) mandam para a lixeira.
  • Antes de rm com curinga, confira com echo.
