Debian Backports e Pinning

O Debian estável não muda as versões dos programas durante a vida dele: recebe só correções. Isso o torna confiável, mas às vezes você precisa de uma versão mais nova de um programa específico. O backports resolve isso sem trocar o resto do sistema, e o pinning deixa você escolher, pacote por pacote, de onde cada um vem.

Você vai aprender
  • O que é o trixie-backports e o que significa o ~bpo13 numa versão.
  • A ativar o backports e instalar um pacote dele com apt install -t.
  • A ler as prioridades (100, 500) no apt policy.
  • A usar o pinning em /etc/apt/preferences.d.
  • Por que misturar testing ou unstable no estável cria um "FrankenDebian".
Pré-requisito

Esta aula supõe que você já leu Repositórios (sources). Todos os comandos que mudam o sistema são feitos como root (su -).

O que é o backports

A equipe do Debian pega o pacote de uma versão mais nova (da testing), recompila para as bibliotecas do Debian 13 e publica num repositório à parte, o trixie-backports. Você continua no Debian 13 e escolhe, um a um, quais programas vêm de lá.

trixie-security8.14.1-2+deb13u7A mesma versão, com correções de segurança
trixie-backports8.21.0-2~bpo13+1Versão nova, recompilada para o 13
8.21.0

~bpo13+1
"Backport para o Debian 13, primeira compilação". O ~ faz essa versão ser considerada menor que a 8.21.0-2 oficial, para que um upgrade futuro para o Debian 14 a substitua naturalmente.

Ativar o trixie-backports

É só uma linha a mais, num arquivo próprio em /etc/apt/sources.list.d/. Como root:

#> echo "deb http://deb.debian.org/debian trixie-backports main non-free-firmware" > /etc/apt/sources.list.d/backports.list
#> apt update
…
Obter:5 http://deb.debian.org/debian trixie-backports/main amd64 Packages [285 kB]
Obter:6 http://deb.debian.org/debian trixie-backports/main Translation-en [223 kB]
Obter:7 http://deb.debian.org/debian trixie-backports/non-free-firmware amd64 Packages [6.564 B]
…

Se preferir o formato novo (veja Repositórios), o arquivo /etc/apt/sources.list.d/backports.sources fica assim:

Types: deb
URIs: http://deb.debian.org/debian
Suites: trixie-backports
Components: main non-free-firmware
Signed-By: /usr/share/keyrings/debian-archive-keyring.gpg
Ativar não instala nada

Depois do apt update, nenhum pacote muda de versão. O backports fica "de reserva": o apt só usa um pacote de lá quando você pede.

Por que nada muda sozinho: as prioridades

O apt policy mostra cada versão com um número na frente, a prioridade:

$ apt policy curl
curl:
  Instalado: (nenhum)
  Candidato: 8.14.1-2+deb13u7                               « o que o apt install escolheria
  Tabela de versão:
     8.21.0-2~bpo13+1 100                                    « backports: prioridade 100
        100 http://deb.debian.org/debian trixie-backports/main amd64 Packages
     8.14.1-2+deb13u7 500                                    « segurança: prioridade 500
        500 http://security.debian.org/debian-security trixie-security/main amd64 Packages
     8.14.1-2+deb13u5 500
        500 http://deb.debian.org/debian trixie/main amd64 Packages

A regra do apt é: primeiro a maior prioridade, depois a maior versão. As versões do estável têm 500; as do backports, 100. Por isso a 8.21, mesmo sendo mais nova, perde.

De onde vem o 100? O próprio repositório se declara assim no arquivo Release:

$ grep -E "^(Suite|NotAutomatic|ButAutomaticUpgrades)" /var/lib/apt/lists/deb.debian.org_debian_dists_trixie-backports_InRelease
Suite: stable-backports
NotAutomatic: yes                « não instale daqui sem pedir (prioridade 1)…
ButAutomaticUpgrades: yes        « …mas atualize o que já veio daqui (prioridade 100)
PrioridadeEfeitoQuem tem
1000 ou maisInstala mesmo que seja um downgradeSó com pinning manual
500Padrão: instala e atualiza normalmentetrixie, trixie-security, trixie-updates
100Não instala sozinho; só atualiza o que já veio dalitrixie-backports; a versão já instalada (/var/lib/dpkg/status)
1 a 99Só instala se você pedir explicitamenteRepositórios com NotAutomatic sem atualização automática
menor que 0Nunca instalaPinning para bloquear um pacote

Instalar do backports: apt install -t

apt install
Instalar, como sempre.
-t trixie-backports
Alvo (target): nesta instalação, trate o backports como se tivesse prioridade alta. Vale para o pacote e para as dependências que ele exigir de lá.
cockpit
O pacote (um painel de administração pelo navegador).

Compare o que o apt faria com e sem o -t, usando -s (simular, sem instalar):

#> apt-get -s install cockpit | grep "^Inst cockpit "
Inst cockpit (337-1+deb13u2 Debian:13.7/stable, Debian-Security:13/stable-security [all])
#> apt-get -s install -t trixie-backports cockpit | grep "^Inst cockpit "
Inst cockpit (368-1~bpo13+1 Debian Backports:stable-backports [all])

Sem o -t, vem a versão 337 do estável. Com ele, a 368 do backports. Para instalar de verdade, é o mesmo comando sem o -s:

#> apt install -t trixie-backports cockpit

Formas diferentes de escolher a origem

ComandoO que fazQuando usar

Depois de instalado

Graças ao ButAutomaticUpgrades, um pacote instalado do backports continua sendo atualizado pelo backports no apt upgrade comum. Para ver quais pacotes da máquina vieram de lá:

$ apt list --installed 2>/dev/null | grep backports
cockpit/stable-backports,now 368-1~bpo13+1 all [instalado]

Pinning: regras permanentes

Pinning ("alfinetar") é mudar a prioridade de pacotes com um arquivo em /etc/apt/preferences.d/. Exemplo: o curl deve vir sempre do backports.

Package: curl
Pin: release n=trixie-backports
Pin-Priority: 500
Package: curl
A quais pacotes a regra vale. Aceita vários separados por espaço e curingas (libcurl*).
Pin: release n=trixie-backports
A qual origem. n= é o codinome da suíte; a=stable-backports também funciona.
Pin-Priority: 500
A nova prioridade: igual à do estável, então ganha a versão mais alta, a do backports.
$ apt policy curl
curl:
  Instalado: (nenhum)
  Candidato: 8.21.0-2~bpo13+1                         « agora o backports ganha
  Tabela de versão:
     8.21.0-2~bpo13+1 500                              « prioridade efetiva 500
        100 http://deb.debian.org/debian trixie-backports/main amd64 Packages
     8.14.1-2+deb13u7 500
        500 http://security.debian.org/debian-security trixie-security/main amd64 Packages
     8.14.1-2+deb13u5 500
        500 http://deb.debian.org/debian trixie/main amd64 Packages

Repare: a linha do repositório continua com 100, mas a versão ganhou 500, que é a prioridade dada pela sua regra. O apt policy sem nome de pacote lista todas as regras em vigor no fim, em "Pacotes alfinetados (pinned)".

Por que não misturar testing: o "FrankenDebian"

É tentador acrescentar a linha da testing (forky) ou da unstable (sid) para ter "tudo mais novo". Não faça isso num Debian estável.

  • Os pacotes da testing são compilados para as bibliotecas da testing. Instalar um deles puxa uma libc6 nova, que puxa dezenas de outras, e em pouco tempo o sistema é metade 13, metade 14.
  • Essa mistura não é testada por ninguém. Atualizações começam a falhar com dependências impossíveis, e a próxima atualização de versão vira uma loteria.
  • A equipe de segurança não cobre a testing como cobre o estável.

A própria documentação do Debian chama essa mistura de FrankenDebian. Se você precisa de um programa mais novo, a ordem de preferência é: backports; o repositório oficial do fabricante para Debian 13; um Flatpak; um container. Se você quer tudo mais novo, instale a testing inteira numa máquina separada, sabendo o que isso significa (veja Versões do Debian).

Quando não funciona

"apt install pacote" não pega a versão do backports 
#> apt-get -s install cockpit | grep "^Inst cockpit "
Inst cockpit (337-1+deb13u2 Debian:13.7/stable, Debian-Security:13/stable-security [all])

O que aconteceu: é o comportamento esperado: o backports tem prioridade 100.

Como resolver: use -t trixie-backports ou uma regra de pinning.

"-t trixie-backports" diz que o valor é inválido 
#> apt install -t trixie-backports cockpit
Erro: O valor 'trixie-backports' é inválido para APT::Default-Release, pois essa versão não está disponível nas fontes
#> apt install cockpit/trixie-backports
Erro: Release 'trixie-backports' para 'cockpit' não foi encontrada

O que aconteceu: para o apt, a suíte trixie-backports não existe: o repositório não foi ativado, ou você não rodou o apt update depois de ativá-lo.

Como resolver: confira o arquivo em /etc/apt/sources.list.d/, rode apt update e veja com apt policy cockpit se a versão ~bpo13 aparece.

Quero voltar à versão do estável 
#> apt install cockpit/trixie

O que acontece: o apt instala a versão do estável, que é menor: um downgrade. Ele pede confirmação. Depois, apague a regra de pinning (se houver) para o backports não voltar no próximo upgrade.

Resumo

  • O trixie-backports traz versões novas recompiladas para o Debian 13 (~bpo13).
  • Ativá-lo não muda nada: ele tem prioridade 100, contra 500 do estável.
  • Para instalar de lá: apt install -t trixie-backports pacote; depois, ele se atualiza pelo backports.
  • Pinning em /etc/apt/preferences.d/ muda prioridades de forma permanente.
  • Nunca misture testing ou unstable no estável: é o "FrankenDebian".
