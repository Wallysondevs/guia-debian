Debian ZFS

O ZFS junta num só sistema o que no Linux costuma ser separado: RAID, gerenciador de volumes (como o LVM) e sistema de arquivos. Ele confere cada bloco com um "dígito verificador", tira snapshots instantâneos e comprime os dados. No Debian, ele dá um pouco mais de trabalho para instalar do que no Ubuntu, por causa de uma questão de licença.

Você vai aprender
  • As peças do ZFS: pool, vdev e dataset.
  • Por que o ZFS fica no repositório contrib do Debian e como ativá-lo.
  • Instalar o OpenZFS com DKMS e entender o aviso de licença.
  • Criar um pool espelhado, datasets com compressão e snapshots.
  • Conferir os dados com scrub e trocar um disco com defeito.

Comandos como root (su -), na máquina fictícia servidor. Os nomes e versões de pacotes foram conferidos no Debian 13 (OpenZFS 2.3.9). As saídas dos comandos zpool e zfs são típicas: os números variam de máquina para máquina. O ZFS responde em inglês.

Conceito: pool, vdev e dataset

PeçaO que éComparando com o LVM
vdevUm grupo de discos com uma regra de redundância: mirror (espelho), raidz1, raidz2…Um RAID do mdadm
pool (zpool)O reservatório formado por um ou mais vdevsO VG
datasetUm "sistema de arquivos" dentro do pool, que já nasce montado e cresce sozinhoUm LV já formatado
snapshotFoto de um dataset num instanteSnapshot do LVM, mas instantâneo e sem tamanho fixo

Dois comandos fazem tudo: zpool cuida dos discos e do pool; zfs cuida dos datasets e snapshots.

Por que o ZFS não vem pronto no Debian

O OpenZFS usa a licença CDDL; o kernel Linux usa a GPL-2. As duas licenças são livres, mas não combinam num mesmo programa distribuído. Por isso o Debian:

  • coloca o ZFS na seção contrib (software livre que depende de algo fora do "main" ou tem restrições), que não vem ativada;
  • não entrega o módulo pronto: o pacote zfs-dkms traz o código-fonte, e o DKMS (Dynamic Kernel Module Support) compila o módulo na sua máquina, para o seu kernel.

Sem o contrib, o pacote "não existe":

#> apt policy zfsutils-linux
zfsutils-linux:
  Instalado: (nenhum)
  Candidato: (nenhum)                                « não aparece no repositório main
  Tabela de versão:

Instalar e montar o laboratório

  1. Ative o contrib. No Debian 13 instalado pelo netinst, as fontes ficam em /etc/apt/sources.list (veja Repositórios). Acrescente contrib depois de main nas linhas do Debian: 
    deb http://deb.debian.org/debian trixie main contrib non-free-firmware
deb http://security.debian.org/debian-security trixie-security main contrib non-free-firmware
deb http://deb.debian.org/debian trixie-updates main contrib non-free-firmware
    #> nano /etc/apt/sources.list
#> apt update
#> apt policy zfsutils-linux | head -3
zfsutils-linux:
  Instalado: (nenhum)
  Candidato: 2.3.9-0+deb13u1                         « agora aparece
  2. Instale os cabeçalhos do kernel e o ZFS. O DKMS precisa dos cabeçalhos (linux-headers-amd64) e de um compilador, que o apt puxa junto: 
    #> apt install linux-headers-amd64 zfs-dkms zfsutils-linux
    No meio da instalação aparece uma tela azul com o aviso "Licenses of OpenZFS and Linux are incompatible" (num sistema em português, o texto vem traduzido). É só um aviso: aperte Enter em Ok. Em seguida o DKMS compila o módulo, o que leva alguns minutos; a tela parece parada, mas está trabalhando.
  3. Carregue o módulo e confira: 
    #> modprobe zfs
#> zfs version
zfs-2.3.9-0+deb13u1
zfs-kmod-2.3.9-0+deb13u1
  4. Crie os "discos" de treino. O ZFS aceita arquivos direto, sem losetup; use o caminho completo: 
    #> truncate -s 1G /root/lab/z1.img /root/lab/z2.img /root/lab/z3.img
Ao atualizar o kernel

A cada kernel novo, o DKMS recompila o módulo durante o apt upgrade. Se os cabeçalhos do kernel novo faltarem, o módulo não é gerado e o pool não monta depois de reiniciar. Por isso instale o metapacote linux-headers-amd64, que acompanha o kernel automaticamente.

Criar um pool espelhado

zpool create
Cria um pool.
tanque
O nome do pool. Ele vira também a pasta /tanque, já montada.
mirror
O tipo do vdev: espelho, como um RAID 1.
/root/lab/z1.img /root/lab/z2.img
Os "discos". Num servidor real, use nomes estáveis: /dev/disk/by-id/….
#> zpool create tanque mirror /root/lab/z1.img /root/lab/z2.img
#> zpool list
NAME     SIZE  ALLOC   FREE  CKPOINT  EXPANDSZ   FRAG    CAP  DEDUP    HEALTH  ALTROOT
tanque   960M   114K   960M        -         -     0%     0%  1.00x    ONLINE  -
#> df -h /tanque
Sist. Arq.      Tam. Usado Disp. Uso% Montado em
tanque          832M  128K  832M   1% /tanque          « já montado, sem mkfs nem fstab

Repare no que não foi preciso: formatar, criar ponto de montagem ou editar o /etc/fstab. O ZFS faz tudo isso sozinho.

Datasets: organizar o pool

zfs create
Cria um dataset.
-o compression=zstd
-o define uma propriedade: aqui, comprimir tudo com o algoritmo zstd.
tanque/fotos
Pool/nome. Vira a pasta /tanque/fotos.
#> zfs create tanque/documentos
#> zfs create -o compression=zstd tanque/fotos
#> zfs list
NAME                USED  AVAIL  REFER  MOUNTPOINT
tanque              201K   832M    24K  /tanque
tanque/documentos    24K   832M    24K  /tanque/documentos
tanque/fotos         24K   832M    24K  /tanque/fotos
#> zfs get compression,compressratio tanque/fotos
NAME          PROPERTY       VALUE           SOURCE
tanque/fotos  compression    zstd            local
tanque/fotos  compressratio  1.00x           -

Os datasets dividem o espaço livre do pool: nenhum tem tamanho fixo. Para limitar um, use uma cota: zfs set quota=200M tanque/fotos.

Snapshots e rollback

zfs snapshot
Tira a foto.
tanque/documentos@antes-da-limpeza
Dataset + @ + nome da foto.
#> echo "contrato importante" > /tanque/documentos/contrato.txt
#> zfs snapshot tanque/documentos@antes-da-limpeza
#> rm /tanque/documentos/contrato.txt                          « ops, apagado
#> zfs list -t snapshot
NAME                                 USED  AVAIL  REFER  MOUNTPOINT
tanque/documentos@antes-da-limpeza    13K      -  25.5K  -

Duas formas de recuperar:

FormaComandoQuando usar
Pegar só o arquivocp /tanque/documentos/.zfs/snapshot/antes-da-limpeza/contrato.txt /tanque/documentos/Recuperar um ou poucos arquivos. A pasta .zfs é escondida, mas existe.
Voltar tudozfs rollback tanque/documentos@antes-da-limpezaDesfazer todas as mudanças feitas depois da foto.
#> zfs rollback tanque/documentos@antes-da-limpeza
#> cat /tanque/documentos/contrato.txt
contrato importante

Scrub: conferir todos os dados

O scrub lê o pool inteiro e confere cada bloco. Se achar um bloco corrompido, conserta a partir da cópia boa do espelho.

#> zpool scrub tanque
#> zpool status tanque | grep scan
  scan: scrub repaired 0B in 00:00:01 with 0 errors on Thu Oct 15 23:10:12 2026

O pacote zfsutils-linux do Debian já agenda um scrub mensal dos pools.

Trocar um disco com defeito

  1. Simule a falha tirando um disco do ar: 
    #> zpool offline tanque /root/lab/z2.img
#> zpool status tanque
  pool: tanque
 state: DEGRADED                                        « funcionando, mas sem redundância
status: One or more devices has been taken offline by the administrator.
…
	NAME                  STATE     READ WRITE CKSUM
	tanque                DEGRADED     0     0     0
	  mirror-0            DEGRADED     0     0     0
	    /root/lab/z1.img  ONLINE       0     0     0
	    /root/lab/z2.img  OFFLINE      0     0     0
  2. Troque pelo disco novo: 
    #> zpool replace tanque /root/lab/z2.img /root/lab/z3.img
#> zpool status tanque | grep -E "state|scan"
 state: ONLINE
  scan: resilvered 300K in 00:00:00 with 0 errors on Thu Oct 15 23:12:40 2026
    O ZFS chama a reconstrução de resilver. Ele copia só os blocos usados, por isso costuma ser bem mais rápido que um RAID tradicional.

Desmontar o laboratório

#> zpool destroy tanque                                « apaga o pool e todos os datasets
#> rm /root/lab/z1.img /root/lab/z2.img /root/lab/z3.img

Quando não funciona

"O pacote 'zfsutils-linux' não tem candidato para instalação" 
#> apt install zfsutils-linux
Erro: O pacote 'zfsutils-linux' não tem candidato para instalação

O que aconteceu: o contrib não está ativado, ou você esqueceu o apt update depois de editar o sources.list.

Como resolver: confira com grep contrib /etc/apt/sources.list e rode apt update.

"The ZFS modules are not loaded." 
#> zpool list
The ZFS modules are not loaded.
Try running '/sbin/modprobe zfs' as root to load them.

O que aconteceu: o módulo não foi carregado ou não foi compilado (faltavam os cabeçalhos do kernel em uso).

Como resolver: rode modprobe zfs. Se der "Module zfs not found", confira dkms status, instale linux-headers-$(uname -r) e rode dpkg-reconfigure zfs-dkms para recompilar.

"cannot create 'tanque': pool already exists"

O que aconteceu: já existe um pool com esse nome.

Como resolver: veja os pools com zpool list; escolha outro nome ou, no laboratório, destrua o antigo com zpool destroy tanque.

"invalid vdev specification … use '-f' to override"

O que aconteceu: os discos já têm marcas de outro formato (partições, ext4, RAID antigo). O ZFS se recusa a apagar sem confirmação.

Como resolver: confira se é mesmo o disco certo e use zpool create -f, ou limpe antes com wipefs -a (veja Particionar e Formatar).

Resumo

  • ZFS = RAID + volumes + sistema de arquivos, com verificação de cada bloco.
  • No Debian: ative o contrib, instale linux-headers-amd64 zfs-dkms zfsutils-linux e aceite o aviso de licença.
  • zpool cuida de discos e pools; zfs cuida de datasets e snapshots.
  • Pools e datasets já nascem montados; não precisa de mkfs nem fstab.
  • scrub confere os dados; replace troca disco; snapshots salvam você de erros.
