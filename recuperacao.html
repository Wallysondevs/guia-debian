Debian Recuperar um Sistema

Um dia o Debian não vai ligar: uma linha errada no /etc/fstab, uma senha esquecida, um GRUB apagado. Quase sempre dá para consertar sem reinstalar. Nesta aula você vai subir uma "escada" de ferramentas de resgate, da mais simples à mais poderosa.

Você vai aprender
  • Usar o modo de recuperação do Debian, que é diferente do Ubuntu: ele pede a senha do root.
  • Sair do modo de emergência causado por um /etc/fstab errado.
  • Trocar uma senha esquecida com init=/bin/bash.
  • Consertar o GRUB a partir de um pendrive com chroot.
  • Verificar o disco com fsck.
Pratique antes de precisar

Faça estes exercícios numa máquina virtual, de preferência com um snapshot salvo. O projeto Quebre e Conserte guia você por isso.

Antes do comando: a escada do resgate

  1. Kernel anterior no menu do GRUB (problema depois de atualizar). Veja Boot, GRUB e Kernel.
  2. Modo de recuperação (recovery mode): o sistema sobe o mínimo e abre um terminal de root.
  3. Modo de emergência: aparece sozinho quando um disco do fstab falha.
  4. init=/bin/bash: um terminal de root sem senha nenhuma, para senhas esquecidas.
  5. Pendrive live + chroot: quando nem o GRUB funciona.

O modo de recuperação do Debian

No menu do GRUB, entre em Advanced options for Debian GNU/Linux e escolha a linha que termina em (recovery mode). Em vez do menu colorido do Ubuntu, o Debian mostra direto um pedido de senha. Esta é a tela real do Debian 13:

You are in rescue mode. After logging in, type "journalctl -xb" to view
system logs, "systemctl reboot" to reboot, or "exit"
to continue bootup.
Give root password for maintenance
(ou pressione Contrl-D para continuar):                      « digite a senha do ROOT (nada aparece)

A tela mistura inglês e português porque as traduções estão incompletas (o "Contrl-D", com erro de digitação, é da tradução original). O que ela diz:

  • Você está no rescue mode (modo de manutenção).
  • Digite a senha do root para entrar.
  • Ctrl+D desiste e continua o boot normal.
  • Lá dentro: journalctl -xb mostra os logs, systemctl reboot reinicia e exit continua o boot.

Com a senha certa, você ganha um terminal de root:

#> journalctl -xb -p err
#> systemctl reboot
"a conta root está travada" 
Não foi possível abrir acesso ao console, a conta root está travada.
Veja a página man do sulogin(8) para mais detalhes.

Pressione Enter para continuar.

O que aconteceu: na instalação, você deixou a senha do root em branco. Nesse caso o Debian trava a conta root e dá sudo ao primeiro usuário (veja root, su e sudo). Sem senha de root, o modo de recuperação não deixa entrar.

Como resolver: use o init=/bin/bash (mais abaixo) ou o pendrive live. Com o sistema funcionando de novo, considere dar uma senha ao root só para emergências.

Caso 1: o fstab errado impede o boot

Um disco listado no /etc/fstab que não existe mais (UUID errado, HD externo desconectado) faz o systemd esperar 90 segundos e cair no modo de emergência:

[ TIME ] Timed out waiting for device dev-disk-by\x2duuid-aaaa958f\x2d….device - /dev/disk/by-uuid/aaaa958f-…
[DEPEND] Dependency failed for local-fs.target - Local File Systems.
You are in emergency mode. After logging in, type "journalctl -xb" to view
system logs, "systemctl reboot" to reboot, "systemctl default" or "exit"
to boot into default mode.
Give root password for maintenance
(ou pressione Contrl-D para continuar):

As duas primeiras linhas variam conforme o disco (são as típicas do systemd); a parte de baixo é a mensagem real do Debian 13. Para consertar:

  1. Digite a senha do root.
  2. A raiz pode estar só para leitura. Remonte para escrita: mount -o remount,rw /
  3. Descubra a linha culpada com findmnt --verify (veja abaixo).
  4. Edite: nano /etc/fstab. Corrija o UUID (os certos aparecem em blkid) ou comente a linha com #.
  5. Confira de novo, rode systemctl daemon-reload e systemctl reboot.

O findmnt --verify lê o fstab e aponta erros sem montar nada. Esta é a saída real com um UUID de swap inventado:

#> findmnt --verify
none
   [E] fonte não alcançável na inicialização: UUID=aaaa958f-02ec-4d04-9252-01fabc01bb17     « [E] = erro
/media/cdrom0
   [W] não foi possível detectar o tipo de sistema de arquivos em disco (Mídia não encontrada)  « [W] = só aviso

0 erro de análise, 1 erro, 1 aviso

O aviso sobre /media/cdrom0 é normal: o instalador do Debian deixa uma linha para o leitor de CD/DVD, e sem disco no leitor ele não detecta nada.

Prevenção

Para discos que podem não estar presentes (HD externo, pendrive), acrescente nofail às opções no fstab. E sempre rode findmnt --verify depois de editar o arquivo, antes de reiniciar. Veja mount e fstab.

Caso 2: esqueci a senha

Se você esqueceu a senha do root (ou do seu usuário, e não tem sudo), o modo de recuperação não ajuda: ele mesmo pede a senha do root. A saída é pedir ao kernel para iniciar um bash no lugar do systemd.

  1. No menu do GRUB, deixe Debian GNU/Linux selecionado e aperte e.
  2. Ache a linha que começa com linux e termina com ro quiet.
  3. No fim dela, acrescente um espaço e init=/bin/bash.
  4. Aperte Ctrl+X para iniciar.
linux /boot/vmlinuz-6.12.111+deb13-amd64 root=UUID=50185294-cee5-49de-a27c-2cf995361c67 ro quiet init=/bin/bash

Em segundos aparece um prompt de root, sem pedir senha:

#> mount -o remount,rw /
#> passwd root
Nova senha:
Redigite a nova senha:
passwd: senha atualizada com sucesso
#> sync
#> exec /sbin/init
mount -o remount,rw /
A raiz começa só para leitura (ro); sem isso o passwd não consegue gravar.
passwd root
Define a nova senha (troque root por ana para mudar a dela). Nada aparece enquanto você digita.
sync
Grava no disco tudo o que estiver pendente.
exec /sbin/init
Entrega a máquina ao systemd e o boot continua normalmente.
Isso também é um risco de segurança

Qualquer pessoa com acesso físico ao computador pode fazer o mesmo. Por isso, em máquinas sensíveis, use criptografia de disco (LUKS, oferecida no instalador do Debian) e uma senha no GRUB ou no firmware.

Caso 3: nem o GRUB aparece — pendrive live + chroot

Se a tela mostra grub rescue>, ou o computador diz que não há sistema operacional, inicie por um pendrive do Debian Live (por exemplo, debian-live-13.5.0-amd64-gnome.iso). No live, o usuário é user, a senha é live e o sudo funciona.

chroot (de change root) faz um terminal "entrar" no Debian instalado no disco, como se ele tivesse iniciado. Dali você reinstala o GRUB.

  1. Abra um terminal no live e vire root: sudo -i.
  2. Descubra a partição do Debian com lsblk -f (procure a ext4 grande).
  3. Monte e prepare as pastas especiais, entre com chroot e reinstale o GRUB, como abaixo.
#> mount /dev/sda1 /mnt
#> for d in dev proc sys run; do mount --rbind /$d /mnt/$d; done
#> chroot /mnt
#> grub-install /dev/sda
Installing for i386-pc platform.
Installation finished. No error reported.
#> update-grub
#> exit
#> umount -R /mnt
#> reboot
mount /dev/sda1 /mnt
Monta a raiz do Debian instalado em /mnt.
mount --rbind /dev …
Leva /dev, /proc, /sys e /run do live para dentro; sem eles, comandos como o grub-install não enxergam o hardware.
chroot /mnt
A partir daqui, / é o disco do Debian instalado.
grub-install /dev/sda
Grava o GRUB no disco (não na partição: /dev/sda, e não /dev/sda1).

Em computadores com UEFI, monte também a partição EFI antes do chroot (mount /dev/sda1 /mnt/boot/efi, se ela for a primeira) e o grub-install mostra "Installing for x86_64-efi platform." As mensagens do grub-install acima são as típicas.

Verificar o sistema de arquivos: fsck

O fsck (de file system check) procura e corrige erros num sistema de arquivos. Ele precisa que a partição não esteja montada (ou esteja só para leitura). Por isso se usa no pendrive live ou no modo de recuperação. Esta é a saída real numa partição ext4 saudável:

#> fsck.ext4 -f /dev/sdb1
e2fsck 1.47.2 (1-Jan-2025)
Pass 1: Checking inodes, blocks, and sizes
Pass 2: Checking directory structure
Pass 3: Checking directory connectivity
Pass 4: Checking reference counts
Pass 5: Checking group summary information
/dev/sdb1: 12/16384 files (0.0% non-contiguous), 9545/65536 blocks       « sem erros

O e2fsck do Debian não tem tradução: as mensagens são sempre em inglês. Se você rodar numa partição montada, ele avisa:

#> e2fsck -n /dev/sda1
e2fsck 1.47.2 (1-Jan-2025)
Warning!  /dev/sda1 is mounted.
Warning: skipping journal recovery because doing a read-only filesystem check.
OpçãoEfeito
-fForça a verificação mesmo se o disco parece "limpo"
-nSó olha, não corrige nada (seguro em partição montada)
-yResponde "sim" a todas as correções
-pCorrige sozinho só o que é seguro
Atenção

Nunca rode fsck com correção (-y, -p ou sem opções) numa partição montada para escrita: pode destruir dados.

Quando não funciona

Digitei a senha no modo de recuperação e aparece "Login incorreto"

O que aconteceu: ele pede a senha do root, não a sua. Lembre também que o teclado pode estar em inglês nessa hora (os símbolos mudam de lugar).

Com init=/bin/bash, o passwd diz que não pode gravar

O que aconteceu: faltou mount -o remount,rw /.

No chroot, o grub-install reclama de /dev ou de EFI

O que aconteceu: faltaram os mount --rbind, ou, em UEFI, montar a partição EFI em /mnt/boot/efi antes do chroot.

Resumo

  • Recovery mode e modo de emergência do Debian pedem a senha do root.
  • fstab errado: mount -o remount,rw /, findmnt --verify, corrigir, reiniciar.
  • Senha esquecida: init=/bin/bash na linha linux do GRUB.
  • GRUB quebrado: pendrive live + mount --rbind + chroot + grub-install.
  • fsck só em partição desmontada; -n só olha.
