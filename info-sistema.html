Debian Informações do Sistema

"Qual versão do Debian é essa?", "Quanta memória tem?", "Qual é a placa de rede?". Antes de instalar um programa, pedir ajuda num fórum ou relatar um bug, você vai precisar dessas respostas. Nesta aula você vai encontrá-las pelo terminal, sem abrir o computador.

Você vai aprender
  • Descobrir a versão exata do Debian (13, 13.7, trixie) de três jeitos.
  • Ver o kernel, o processador, a memória e os discos.
  • Listar as placas (lspci) e os dispositivos USB (lsusb).
  • Juntar tudo num relatório com inxi.

As saídas desta aula foram tiradas de um Debian 13.7 real, rodando numa máquina virtual (VirtualBox). Por isso aparecem palavras como "VirtualBox" e "oracle"; num notebook de verdade você verá o fabricante e o modelo dele.

As mensagens "Access denied" aparecem porque a ana não é root: alguns dados de hardware (número de série, UUID do produto) só o root pode ler. Como root, elas somem.

Versão do Debian

O Debian tem um número (13), um número de revisão (13.7) e um codinome (trixie, um personagem de Toy Story). Veja Versões do Debian. Três formas de descobrir:

/etc/debian_version: a revisão exata

$ cat /etc/debian_version
13.7

É o único lugar que mostra a revisão (o ".7"). Cada revisão (point release) junta as correções de segurança e de bugs publicadas desde a anterior.

/etc/os-release: para pessoas e scripts

$ cat /etc/os-release
PRETTY_NAME="Debian GNU/Linux 13 (trixie)"
NAME="Debian GNU/Linux"
VERSION_ID="13"
VERSION="13 (trixie)"
VERSION_CODENAME=trixie                     « o codinome, usado no sources.list
DEBIAN_VERSION_FULL=13.7
ID=debian
HOME_URL="https://www.debian.org/"
SUPPORT_URL="https://www.debian.org/support"
BUG_REPORT_URL="https://bugs.debian.org/"

lsb_release

$ lsb_release -a
Distributor ID:	Debian
Description:	Debian GNU/Linux 13 (trixie)
Release:	13
Codename:	trixie
Em scripts

Use o /etc/os-release, que existe em qualquer distribuição moderna: . /etc/os-release; echo $VERSION_CODENAME imprime trixie.

Memória: free

$ free -h
               total       usada       livre    compart.  buff/cache  disponível
Mem.:          3,8Gi       475Mi       3,0Gi       9,1Mi       631Mi       3,4Gi
Swap:          1,3Gi          0B       1,3Gi

O número que importa é disponível: quanto ainda cabe para programas novos. O buff/cache é memória usada como cache de disco, que o sistema libera quando alguém precisa. Mais em Desempenho e Monitoramento.

Discos: lsblk e df

$ lsblk
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sda      8:0    0   25G  0 disk                     « o disco inteiro
├─sda1   8:1    0 23,7G  0 part /                   « a raiz
├─sda2   8:2    0    1K  0 part                     « partição "estendida": só um contêiner
└─sda5   8:5    0  1,3G  0 part [SWAP]              « a swap, dentro da estendida
sr0     11:0    1 1024M  1 rom                      « o leitor de CD/DVD

Esse é o particionamento clássico do instalador do Debian em computadores com BIOS (tabela MBR): uma partição primária para tudo e a swap numa partição lógica, que começa no número 5. Por isso não existe sda3 nem sda4.

$ df -h /
Sist. Arq.      Tam. Usado Disp. Uso% Montado em
/dev/sda1        24G  1,3G   21G   6% /

Para ver também o tipo e o UUID de cada partição, use lsblk -f. Veja lsblk, df, du.

O lspci lista tudo o que está ligado ao barramento PCI: vídeo, rede, som, controladora de disco. Ele vem instalado:

00:03.0 Ethernet controller: Intel Corporation 82540EM Gigabit Ethernet Controller (rev 02)   « rede
00:04.0 System peripheral: InnoTek Systemberatung GmbH VirtualBox Guest Service

Para saber qual driver (módulo do kernel) cada placa usa, acrescente -k: lspci -k. Isso é útil quando o Wi-Fi ou o vídeo não funcionam.

Já o lsusb não vem instalado no Debian mínimo:

$ lsusb
bash: lsusb: comando não encontrado

Ele está no pacote usbutils: como root, apt install usbutils.

#> apt install usbutils
#> exit
$ lsusb
$ echo $?
1                                    « nada: esta máquina virtual não tem controladora USB

Na máquina virtual usada nesta aula não há USB, por isso nada aparece. Num notebook de verdade, cada linha é um dispositivo (exemplo ilustrativo):

$ lsusb
Bus 001 Device 001: ID 1d6b:0002 Linux Foundation 2.0 root hub
Bus 001 Device 003: ID 046d:c52b Logitech, Inc. Unifying Receiver      « o receptor do mouse
Bus 002 Device 001: ID 1d6b:0003 Linux Foundation 3.0 root hub

O ID 046d:c52b identifica o fabricante (046d = Logitech) e o produto; é o que você pesquisa quando um dispositivo não funciona.

Cuidado: o inxi puxa muitos pacotes

No Debian, apt install inxi instala também as "recomendações" dele: dezenas de pacotes (ferramentas de vídeo, Mesa, GTK…). Num servidor pequeno, prefira apt install --no-install-recommends inxi.

Quando não funciona

"lsusb: comando não encontrado" (ou inxi, lshw, sensors)

O que aconteceu: a instalação mínima do Debian traz pouca coisa. Não existe o command-not-found, que no Ubuntu sugere o pacote.

Como descobrir o pacote: apt search lsusb, ou instale o apt-file (como root: apt install apt-file && apt-file update) e rode apt-file search bin/lsusb.

hostnamectl mostra "Access denied"

O que aconteceu: alguns dados do firmware só o root lê. Não é erro. Como root (su -), aparecem também o número de série e o UUID.

Resumo

  • hostnamectl é o resumo; /etc/debian_version dá a revisão exata.
  • uname -r, lscpu, free -h, lsblk e lspci vêm instalados.
  • lsusb (usbutils) e inxi precisam ser instalados como root.
  • Numa máquina virtual, o hardware mostrado é o virtual.
