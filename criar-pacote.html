Debian Criar um Pacote .deb

Todo programa que o apt instala chega num arquivo .deb. Você também pode criar o seu: um script que a equipe toda usa, uma configuração padrão, uma ferramenta interna. Empacotado, ele instala, atualiza e remove com os mesmos comandos de qualquer outro programa, e o sistema sabe exatamente quais arquivos são dele.

Você vai aprender
  • O que existe dentro de um .deb.
  • Montar um pacote à mão: a pasta, o arquivo DEBIAN/control e o dpkg-deb --build.
  • Inspecionar, instalar, conferir e remover o pacote.
  • Revisar o pacote com o lintian.
  • Quando sair do "à mão" e usar o caminho oficial do Debian (debhelper, dpkg-buildpackage).

Pré-requisitos: dpkg e .deb e chmod. As saídas abaixo vêm de um Debian 13 real.

Conceito: um .deb é uma "caixa" com duas partes

ParteO que temExemplo
DadosOs arquivos que vão para o sistema, com os caminhos finais/usr/bin/ola
ControleInformações sobre o pacote: nome, versão, dependências, descrição e scripts de instalaçãoPackage: ola

Para criar os dois, você monta uma pasta que imita a raiz do sistema (/) e acrescenta uma subpasta especial chamada DEBIAN com a parte de controle. O dpkg-deb transforma a pasta em .deb.

Passo 1: o programa

Nosso exemplo é um script de uma linha, o ola. Ele vai morar em /usr/bin, então dentro da pasta do pacote ele fica em usr/bin/ola:

$ mkdir -p ~/pacote/ola_1.0-1_all/DEBIAN ~/pacote/ola_1.0-1_all/usr/bin
$ cd ~/pacote
$ nano ola_1.0-1_all/usr/bin/ola
#!/bin/sh
echo "Olá, ${1:-mundo}! Hoje é $(date +%d/%m/%Y)."
$ chmod 755 ola_1.0-1_all/usr/bin/ola
$ chmod 755 ola_1.0-1_all ola_1.0-1_all/usr ola_1.0-1_all/usr/bin   « pastas com 755 (o umask 0002 da ana criaria 775)

O nome da pasta segue a convenção do Debian, nome_versão_arquitetura. Não é obrigatório, mas ajuda.

Passo 2: o arquivo DEBIAN/control

É a "etiqueta" do pacote. Cada linha é Campo: valor.

Package: ola
Version: 1.0-1
Architecture: all
Maintainer: Ana <ana@example.com>
Description: diz olá no terminal
 Um script de exemplo do Guia Debian, empacotado à mão.
Package: ola
O nome do pacote: letras minúsculas, números e + - .. É o que você usa em apt remove ola.
Version: 1.0-1
A versão: 1.0 é a do programa e -1 é a revisão do pacote. Precisa começar com um número.
Architecture: all
all = roda em qualquer processador (scripts). Programas compilados usam amd64, arm64…
Maintainer
Quem cuida do pacote, com e-mail.
Description
A primeira linha é o resumo curto. As linhas seguintes, que começam com um espaço, são a descrição longa.

Outros campos comuns:

CampoPara quêExemplo
DependsPacotes que precisam estar instaladosDepends: curl, jq (>= 1.6)
RecommendsInstalados junto por padrão, mas não obrigatóriosRecommends: bash-completion
SectionCategoriaSection: utils
PriorityImportânciaPriority: optional
HomepageSite do projetoHomepage: https://exemplo.com

Passo 3: construir com dpkg-deb

dpkg-deb
A ferramenta que monta e desmonta arquivos .deb. Já vem no Debian.
--build
Constrói um pacote a partir de uma pasta.
--root-owner-group
Grava os arquivos como pertencentes ao root, mesmo que você tenha montado a pasta como ana. É o certo para arquivos que vão para /usr.
ola_1.0-1_all
A pasta.
$ find ola_1.0-1_all
ola_1.0-1_all
ola_1.0-1_all/DEBIAN
ola_1.0-1_all/DEBIAN/control
ola_1.0-1_all/usr
ola_1.0-1_all/usr/bin
ola_1.0-1_all/usr/bin/ola
$ dpkg-deb --build --root-owner-group ola_1.0-1_all
dpkg-deb: construindo o pacote 'ola' em 'ola_1.0-1_all.deb'.
$ ls -l *.deb
-rw-r--r-- 1 ana ana 816 out 15 21:31 ola_1.0-1_all.deb          « 816 bytes

O que acontece sem o --root-owner-group

$ dpkg-deb --build ola_1.0-1_all
dpkg-deb: aviso: diretório raiz ola_1.0-1_all tem proprietário ou grupo incomum 1000:1000
dpkg-deb: dica: talvez você precise passar --root-owner-group, veja <https://wiki.debian.org/Teams/Dpkg/RootlessBuilds> para mais detalhes
dpkg-deb: aviso: ignorando 1 aviso sobre o(s) arquivo(s) de controle
dpkg-deb: construindo o pacote 'ola' em 'ola_1.0-1_all.deb'.

O pacote é criado, mas os arquivos ficariam com o dono 1000 (a ana). Use sempre a opção.

--info mostra a etiqueta e --contents mostra os arquivos, como o tar -tvf. Faça isso com qualquer .deb baixado da internet antes de instalar.

Passo 5: instalar, usar e remover

Instalar mexe no sistema, então precisa de root (veja root, su e sudo).

$ su -
Senha:
#> apt install /home/ana/pacote/ola_1.0-1_all.deb
…
Instalando:
  ola

Resumo:
  Atualizando: 0, Instalando: 1, Removendo: 0, Não atualizando: 0
  Tamanho de download: 0 B / 816 B
  Espaço necessário: 0 B / 18,1 GB disponível
…
Desempacotando ola (1.0-1) ...
Configurando ola (1.0-1) ...
Nota: O download é executado sem isolamento e como root, pois o arquivo '/home/ana/pacote/ola_1.0-1_all.deb' não pôde ser acessado pelo usuário '_apt'. - pkgAcquire::Run (13: Permissão negada)
#> exit

A "Nota" do fim é inofensiva. O apt prefere ler os arquivos com um usuário sem poderes, o _apt, mas a pasta pessoal da ana tem permissão 700 e ele não entra. Para evitar o aviso, copie o .deb para /tmp antes de instalar.

De volta como ana, o comando novo funciona e o sistema sabe que ele pertence ao pacote:

$ ola Ana
Olá, Ana! Hoje é 15/10/2026.
$ dpkg -l ola | tail -1
ii  ola            1.0-1        all          diz olá no terminal     « ii = instalado
$ dpkg -L ola
/.
/usr
/usr/bin
/usr/bin/ola

E para remover:

#> apt remove ola
REMOVENDO:
  ola

Resumo:
  Atualizando: 0, Instalando: 0, Removendo: 1, Não atualizando: 0
  Espaço necessário: 0 B / 18,1 GB disponível

Removendo ola (1.0-1) ...

Repare que o apt trata o seu pacote como qualquer outro: ele aparece no dpkg -l, o dpkg -L lista os arquivos, e o apt remove apaga exatamente o que ele instalou.

apt install ./arquivo.deb ou dpkg -i?

Prefira apt install ./ola_1.0-1_all.deb (com o ./): ele instala também as dependências do campo Depends. O dpkg -i só instala o arquivo e reclama se faltar algo.

Passo 6: revisar com o lintian

O lintian confere o pacote contra as regras do Debian e aponta problemas. Cada aviso tem uma letra: E (erro), W (aviso), I (informação).

$ lintian ola_1.0-1_all.deb
E: ola: no-changelog usr/share/doc/ola/changelog.Debian.gz (non-native package)
E: ola: no-copyright-file
W: ola: no-manual-page [usr/bin/ola]
W: ola: recommended-field ola_1.0-1_all.deb Priority
W: ola: recommended-field ola_1.0-1_all.deb Section
$ echo $?
2
AvisoO que pede
no-changelogUm histórico de mudanças em /usr/share/doc/ola/changelog.Debian.gz
no-copyright-fileA licença em /usr/share/doc/ola/copyright
no-manual-pageUm man ola (página de manual)
recommended-field … Priority/SectionOs campos Priority: e Section: no control
"wrong-file-owner-uid-or-gid" e "non-standard-dir-perm" 
$ lintian ola_1.0-1_all.deb
…
E: ola: wrong-file-owner-uid-or-gid 1000/1000 [usr/bin/ola]
W: ola: non-standard-dir-perm 0775 != 0755 [usr/bin/]

O que aconteceu: o pacote foi construído sem --root-owner-group (dono 1000 = ana), e as pastas ficaram com 0775 porque o umask da ana no Debian é 0002.

Como resolver: chmod 755 nas pastas do pacote e construa com --root-owner-group.

Para um pacote interno, alguns avisos são aceitáveis. Para mandar algo para o Debian oficial, o pacote precisa estar limpo.

Scripts de instalação: postinst e companhia

Dentro de DEBIAN/ podem existir scripts que o dpkg roda em momentos certos:

ArquivoQuando rodaUso típico
preinstAntes de copiar os arquivosParar um serviço antigo
postinstDepois de copiarCriar usuário, ativar serviço
prermAntes de removerParar o serviço
postrmDepois de removerLimpar dados (no purge)
conffiles(lista) arquivos de configuraçãoArquivos em /etc que o apt não sobrescreve sem perguntar

Os scripts precisam ter permissão 755 e começar com #!/bin/sh.

Formas diferentes de criar um .deb

FormaComoMelhor quando…
À mão (esta aula)Pasta + DEBIAN/control + dpkg-deb --buildScripts e arquivos internos da sua equipe
Oficial do DebianPasta debian/ no código-fonte + dh (debhelper) + dpkg-buildpackage ou debuildProgramas com código-fonte, pacotes para o Debian, repositórios sérios
Começar pelo oficialdh_make cria os arquivos de debian/ de modeloPrimeiro contato com o empacotamento oficial
Ferramentas externasfpm, nfpm, checkinstallGerar .deb e .rpm a partir do mesmo projeto

Uma olhada no caminho oficial

No empacotamento oficial, você não monta a pasta final: descreve como compilar e instalar o programa, e as ferramentas fazem o resto. Os arquivos mínimos em debian/:

ArquivoO que é
debian/controlPacote-fonte e pacotes binários (parecido com o DEBIAN/control)
debian/changelogHistórico de versões, num formato rígido (use o dch)
debian/rulesUm Makefile; com debhelper, quase sempre só %: dh $@
debian/copyrightLicenças
debian/source/formatNormalmente 3.0 (quilt)

Depois, dpkg-buildpackage -us -uc (pacotes dpkg-dev e debhelper) gera o .deb. O guia oficial é o Guide for Debian Maintainers.

Quando não funciona

"número da versão não começa com dígito" 
$ dpkg-deb --build --root-owner-group ola_1.0-1_all
dpkg-deb: erro: processando arquivo 'ola_1.0-1_all/DEBIAN/control' próximo à linha 2 do pacote 'ola':
 o valor do campo 'Version' 'um': número da versão não começa com dígito

O que aconteceu: o campo Version tem texto (um). Como resolver: use números: 1.0-1.

"campo 'Description' faltando" 
$ dpkg-deb --build --root-owner-group ola_1.0-1_all
dpkg-deb: aviso: processando arquivo 'ola_1.0-1_all/DEBIAN/control' próximo à linha 5 do pacote 'ola':
 campo 'Description' faltando
dpkg-deb: aviso: ignorando 1 aviso sobre o(s) arquivo(s) de controle
dpkg-deb: construindo o pacote 'ola' em 'ola_1.0-1_all.deb'.

É só um aviso: o pacote sai, mas incompleto. Acrescente a descrição.

"diretório de controle possui permissões ruins" 
$ dpkg-deb --build --root-owner-group ola_1.0-1_all
dpkg-deb: erro: diretório de controle possui permissões ruins 777 (devem ser >=0755 e <=0755)

Como resolver: chmod 755 ola_1.0-1_all/DEBIAN. Isso acontece muito quando a pasta foi copiada de um pendrive ou de outro sistema.

Instalou, mas o comando "não existe"

O que aconteceu: o arquivo foi para o lugar errado (por exemplo, ola_1.0-1_all/ola em vez de ola_1.0-1_all/usr/bin/ola) ou não tem permissão de execução.

Como confirmar: dpkg -L ola mostra para onde os arquivos foram. Como resolver: corrija a pasta, aumente a revisão (1.0-2) e construa de novo.

Resumo

  • Um .deb = arquivos com os caminhos finais + a pasta DEBIAN com o control.
  • dpkg-deb --build --root-owner-group pasta cria o pacote.
  • --info e --contents mostram o que tem dentro, antes de instalar.
  • apt install ./arquivo.deb instala com dependências; apt remove desfaz.
  • O lintian revisa; para projetos sérios, use debhelper e dpkg-buildpackage.
