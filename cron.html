Debian cron

O cron executa comandos sozinho, em horários marcados: "todo dia às 2h, faça backup", "a cada 5 minutos, confira o disco". O nome vem do grego chronos, "tempo". Você escreve a agenda num arquivo chamado crontab (cron table, "tabela do cron").

Você vai aprender
  • Como ler e escrever uma linha do crontab, campo por campo.
  • Os comandos crontab -e, -l e -r (e por que o -r é perigoso).
  • Onde ver se a tarefa rodou: no Debian, pelo journalctl, porque não há /var/log/syslog.
  • Por que um script que funciona no terminal pode falhar no cron, e como resolver.

Antes, leia Primeiro Script. Os exemplos rodam na máquina fictícia notebook, com a usuária ana, e foram conferidos num Debian 13.

Como o cron funciona

O cron é um serviço: um programa que fica rodando em segundo plano desde que o computador liga. A cada minuto, ele acorda, olha as agendas de todos os usuários e executa o que estiver marcado para aquele minuto. No Debian ele já vem instalado e ligado, inclusive na instalação mínima de servidor:

$ systemctl is-active cron
active

Cada usuário tem a sua agenda. As tarefas da ana rodam como a ana, com as permissões dela. Tarefas do sistema ficam em arquivos separados, que você verá mais abaixo.

Ver e editar a sua agenda

crontab -l: listar

O -l (de list) mostra a sua agenda. Na primeira vez, ela não existe:

$ crontab -l
no crontab for ana

crontab -e: editar

O -e (de edit) abre a agenda num editor de texto. Como a variável EDITOR vem vazia no Debian, na primeira vez ele pergunta qual editor usar:

$ crontab -e
no crontab for ana - using an empty one

Select an editor.  To change later, run select-editor again.
  1. /bin/nano        <---- easiest
  2. /usr/bin/vim.tiny

Choose 1-2 [1]: 1                                   « Enter ou 1 escolhe o nano

Num Debian recém-instalado só aparecem esses dois, porque são os únicos editores instalados. A escolha fica gravada em ~/.selected_editor; para mudar depois, rode select-editor. Escolha o nano, o mais fácil (veja nano e vim).

O arquivo abre com um texto explicativo, todo em linhas que começam com # (comentários). Vá até o fim, escreva sua tarefa, salve com Ctrl+O, Enter e saia com Ctrl+X. Se estiver tudo certo, o cron confirma:

$ crontab -e
crontab: installing new crontab                     « a agenda foi gravada
$ crontab -l
# m h  dom mon dow   command
30 2 * * * /home/ana/bin/backup.sh

As mensagens do crontab são em inglês, mesmo com o sistema em português. Se você sair sem mudar nada, ele avisa No modification made.

Não edite o arquivo da agenda diretamente

As agendas ficam em /var/spool/cron/crontabs/, mas não mexa lá: use sempre crontab -e. Ele confere se as linhas estão certas antes de gravar.

Anatomia de uma linha do crontab

Cada linha é uma tarefa: cinco campos de tempo, separados por espaço, e depois o comando. Este desenho é o mesmo que aparece nos comentários do /etc/crontab do Debian:

.---------------- minuto        (0 - 59)
|  .------------- hora          (0 - 23)
|  |  .---------- dia do mês    (1 - 31)
|  |  |  .------- mês           (1 - 12 ou jan, feb, mar…)
|  |  |  |  .---- dia da semana (0 - 6: 0 = domingo, 1 = segunda… ou sun, mon…; 7 também é domingo)
|  |  |  |  |
*  *  *  *  *  comando a executar
30
Minuto: aos 30 minutos.
2
Hora: das 2h. Junto com o minuto: 2h30.
*
Dia do mês: qualquer um. O asterisco significa "todos".
*
Mês: qualquer um.
1-5
Dia da semana: de segunda (1) a sexta (5).
/home/ana/bin/backup.sh
O comando, de preferência com caminho completo.

Lendo tudo junto: "às 2h30, de segunda a sexta, rode o backup".

Dia do mês e dia da semana juntos: é "OU"

0 9 13 * 5 não é "sexta-feira 13". Quando os dois campos de dia têm valores, o cron roda se qualquer um bater: todo dia 13 e também toda sexta.

Confira antes de gravar

O site crontab.guru traduz uma linha do cron para inglês ("At 02:30 on every day-of-week from Monday through Friday"). É ótimo para conferir.

Exemplo completo: backup todo dia às 2h

  1. Tenha um script que funciona. Teste no terminal primeiro: 
    #!/usr/bin/env bash
destino="/home/ana/backups/docs-$(date +%F).tar.gz"
mkdir -p /home/ana/backups
tar -czf "$destino" -C /home/ana Documentos
echo "$(date '+%F %T') backup criado: $destino"
    $ chmod +x ~/bin/backup.sh
$ ~/bin/backup.sh
2026-10-15 10:30:00 backup criado: /home/ana/backups/docs-2026-10-15.tar.gz
  2. Abra a agenda com crontab -e e acrescente no fim: 
    0 2 * * * /home/ana/bin/backup.sh >> /home/ana/backup.log 2>&1
    0 2 * * *
    Todo dia às 2h00.
    /home/ana/bin/backup.sh
    O script, com caminho completo.
    >> /home/ana/backup.log
    Acrescenta o que o script escreve num arquivo de log.
    2>&1
    Manda também as mensagens de erro para o mesmo log.
  3. No dia seguinte, confira o log: 
    $ cat ~/backup.log
2026-10-16 02:00:01 backup criado: /home/ana/backups/docs-2026-10-16.tar.gz
  4. Confira o registro do sistema. O Debian 13 não instala o rsyslog, então não existe /var/log/syslog. Os registros do cron ficam no journal do systemd. A usuária comum só vê os próprios registros, e os do cron são do sistema; por isso, consulte como root: 
    $ ls /var/log/syslog
ls: não foi possível acessar '/var/log/syslog': Arquivo ou diretório inexistente
$ journalctl -u cron
Hint: You are currently not seeing messages from other users and the system.
      Users in groups 'adm', 'systemd-journal' can see all messages.
      Pass -q to turn off this notice.
-- No entries --
$ su -c "journalctl -u cron --since today"
Senha:
out 16 02:00:01 notebook CRON[8245]: pam_unix(cron:session): session opened for user ana(uid=1000) by ana(uid=0)
out 16 02:00:01 notebook CRON[8247]: (ana) CMD (/home/ana/bin/backup.sh >> /home/ana/backup.log 2>&1)
out 16 02:00:01 notebook CRON[8245]: pam_unix(cron:session): session closed for user ana

    A linha (ana) CMD (…) prova que o cron tentou rodar o comando. Se o comando falhou, o motivo estará no seu backup.log. Por isso o redirecionamento é tão importante. Para ler o journal sem virar root, o root pode pôr a ana no grupo adm (veja Usuários e Grupos e journalctl).

Teste com "a cada minuto"

Para não esperar até as 2h, comece com * * * * *, confira o log após um ou dois minutos e só então troque pelo horário real.

O ambiente do cron é diferente do seu terminal

Esta é a causa número 1 de "funciona no terminal, mas não no cron". O cron roda seus comandos num ambiente mínimo. Este é o ambiente real de uma tarefa da ana no Debian 13 (capturado com env > /tmp/cronenv dentro do cron):

$ cat /tmp/cronenv
LANGUAGE=pt_BR:pt:en
HOME=/home/ana
LOGNAME=ana
PATH=/usr/bin:/bin                                  « só duas pastas
LANG=pt_BR.UTF-8                                    « o idioma vem do sistema
SHELL=/bin/sh                                       « não é o bash
PWD=/home/ana
ItemNo seu terminalNo cron
Shellbash/bin/sh (o dash, mais simples)
PATHVárias pastas, incluindo ~/.local/bin se existirSó /usr/bin:/bin
Pasta atualOnde você estiverA sua pasta pessoal
~/.bashrc, aliasesCarregadosNão são carregados
Idiomapt_BR.UTF-8pt_BR.UTF-8 também (o Debian lê /etc/default/locale)
Saída do comandoAparece na telaSome, a não ser que você redirecione

Você pode definir variáveis no topo do crontab, e elas valem para as linhas de baixo:

PATH=/home/ana/.local/bin:/usr/local/bin:/usr/bin:/bin
SHELL=/bin/bash
0 2 * * * /home/ana/bin/backup.sh >> /home/ana/backup.log 2>&1
Nas variáveis, escreva o caminho inteiro

O cron copia o valor das variáveis ao pé da letra: PATH=~/bin:$PATH fica literalmente com ~ e $PATH, sem expandir (é o que diz o man 5 crontab). Já na linha do comando o ~ funciona, porque quem a executa é o /bin/sh.

O sinal % é especial no crontab

Na linha do comando, o cron troca % por uma quebra de linha. date +%F direto no crontab quebra o comando. Escreva \% (date +\%F) ou, melhor, coloque o comando dentro de um script.

Formas diferentes de agendar

FormaOndeMelhor quando…

Nos arquivos de sistema, a linha tem o usuário entre o horário e o comando. Este é um trecho real do /etc/crontab do Debian:

$ grep cron.daily /etc/crontab
25 6	* * *	root	test -x /usr/sbin/anacron || { cd / && run-parts --report /etc/cron.daily; }
Servidor desligado de madrugada? Conheça o anacron

A linha acima diz: "às 6h25, se o anacron não estiver instalado, rode os scripts de /etc/cron.daily". Numa instalação de servidor do Debian, o anacron não vem instalado, então quem roda as tarefas diárias é o próprio cron, às 6h25; se a máquina estiver desligada nessa hora, a tarefa é pulada. Nos ambientes de desktop, o anacron vem junto (recomendado pelo pacote task-desktop) e roda depois o que foi perdido com o computador desligado. Para ter isso num servidor: apt install anacron.

Numa instalação nova, /etc/cron.daily já tem tarefas do próprio Debian:

$ ls /etc/cron.daily
apt-compat  dpkg  logrotate  man-db

Apagar a agenda: cuidado com o -r

crontab -r apaga tudo, sem perguntar

O r fica ao lado do e no teclado. Um erro de digitação e todas as suas tarefas somem. Antes de mexer, faça uma cópia:

$ crontab -l > ~/crontab-backup.txt
$ crontab -r
$ crontab -l
no crontab for ana                                  « a agenda inteira sumiu
$ crontab ~/crontab-backup.txt
$ crontab -l
# m h  dom mon dow   command
0 2 * * * /home/ana/bin/backup.sh >> /home/ana/backup.log 2>&1

Na sessão acima: a primeira linha guarda uma cópia, o -r apaga tudo e crontab ~/crontab-backup.txt restaura a cópia. Para apagar com confirmação, use crontab -ri. Para remover só uma tarefa, use crontab -e e apague a linha.

Quando não funciona: "meu cron não roda"

Siga estes passos na ordem. Quase sempre o problema aparece até o passo 4.

  1. O cron está ligado? 
    $ systemctl is-active cron
active
  2. A linha está na agenda certa? Uma tarefa que precisa de root não roda na agenda da ana, e vice-versa. 
    $ crontab -l
# m h  dom mon dow   command
0 2 * * * /home/ana/bin/backup.sh >> /home/ana/backup.log 2>&1
$ su -c "crontab -l"
Senha:
no crontab for root                                 « a agenda do root é outra
  3. O cron tentou executar? Procure a linha no journal, como root: 
    $ su -c "journalctl -u cron --since today | grep ana"
Senha:

    Se não houver nenhuma linha (ana) CMD, o horário está errado ou a linha tem erro.

  4. O comando falhou? Sem redirecionamento, a mensagem de erro se perde. Acrescente >> /home/ana/cron.log 2>&1 e espere a próxima execução. Estes erros foram capturados de verdade num cron do Debian:
    Mensagem no logCausaSolução
    /bin/sh: 1: node: not foundO programa está fora do PATH do cronUse o caminho completo (which node mostra) ou defina PATH= no topo
    /bin/sh: 1: /home/ana/bin/backup.sh: Permission deniedScript sem permissão de execuçãochmod +x ~/bin/backup.sh
    /bin/sh: 1: /home/ana/bin/nada.sh: not foundO caminho do script está errado (o ~ funciona, mas o arquivo não existe)Confira o caminho com ls
    tar: Documentos: Função stat falhou: Arquivo ou diretório inexistenteO script supõe estar em outra pastaUse caminhos absolutos dentro do script

    Repare: as mensagens do /bin/sh (o dash) ficam em inglês, mas as do tar saem em português, porque o cron do Debian recebe o idioma do sistema.

  5. Teste no mesmo ambiente do cron. Este comando roda o script com o ambiente mínimo do cron, e mostra o erro na hora: 
    $ env -i HOME=/home/ana PATH=/usr/bin:/bin LANG=pt_BR.UTF-8 /bin/sh -c '/home/ana/bin/backup.sh'
"bad minute" ao salvar 
$ crontab -e
"/tmp/crontab.Hk2v1Q/crontab":23: bad minute
errors in crontab file, can't install.
Do you want to retry the same edit? (y/n)

O que aconteceu: o minuto está fora do intervalo 0–59 (por exemplo, 60) ou com um símbolo inválido. O número depois dos dois pontos é a linha com problema.

Como resolver: responda y para voltar ao editor e corrigir. Variações: bad hour, bad day-of-month, bad month, bad day-of-week.

"crontab: comando não encontrado"? Não no Debian

Ao contrário do rsync, o cron faz parte da instalação padrão do Debian, inclusive em servidores mínimos. Se o comando sumiu, alguém removeu o pacote: su -c "apt install cron".

Resumo

  • Cinco campos de tempo (minuto, hora, dia, mês, dia da semana) + o comando.
  • crontab -e edita (na primeira vez, pergunta o editor), -l lista, -r apaga tudo.
  • Redirecione a saída (>> log 2>&1) e use caminhos completos.
  • O cron usa /bin/sh e PATH /usr/bin:/bin; no Debian, recebe o idioma do sistema.
  • Sem syslog no Debian 13: veja as execuções com journalctl -u cron, como root.
