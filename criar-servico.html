Debian Criar um Serviço

Você tem um script que precisa rodar o tempo todo: um bot, um monitor, um pequeno servidor. Rodá-lo com & ou nohup funciona até a máquina reiniciar ou o script travar. A forma certa no Debian é transformá-lo num serviço do systemd, que liga no boot, guarda os logs e reinicia sozinho se cair.

Você vai aprender
  • Como o systemd lê um arquivo .service, seção por seção.
  • Criar, ligar e conferir um serviço de verdade, passo a passo.
  • Testar o reinício automático matando o processo.
  • Agendar o serviço com um .timer (a alternativa moderna ao cron).
  • Ler os erros mais comuns: 203/EXEC, "changed on disk" e "Start request repeated too quickly".
Antes de começar

Tudo aqui é feito como root, porque cria arquivos em /etc e /usr/local. No Debian sem sudo, entre com su - (veja root, su e sudo). Os prompts root@notebook:~# abaixo indicam isso. Os exemplos foram rodados num Debian 13 de verdade.

Antes do comando: como o systemd lê um serviço

Um serviço é um arquivo de texto com três seções entre colchetes. O systemd lê esse arquivo e sabe: o que rodar, quando, como quem e o que fazer se cair.

SeçãoRespondeExemplos de opções
[Unit]O que é e depois de quem ligaDescription, After, Wants
[Service]O que rodar e comoExecStart, User, Restart
[Install]Em que estágio do boot entra quando você dá enableWantedBy

Os serviços que você cria ficam em /etc/systemd/system/. Os que vêm dos pacotes ficam em /usr/lib/systemd/system/; não mexa neles.

Passo a passo: o serviço "teste-guia"

Vamos criar um serviço que escreve uma mensagem no log a cada 10 segundos. É simples de propósito: o importante é o caminho.

  1. Criar o script. Programas locais, que não vêm de pacotes, vão em /usr/local/bin. 
    #> nano /usr/local/bin/teste-guia.sh
    #!/usr/bin/env bash
# Registra uma mensagem a cada 10 segundos
while true; do
  echo "teste-guia: tudo certo às $(date +%H:%M:%S)"
  sleep 10
done

    O echo não precisa escrever em arquivo nenhum: tudo o que um serviço imprime vai automaticamente para o journal, o log do systemd.

    #> chmod 755 /usr/local/bin/teste-guia.sh       « o serviço precisa poder executar o script
  2. Criar o arquivo do serviço. 
    #> nano /etc/systemd/system/teste-guia.service
    [Unit]
# Nome amigável, aparece no status e nos logs
Description=Serviço de teste do Guia Debian
# Só liga depois que a rede estiver pronta
After=network-online.target
Wants=network-online.target

[Service]
# Simple: o programa fica rodando em primeiro plano
Type=simple
# O comando, sempre com caminho completo
ExecStart=/usr/local/bin/teste-guia.sh
# Se cair com erro, reinicia
Restart=on-failure
# ...esperando 5 segundos antes
RestartSec=5
# Roda como a ana, não como root (mais seguro)
User=ana

[Install]
# Entra no boot normal (modo multiusuário)
WantedBy=multi-user.target
  3. Avisar o systemd que existe um arquivo novo. 
    #> systemctl daemon-reload
  4. Ligar agora e no boot.
    systemctl
    O programa.
    enable
    Liga no boot (cria o link em multi-user.target.wants).
    --now
    E também liga agora.
    teste-guia
    O nome do arquivo, sem o .service.
    #> systemctl enable --now teste-guia
Created symlink '/etc/systemd/system/multi-user.target.wants/teste-guia.service' → '/etc/systemd/system/teste-guia.service'.
  5. Conferir. 
    #> systemctl status teste-guia

Teste: mate o processo e veja o systemd reiniciar

A grande vantagem de um serviço é o Restart=on-failure. Vamos provar que funciona. Primeiro, pegue o PID principal:

#> systemctl show -p MainPID --value teste-guia
7107
#> kill -9 7107                                     « o -9 (SIGKILL) "mata na marra", como um travamento
#> systemctl status teste-guia
● teste-guia.service - Serviço de teste do Guia Debian
     Loaded: loaded (/etc/systemd/system/teste-guia.service; enabled; preset: enabled)
     Active: activating (auto-restart) (Result: signal) since Thu 2026-10-15 21:09:12 -03; 1s ago   « esperando os 5 s
    Process: 7107 ExecStart=/usr/local/bin/teste-guia.sh (code=killed, signal=KILL)

E se eu parar com systemctl stop?

Aí ele não volta. O on-failure só reinicia quando o serviço cai sozinho (erro, sinal, travamento). Parar de propósito é respeitado: o status fica inactive (dead).

Parar e remover o serviço

#> systemctl disable --now teste-guia
Removed '/etc/systemd/system/multi-user.target.wants/teste-guia.service'.
#> rm /etc/systemd/system/teste-guia.service /usr/local/bin/teste-guia.sh
#> systemctl daemon-reload
#> systemctl status teste-guia
Unit teste-guia.service could not be found.         « sumiu de verdade

Agendar com um timer

Para rodar algo de tempos em tempos (um backup, uma limpeza), o systemd tem os timers. Um .timer com o mesmo nome do .service liga esse serviço no horário marcado. Nesse caso, o serviço deve fazer a tarefa e terminar, sem laço infinito.

[Unit]
Description=Roda o teste-guia todo dia às 3h

[Timer]
# Todo dia, às 03:00
OnCalendar=*-*-* 03:00:00
# Se a máquina estava desligada às 3h, roda assim que ligar
Persistent=true

[Install]
WantedBy=timers.target
#> systemctl daemon-reload
#> systemctl enable --now teste-guia.timer
Created symlink '/etc/systemd/system/timers.target.wants/teste-guia.timer' → '/etc/systemd/system/teste-guia.timer'.
#> systemctl list-timers teste-guia.timer
NEXT                            LEFT LAST PASSED UNIT             ACTIVATES
Fri 2026-10-16 03:00:00 -03 5h 50min -         - teste-guia.timer teste-guia.service

1 timers listed.

Não tem certeza se escreveu o horário certo? O systemd-analyze confere para você:

$ systemd-analyze calendar "*-*-* 03:00:00"

Quando não funciona

status=203/EXEC: o programa não foi encontrado 
#> systemctl status teste-guia
× teste-guia.service - Serviço de teste do Guia Debian
     Active: failed (Result: exit-code) since Thu 2026-10-15 21:09:55 -03; 1s ago
    Process: 8060 ExecStart=/usr/local/bin/teste-gia.sh (code=exited, status=203/EXEC)
#> journalctl -u teste-guia -n 4
out 15 21:09:55 notebook (e-gia.sh)[8060]: teste-guia.service: Unable to locate executable '/usr/local/bin/teste-gia.sh': No such file or directory
out 15 21:09:55 notebook (e-gia.sh)[8060]: teste-guia.service: Failed at step EXEC spawning /usr/local/bin/teste-gia.sh: No such file or directory
out 15 21:09:55 notebook systemd[1]: teste-guia.service: Main process exited, code=exited, status=203/EXEC
out 15 21:09:55 notebook systemd[1]: teste-guia.service: Failed with result 'exit-code'.

O que aconteceu: erro de digitação no ExecStart (teste-gia). O código 203 sempre significa "não consegui executar": caminho errado, arquivo sem permissão de execução (chmod 755) ou falta a primeira linha #! no script.

Como resolver: confira com ls -l o caminho exato, corrija o arquivo, daemon-reload e restart.

"Start request repeated too quickly" 
out 15 21:09:45 notebook systemd[1]: teste-guia.service: Scheduled restart job, restart counter is at 5.
out 15 21:09:45 notebook systemd[1]: teste-guia.service: Start request repeated too quickly.
out 15 21:09:45 notebook systemd[1]: Failed to start teste-guia.service - Serviço de teste do Guia Debian.

O que aconteceu: o serviço tem Restart=on-failure, mas cai logo ao ligar. O systemd tentou 5 vezes seguidas e desistiu, para não ficar num laço eterno.

Como resolver: descubra o erro de verdade nas linhas anteriores do journalctl -u. Depois de consertar, rode systemctl reset-failed teste-guia para zerar o contador e start de novo.

"changed on disk. Run 'systemctl daemon-reload'"

O que aconteceu: você editou o .service e o systemd ainda está com a versão antiga na memória. Cuidado: até o reload, ele continua usando a antiga, inclusive para ligar o serviço.

Como resolver: systemctl daemon-reload sempre que mexer no arquivo.

O serviço funciona no terminal mas não pelo systemd

O que aconteceu: o systemd não lê o seu .bashrc: o PATH é mínimo, não há variáveis suas e a pasta inicial é /.

Como resolver: use caminhos completos no script e no ExecStart, defina WorkingDirectory e passe variáveis com Environment.

Resumo

  • Script em /usr/local/bin, serviço em /etc/systemd/system/nome.service.
  • [Unit] descreve, [Service] diz o que rodar, [Install] diz quando entra no boot.
  • Criou ou editou? daemon-reload. Para ligar: enable --now.
  • Restart=on-failure reinicia quando o serviço cai, não quando você para.
  • Erro? systemctl status diz que falhou; journalctl -u diz por quê.
