Debian ufw (opcional)

O ufw (de Uncomplicated Firewall, "firewall descomplicado") foi criado pelo Ubuntu para quem não quer escrever regras de nftables. No Debian ele não vem instalado: o firewall oficial é o nftables. Mas o ufw está nos repositórios e funciona bem. Esta aula é para quem prefere comandos curtos como ufw allow ssh.

Você vai aprender
  • Quando vale a pena usar ufw no lugar de escrever o nftables.conf.
  • Instalar o ufw e entender o que ele traz junto (o iptables).
  • Criar regras com ele ainda desligado e ligar sem derrubar o SSH.
  • Por que não misturar ufw com o serviço nftables.

Os exemplos são na máquina servidor, como root (entre com su -).

Regra prática: se você administra um servidor simples (SSH + site) e já usou ufw no Ubuntu, pode usá-lo. Se precisa de regras específicas, ou quer o padrão do Debian, use o nftables.

Instalar

#> apt install ufw
…
Configurando iptables (1.8.11-2) ...
update-alternatives: usando /usr/sbin/iptables-nft para fornecer /usr/sbin/iptables (iptables) no modo automático
…
Configurando ufw (0.36.2-9) ...
Created symlink '/etc/systemd/system/multi-user.target.wants/ufw.service' → '/usr/lib/systemd/system/ufw.service'.

Duas coisas para reparar:

  • O ufw instala o iptables junto. No Debian, o iptables escolhido é o iptables-nft: ele aceita os comandos antigos, mas grava regras nftables. Ou seja, o ufw também usa o nftables por baixo.
  • O serviço ufw.service fica habilitado, mas o firewall continua desligado até você mandar. Instalar não bloqueia nada.
#> ufw status
Status: inactive

Criar regras antes de ligar

O ufw aceita regras mesmo desligado. Elas ficam guardadas e só valem quando você ligar. Comece sempre pelo SSH:

ufw
O programa.
allow
Permitir (deny bloqueia, limit permite com limite de tentativas).
OpenSSH
Um "perfil de aplicativo": um nome que já sabe quais portas abrir (aqui, 22/tcp).
#> ufw allow OpenSSH
Rules updated
Rules updated (v6)                          « v6: a mesma regra para IPv6
#> ufw allow 80,443/tcp
Rules updated
Rules updated (v6)
#> ufw show added
Added user rules (see 'ufw status' for running firewall):
ufw allow OpenSSH
ufw allow 80,443/tcp

Os perfis disponíveis aparecem com ufw app list, e os detalhes de um deles com ufw app info:

#> ufw app info OpenSSH
Profile: OpenSSH
Title: Secure shell server, an rshd replacement
Description: OpenSSH is a free implementation of the Secure Shell protocol.

Port:
  22/tcp

Formas diferentes de liberar o SSH

ComandoO que libera
ufw allow OpenSSHPelo perfil (22/tcp)
ufw allow 22/tcpA porta diretamente
ufw limit 22/tcpA porta, mas bloqueia quem tentar 6 conexões em 30 segundos
ufw allow from 192.168.0.0/24 to any port 22 proto tcpSó para a rede da casa/escritório

Ligar sem perder o acesso

  1. Confira com ufw show added que a regra do SSH está lá.
  2. Ligue com ufw enable. Ele avisa que pode derrubar conexões SSH; responda y.
  3. Abra uma segunda sessão SSH antes de fechar a primeira.
#> ufw enable
Command may disrupt existing ssh connections. Proceed with operation (y|n)? y
Firewall is active and enabled on system startup
#> ufw status verbose
Status: active
Logging: on (low)
Default: deny (incoming), allow (outgoing), deny (routed)
New profiles: skip

To                         Action      From
--                         ------      ----
22/tcp (OpenSSH)           ALLOW IN    Anywhere
80,443/tcp                 ALLOW IN    Anywhere
22/tcp (OpenSSH (v6))      ALLOW IN    Anywhere (v6)
80,443/tcp (v6)            ALLOW IN    Anywhere (v6)

A linha Default: deny (incoming) mostra a política: entrada bloqueada, exceto o que está na tabela. Esses padrões vêm de /etc/default/ufw (DEFAULT_INPUT_POLICY="DROP").

Atenção

Nunca rode ufw enable num servidor remoto sem antes liberar o SSH. Se acontecer, só o console do provedor (ou acesso físico) resolve: lá, rode ufw disable.

Listar e apagar regras

#> ufw status numbered
Status: active

     To                         Action      From
     --                         ------      ----
[ 1] OpenSSH                    ALLOW IN    Anywhere
[ 2] 80,443/tcp                 ALLOW IN    Anywhere
[ 3] OpenSSH (v6)               ALLOW IN    Anywhere (v6)
[ 4] 80,443/tcp (v6)            ALLOW IN    Anywhere (v6)
#> ufw delete 2
Deleting:
 allow 80,443/tcp
Proceed with operation (y|n)? y
Rule deleted

Também dá para apagar repetindo a regra com delete na frente: ufw delete allow 80,443/tcp. Os números mudam a cada exclusão; liste de novo antes de apagar outra.

As saídas com o firewall ativo acima são as típicas do ufw 0.36. Para desligar, ufw disable; para voltar ao zero, ufw reset.

ufw e o serviço nftables juntos: não

O ufw grava as regras dele no nftables, numa tabela chamada ip filter (e ip6 filter), por meio do iptables-nft:

#> nft list tables
table ip filter
table ip6 filter

O /etc/nftables.conf do Debian começa com flush ruleset. Se o serviço nftables também estiver ligado, um systemctl reload nftables apaga as regras do ufw. Escolha um dos dois:

#> systemctl is-enabled nftables ufw
disabled                                    « nftables desligado
enabled                                     « ufw no controle

Quando não funciona

"ufw: comando não encontrado"

O que aconteceu: ou o ufw não está instalado (o padrão no Debian), ou você está como usuário comum: o ufw fica em /usr/sbin, fora do PATH da ana.

Como resolver: su - e depois apt install ufw.

Liguei o ufw e o Docker continuou acessível de fora

O que aconteceu: o Docker cria regras próprias que passam antes das do ufw para as portas publicadas com -p.

Como resolver: publique as portas só no localhost (-p 127.0.0.1:8080:80) e use um proxy reverso. Veja Docker.

As regras sumiram depois do reboot

O que aconteceu: provavelmente o serviço nftables também está habilitado e o flush ruleset dele apagou as regras do ufw no boot.

Como resolver: systemctl disable --now nftables e ufw reload.

Resumo

  • No Debian o ufw é opcional: apt install ufw (como root).
  • Ele instala o iptables-nft e grava regras no nftables por baixo.
  • Crie a regra do SSH, confira com ufw show added e só então ufw enable.
  • Use ufw ou o serviço nftables, nunca os dois.
