Debian ps, pgrep, top

Todo programa aberto no seu Debian vira um ou mais processos. Nesta aula você vai listar esses processos, encontrar um pelo nome e entender os casos em que o terminal "não acha nada", mesmo com o programa aberto na sua frente.

Você vai aprender
  • O que é um processo e o que é um PID.
  • Por que ps sozinho mostra só dois processos.
  • Como ler cada coluna do ps aux.
  • Por que as abas do Firefox se chamam Isolated Web Co, e como achar um processo pelo nome certo.
  • Como acompanhar tudo ao vivo com top.

O que é um processo

Um programa é um arquivo parado no disco, como /usr/lib/firefox-esr/firefox-esr. Quando você o abre, o sistema carrega esse arquivo na memória e começa a executá-lo. Essa execução é um processo.

  • Cada processo recebe um número único, o PID (process ID, "identificador do processo").
  • Cada processo tem um dono: o usuário que o iniciou.
  • Um programa pode virar vários processos. O Firefox cria um processo principal e outros para as abas.
  • Cada processo tem um nome curto (no máximo 15 caracteres), que nem sempre é o nome que aparece no menu de aplicativos.

Nos exemplos, a máquina fictícia notebook é um Debian 13 com GNOME e está com o Firefox ESR, o Arquivos (Nautilus) e o Editor de Texto abertos.

Firefox ESR

O Debian instala o Firefox ESR (Extended Support Release, a versão de suporte estendido). Por isso o programa e o processo se chamam firefox-esr, e não firefox.

ps: a foto dos processos

ps vem de process status, "situação dos processos". Ele tira uma foto do momento: mostra a lista e termina.

ps
O programa, sem nenhuma opção.
$ ps
    PID TTY          TIME CMD
   3001 pts/0    00:00:00 bash          « o shell deste terminal
   3100 pts/0    00:00:00 ps            « o próprio ps

Por que só aparecem dois processos?

O Firefox está aberto, mas não apareceu. Isso não é erro: ps sem opções mostra só os processos do terminal em que você está. Neste terminal só existem o bash (o programa que lê o que você digita) e o próprio ps.

TIME00:00:00Tempo de processador já usado (não é há quanto tempo está aberto).

Missão: rode ps e confira que só aparecem o bash e o próprio ps. Depois rode ps aux e compare.

pgrep: achar um processo pelo nome

pgrep junta process e grep (procurar). Ele procura pelo nome curto do processo e devolve os PIDs.

pgrep
O programa.
-l
Mostra o nome junto do PID (list name).
firefox
O texto a procurar. Basta ser parte do nome.
$ pgrep firefox
2210
$ pgrep -l firefox
2210 firefox-esr

Como firefox é parte de firefox-esr, ele achou o processo principal. Mas cadê a aba (PID 2251)?

O nome curto de 15 caracteres

O nome curto de um processo (chamado comm) tem no máximo 15 caracteres. As abas do Firefox se dão o nome "Isolated Web Content", que é cortado para Isolated Web Co:

$ pgrep -l Isolated
2251 Isolated Web Co

O mesmo acontece com o terminal do GNOME: o programa é gnome-terminal-server, mas o processo se chama gnome-terminal-. Se você pesquisar o nome inteiro, o pgrep do Debian avisa:

$ pgrep -l gnome-terminal-server
pgrep: o padrão que pesquisa por nomes de processo maiores que 15 caracteres vai resultar em zero correspondências
Tente a opção "pgrep -f" para corresponder com a linha de comando completa.
$ pgrep -l gnome-terminal
2950 gnome-terminal-

-f: procurar na linha de comando inteira

A opção -f (de full, "completa") procura na linha de comando inteira, e não só no nome curto. Como as abas foram iniciadas a partir de /usr/lib/firefox-esr/firefox-esr, elas aparecem:

pgrep
O programa.
-a
Mostra a linha de comando completa (all).
-f
Procura na linha de comando, não só no nome curto.
firefox
O texto a procurar.
$ pgrep -af firefox
2210 /usr/lib/firefox-esr/firefox-esr
2251 /usr/lib/firefox-esr/firefox-esr -contentproc -isForBrowser 4 tab

O que o pgrep devolve quando não acha nada

Quando não encontra nada, o pgrep não mostra mensagem nenhuma. Ele só devolve o código de saída 1. Isso confunde quem está começando:

$ pgrep chromium
$ echo $?
1                                « 1 = nada encontrado
$ pgrep firefox
2210
$ echo $?
0                                « 0 = achou

Esse código é útil em scripts: pgrep firefox-esr > /dev/null || echo "O Firefox está fechado".

Missão: descubra o PID das abas do Firefox. Tente primeiro pgrep -l firefox, depois pgrep -af firefox, e compare. Confira o código de saída com echo $? depois de um pgrep que não acha nada.

Descobrir o nome real de um processo

Quando você não sabe como o processo se chama, procure na lista completa com grep:

$ ps aux | grep firefox
ana         2210  5.4  6.8 371600 112800 ?        Ssl  08:00   0:16 /usr/lib/firefox-esr/firefox-esr
ana         2251  2.0  3.9 220800 66400 ?        Ssl  08:00   0:06 /usr/lib/firefox-esr/firefox-esr -contentproc -isForBrowser 4 tab
ana         3103  0.0  0.0  18000  4000 pts/0    S+   08:00   0:00 grep firefox      « o próprio grep

A última linha é o próprio grep: ele também é um processo e contém a palavra que você procurou. Ignore-a, ou use pgrep -af, que não se lista.

O htop é uma versão mais amigável, com cores e mouse. Ele não vem instalado; como root: apt install htop (veja apt).

Quando não funciona

O programa está aberto, mas o pgrep não mostra nada

O que aconteceu: o nome curto do processo é diferente do nome que você conhece (as abas do Firefox se chamam Isolated Web Co, e o terminal do GNOME é gnome-terminal-, e não terminal), ou você usou maiúsculas.

Como resolver: procure por um pedaço com pgrep -ail pedaço, ou na linha inteira com pgrep -af pedaço.

"…maiores que 15 caracteres vai resultar em zero correspondências"

O que aconteceu: o nome que você pesquisou é maior que o nome curto, que tem no máximo 15 caracteres.

Como resolver: pesquise só o começo (pgrep gnome-terminal) ou use -f.

"bash: htop: comando não encontrado"

O que aconteceu: o htop não vem no Debian, e o Debian não sugere pacotes quando um comando não existe.

Como resolver: use top, que já vem, ou instale com su - e apt install htop.

Resumo

  • ps sozinho mostra só o seu terminal; ps aux mostra tudo.
  • pgrep procura no nome curto (até 15 caracteres); pgrep -af, na linha inteira.
  • No Debian, o Firefox é firefox-esr e as abas são Isolated Web Co.
  • Sem resultado, o pgrep fica calado e devolve 1. Confira com echo $?.
  • top mostra tudo ao vivo; saia com q.
