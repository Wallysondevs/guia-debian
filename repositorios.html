Debian Repositórios (sources)

O apt não "procura na internet": ele só conhece os programas dos repositórios que estão configurados. Esta aula mostra onde fica essa lista no Debian, como ler cada linha, como ligar as partes "non-free" e como adicionar um repositório de fora com segurança.

Você vai aprender
  • A ler o /etc/apt/sources.list do Debian 13, palavra por palavra.
  • O que são main, contrib, non-free e non-free-firmware, e como ligar cada um.
  • O formato novo .sources e o comando apt modernize-sources.
  • A adicionar um repositório de terceiros com chave própria (Signed-By).
  • Por que PPAs do Ubuntu não devem entrar num Debian.

Antes do comando: como o apt sabe o que existe

Um repositório é um servidor com milhares de pacotes .deb e um índice: a lista de tudo o que ele tem, com versões e dependências. O apt update baixa esses índices; o apt install consulta o que foi baixado.

#> apt update
Atingido:1 http://deb.debian.org/debian trixie InRelease                    « nada mudou desde a última vez
Atingido:2 http://security.debian.org/debian-security trixie-security InRelease
Obter:3 http://deb.debian.org/debian trixie-updates InRelease [47,3 kB]       « índice novo baixado
Obtidos 47,3 kB em 1s (39,2 kB/s)
Todos os pacotes estão atualizados.
PalavraSignifica
Atingido (Hit)O índice não mudou; nada a baixar.
Obter (Get)Havia índice novo, e ele foi baixado.
Ign (Ignore)Arquivo opcional que não existe no servidor; normal.
Erro / E:Falhou; leia a mensagem (veja "Quando não funciona").

Onde fica a configuração

No Debian 13 instalado pelo netinst, os repositórios estão em um arquivo só, no formato clássico de uma linha:

$ cat /etc/apt/sources.list
#deb cdrom:[Debian GNU/Linux 13.5.0 _Trixie_ - Official amd64 NETINST with firmware 20260516-10:08]/ trixie contrib main non-free-firmware

deb http://deb.debian.org/debian trixie main non-free-firmware
deb-src http://deb.debian.org/debian trixie main non-free-firmware

deb http://security.debian.org/debian-security trixie-security main non-free-firmware
deb-src http://security.debian.org/debian-security trixie-security main non-free-firmware

# trixie-updates, to get updates before a point release is made;
# see https://www.debian.org/doc/manuals/debian-reference/ch02.en.html#_updates_and_backports
deb http://deb.debian.org/debian trixie-updates main non-free-firmware
deb-src http://deb.debian.org/debian trixie-updates main non-free-firmware
…
$ ls /etc/apt/sources.list.d/
$                                       « pasta vazia: nenhum repositório extra

Linhas que começam com # são comentários. A primeira é a do pendrive/DVD de instalação, que o instalador desliga no fim.

Uma linha, palavra por palavra

deb
Tipo: deb = pacotes prontos para instalar. deb-src = o código-fonte deles (só para quem vai recompilar; pode ficar comentado).
http://deb.debian.org/debian
O endereço do repositório. deb.debian.org redireciona para um espelho perto de você.
trixie
A suíte: de qual versão do Debian são os pacotes. trixie é o Debian 13.
main non-free-firmware
Os componentes: quais "prateleiras" do repositório você quer.

As três suítes do Debian estável

SuíteServidorO que traz
trixiedeb.debian.orgA versão estável em si, atualizada nos "point releases" (13.1, 13.2…)
trixie-securitysecurity.debian.orgCorreções de segurança, assim que saem
trixie-updatesdeb.debian.orgAtualizações que não podem esperar o próximo point release (fusos horários, antivírus…)

Existe uma quarta, opcional: trixie-backports, com versões mais novas de alguns programas. Ela tem uma aula própria: Backports e Pinning.

Use o nome (trixie), não "stable"

Também funciona escrever stable no lugar de trixie. Mas, quando o Debian 14 for lançado, stable passa a apontar para ele, e o próximo apt full-upgrade faz uma atualização de versão inteira sem você ter decidido. Com o codinome, você só muda quando quiser (veja Atualizar a Versão do Debian).

Os componentes: main, contrib, non-free e non-free-firmware

O Debian separa os pacotes conforme a licença. Por padrão, só entra o que é software livre.

ComponenteO que temExemplos
mainSoftware livre, com tudo de que depende também livre. É o Debian "oficial".bash, firefox-esr, libreoffice
non-free-firmwareFirmware fechado de hardware: Wi-Fi, placas de vídeo, microcódigo do processador. Ligado por padrão desde o Debian 12.firmware-iwlwifi, firmware-realtek, intel-microcode (veja Wi-Fi que Não Funciona)
contribSoftware livre que depende de algo não livre (por exemplo, baixa um arquivo proprietário).ttf-mscorefonts-installer
non-freeSoftware com licença restrita.nvidia-driver, unrar

Ligar contrib e non-free

Basta acrescentar as palavras no fim das linhas e atualizar os índices. Como root:

  1. Faça uma cópia de segurança e abra o arquivo:

    #> cp /etc/apt/sources.list /etc/apt/sources.list.bak
#> nano /etc/apt/sources.list

  2. Nas linhas deb (as que você usa), acrescente os componentes:

    deb http://deb.debian.org/debian trixie main contrib non-free non-free-firmware
deb http://security.debian.org/debian-security trixie-security main contrib non-free non-free-firmware
deb http://deb.debian.org/debian trixie-updates main contrib non-free non-free-firmware

  3. Atualize e confira:

    #> apt update
#> apt policy unrar

O formato novo: arquivos .sources

O apt também aceita um formato em blocos (chamado deb822), mais fácil de ler e de editar com segurança. Cada repositório vira um bloco de "Campo: valor" dentro de um arquivo .sources em /etc/apt/sources.list.d/.

O apt 3 do Debian 13 tem um comando que converte o arquivo antigo. Responda n na pergunta para só simular e ver o resultado sem mudar nada:

#> apt modernize-sources
The following files need modernizing:
  - /etc/apt/sources.list

Modernizing will replace .list files with the new .sources format,
add Signed-By values where they can be determined automatically,
and save the old files into .list.bak files.
…
For a simulation, respond N in the following prompt.
Reescrever 1 fontes? [S/n] n
Simulating only...
Modernizing /etc/apt/sources.list...

# Would write to: /etc/apt/sources.list.d/debian.sources
# Modernized from /etc/apt/sources.list
Types: deb deb-src
URIs: http://deb.debian.org/debian/
Suites: trixie
Components: main non-free-firmware
Signed-By: /usr/share/keyrings/debian-archive-keyring.gpg
…
Types: deb deb-src
Os tipos, que antes eram duas linhas separadas.
URIs:
O endereço do repositório.
Suites: trixie
A suíte; pode listar várias: trixie trixie-updates.
Components:
Os componentes.
Signed-By:
Qual chave confere a assinatura deste repositório (para o Debian, o chaveiro oficial).

Respondendo S, o apt grava /etc/apt/sources.list.d/debian.sources e guarda o antigo como sources.list.bak. Os dois formatos funcionam no Debian 13; não misture o mesmo repositório nos dois, ou ele aparece duplicado (veja os cenários).

FormatoArquivoVantagem
Uma linhasources.list ou *.listCompacto; o que a maioria dos tutoriais mostra
deb822*.sourcesCampos com nome, várias suítes por bloco, chave declarada; é o futuro do apt

De onde vem este pacote? apt policy

Quando o mesmo pacote existe em mais de um repositório, o apt escolhe a versão mais alta entre os de maior prioridade. O apt policy mostra a escolha:

$ apt policy curl
curl:
  Instalado: (nenhum)
  Candidato: 8.14.1-2+deb13u7                              « o que o apt install instalaria
  Tabela de versão:
     8.14.1-2+deb13u7 500
        500 http://security.debian.org/debian-security trixie-security/main amd64 Packages
     8.14.1-2+deb13u5 500
        500 http://deb.debian.org/debian trixie/main amd64 Packages

As duas versões têm prioridade 500 (a padrão), então ganha a mais alta: a correção de segurança deb13u7. O apt policy também mostra um aviso em inglês ("apt does not have a stable CLI interface") quando a saída vai para um pipe; é normal.

Repositórios de terceiros

Alguns programas (Docker, VS Code, navegadores) têm repositório próprio da empresa. A receita segura tem sempre três partes: a chave da empresa, guardada à parte; o arquivo do repositório, dizendo que só essa chave vale para ele; e o apt update.

Exemplo com o repositório oficial do Docker para Debian, como root:

  1. Baixe a chave para /etc/apt/keyrings, a pasta das chaves de terceiros:

    #> install -m 0755 -d /etc/apt/keyrings
#> wget -qO /etc/apt/keyrings/docker.asc https://download.docker.com/linux/debian/gpg
#> head -1 /etc/apt/keyrings/docker.asc
-----BEGIN PGP PUBLIC KEY BLOCK-----

  2. Crie o arquivo do repositório amarrado a essa chave:

    Types: deb
URIs: https://download.docker.com/linux/debian
Suites: trixie
Components: stable
Signed-By: /etc/apt/keyrings/docker.asc

  3. Atualize e veja de onde vem o pacote:

    #> apt update
Obter:1 https://download.docker.com/linux/debian trixie InRelease [32,5 kB]
Obter:2 https://download.docker.com/linux/debian trixie/stable amd64 Packages [49,8 kB]
…
#> apt policy docker-ce
docker-ce:
  Instalado: (nenhum)
  Candidato: 5:29.9.1-1~debian.13~trixie
  Tabela de versão:
     5:29.9.1-1~debian.13~trixie 500
        500 https://download.docker.com/linux/debian trixie/stable amd64 Packages
Por que a chave fica separada (e o apt-key sumiu)

Antigamente, as chaves iam para um chaveiro único com apt-key add: uma chave de terceiros passava a valer para todos os repositórios, inclusive para "assinar" pacotes falsos do Debian. O Signed-By limita a chave ao repositório dela. O apt-key nem existe mais no Debian 13.

Atalho do Debian: extrepo

O pacote extrepo mantém uma lista revisada de repositórios externos populares, com as chaves certas. Depois de apt install extrepo, um extrepo search docker mostra as opções e extrepo enable docker-ce faz os passos acima por você.

PPAs não são do Debian

Muitos tutoriais mandam rodar add-apt-repository ppa:alguem/programa. PPA (Personal Package Archive) é um serviço do Ubuntu: os pacotes ali foram compilados para as bibliotecas de uma versão específica do Ubuntu. No Debian, eles podem instalar até funcionar, mas puxam ou substituem bibliotecas que não batem com as do Debian, e a próxima atualização pode quebrar o sistema.

$ add-apt-repository ppa:alguem/programa
bash: add-apt-repository: comando não encontrado        « nem vem instalado no Debian
Não transforme o Debian num "FrankenDebian"

Misturar repositórios de outras distribuições (PPAs, repositórios do Ubuntu) ou de outras versões do Debian (testing, unstable) no mesmo sistema é o jeito mais comum de quebrar um Debian. Prefira, nesta ordem: o pacote do próprio Debian; o backports; o repositório oficial do fabricante para Debian; um Flatpak.

Riscos de cada repositório extra

RiscoPor quê
ConfiançaQuem controla o repositório pode instalar qualquer coisa como root na sua máquina, a cada atualização.
ConflitosPacotes de fora podem substituir bibliotecas do Debian e quebrar outros programas.
Atualização de versãoNa hora de ir do Debian 13 para o 14, repositórios de terceiros são a principal fonte de problemas; desligue-os antes.
AbandonoUm repositório que some passa a dar erro no apt update.

Quando não funciona

"está configurado várias vezes" 
#> apt update
…
W: O alvo Packages (main/binary-amd64/Packages) está configurado várias vezes em /etc/apt/sources.list:1 e /etc/apt/sources.list:2

O que aconteceu: o mesmo repositório aparece duas vezes, em duas linhas ou em dois arquivos (por exemplo, no sources.list e num .sources).

Como resolver: apague ou comente uma das cópias. A mensagem diz o arquivo e a linha (:1 e :2).

"não tem um arquivo Release" 
#> apt update
Erro:2 http://deb.debian.org/debian trixy Release
  404  Not Found [IP: 151.101.250.132 80]
E: O repositório 'http://deb.debian.org/debian trixy Release' não tem um arquivo Release.

O que aconteceu: a suíte não existe nesse servidor. Aqui foi erro de digitação (trixy). Também acontece com versões antigas, que saem do servidor principal e vão para archive.debian.org.

Como resolver: confira o nome da suíte e o endereço.

"não está assinado" / "Missing key" 
#> apt update
Erro:1 https://download.docker.com/linux/debian trixie InRelease
  Sub-process /usr/bin/sqv returned an error code (1), error message is: Missing key 7EA0A9C3F273FCD8, which is needed to verify signature.
W: Verificação de assinatura OpenPGP falhou: https://download.docker.com/linux/debian trixie InRelease: …
E: O repositório 'http://download.docker.com/linux/debian trixie InRelease' não está assinado.

O que aconteceu: o repositório foi adicionado sem a chave dele (ou o Signed-By aponta para o arquivo errado). O apt 3 confere as assinaturas com o programa sqv, que aparece na mensagem.

Como resolver: baixe a chave para /etc/apt/keyrings e aponte o Signed-By para ela, como na receita acima. Nunca "resolva" desligando a verificação (trusted=yes).

Liguei o non-free e o pacote ainda não aparece 
#> apt install nvidia-driver
O pacote nvidia-driver não está disponível, mas é referenciado por outro pacote.
Isto pode significar que o pacote está faltando, ficou obsoleto ou
está disponível somente a partir de outra fonte

Erro: O pacote 'nvidia-driver' não tem candidato para instalação

O que aconteceu: o apt sabe que o pacote existe (outro pacote cita o nome dele), mas nenhum repositório ligado o oferece. Ou o non-free não está na linha, ou você editou o arquivo e não rodou o apt update, e os índices ainda são os velhos.

Como resolver: confira se non-free está na linha, rode apt update e tente de novo. Um nome errado dá outra mensagem: Erro: Não é possível encontrar o pacote nvidea-driver.

Resumo

  • O apt só conhece o que está nos repositórios configurados; apt update baixa os índices.
  • No Debian 13 instalado pelo netinst, tudo está em /etc/apt/sources.list, com trixie, trixie-security e trixie-updates.
  • Componentes: main (livre), non-free-firmware (firmware, ligado por padrão), contrib e non-free.
  • apt modernize-sources converte para o formato .sources; responda N para simular.
  • Repositório de terceiros: chave em /etc/apt/keyrings + Signed-By. Nada de apt-key, nada de PPA.
