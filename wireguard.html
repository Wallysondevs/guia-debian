Debian VPN (WireGuard)

Uma VPN (Virtual Private Network, rede privada virtual) liga computadores distantes por um "túnel" criptografado, como se estivessem na mesma rede. O WireGuard é a VPN moderna do Linux: rápida, com pouca configuração e já embutida no kernel do Debian. Nesta aula você vai ligar o notebook da Ana ao servidor dela.

Você vai aprender
  • Como o WireGuard funciona: um par de chaves para cada lado.
  • Gerar chaves com wg genkey e wg pubkey.
  • Escrever o /etc/wireguard/wg0.conf do servidor e do notebook.
  • Liberar a porta no nftables, subir o túnel com wg-quick e ler o wg show.

Os comandos rodam como root nas duas máquinas (su -). As chaves e saídas mostradas vêm de um Debian 13 real; as suas chaves serão outras, porque são geradas ao acaso.

Antes do comando: o desenho da VPN

servidornotebook
Endereço na internet203.0.113.10 (fixo)qualquer (Wi-Fi de casa, 4G…)
Endereço dentro da VPN10.8.0.110.8.0.2
Portaescuta em 51820/udpsai por qualquer porta
Chavesprivada do servidor + pública do notebookprivada do notebook + pública do servidor

Cada lado guarda a sua chave privada em segredo e entrega a chave pública ao outro. Um lado só aceita pacotes assinados por quem ele conhece. Não existe usuário nem senha.

Passo 1: instalar

O módulo do kernel já vem no Debian 13; falta só o pacote com as ferramentas:

#> apt install wireguard-tools
…
Configurando wireguard-tools (1.0.20210914-3) ...
#> wg --version
wireguard-tools v1.0.20210914 - https://git.zx2c4.com/wireguard-tools/

Repita no notebook.

Passo 2: gerar as chaves

umask 077
Os arquivos criados a seguir ficam legíveis só pelo root.
wg genkey
Gera uma chave privada nova e a imprime.
| tee privada.key
Grava a privada no arquivo e passa adiante.
| wg pubkey > publica.key
Calcula a chave pública a partir da privada e grava.
#> cd /etc/wireguard
#> umask 077
#> wg genkey | tee privada.key | wg pubkey > publica.key
#> ls -l
total 8
-rw------- 1 root root 45 out 15 21:46 privada.key        « rw------- : só o root lê
-rw------- 1 root root 45 out 15 21:46 publica.key
#> cat publica.key
hOc8h23OVpONrNvL3PY0cAfxaZJtfGCwJ8vTzZ6cJl4=              « esta você pode compartilhar

Faça o mesmo no notebook e troque as públicas entre as máquinas (por SSH, num arquivo, como preferir). A pasta /etc/wireguard já vem com permissão drwx------.

Nunca compartilhe a chave privada

Quem tem a privada.key se passa pela sua máquina na VPN. Ela não sai do computador onde foi gerada.

Passo 3: o arquivo do servidor

[Interface]
Address = 10.8.0.1/24                       # o endereço do servidor dentro da VPN
ListenPort = 51820                          # porta UDP em que ele espera conexões
PrivateKey = (conteúdo de privada.key do SERVIDOR)

[Peer]                                       # um bloco para cada máquina que pode conectar
PublicKey = (conteúdo de publica.key do NOTEBOOK)
AllowedIPs = 10.8.0.2/32                    # endereço que esse par pode usar na VPN

Proteja o arquivo, porque ele tem a chave privada: chmod 600 /etc/wireguard/wg0.conf.

Passo 4: o arquivo do notebook

[Interface]
Address = 10.8.0.2/24
PrivateKey = (conteúdo de privada.key do NOTEBOOK)

[Peer]
PublicKey = (conteúdo de publica.key do SERVIDOR)
Endpoint = 203.0.113.10:51820               # onde achar o servidor na internet
AllowedIPs = 10.8.0.0/24                    # o que mandar pelo túnel: só a rede da VPN
PersistentKeepalive = 25                    # mantém o túnel vivo atrás de roteador/NAT
AllowedIPs = 10.8.0.0/24
Só o tráfego para a VPN passa pelo túnel; a internet continua saindo normal.
AllowedIPs = 0.0.0.0/0
(alternativa) Todo o tráfego passa pelo servidor, como uma VPN comercial. Aí o servidor também precisa repassar pacotes (NAT).

Passo 5: liberar a porta no firewall do servidor

No Debian o firewall é o nftables. Acrescente uma linha na cadeia input do /etc/nftables.conf (veja Firewall (nftables)):

		udp dport 51820 accept                 # WireGuard
#> nft -c -f /etc/nftables.conf && systemctl reload nftables

Se você usa ufw: ufw allow 51820/udp. Em provedores de nuvem, libere também a porta UDP no painel deles.

Passo 6: subir a VPN

O wg-quick lê o wg0.conf e faz tudo: cria a interface, coloca o endereço e as rotas.

#> wg-quick up wg0
[#] ip link add wg0 type wireguard
[#] wg setconf wg0 /dev/fd/63
[#] ip -4 address add 10.8.0.1/24 dev wg0
[#] ip link set mtu 1420 up dev wg0

Cada linha [#] é um comando que o wg-quick rodou por você (as linhas acima são as típicas). Faça o mesmo no notebook e teste:

$ ping -c 2 10.8.0.1
PING 10.8.0.1 (10.8.0.1) 56(84) bytes of data.
64 bytes from 10.8.0.1: icmp_seq=1 ttl=64 time=21.4 ms
64 bytes from 10.8.0.1: icmp_seq=2 ttl=64 time=20.9 ms

Para derrubar: wg-quick down wg0.

Ver o estado: wg show

Esta é a saída real de uma interface WireGuard no Debian 13, logo depois de criada, antes de o outro lado conectar:

#> wg show
interface: wg0
  public key: hOc8h23OVpONrNvL3PY0cAfxaZJtfGCwJ8vTzZ6cJl4=     « a pública deste lado
  private key: (hidden)                                     « nunca é mostrada
  listening port: 51820

peer: BZCpqO5qEQPs6XAn/nRRr/b7hkiSvOgWHMx8mK9PWGg=          « a pública do notebook
  allowed ips: 10.8.0.2/32

Quando o notebook conecta, o bloco do peer ganha mais linhas:

#> wg show
…
peer: BZCpqO5qEQPs6XAn/nRRr/b7hkiSvOgWHMx8mK9PWGg=
  endpoint: 198.51.100.7:41263                « de onde o notebook está falando agora
  allowed ips: 10.8.0.2/32
  latest handshake: 12 seconds ago            « o "aperto de mão" mais recente: o túnel está vivo
  transfer: 4.18 KiB received, 3.92 KiB sent

Sem a linha latest handshake, os dois lados nunca se falaram: confira chaves, porta e firewall. O wg show é em inglês; não há tradução.

A interface também aparece no ip, com a rota da VPN:

$ ip -br a show wg0
wg0              UNKNOWN        10.8.0.1/24
$ ip r | grep wg0
10.8.0.0/24 dev wg0 proto kernel scope link src 10.8.0.1

Passo 7: ligar no boot

O pacote traz um serviço do systemd para cada arquivo em /etc/wireguard: wg-quick@wg0 usa o wg0.conf.

#> wg-quick down wg0
#> systemctl enable --now wg-quick@wg0
Created symlink '/etc/systemd/system/multi-user.target.wants/wg-quick@wg0.service' → '/usr/lib/systemd/system/wg-quick@.service'.
#> systemctl status wg-quick@wg0 --no-pager | head -3

Formas diferentes de fazer

FormaComoQuando usar
wg-quick + serviçowg0.conf + wg-quick@wg0O jeito mais comum, no servidor e no notebook.
NetworkManagerImportar o wg0.conf nas configurações de rede do GNOMENotebook com interface gráfica.
Comandos ip + wg setip link add wg0 type wireguard…Entender o que o wg-quick faz; scripts.
systemd-networkdArquivos .netdev e .networkServidores que já usam networkd.

Quando não funciona

"resolvconf: command not found" ao subir 
#> wg-quick up wg0
…
[#] resolvconf -a wg0 -m 0 -x
/usr/bin/wg-quick: line 32: resolvconf: command not found

O que aconteceu: o seu wg0.conf tem uma linha DNS = …, e para aplicá-la o wg-quick precisa do programa resolvconf, que não vem no Debian.

Como resolver: instale o openresolv (apt install openresolv) ou apague a linha DNS.

wg show não mostra "latest handshake"

Como confirmar: as chaves trocadas estão certas? (a PublicKey de um lado tem de ser a pública do outro). A porta UDP 51820 está liberada no nftables e na nuvem? O Endpoint do notebook tem o IP público certo?

O túnel sobe, mas o ping não passa

O que aconteceu: os AllowedIPs não cobrem o endereço. No servidor, o par precisa ter 10.8.0.2/32; no notebook, 10.8.0.0/24 (ou o IP do servidor).

"wg: comando não encontrado"

O que aconteceu: o pacote wireguard-tools não está instalado, ou você está como usuário comum e o wg exige root. Entre com su -.

Resumo

  • O módulo do WireGuard já está no kernel do Debian; instale só wireguard-tools.
  • Cada lado tem uma privada (secreta) e uma pública (compartilhada).
  • wg0.conf: [Interface] com a própria privada; [Peer] com a pública do outro.
  • Libere udp dport 51820 no nftables e use wg-quick@wg0 para ligar no boot.
  • latest handshake no wg show é o sinal de que o túnel está vivo.
