Debian mount e fstab

Montar é ligar uma partição a uma pasta, para que os arquivos dela apareçam ali. No desktop, o GNOME faz isso sozinho quando você conecta um pendrive. Num servidor, num segundo HD ou quando algo dá errado, você faz pelo terminal com mount. Para montar automaticamente a cada boot, existe o arquivo /etc/fstab.

Você vai aprender
  • O que é um ponto de montagem e como ver o que está montado.
  • Montar e desmontar à mão com mount e umount, entendendo cada parte.
  • A ler o /etc/fstab real do Debian, linha por linha.
  • Praticar sem risco, usando um arquivo como se fosse um disco.
  • Configurar um HD extra para montar sozinho no boot, sem travar o sistema.
Montar exige o root

No Debian instalado com senha de root, a usuária comum não tem sudo. Os comandos de montagem desta aula são rodados depois de su -, e aparecem com o prompt root@notebook:~#. Reveja em root, su e sudo.

Antes dos comandos: uma árvore só

No Windows, cada disco vira uma letra: C:, D:, E:. No Linux existe uma árvore única que começa em /. Os outros discos são "pendurados" em pastas dessa árvore. A pasta onde um disco é pendurado se chama ponto de montagem.

PartiçãoPonto de montagemQuem montou
/dev/sda1/O sistema, no boot (está no fstab).
/dev/sda5nenhum (é a swap)O sistema, no boot (está no fstab).
/dev/sdb1 (pendrive)/media/ana/PENDRIVEO GNOME, ao conectar.
Um HD extra/mnt/backup ou /dadosVocê, com mount ou fstab.

Por convenção, /media é para montagens automáticas e /mnt é para montagens temporárias feitas à mão. O instalador do Debian também cria /media/cdrom0 (e um atalho /media/cdrom) para o leitor de DVD.

Ver o que está montado

O findmnt (de find mount) mostra as montagens. Para uma pasta específica, passe o caminho. Ele funciona como usuária comum:

findmnt
O programa: lista o que está montado.
/
Mostra só a montagem da pasta /.
$ findmnt /
TARGET SOURCE    FSTYPE OPTIONS
/      /dev/sda1 ext4   rw,relatime,errors=remount-ro
ColunaSignificado
TARGETO ponto de montagem (a pasta).
SOURCEA partição que está ali.
FSTYPEO sistema de arquivos.
OPTIONSAs opções: rw = leitura e escrita, ro = só leitura. errors=remount-ro é uma escolha do instalador do Debian: se o disco der erro, o sistema passa a só leitura para não estragar mais nada.

Outras formas de ver as montagens:

ComandoQuando usar
findmntVer tudo em árvore, inclusive montagens internas do sistema (/proc, /sys…).
findmnt -t ext4,vfatSó os sistemas de arquivos de disco de verdade.
df -hVer os discos com o espaço livre (veja lsblk, df, du).
lsblkVer discos montados e não montados (coluna MOUNTPOINTS vazia).
mount (sem nada)A forma antiga: uma linha por montagem. No Debian 13 são mais de 20 linhas, quase todas internas.

Laboratório sem risco: um arquivo que finge ser um disco

Para praticar sem tocar em nenhum disco de verdade, crie um arquivo, formate-o e use-o como disco. O Linux faz isso com os dispositivos loop: um arquivo vira /dev/loop0. Tudo o que você aprender aqui vale igual para um pendrive ou um HD.

  1. Crie um arquivo de 64 MB e formate-o como ext4.
    truncate -s 64M hd.img
    Cria o arquivo hd.img com 64 MB (vazio, não ocupa espaço de verdade até ser usado).
    mkfs.ext4 -q -L DADOS hd.img
    Formata como ext4 (-q = sem falar muito; -L = rótulo "DADOS").
    #> truncate -s 64M hd.img
#> mkfs.ext4 -q -L DADOS hd.img
  2. Transforme o arquivo num dispositivo. O losetup (de loop setup) liga o arquivo a um /dev/loopN livre e mostra qual escolheu: 
    #> losetup -f --show hd.img
/dev/loop0                                     « o "disco" novo
#> lsblk -f /dev/loop0
NAME  FSTYPE FSVER LABEL UUID                                 FSAVAIL FSUSE% MOUNTPOINTS
loop0 ext4   1.0   DADOS fb1d2c8d-ee57-44f8-b7f8-a43bf0439a12

    -f = primeiro loop livre; --show = mostra o nome escolhido.

  3. Continue as próximas seções usando /dev/loop0 no lugar de /dev/sdb1. No fim, desfaça com umount e losetup -d /dev/loop0.

Montar à mão: mount

Vamos montar o "HD" na pasta /mnt/dados. São dois passos.

  1. Crie a pasta que vai servir de ponto de montagem. Ela precisa existir antes. 
    #> mkdir -p /mnt/dados
  2. Monte.
    mount
    O programa que monta.
    /dev/loop0
    O quê: a partição (num HD de verdade, algo como /dev/sdb1).
    /mnt/dados
    Onde: o ponto de montagem.
    #> mount /dev/loop0 /mnt/dados
#> findmnt /mnt/dados
TARGET     SOURCE     FSTYPE OPTIONS
/mnt/dados /dev/loop0 ext4   rw,relatime
#> df -h /mnt/dados
Sist. Arq.      Tam. Usado Disp. Uso% Montado em
/dev/loop0       55M   46K   51M   1% /mnt/dados
#> ls -l /mnt/dados
total 12
drwx------ 2 root root 12288 out 15 21:14 lost+found       « todo ext4 novo tem esta pasta

Mais uma vez, silêncio significa sucesso: o mount não mostra nada quando dá certo. Ele descobre sozinho o tipo (aqui, ext4). Para forçar um tipo, use -t: mount -t vfat /dev/sdb1 /mnt/pendrive.

Para que serve o lost+found?

É onde a verificação do disco (fsck) coloca pedaços de arquivos recuperados depois de um desligamento brusco. Não apague.

Opções de montagem: -o

A opção -o (de options) passa ajustes separados por vírgula, sem espaço.

mount
Montar.
-o ro
Opção: ro = só leitura (read-only).
/dev/loop0 /mnt/dados
O quê e onde.
#> mount -o ro /dev/loop0 /mnt/dados
#> findmnt -o TARGET,SOURCE,FSTYPE,OPTIONS /mnt/dados
TARGET     SOURCE     FSTYPE OPTIONS
/mnt/dados /dev/loop0 ext4   ro,relatime
#> touch /mnt/dados/teste
touch: não foi possível tocar '/mnt/dados/teste': Sistema de arquivos somente para leitura
OpçãoPara quê
ro / rwSó leitura / leitura e escrita. ro é ótimo para examinar um disco sem risco.
uid=1000,gid=1000Em FAT32, exFAT e NTFS (que não têm donos), define quem é o dono dos arquivos. Sem isso, só o root grava.
noexecImpede rodar programas a partir desse disco.
nofailNo fstab: se o disco não estiver conectado, o boot continua.
user,noautoNo fstab: qualquer usuário pode montar, mas não monta no boot (é o que o Debian usa para o DVD).
remount,rwRemonta como leitura e escrita algo que está só leitura (ex.: depois de um errors=remount-ro).

Para descobrir o seu número de usuário (o uid), rode id -u. O primeiro usuário criado no Debian é o 1000.

Desmontar: umount

Repare: é umount, sem o "n". Desmontar grava no disco o que ainda estava na memória. Sempre desmonte antes de tirar um pendrive, ou arquivos podem ficar corrompidos.

umount
O programa que desmonta.
/mnt/dados
A pasta ou a partição (/dev/loop0); os dois funcionam.
#> umount /mnt/dados
#> findmnt /mnt/dados
#> echo $?
1                              « 1 = nada montado ali; deu certo
#> umount /mnt/dados
umount: /mnt/dados: não montado.

Para terminar o laboratório, solte o loop: losetup -d /dev/loop0 e apague o arquivo hd.img.

Formas diferentes de montar

Forma 1: o desktop

No GNOME, conecte o pendrive: ele aparece no app Arquivos e é montado em /media/ana/RÓTULO, sem pedir senha. Para desmontar, clique no ícone de ejetar ao lado do nome.

Forma 2: udisksctl, sem root (só no desktop)

O udisksctl faz pelo terminal o mesmo que o GNOME: monta em /media/ana e não pede senha para discos removíveis. Ele faz parte do pacote udisks2, que vem com os ambientes de desktop; numa instalação de servidor ele não existe.

$ udisksctl mount -b /dev/sdb1
Mounted /dev/sdb1 at /media/ana/PENDRIVE
$ udisksctl unmount -b /dev/sdb1
Unmounted /dev/sdb1.
$ udisksctl power-off -b /dev/sdb          « desliga o pendrive para remover com segurança

-b vem de block device. Saída ilustrativa: o texto pode variar conforme a versão.

Forma 3: mount, à mão

É o que você aprendeu acima. Use para montagens temporárias, em servidores ou quando precisa de opções especiais.

Forma 4: /etc/fstab, automático no boot

Para um HD que fica sempre conectado. É o assunto da próxima seção.

FormaPrecisa de root?Melhor quando…
DesktopNãoPendrive no dia a dia.
udisksctlNão (removíveis)Pendrive pelo terminal, num Debian com desktop.
mountSimMontagem temporária ou com opções especiais.
/etc/fstabSim, para editarDisco fixo que deve montar sozinho a cada boot.

/etc/fstab: montar sozinho no boot

fstab vem de file systems table, "tabela de sistemas de arquivos". Cada linha diz ao sistema: "monte isto, ali, desse jeito". Este é o fstab de um Debian 13 recém-instalado (qualquer usuário pode ler):

$ cat /etc/fstab
# /etc/fstab: static file system information.
#
# Use 'blkid' to print the universally unique identifier for a
# device; this may be used with UUID= as a more robust way to name devices
# that works even if disks are added and removed. See fstab(5).
#
# systemd generates mount units based on this file, see systemd.mount(5).
# Please run 'systemctl daemon-reload' after making changes here.
#
# <file system> <mount point>   <type>  <options>       <dump>  <pass>
# / was on /dev/sda1 during installation
UUID=50185294-cee5-49de-a27c-2cf995361c67 /               ext4    errors=remount-ro 0       1
# swap was on /dev/sda5 during installation
UUID=889d958f-02ec-4d04-9252-01fabc01bb17 none            swap    sw              0       0
/dev/sr0        /media/cdrom0   udf,iso9660 user,noauto     0       0

Os comentários do próprio arquivo já dão duas dicas importantes: use UUID= e rode systemctl daemon-reload depois de editar. As três linhas de verdade são:

LinhaO que faz
UUID=5018… / ext4 errors=remount-ro 0 1Monta a partição do sistema em /. Se der erro de disco, ela vira só leitura. Verificada primeiro no boot (1).
UUID=889d… none swap sw 0 0Liga a partição de swap. Não tem pasta (none).
/dev/sr0 /media/cdrom0 udf,iso9660 user,noauto 0 0O leitor de DVD: não monta no boot (noauto), mas qualquer usuário pode montar com mount /media/cdrom0 (user). Só aparece se você instalou a partir de um CD/DVD/ISO.

Cada linha tem seis colunas, separadas por espaços ou tabs:

UUID=fb1d…
1. O quê: a partição. Use o UUID: o nome /dev/sdb1 pode mudar se você trocar um cabo de lugar.
/dados
2. Onde: o ponto de montagem (a pasta precisa existir).
ext4
3. Tipo do sistema de arquivos.
defaults,nofail
4. Opções. defaults é o padrão; nofail evita travar o boot se o disco faltar.
0
5. dump: coluna antiga de backup. Use sempre 0.
2
6. Ordem de verificação no boot: 1 para o /, 2 para os outros discos, 0 para não verificar.

Passo a passo: um HD extra em /dados

Os passos abaixo valem para um HD de verdade (/dev/sdb1). Para treinar, use o /dev/loop0 do laboratório.

  1. Ache o UUID da partição do HD (como root, o blkid está disponível): 
    #> blkid /dev/loop0
/dev/loop0: LABEL="DADOS" UUID="fb1d2c8d-ee57-44f8-b7f8-a43bf0439a12" BLOCK_SIZE="1024" TYPE="ext4"
  2. Crie a pasta e faça uma cópia do fstab atual, para poder voltar atrás: 
    #> mkdir -p /dados
#> cp /etc/fstab /etc/fstab.bak
  3. Acrescente a linha no fim do arquivo com nano /etc/fstab (veja nano e vim): 
    UUID=fb1d2c8d-ee57-44f8-b7f8-a43bf0439a12  /dados  ext4  defaults,nofail  0  2
  4. Confira o arquivo antes de reiniciar. O findmnt --verify procura erros. Num Debian instalado por DVD/ISO, ele sempre mostra um aviso sobre o leitor de DVD vazio, o que é normal: 
    #> findmnt --verify

0 erro de análise, 0 erro, 1 aviso
/media/cdrom0
   [W] não foi possível detectar o tipo de sistema de arquivos em disco (Mídia não encontrada)   « normal: não há DVD

    O que importa é 0 erro. Avisos [W] merecem uma lida; erros [E] precisam ser corrigidos.

  5. Teste sem reiniciar. O systemctl daemon-reload avisa o sistema que o fstab mudou (o próprio arquivo pede isso), e o mount -a monta tudo o que está no fstab e ainda não está montado: 
    #> systemctl daemon-reload
#> mount -a
#> findmnt /dados
TARGET SOURCE     FSTYPE OPTIONS
/dados /dev/loop0 ext4   rw,relatime

    Se o mount -a mostrar qualquer erro, não reinicie: corrija a linha ou volte o backup com cp /etc/fstab.bak /etc/fstab.

  6. Dê a pasta para a sua usuária, porque um ext4 novo pertence ao root: 
    #> chown ana:ana /dados

Como o findmnt --verify mostra um erro

Veja o que acontece se a linha nova tiver um UUID errado e outra linha tiver um tipo digitado errado (ext44). O teste foi feito numa cópia do fstab, com --tab-file:

#> findmnt --verify --tab-file /tmp/fstab.teste
/media/cdrom0
   [W] não foi possível detectar o tipo de sistema de arquivos em disco (Mídia não encontrada)
/dados
   [E] alvo não alcançável na inicialização: Arquivo ou diretório inexistente   « a pasta /dados não existe
   [E] fonte não alcançável na inicialização: UUID=0000-ERRADO                   « UUID que não existe
/backup
   [E] alvo não alcançável na inicialização: Arquivo ou diretório inexistente
   [W] fonte não alcançável: /dev/sdb1: Arquivo ou diretório inexistente
   [W] ext44 parece não possuir suporte no kernel atual                          « erro de digitação no tipo
   [W] não foi possível detectar o tipo de sistema de arquivos em disco (Arquivo ou diretório inexistente)

0 erro de análise, 3 erros, 4 avisos
Treine com uma cópia

Copie o fstab (cp /etc/fstab /tmp/fstab.teste), edite a cópia e verifique com findmnt --verify --tab-file /tmp/fstab.teste. Assim você aprende a ler os erros sem nenhum risco.

Um fstab errado pode impedir o boot

Sem nofail, se o disco não for encontrado, o sistema espera 90 segundos e para no modo de emergência (uma tela de texto, em inglês, que pede a senha do root). Sempre rode findmnt --verify e mount -a antes de reiniciar. Se acontecer, digite a senha do root, corrija o arquivo com nano /etc/fstab e reinicie. Veja Recuperar um Sistema.

Quando não funciona

"é necessário ser superusuário para montar" 
$ mount /dev/sda1 /mnt
mount: /mnt: é necessário ser superusuário para montar.
       dmesg(1) pode ter mais informação após uma chamada a montar o sistema falhada.

O que aconteceu: só o root pode montar com mount (exceto entradas do fstab marcadas com user, como o DVD).

Como resolver: entre como root com su - e repita. No desktop, para pendrives, use o app Arquivos ou udisksctl, que não pedem senha.

"o ponto de montagem não existe" 
#> mount /dev/loop0 /mnt/usb
mount: /mnt/usb: o ponto de montagem não existe.
       dmesg(1) pode ter mais informação após uma chamada a montar o sistema falhada.

Como resolver: crie a pasta antes: mkdir -p /mnt/usb.

"Can't lookup blockdev": o dispositivo não existe 
#> mount /dev/sdz9 /mnt/dados
mount: /mnt/dados: fsconfig() falhou: /dev/sdz9: Can't lookup blockdev.
       dmesg(1) pode ter mais informação após uma chamada a montar o sistema falhada.

O que aconteceu: o nome está errado ou o pendrive não foi detectado. A parte "Can't lookup blockdev" vem do kernel e fica em inglês.

Como resolver: confira o nome com lsblk. Se o pendrive não aparece, troque de porta USB e veja as mensagens do kernel com dmesg | tail (como root).

"o alvo está ocupado" ao desmontar 
#> umount /mnt/dados
umount: /mnt/dados: o alvo está ocupado.
#> lsof /mnt/dados
COMMAND   PID USER  FD   TYPE DEVICE SIZE/OFF NODE NAME
bash    11032 ana  cwd    DIR    7,0     1024    2 /mnt/dados          « um terminal está dentro da pasta

O que aconteceu: algum programa está usando arquivos do disco. Muitas vezes é um terminal que está dentro da pasta (cwd = pasta atual).

Como resolver: saia da pasta com cd ou feche o programa e tente de novo. O lsof vem instalado no Debian; o fuser, não (está no pacote psmisc).

"tipo de sistema de arquivos incorreto" 
#> mount -t vfat /dev/loop0 /mnt/dados
mount: /mnt/dados: tipo de sistema de arquivos incorreto, opção inválida, superbloco inválido em /dev/loop0, página de código ou programa auxiliar faltando ou outro erro.
       dmesg(1) pode ter mais informação após uma chamada a montar o sistema falhada.

O que aconteceu: o tipo informado com -t está errado (o disco é ext4), a partição está danificada ou falta o programa do sistema de arquivos (para exFAT/NTFS, instale exfatprogs ou ntfs-3g).

Como resolver: tire o -t e deixe o mount descobrir, ou confira o tipo com lsblk -f.

Resumo

  • Montar = ligar uma partição a uma pasta. Veja com findmnt.
  • No Debian sem sudo, mount e umount são feitos como root (su -).
  • O fstab do Debian usa UUID=, errors=remount-ro no /, uma partição de swap e uma linha para o DVD.
  • Antes de reiniciar: findmnt --verify, systemctl daemon-reload e mount -a.
  • Use nofail em discos extras e pratique com arquivos-imagem e losetup.
