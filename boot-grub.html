Debian Boot, GRUB e Kernel

Entre apertar o botão de ligar e ver a tela de login, várias peças trabalham em sequência. Quando o sistema não liga, saber qual peça falhou é metade da solução. Nesta aula você vai conhecer o caminho do boot no Debian 13, o menu do GRUB, os kernels instalados e como medir o tempo de inicialização.

Você vai aprender
  • O caminho do boot: firmware → GRUB → kernel → initramfs → systemd.
  • Ler o menu do GRUB do Debian, que aparece por 5 segundos a cada boot.
  • Mudar o /etc/default/grub e aplicar com update-grub.
  • Ver os kernels instalados e iniciar com o anterior quando o novo falhar.
  • Medir o boot com systemd-analyze.

As saídas desta aula vêm de um Debian 13.7 real. Os comandos que alteram o boot precisam de root (su -).

Antes do comando: o caminho do boot

  1. Firmware (BIOS ou UEFI). O programa gravado na placa-mãe testa o hardware e procura um disco para iniciar.
  2. GRUB. O carregador de boot (bootloader) do Debian. Mostra o menu e carrega o kernel escolhido.
  3. Kernel (/boot/vmlinuz-…). O núcleo do sistema: conversa com o hardware.
  4. initramfs (/boot/initrd.img-…). Um mini-sistema temporário com o que o kernel precisa para achar e montar o disco de verdade.
  5. systemd. O primeiro programa (PID 1). Monta os discos do /etc/fstab, liga a rede e os serviços, e mostra o login.

Para saber se a máquina usa BIOS ou UEFI, veja se existe a pasta /sys/firmware/efi:

$ ls /sys/firmware/efi
ls: não foi possível acessar '/sys/firmware/efi': Arquivo ou diretório inexistente     « não existe: BIOS (modo legado)

Com BIOS, o Debian usa o pacote grub-pc. Com UEFI, usa grub-efi-amd64 e o shim-signed (para o Secure Boot). Confira qual está instalado:

$ dpkg -l 'grub-pc' 'grub-efi-amd64' 2>/dev/null | grep ^ii
ii  grub-pc         2.12-9+deb13u2 amd64        GRand Unified Bootloader, version 2 (PC/BIOS version)

Configurar o GRUB: /etc/default/grub

Você não edita o /boot/grub/grub.cfg direto: ele é gerado de novo a cada atualização de kernel. As preferências ficam em /etc/default/grub. Estas são as linhas ativas no Debian 13:

GRUB_DEFAULT=0                    # qual opção vem selecionada (0 = a primeira)
GRUB_TIMEOUT=5                    # segundos de espera no menu
GRUB_DISTRIBUTOR=`( . /etc/os-release && echo ${NAME} )`   # vira "Debian GNU/Linux" no menu
GRUB_CMDLINE_LINUX_DEFAULT="quiet"  # parâmetros do kernel no boot normal
GRUB_CMDLINE_LINUX=""             # parâmetros em todos os boots, inclusive recuperação

Exemplo: mais tempo no menu e boot sem "quiet"

  1. Edite como root: nano /etc/default/grub.
  2. Troque GRUB_TIMEOUT=5 por GRUB_TIMEOUT=10 e "quiet" por "" (assim você vê as mensagens do kernel no boot).
  3. Gere o menu de novo com update-grub.
#> update-grub
Generating grub configuration file ...
Found linux image: /boot/vmlinuz-6.12.111+deb13-amd64          « os kernels que ele achou
Found initrd image: /boot/initrd.img-6.12.111+deb13-amd64
Found linux image: /boot/vmlinuz-6.12.86+deb13-amd64
Found initrd image: /boot/initrd.img-6.12.86+deb13-amd64
Warning: os-prober will not be executed to detect other bootable partitions.
Systems on them will not be added to the GRUB boot configuration.
Check GRUB_DISABLE_OS_PROBER documentation entry.
Adding boot menu entry for UEFI Firmware Settings ...
done

O aviso do os-prober é normal. Ele só importa se você tem outro sistema (Windows, outra distro) no mesmo computador e quer que ele apareça no menu. Nesse caso, descomente GRUB_DISABLE_OS_PROBER=false no /etc/default/grub e rode update-grub de novo.

+deb13
Compilado pelo Debian para o Debian 13.
-amd64
Arquitetura: PCs de 64 bits.

E os pacotes de kernel instalados:

$ dpkg -l 'linux-image*' | grep ^ii
ii  linux-image-6.12.111+deb13-amd64  6.12.111-1  amd64  Linux 6.12 for 64-bit PCs (signed)   « o atual
ii  linux-image-6.12.86+deb13-amd64   6.12.86-1   amd64  Linux 6.12 for 64-bit PCs (signed)   « o da instalação
ii  linux-image-amd64                 6.12.111-1  amd64  Linux for 64-bit PCs (meta-package)   « puxa sempre o mais novo

O pacote linux-image-amd64 é um metapacote: ele não tem kernel dentro, só aponta para o mais recente. É por causa dele que o apt upgrade instala kernels novos. O Debian mantém o kernel anterior como reserva; o apt autoremove só remove os mais antigos que esses dois.

Iniciar com o kernel anterior

Se o computador parou de ligar depois de uma atualização de kernel:

  1. No menu do GRUB, escolha Advanced options for Debian GNU/Linux.
  2. Escolha a linha com o kernel anterior, sem "(recovery mode)": Debian GNU/Linux, with Linux 6.12.86+deb13-amd64.
  3. Com o sistema de pé, investigue o problema (journalctl -b -1 -p err mostra os erros do boot que falhou; veja Logs).

O initramfs

No Debian o initramfs é gerado pelo initramfs-tools, automaticamente a cada kernel novo. Se você mudar algo que o boot precisa (um módulo, a configuração de criptografia do disco), gere de novo:

#> update-initramfs -u
update-initramfs: Generating /boot/initrd.img-6.12.111+deb13-amd64

Parâmetros do kernel

Os parâmetros com que o kernel atual foi iniciado ficam em /proc/cmdline:

$ cat /proc/cmdline
BOOT_IMAGE=/boot/vmlinuz-6.12.111+deb13-amd64 root=UUID=50185294-cee5-49de-a27c-2cf995361c67 ro quiet
root=UUID=…
Qual partição é a raiz (/), pelo identificador único.
ro
Montar a raiz só para leitura no começo; o systemd remonta como leitura e escrita depois de verificar.
quiet
Esconder a maior parte das mensagens do kernel.

Para mudar um parâmetro só uma vez, sem tocar em arquivos: no menu do GRUB, selecione a opção, aperte e, ache a linha que começa com linux, acrescente o parâmetro no fim e aperte Ctrl+X (ou F10) para iniciar. Na próxima vez, tudo volta ao normal.

ParâmetroPara quê
systemd.unit=rescue.targetModo de manutenção (pede a senha do root). Veja Recuperar um Sistema.
systemd.unit=emergency.targetO mínimo possível: só a raiz, em modo leitura
nomodesetTela preta com placa de vídeo nova: usa o vídeo básico
3 ou systemd.unit=multi-user.targetInicia sem interface gráfica

Medir o tempo de boot

$ systemd-analyze
Startup finished in 23.386s (kernel) + 9.122s (userspace) = 32.508s
graphical.target reached after 9.121s in userspace.

A primeira parte é o tempo do kernel e do initramfs; a segunda, o dos serviços. Para ver quem demorou mais:

$ systemd-analyze blame | head -6
2.585s dev-sda1.device
2.245s e2scrub_reap.service
2.025s wtmpdb-update-boot.service
1.659s apparmor.service
 895ms ssh.service
 822ms systemd-journal-flush.service

Os números variam muito entre computadores (esses vêm de uma máquina virtual). O blame mostra quanto cada serviço levou, mas serviços rodam em paralelo; para ver o que realmente atrasou o login, use systemd-analyze critical-chain. Veja mais em Desempenho e Monitoramento.

Quando não funciona

Mudei o /etc/default/grub e nada mudou

O que aconteceu: faltou rodar update-grub. O GRUB lê o /boot/grub/grub.cfg, não o /etc/default/grub.

"update-grub: comando não encontrado"

O que aconteceu: você está como usuário comum; o comando fica em /usr/sbin. Entre com su -.

O Windows sumiu do menu depois de instalar o Debian

O que aconteceu: o os-prober vem desativado (é o aviso que o update-grub mostra).

Como resolver: instale o pacote os-prober, descomente GRUB_DISABLE_OS_PROBER=false e rode update-grub. A linha Found Windows Boot Manager … deve aparecer.

Depois de atualizar, a tela fica preta

Como resolver: inicie com o kernel anterior (Advanced options) ou edite a opção com e e acrescente nomodeset. Com o sistema de pé, veja os erros com journalctl -b -1 -p err.

O GRUB nem aparece: tela com "grub rescue>"

O que aconteceu: o GRUB não achou seus arquivos (disco trocado, partição apagada).

Como resolver: inicie por um pendrive do Debian e reinstale o GRUB com chroot. Passo a passo em Recuperar um Sistema.

Resumo

  • Boot: firmware → GRUB → kernel → initramfs → systemd.
  • O Debian mostra o menu do GRUB por 5 segundos; os outros kernels e a recuperação ficam em "Advanced options".
  • Preferências em /etc/default/grub; aplique com update-grub.
  • linux-image-amd64 traz kernels novos; o anterior fica como reserva.
  • e no menu muda parâmetros só uma vez; systemd-analyze mede o boot.
