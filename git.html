Debian Git

O Git guarda o histórico de uma pasta: cada versão salva (um commit) fica registrada com data, autor e uma mensagem. Você volta no tempo, compara versões, testa ideias num "ramo" separado e junta o trabalho de várias pessoas. Serve para código, mas também para configurações de servidor, documentos e até receitas.

Você vai aprender
  • Instalar e configurar o Git no Debian.
  • O ciclo básico: status, add, commit, log, diff.
  • Ramos (branches), merge e como resolver um conflito.
  • Ignorar arquivos com .gitignore e enviar para o GitHub com SSH.
  • Por que o Git do Debian aparece em inglês, ou em português de Portugal.

Tudo nesta página foi rodado no Debian 13 de laboratório, com Git 2.47.3, pela usuária ana, num projeto de exemplo chamado receitas.

Conceito: três lugares

Pense numa mudança de casa: você mexe nas coisas (pasta de trabalho), coloca o que vai levar numa caixa (preparação) e fecha a caixa com uma etiqueta (commit).

Instalar e configurar

O Git não vem no Debian mínimo. Instale como root (veja root, su e sudo):

$ git status
bash: git: comando não encontrado
$ su -
Senha:
#> apt install git
#> exit
$ git --version
git version 2.47.3

Antes do primeiro commit, diga quem você é. Isso vai em cada commit:

git config
Lê e grava configurações do Git.
--global
Para todos os seus projetos (fica em ~/.gitconfig).
user.name "Ana"
A opção e o valor.
$ git config --global user.name "Ana"
$ git config --global user.email "ana@example.com"
$ git config --global init.defaultBranch main

A última linha define o nome do ramo principal dos projetos novos. Sem ela, o Git do Debian usa master e mostra um aviso longo a cada git init.

Começar um projeto: git init

$ mkdir ~/receitas
$ cd ~/receitas
$ git status
fatal: not a git repository (or any of the parent directories): .git      « ainda não é um projeto Git
$ git init
Initialized empty Git repository in /home/ana/receitas/.git/

O git init criou a pasta oculta .git, onde fica todo o histórico. Apagar essa pasta apaga o histórico (mas não os seus arquivos).

O ciclo: status → add → commit

1. git status: o que mudou?

$ echo "# Receitas" > README.md
$ echo "bolo de cenoura" > bolo.txt
$ git status
On branch main                                      « você está no ramo main

No commits yet

Untracked files:                                    « arquivos que o Git ainda não acompanha
  (use "git add <file>..." to include in what will be committed)
	README.md
	bolo.txt

nothing added to commit but untracked files present (use "git add" to track)

2. git add: preparar

$ git add README.md bolo.txt
$ git status
On branch main

No commits yet

Changes to be committed:                            « estão na "caixa"
  (use "git rm --cached <file>..." to unstage)
	new file:   README.md
	new file:   bolo.txt

3. git commit: salvar a versão

git commit
Grava tudo o que está preparado como uma versão nova.
-m "…"
A mensagem. Sem -m, o Git abre um editor (no Debian, o nano por padrão) para você escrever.
$ git commit -m "Primeira versão das receitas"
[main (root-commit) b7f4d29] Primeira versão das receitas
 2 files changed, 2 insertions(+)
 create mode 100644 README.md
 create mode 100644 bolo.txt

b7f4d29 é o começo do identificador do commit. Você usa ele para se referir a essa versão.

Ver o histórico e as diferenças

$ echo "2 xícaras de farinha" >> bolo.txt
$ git diff
diff --git a/bolo.txt b/bolo.txt
index 50d486e..7973c97 100644
--- a/bolo.txt
+++ b/bolo.txt
@@ -1 +1,2 @@
 bolo de cenoura
+2 xícaras de farinha                       « + = linha acrescentada (- seria removida)
$ git commit -am "Ingredientes do bolo"
[main 52f0996] Ingredientes do bolo
 1 file changed, 1 insertion(+)
$ git log --oneline
52f0996 Ingredientes do bolo                « o mais novo em cima
b7f4d29 Primeira versão das receitas
-a
Faz o add automático de arquivos que o Git já acompanha. Arquivos novos ainda precisam de git add.
-m
A mensagem.

Ramos: testar sem medo

Um ramo (branch) é uma linha paralela de commits. Você cria um, experimenta, e só junta no principal se der certo.

$ git switch -c cobertura
Switched to a new branch 'cobertura'
$ echo "cobertura de chocolate" >> bolo.txt
$ git commit -qam "Cobertura"
$ git switch main
Switched to branch 'main'
$ echo "forno 180 graus" >> bolo.txt
$ git commit -qam "Forno"
git switch
Muda de ramo.
-c cobertura
create: cria o ramo cobertura e já muda para ele.
-q
quiet: sem mensagens.

Juntar: git merge e o conflito

Os dois ramos mudaram a mesma linha (a última do bolo.txt). O Git não sabe qual escolher e pede ajuda:

$ git merge cobertura
Auto-merging bolo.txt
CONFLICT (content): Merge conflict in bolo.txt
Automatic merge failed; fix conflicts and then commit the result.
$ git status
On branch main
You have unmerged paths.
  (fix conflicts and run "git commit")
  (use "git merge --abort" to abort the merge)

Unmerged paths:
  (use "git add <file>..." to mark resolution)
	both modified:   bolo.txt               « os dois lados mexeram aqui
$ cat bolo.txt
bolo de cenoura
2 xícaras de farinha
<<<<<<< HEAD                                « início da versão do ramo atual (main)
forno 180 graus
=======                                     « separador
cobertura de chocolate
>>>>>>> cobertura                           « fim da versão do outro ramo
  1. Abra o arquivo no editor (nano bolo.txt).
  2. Decida o resultado final. Aqui queremos as duas linhas.
  3. Apague as marcas <<<<<<<, ======= e >>>>>>>.
  4. Marque como resolvido com git add e termine com git commit.
bolo de cenoura
2 xícaras de farinha
forno 180 graus
cobertura de chocolate
$ git add bolo.txt
$ git commit -m "Junta forno e cobertura"
[main a0f6b5e] Junta forno e cobertura
$ git log --oneline --graph --all
*   a0f6b5e Junta forno e cobertura          « o commit de merge tem dois "pais"
|\
| * 094da9c Cobertura
* | c24cd6e Forno
|/
* 52f0996 Ingredientes do bolo
* b7f4d29 Primeira versão das receitas
$ git branch -d cobertura
Deleted branch cobertura (was 094da9c).
Desistir do merge

No meio de um conflito, git merge --abort volta tudo para antes do merge.

Ignorar arquivos: .gitignore

Senhas, arquivos temporários e pastas geradas não devem ir para o histórico. Liste-os no arquivo .gitignore:

$ echo "senha=123" > .env
$ echo ".env" > .gitignore
$ git status --short
?? .gitignore                    « o .env nem aparece: está ignorado
Atenção: o .gitignore não apaga o passado

Se uma senha já entrou num commit, ela continua no histórico mesmo depois de ignorada. Troque a senha.

GitHub (ou outro servidor) com SSH

  1. Crie uma chave SSH, se ainda não tiver: ssh-keygen -t ed25519 (veja SSH).
  2. Copie a chave pública (cat ~/.ssh/id_ed25519.pub) para o site, em Settings → SSH keys.
  3. Crie o repositório vazio no site e ligue o seu projeto a ele.
git remote add
Cadastra um servidor remoto.
origin
O apelido do remoto (por convenção, origin).
git@github.com:ana/receitas.git
O endereço SSH do repositório.
$ git remote add origin git@github.com:ana/receitas.git
$ git push -u origin main
$ git pull                     « traz as mudanças feitas por outras pessoas

O -u do primeiro push liga o ramo local ao remoto; depois disso, basta git push e git pull.

Por que o Git está em inglês?

Quase tudo no Debian em pt-BR aparece em português, mas o Git não. O pacote do Debian só traz a tradução de Portugal (pt_PT), não a do Brasil:

$ ls /usr/share/locale/pt_BR/LC_MESSAGES/git.mo
ls: não foi possível acessar '/usr/share/locale/pt_BR/LC_MESSAGES/git.mo': Arquivo ou diretório inexistente
$ ls /usr/share/locale/pt_PT/LC_MESSAGES/git.mo
/usr/share/locale/pt_PT/LC_MESSAGES/git.mo
$ LANGUAGE=pt_PT git status
Em ramo main
nada a memorizar, árvore-trabalho limpa              « o português de Portugal do Git

Como os tutoriais e as respostas na internet usam o Git em inglês, a recomendação é deixá-lo assim. Se o seu sistema estiver em pt-BR e você quiser garantir o inglês, crie o apelido alias git='LANGUAGE=en git' no .bashrc.

Quando não funciona

"Author identity unknown"

O que aconteceu: faltou configurar nome e e-mail. Como resolver: git config --global user.name "…" e user.email.

"fatal: No configured push destination." 
$ git push
fatal: No configured push destination.
Either specify the URL from the command-line or configure a remote repository using

    git remote add <name> <url>

O que aconteceu: o projeto não tem remoto. Como resolver: git remote add origin … e git push -u origin main.

"Host key verification failed" / "Permission denied (publickey)" 
$ git push -u origin main
Host key verification failed.
fatal: Could not read from remote repository.

Please make sure you have the correct access rights
and the repository exists.

O que aconteceu: o primeiro contato SSH com o servidor não foi confirmado, ou a sua chave não está cadastrada no site. Como resolver: rode ssh -T git@github.com uma vez e confirme a impressão digital; confira se a chave pública está no site. Veja SSH.

Commitei no ramo errado

Como resolver: se ainda não fez push, crie o ramo certo ali mesmo (git branch ramo-certo) e volte o ramo atual um commit: git reset --hard HEAD~1.

Cuidado

reset --hard descarta alterações não salvas. Confira com git status antes.

Resumo

  • Ciclo: editar → git add → git commit -m; confira sempre com git status.
  • git log --oneline --graph mostra o histórico; git diff, o que mudou.
  • Ramos (git switch -c) isolam experimentos; git merge junta.
  • Conflito: edite, apague as marcas, git add, git commit.
  • No Debian, o Git fica em inglês (só há tradução pt_PT), e é assim que os tutoriais o mostram.
