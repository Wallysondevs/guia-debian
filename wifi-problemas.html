Debian Wi-Fi que Não Funciona

Às vezes o Wi-Fi nem chega a pedir senha: a lista de redes vem vazia, o ícone some ou a placa aparece como "não disponível". Quase sempre a causa é uma de três: o rádio está bloqueado (modo avião), falta o firmware da placa, ou o kernel não tem driver para ela (comum em adaptadores USB). Esta aula é um roteiro para descobrir qual é, e o que fazer em cada caso.

Você vai aprender
  • Verificar se o Linux enxerga a placa Wi-Fi (ip link, nmcli device).
  • Destravar o Wi-Fi bloqueado com rfkill e entender a diferença entre bloqueio soft e hard.
  • Identificar a placa e o driver com lspci -k e lsusb.
  • Achar no dmesg o firmware que falta e instalar o pacote firmware-* certo, do componente non-free-firmware.
  • Saber quais adaptadores Realtek USB o Debian 13 reconhece, e qual é o plano B.
De onde vêm as saídas desta aula

Os comandos de bloqueio (rfkill, nmcli radio, ifup), as listas de pacotes e de drivers foram conferidos no Debian 13 da máquina de laboratório, com placas Wi-Fi virtuais (veja Como o laboratório foi feito). Uma placa virtual nunca precisa de firmware e a VM não tem USB, então as mensagens de firmware faltando e as linhas de adaptadores reais estão marcadas como ilustrativas.

Passo 2: o rádio está bloqueado? rfkill

Notebooks têm um "modo avião": uma tecla (Fn+F2, Fn+F12, uma tecla com desenho de antena ou avião) ou, nos mais antigos, uma chavinha na lateral. Ela desliga o rádio. O Linux chama isso de rfkill (radio frequency kill, "desligar o rádio").

O rfkill vem no pacote de mesmo nome, que um servidor mínimo não tem:

#> rfkill
bash: rfkill: comando não encontrado
#> apt install rfkill

Com ele instalado (os desktops costumam tê-lo), rode como root:

#> rfkill
ID TYPE DEVICE         SOFT         HARD
 2 wlan phy2   desbloqueado desbloqueado     « a placa do notebook (wlp2s0)
 3 wlan phy3   desbloqueado desbloqueado     « só no laboratório: o "roteador"
ColunaO que quer dizer
IDO número do rádio. Serve para bloquear ou desbloquear só ele.
TYPEwlan (Wi-Fi), bluetooth, wwan (modem 4G).
DEVICEO rádio físico (phy2). Para saber de qual placa é: iw dev wlp2s0 info mostra wiphy 2.
SOFTBloqueio por software: um programa ou uma tecla que avisa o sistema. Destrava com rfkill unblock.
HARDBloqueio por hardware: chave física, tecla ligada direto à placa ou opção da BIOS. Nenhum comando destrava.

No seu notebook aparece um rádio wlan (e talvez um bluetooth). A forma longa, rfkill list, diz o mesmo em outro formato.

O que acontece com o Wi-Fi bloqueado

Sequência real: o bloqueio foi feito de propósito, com rfkill block, para simular a tecla de modo avião.

rfkill block
Bloqueia (desliga) o rádio.
wifi
Todos os rádios Wi-Fi. Também aceita o ID de um só (rfkill block 2), bluetooth ou all.
#> rfkill block wifi
#> rfkill list
2: phy2: Wireless LAN
	Soft blocked: yes             « bloqueado por software
	Hard blocked: no
3: phy3: Wireless LAN
	Soft blocked: yes
	Hard blocked: no
#> nmcli radio
WIFI-HW     WIFI          WWAN-HW  WWAN
habilitado  desabilitado  missing  habilitado     « o NetworkManager percebe
#> nmcli device status | grep wlp2s0
wlp2s0          wifi      não disponível          --
#> nmcli device wifi list ifname wlp2s0
IN-USE  BSSID  SSID  MODE  CHAN  RATE  SIGNAL  BARS  SECURITY     « lista vazia
#> nmcli connection up CasaDaAna
Erro: Ativação da conexão falhou: No suitable device found for this connection (device wlp2s0 not available because device is not available).

No servidor, com o Wi-Fi no /etc/network/interfaces, o ifup avisa com todas as letras (aqui só a placa do notebook foi bloqueada, com rfkill block 2):

#> ifup wlp2s0
…
dhcpcd_prestartinterface: Operation not possible due to RF-kill     « "operação impossível por causa do RF-kill"
wlp2s0: waiting for carrier
timed out

Para destravar:

#> rfkill unblock wifi
#> rfkill
ID TYPE DEVICE         SOFT         HARD
 2 wlan phy2   desbloqueado desbloqueado
 3 wlan phy3   desbloqueado desbloqueado

Como de costume, block e unblock não mostram nada quando dão certo (código 0). No desktop, a conexão salva voltou sozinha alguns segundos depois do desbloqueio (o autoconnect do NetworkManager). No servidor, rode ifdown wlp2s0 e ifup wlp2s0.

nmcli radio wifi off é um rfkill

No laboratório, depois de nmcli radio wifi off, o rfkill mostrou os rádios como bloqueado na coluna SOFT. São dois jeitos de fazer a mesma coisa: nmcli radio wifi on também destrava.

Bloqueio por hardware (ilustrativo)

Uma placa virtual não tem chave física, então este caso não foi reproduzido. Num notebook com a chave do Wi-Fi desligada, o rfkill mostra algo assim:

#> rfkill list
0: phy0: Wireless LAN
	Soft blocked: no
	Hard blocked: yes             « chave física, tecla ou BIOS

E o nmcli radio mostra WIFI-HW como desabilitado. O rfkill unblock não muda nada. Procure a chave na lateral ou na frente do notebook, a tecla de modo avião (às vezes com um LED), ou a opção "Wireless"/"WLAN" no setup da BIOS/UEFI.

Passo 3: qual é a placa? lspci -k e lsusb

Se nenhuma placa wl… aparece, descubra se o computador enxerga o aparelho e qual driver o kernel tentou usar. Placas internas ficam no barramento PCI; adaptadores "pen drive" ficam no USB.

Placa interna: lspci -k

lspci
(list PCI) Lista os aparelhos ligados à placa-mãe (pacote pciutils, já instalado no Debian).
-k
(kernel) Mostra o driver (módulo do kernel) de cada aparelho.

Saída real da máquina de laboratório, só com a placa de cabo (uma VM não tem placa Wi-Fi PCI):

$ lspci -k | grep -A3 -i -E 'ethernet|network'
00:03.0 Ethernet controller: Intel Corporation 82540EM Gigabit Ethernet Controller (rev 02)
	Subsystem: Intel Corporation PRO/1000 MT Desktop Adapter
	Kernel driver in use: e1000          « o driver que está cuidando dela
	Kernel modules: e1000                « os drivers que servem para ela

(O grep -A3 mostra a linha encontrada e as 3 seguintes; veja grep.) Placas Wi-Fi aparecem como Network controller. Num notebook com Wi-Fi Intel, a saída seria assim (ilustrativa):

$ lspci -k | grep -A3 -i network
02:00.0 Network controller: Intel Corporation Wi-Fi 6 AX201 (rev 20)
	Subsystem: Intel Corporation Device 0070
	Kernel driver in use: iwlwifi        « se esta linha falta, o driver não conseguiu assumir a placa
	Kernel modules: iwlwifi
Você vêO que quer dizer
Kernel driver in use e uma placa wl… no ip linkTudo certo com o hardware. Volte ao rfkill ou a Wi-Fi.
Kernel modules, mas sem Kernel driver in useExiste driver, mas ele falhou ao ligar a placa. Quase sempre: firmware faltando (Passo 4).
Nem Kernel modulesO kernel não tem driver para essa placa. Veja placas sem driver.
A placa nem aparece no lspciDesligada na BIOS, mal encaixada, ou é USB (use o lsusb).

Adaptador USB: lsusb

O lsusb (list USB) vem no pacote usbutils, que um servidor mínimo também não tem (apt install usbutils). Na VM do laboratório, que não tem USB, ele não mostrou nada e devolveu o código 1. Num computador com um adaptador Wi-Fi Realtek, a saída seria assim (ilustrativa):

$ lsusb
Bus 001 Device 001: ID 1d6b:0002 Linux Foundation 2.0 root hub
Bus 001 Device 003: ID 0bda:b812 Realtek Semiconductor Corp. RTL88x2bu [AC1200 Techkey]   « o adaptador Wi-Fi
Bus 002 Device 001: ID 1d6b:0003 Linux Foundation 3.0 root hub

O que importa é o ID 0bda:b812: 0bda é o fabricante (Realtek) e b812, o produto. Com esse número, pesquise "0bda:b812 linux" para descobrir o chip (aqui, RTL8822BU) e o driver. Se o adaptador nem aparece no lsusb, troque de porta (de preferência direto no computador, sem hub) ou teste-o em outro computador.

Passo 4: falta firmware? dmesg

Uma placa Wi-Fi precisa de duas coisas: o driver, código do kernel que fala com a placa, e o firmware, um programinha que roda dentro da própria placa e que o driver envia para ela ao ligar. Quase todo firmware de Wi-Fi é fechado (não livre), então o Debian o coloca num componente separado do repositório, o non-free-firmware (veja Repositórios).

O instalador já cuida disso, na maioria das vezes

Desde o Debian 12, a ISO oficial traz os pacotes de firmware e o instalador instala sozinho os que o seu hardware pede. Num Debian que não precisou de nenhum (como a VM do guia), a pasta de firmware fica quase vazia. Saída real:

$ ls /lib/firmware
intel-ucode  regulatory.db  regulatory.db-debian  regulatory.db.p7s  regulatory.db.p7s-debian  regulatory.db.p7s-upstream  regulatory.db-upstream

O problema aparece quando você troca a placa, conecta um adaptador USB novo, ou instalou com uma imagem sem firmware.

Achar a mensagem do kernel

dmesg
(display message) As mensagens do kernel desde o boot. No Debian, só o root pode ler.
| grep -i firmware
Só as linhas com "firmware", sem diferenciar maiúsculas (-i).

Na máquina de laboratório, onde nada falta, a única linha é de outro assunto (real):

#> dmesg | grep -i firmware
[   24.283349] systemd[1]: systemd-hibernate-clear.service - Clear Stale Hibernate Storage Info skipped, unmet condition check ConditionPathExists=/sys/firmware/efi/efivars/HibernateLocation-8cf2644b-4b0b-428f-9387-6d876050dc67

Num computador com o problema, aparece uma linha com Direct firmware load … failed with error -2 ("a carga do firmware falhou, erro −2", isto é, arquivo não encontrado). Dois exemplos ilustrativos:

#> dmesg | grep -i firmware
[    7.412345] iwlwifi 0000:02:00.0: Direct firmware load for iwlwifi-QuZ-a0-hr-b0-77.ucode failed with error -2   « Wi-Fi Intel
[    7.412360] iwlwifi 0000:02:00.0: no suitable firmware found!
[    9.118201] rtw_8822bu 1-3:1.0: Direct firmware load for rtw88/rtw8822b_fw.bin failed with error -2           « adaptador Realtek USB

Leia a linha assim: o começo (iwlwifi, rtw_8822bu) é o driver; depois de for vem o arquivo que faltou, procurado dentro de /lib/firmware. O driver e o arquivo dizem qual pacote instalar (tabela abaixo).

Outro lugar onde o Debian avisa

Toda vez que o kernel ou o initramfs é atualizado (no apt upgrade), o Debian confere os firmwares e avisa com linhas que começam com W: Possible missing firmware /lib/firmware/…. Se o arquivo citado é do seu Wi-Fi, é o mesmo problema.

$ cd /tmp

Instalar o firmware

  1. Confira o componente non-free-firmware no /etc/apt/sources.list (o instalador já o coloca). Linha real da VM: 
    deb http://deb.debian.org/debian trixie main non-free-firmware
    Se a linha só tem main, acrescente non-free-firmware no fim das linhas e rode apt update.
  2. Instale o pacote (como root, com internet por cabo ou pelo celular): 
    #> apt install firmware-iwlwifi
  3. Recarregue o driver para ele pedir o firmware de novo, ou simplesmente reinicie: 
    #> modprobe -r iwlwifi && modprobe iwlwifi
    (modprobe -r tira o driver da memória; modprobe carrega de novo.)
  4. Confira: ip link deve mostrar a placa wl…, e nmcli device wifi list, as redes.
E se o computador não tem nenhuma internet?

Em outro computador, baixe o .deb do pacote em packages.debian.org (distribuição trixie, arquitetura all), copie para um pendrive e instale com dpkg -i firmware-…_all.deb (veja dpkg e .deb). Existe também o pacote isenkram-cli (versão 0.69+deb13u1 no Debian 13), cujo comando isenkram-autoinstall-firmware procura e instala o firmware que o seu hardware pede; ele também precisa de internet.

Adaptadores Wi-Fi USB (Realtek e outros)

Adaptadores Wi-Fi USB baratos são a maior fonte de "meu Wi-Fi não aparece". O motivo: muitos usam chips Realtek cujo driver só entrou no kernel recentemente, ou nunca entrou. O Debian 13 usa o kernel 6.12. Lista real dos drivers Realtek para USB que ele traz (os nomes terminados em u, de USB):

$ ls /usr/lib/modules/$(uname -r)/kernel/drivers/net/wireless/realtek/rtw88/ | grep 'u\.ko'
rtw88_8723du.ko.xz
rtw88_8821cu.ko.xz
rtw88_8822bu.ko.xz
rtw88_8822cu.ko.xz
$ ls /usr/lib/modules/$(uname -r)/kernel/drivers/net/wireless/realtek/
rtl818x  rtl8xxxu  rtlwifi  rtw88  rtw89

(O $(uname -r) vira a versão do kernel em uso, 6.12.111+deb13-amd64.) Em português:

  • Funcionam com o kernel do Debian 13: RTL8723DU, RTL8821CU, RTL8822BU e RTL8822CU (driver rtw88), vários chips antigos pelo rtl8xxxu (como o RTL8188EU e o RTL8192EU), e adaptadores MediaTek (há mt76-usb, mt76x02-usb e mt792x-usb em drivers/net/wireless/mediatek/mt76). Todos precisam do firmware: firmware-realtek ou firmware-mediatek.
  • Não funcionam com o kernel 6.12: a pasta rtw89 (chips Wi-Fi 6 da Realtek) não tem nenhum driver USB, e chips como RTL8812AU e RTL8821AU não estão no rtw88 dele. Kernels mais novos já trazem esses drivers (no Guia Arch, o kernel 7.0 lista rtw88_8812au, rtw88_8821au e rtw89_8852bu, entre outros).

Se o seu chip está do lado "não funcionam":

  1. Instale usando outra conexão: cabo ou o celular por USB.
  2. Tente um kernel mais novo, do repositório trixie-backports (aula Backports e Pinning), junto com o firmware também do backports. Confira antes se o driver do seu chip já está no kernel de lá.
  3. Evite drivers "do fabricante" baixados de sites: precisam ser recompilados a cada kernel novo (DKMS) e costumam quebrar nas atualizações. Prefira trocar o adaptador por um com chip suportado.
Vai comprar um adaptador Wi-Fi USB?

Pesquise o chip (não a marca da caixa) e confira se ele funciona "sem driver extra" (in-kernel) no kernel do Debian que você usa. E tenha sempre um plano B no dia da instalação: um cabo de rede ou o celular por USB.

A placa funciona, mas não navega

Se a placa aparece, a rede aparece na lista e a senha é aceita, o problema é depois: o endereço IP. Saída real, numa rede cujo "roteador" estava sem DHCP:

$ nmcli connection up Escritorio
Erro: Ativação da conexão falhou: A configuração IP não pode estar reservada (nenhum endereço disponível, timeout, etc)
Dica: use “journalctl -xe NM_CONNECTION=9cdd1584-41a5-4a65-81ef-4a6c3907aff9 + NM_DEVICE=wlp2s0” para obter mais detalhes.

O log do NetworkManager conta a história (trecho real; como root, journalctl -u NetworkManager):

#> journalctl -u NetworkManager -o cat | grep wlp2s0
…
<info>  [1792179591.2803] device (wlp2s0): Activation: (wifi) Stage 2 of 5 (Device Configure) successful. Connected to wireless network "Escritorio"   « a senha foi aceita
<info>  [1792179591.2830] dhcp4 (wlp2s0): activation: beginning transaction (timeout in 45 seconds)   « pediu um endereço
<info>  [1792179636.3270] device (wlp2s0): state change: ip-config -> failed (reason 'ip-config-unavailable', managed-type: 'full')   « 45 s depois, desistiu
…

A parte do Wi-Fi está certa; quem falhou foi o roteador, que não emprestou um endereço. Reinicie o roteador, teste com outro aparelho e, em redes de empresa ou hotel, pergunte se é preciso liberar o seu aparelho. Redes de hotel e aeroporto que abrem uma página de login (captive portal) dão endereço, mas só liberam a internet depois do login no navegador.

Outras causas comuns quando a placa funciona:

  • Sinal fraco: iw dev wlp2s0 link mostra o signal em dBm; abaixo de −75, chegue mais perto do roteador (tabela em Wi-Fi).
  • Rede só de 5 GHz numa placa antiga, que só tem 2,4 GHz: a rede nunca aparece na lista. Ative a faixa de 2,4 GHz no roteador.
  • DNS: o ping 1.1.1.1 funciona, mas ping debian.org não. Veja o roteiro "a internet não funciona".

Plano B: internet sem Wi-Fi

Para baixar firmware ou um kernel novo, você precisa de internet. Sem Wi-Fi, use o cabo de rede (funciona sozinho, veja Configurar a Rede) ou o celular pelo cabo USB, que para o Linux vira uma placa de cabo (veja Celular por USB e Modem 4G).

Resumo

  • Roteiro: ip link → rfkill → lspci -k/lsusb → dmesg | grep -i firmware.
  • Bloqueio soft: rfkill unblock wifi ou nmcli radio wifi on. Bloqueio hard: só a chave, a tecla ou a BIOS.
  • Direct firmware load … failed with error -2 = falta firmware: instale o firmware-* do fabricante (componente non-free-firmware) e recarregue o driver.
  • O kernel 6.12 do Debian 13 reconhece alguns adaptadores Realtek USB (8723DU, 8821CU, 8822BU, 8822CU); para os outros, kernel do backports ou outro adaptador.
  • Sempre tenha um plano B: cabo ou celular por USB.
