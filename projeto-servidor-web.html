Projeto Servidor Web do Zero

Você vai pegar um Debian 13 recém-instalado e deixá-lo pronto para servir um site: com um usuário administrador de verdade, acesso SSH só por chave, firewall fechado por padrão e o Apache configurado no jeito Debian, com HTTPS. É o roteiro que se repete em todo servidor novo.

Ao terminar você terá
  • O sudo instalado e a ana como administradora.
  • Login SSH só por chave, sem senha e sem root.
  • Um firewall nftables que só deixa entrar SSH (22), HTTP (80) e HTTPS (443).
  • Um site próprio em /var/www/meusite, publicado com a2ensite.
  • HTTPS com certificado autoassinado, e o caminho para um certificado de verdade com o certbot.

$ VBoxManage snapshot lab take antes-servidor-web

As etapas

  1. Virar root com su - e atualizar

    O que vamos fazer e por quê: numa instalação com senha de root, a ana não tem nenhum poder de administração e o sudo nem está instalado. O primeiro passo é virar root com a senha dele.

    $ sudo apt update
-bash: sudo: comando não encontrado
$ su -
Senha:
#> apt update
#> apt upgrade
    su
    Troca de usuário (substitute user). Sem nome, troca para o root.
    -
    Abre um login completo do root: o PATH passa a incluir /usr/sbin, onde moram usermod, adduser e reboot.
    Se deu errado: "usermod: comando não encontrado" sendo root

    Você usou su sem o hífen. Desde o Debian 10, o su sozinho mantém o PATH da ana, que não tem /usr/sbin. Saia com exit e use su -.

  2. Instalar o sudo e dar poder à ana

    O que vamos fazer e por quê: trabalhar logado como root o tempo todo é perigoso e não deixa rastro de quem fez o quê. Com o sudo, a ana usa a própria senha e cada comando fica registrado.

    #> apt install sudo
#> usermod -aG sudo ana
#> id ana
uid=1000(ana) gid=1000(ana) grupos=1000(ana),24(cdrom),25(floppy),27(sudo),29(audio),30(dip),44(video),46(plugdev),100(users),101(netdev)
#> exit

    O grupo 27(sudo) apareceu. Mas a sessão aberta da ana ainda não sabe disso: grupos só valem num login novo. Saia do SSH e entre de novo.

    Confira:

    $ groups
ana cdrom floppy sudo audio dip video plugdev users netdev
$ sudo -l
[sudo] senha para ana:
Entradas de Defaults correspondentes a ana em lab:
    env_reset, mail_badpass, secure_path=/usr/local/sbin\:/usr/local/bin\:/usr/sbin\:/usr/bin\:/sbin\:/bin, use_pty

Usuário ana pode executar os seguintes comandos em lab:
    (ALL : ALL) ALL                « pode tudo, como qualquer usuário
    Se deu errado: "ana is not in the sudoers file." 
    $ sudo whoami
[sudo] senha para ana:
ana is not in the sudoers file.
This incident has been reported to the administrator.

    A sessão ainda é a antiga (sem o grupo), ou o usermod foi feito sem o -a. Saia, entre de novo e confira com groups. A recusa sai em inglês mesmo com o sistema em português.

  3. SSH por chave

    O que vamos fazer e por quê: senhas podem ser adivinhadas; uma chave ed25519, não. Os passos acontecem no seu computador (prompt ana@notebook):

    $ ssh-keygen -t ed25519 -C "notebook da ana"
Generating public/private ed25519 key pair.
Enter file in which to save the key (/home/ana/.ssh/id_ed25519):
Enter passphrase for "/home/ana/.ssh/id_ed25519" (empty for no passphrase):
Enter same passphrase again:
Your identification has been saved in /home/ana/.ssh/id_ed25519
Your public key has been saved in /home/ana/.ssh/id_ed25519.pub
$ ssh-copy-id -p 2222 ana@127.0.0.1
$ ssh -p 2222 ana@127.0.0.1           « agora entra sem pedir a senha da ana

    Use uma passphrase: se alguém copiar a chave, ainda precisa dela. Veja SSH.

  4. Desligar senha e root no SSH

    O que vamos fazer e por quê: com a chave funcionando, fechamos as portas que robôs da internet tentam a cada minuto. Primeiro, veja o padrão do Debian:

    $ sudo sshd -T | grep -E "^(permitrootlogin|passwordauthentication|pubkeyauthentication) "
permitrootlogin without-password       « root só entra com chave
pubkeyauthentication yes
passwordauthentication yes             « qualquer usuário entra com senha

    Em vez de editar o arquivo principal, crie um arquivo seu na pasta sshd_config.d (atualizações do pacote não mexem nele):

    PermitRootLogin no
PasswordAuthentication no
KbdInteractiveAuthentication no
    $ sudo sshd -t
$ sudo systemctl reload ssh
$ sudo sshd -T | grep -E "^(permitrootlogin|passwordauthentication) "
permitrootlogin no
passwordauthentication no

    O sshd -t confere a configuração: silêncio quer dizer "sem erros". Só então recarregue.

    Teste antes de fechar a sessão atual

    Abra um segundo terminal e faça um ssh -p 2222 ana@127.0.0.1. Só feche o primeiro depois que o segundo entrar. Se não entrar, você ainda tem a sessão antiga para desfazer.

  5. Firewall com nftables

    O que vamos fazer e por quê: por padrão o Debian não filtra nada. Vamos inverter: bloquear tudo que chega e liberar só o necessário. O arquivo padrão vem vazio:

    $ cat /etc/nftables.conf
#!/usr/sbin/nft -f

flush ruleset

table inet filter {
	chain input {
		type filter hook input priority filter;
	}
	chain forward {
		type filter hook forward priority filter;
	}
	chain output {
		type filter hook output priority filter;
	}
}
$ systemctl is-enabled nftables
disabled

    Substitua o conteúdo por este (com sudo nano /etc/nftables.conf):

    #!/usr/sbin/nft -f
flush ruleset

table inet filter {
    chain input {
        type filter hook input priority filter; policy drop;   # bloqueia tudo que não for liberado abaixo
        ct state established,related accept                    # respostas de conexões que já existem
        ct state invalid drop
        iif "lo" accept                                         # a própria máquina falando com ela mesma
        meta l4proto { icmp, ipv6-icmp } accept                 # ping e o básico do IPv6
        tcp dport { 22, 80, 443 } accept                        # SSH, HTTP e HTTPS
    }
    chain forward {
        type filter hook forward priority filter; policy drop;
    }
    chain output {
        type filter hook output priority filter; policy accept;
    }
}

    O nft -c (de check) confere o arquivo sem aplicar. Veja como ele aponta um erro, aqui uma chave } esquecida:

    $ sudo nft -c -f /etc/nftables.conf
/etc/nftables.conf:11:33-38: Error: syntax error, unexpected accept, expecting comma or '}'
        tcp dport { 22, 80, 443 accept
                                ^^^^^^

    Arquivo, linha 11, colunas 33 a 38, e as setinhas embaixo do lugar exato. Corrigido, o nft -c fica em silêncio. Então aplique e ative no boot:

    $ sudo nft -c -f /etc/nftables.conf
$ sudo systemctl enable --now nftables
$ sudo nft list chain inet filter input

    Confira: do seu computador, num terminal novo, ssh -p 2222 ana@127.0.0.1 continua entrando.

    Se deu errado: o SSH parou de responder

    A porta 22 ficou fora da regra. Pelo console da VM, rode sudo nft flush ruleset (libera tudo na hora), corrija o arquivo e aplique de novo. Veja Firewall (nftables).

  6. Instalar o Apache

    $ sudo apt install apache2
$ systemctl is-active apache2
active
$ apache2 -v
-bash: apache2: comando não encontrado
$ sudo apache2 -v
Server version: Apache/2.4.68 (Debian)
$ wget -qO- http://localhost/ | grep -o "<title>.*</title>"
<title>Apache2 Debian Default Page: It works</title>

    Dois detalhes do Debian aparecem aqui. O pacote se chama apache2, e o serviço sobe sozinho logo após a instalação. E o binário mora em /usr/sbin, fora do PATH da ana: por isso o primeiro apache2 -v falha.

  7. Publicar o seu site, no jeito Debian

    O que vamos fazer e por quê: o Debian organiza o Apache em pastas *-available (o que existe) e *-enabled (o que está ligado, por links). Os comandos a2ensite e a2dissite criam e apagam esses links para você.

    $ ls /etc/apache2/
apache2.conf    conf-enabled  magic           mods-enabled  sites-available
conf-available  envvars       mods-available  ports.conf    sites-enabled
$ sudo mkdir -p /var/www/meusite
$ echo '<h1>Olá do Debian</h1>' | sudo tee /var/www/meusite/index.html
    <VirtualHost *:80>
    ServerName meusite.lab
    DocumentRoot /var/www/meusite
    ErrorLog ${APACHE_LOG_DIR}/meusite-erro.log
    CustomLog ${APACHE_LOG_DIR}/meusite-acesso.log combined
</VirtualHost>
    $ sudo a2ensite meusite
Enabling site meusite.
To activate the new configuration, you need to run:
  systemctl reload apache2
$ sudo apache2ctl configtest
Syntax OK
$ sudo systemctl reload apache2
$ ls -l /etc/apache2/sites-enabled/
total 0
lrwxrwxrwx 1 root root 35 out 15 22:52 000-default.conf -> ../sites-available/000-default.conf
lrwxrwxrwx 1 root root 31 out 15 22:53 meusite.conf -> ../sites-available/meusite.conf

    Confira: peça a página dizendo que quer o site meusite.lab (o Apache escolhe o site pelo nome pedido):

    $ wget -qO- --header "Host: meusite.lab" http://localhost/
<h1>Olá do Debian</h1>
$ sudo tail -1 /var/log/apache2/meusite-acesso.log
::1 - - [15/Oct/2026:22:53:01 -0300] "GET / HTTP/1.1" 200 309 "-" "Wget/1.25.0"

    Para abrir no navegador do seu computador, redirecione uma porta da VM (com ela desligada): VBoxManage modifyvm lab --natpf1 "web,tcp,127.0.0.1,8080,,80" e acesse http://localhost:8080. Para o nome meusite.lab funcionar, desative o site padrão com sudo a2dissite 000-default, ou adicione o nome no /etc/hosts do seu computador.

    Se deu errado: o configtest reclama 
    $ sudo apache2ctl configtest
AH00526: Syntax error on line 3 of /etc/apache2/sites-enabled/meusite.conf:
Invalid command 'DocumentRot', perhaps misspelled or defined by a module not included in the server configuration

    Arquivo e linha estão na mensagem. Corrija e rode o configtest de novo antes do reload.

  8. HTTPS

    O que vamos fazer e por quê: sem HTTPS, senhas e cookies viajam abertos. No laboratório, sem domínio, usamos um certificado autoassinado: criptografa, mas o navegador avisa que ninguém confirmou a identidade do site.

    $ sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
    -keyout /etc/ssl/private/meusite.key -out /etc/ssl/certs/meusite.crt -subj "/CN=meusite.lab"
$ sudo openssl x509 -in /etc/ssl/certs/meusite.crt -noout -subject -dates
subject=CN=meusite.lab
notBefore=Oct 16 01:48:50 2026 GMT
notAfter=Oct 16 01:48:50 2027 GMT
$ sudo a2enmod ssl
Considering dependency mime for ssl:
Module mime already enabled
Considering dependency socache_shmcb for ssl:
Enabling module socache_shmcb.
Enabling module ssl.
See /usr/share/doc/apache2/README.Debian.gz on how to configure SSL and create self-signed certificates.
To activate the new configuration, you need to run:
  systemctl restart apache2

    Acrescente ao meusite.conf um segundo bloco, agora na porta 443:

    <VirtualHost *:443>
    ServerName meusite.lab
    DocumentRoot /var/www/meusite
    SSLEngine on
    SSLCertificateFile    /etc/ssl/certs/meusite.crt
    SSLCertificateKeyFile /etc/ssl/private/meusite.key
</VirtualHost>
    $ sudo apache2ctl configtest
Syntax OK
$ sudo systemctl restart apache2
$ wget -qO- --no-check-certificate --header "Host: meusite.lab" https://localhost/
<h1>Olá do Debian</h1>

    O --no-check-certificate faz o mesmo que o "aceitar o risco" do navegador.

    Com um domínio de verdade

    Num servidor com IP público e um domínio apontando para ele, o Debian tem o certbot no próprio repositório: sudo apt install python3-certbot-apache e depois sudo certbot --apache -d meusite.com.br. Ele pede o certificado ao Let's Encrypt, ajusta o Apache e agenda a renovação. Veja HTTPS (Let's Encrypt).

Checklist do que você aprendeu

  • su - (com hífen) para virar root; apt install sudo e usermod -aG sudo para criar um administrador.
  • Grupos novos só valem num login novo.
  • SSH: chave ed25519, depois PasswordAuthentication no e PermitRootLogin no num arquivo em sshd_config.d, com sshd -t antes do reload.
  • nftables: policy drop na entrada, liberar 22/80/443, conferir com nft -c, ativar com systemctl enable --now nftables.
  • Apache no Debian: sites-available + a2ensite, apache2ctl configtest, systemctl reload apache2.

Desafios extras

  • Instale o fail2ban e veja-o bloquear tentativas de senha no SSH. Veja Segurança do Servidor.
  • Troque o Apache pelo nginx (sudo systemctl disable --now apache2, sudo apt install nginx) e publique o mesmo site. Veja Servidor Web (nginx).
  • Redirecione todo acesso HTTP para HTTPS com Redirect permanent / https://meusite.lab/ no bloco da porta 80.

Resumo

  • Num Debian com senha de root, o primeiro passo de um servidor é su -, instalar o sudo e criar um administrador.
  • Segurança em camadas: SSH só por chave, firewall fechado por padrão e serviços testados antes de recarregar.
  • O Apache do Debian se administra com a2ensite, a2enmod e apache2ctl configtest.
