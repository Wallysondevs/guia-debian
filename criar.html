Debian touch e mkdir

Nesta aula você cria arquivos e pastas pelo terminal. São dois comandos: touch cria arquivos vazios e mkdir cria pastas. Eles parecem simples, mas têm truques que economizam muito trabalho, como criar 12 pastas com um comando só.

Você vai aprender
  • O que cada parte dos comandos touch e mkdir faz.
  • Seis formas diferentes de criar várias pastas, e quando usar cada uma.
  • Como criar uma estrutura inteira de pastas de uma vez.
  • O que significam as mensagens do Debian, inclusive a que mistura inglês e português.

Todos os exemplos acontecem na máquina fictícia notebook, com a usuária ana, rodando Debian 13. No seu computador, o começo do prompt terá o seu usuário e o nome da sua máquina.

Antes de começar: leia o prompt

Cada linha que começa com ana@notebook:~$ é um comando que a Ana digitou. As linhas sem esse começo são a resposta do computador.

$ pwd
/home/ana

mkdir: criar uma pasta

mkdir vem de make directory, "criar diretório". Diretório é o nome técnico de pasta.

mkdir
O programa. Ele cria pastas.
estudos
O argumento: o nome da pasta que você quer criar.
$ mkdir estudos
$ ls
'Área de trabalho'   Downloads   frutas.txt   Modelos   Público
 Documentos          estudos     Imagens      Música    Vídeos      « "estudos" apareceu

O mkdir não mostrou nada. No Linux, silêncio significa sucesso: o comando só fala quando dá erro ou quando você pede. Por isso usamos o ls logo depois, para conferir. A pasta nova apareceu entre "Downloads" e "frutas.txt" porque o ls do Debian ordena pelo idioma, ignorando maiúsculas (veja ls).

Pedindo para o mkdir falar: -v

mkdir
O programa.
-v
Uma opção (de verbose, "detalhado"): conta o que foi feito.
aulas
O nome da pasta.
$ mkdir -v aulas
mkdir: foi criado o diretório 'aulas'

O que o comando devolve

Além do que aparece na tela, todo comando devolve um código de saída: 0 quando deu certo e outro número quando deu errado. Você vê esse código com echo $?, logo depois do comando:

$ mkdir provas
$ echo $?
0                                                 « 0 = deu certo
$ mkdir provas
mkdir: cannot create directory ‘provas’: Arquivo existe
$ echo $?
1                                                 « 1 = deu errado
Por que a mensagem mistura inglês e português?

No Debian 13 o começo da frase, cannot create directory, ainda não foi traduzido no pacote coreutils. A segunda parte, Arquivo existe, vem de outra tradução, a da biblioteca do sistema, que está completa. O sentido é: "não foi possível criar o diretório 'provas': o arquivo já existe".

Criar várias pastas: 6 formas diferentes

A Ana quer uma pasta para cada mês do semestre: jan, fev, mar, abr, mai e jun. Todas as formas a seguir chegam ao mesmo resultado; o que muda é a situação em que cada uma é mais prática.

Forma 1: vários nomes separados por espaço

mkdir
O programa.
jan fev mar
Três argumentos. Cada um vira uma pasta.
$ cd estudos
$ mkdir jan fev mar
$ ls
fev  jan  mar

É a forma mais usada no dia a dia. "fev" veio antes de "jan" porque o ls ordena alfabeticamente; ele não sabe que são meses.

Forma 2: chaves { }

Quando os nomes têm uma parte em comum, as chaves evitam repetir. Quem entende as chaves é o shell (o programa que lê o que você digita), não o mkdir: o shell transforma {jan,fev,mar} em jan fev mar antes de chamar o comando. O echo mostra essa transformação:

$ echo relatorio-{jan,fev,mar}.txt
relatorio-jan.txt relatorio-fev.txt relatorio-mar.txt
Atenção às chaves

Não coloque espaço depois da vírgula: {jan, fev} não funciona. Com uma opção só, como {jan}, as chaves também não fazem nada.

Forma 3: sequências {1..12}

Com dois pontos entre o começo e o fim, as chaves geram uma sequência. Com um zero na frente do primeiro número, todos ficam do mesmo tamanho, e a ordem do ls fica certa:

$ echo aula{1..5}
aula1 aula2 aula3 aula4 aula5
$ mkdir mes{01..12}
$ ls
mes01  mes03  mes05  mes07  mes09  mes11
mes02  mes04  mes06  mes08  mes10  mes12

Sem o zero, o ls mostraria mes1 mes10 mes11 mes12 mes2…, porque compara caractere por caractere.

Forma 4: laço for

Um laço repete um comando para cada item de uma lista. É mais longo, mas permite fazer mais de uma coisa por pasta.

for mes in abr mai jun
Para cada palavra da lista, guarde-a na variável mes…
;
Separa as partes do comando.
do mkdir "$mes"
…e rode isto. $mes é trocado pela palavra da vez.
; done
Fim do laço.
$ for mes in abr mai jun; do mkdir "$mes"; echo "criei $mes"; done
criei abr
criei mai
criei jun

Laços em detalhe: Laços.

Forma 5: a partir de uma lista em arquivo

Se os nomes já estão num arquivo de texto, um por linha, o xargs lê o arquivo e entrega os nomes ao mkdir:

$ cat clientes.txt
padaria
oficina
mercado
$ xargs mkdir < clientes.txt
$ ls
clientes.txt  mercado  oficina  padaria
xargs
Lê palavras da entrada e as passa como argumentos para outro comando.
mkdir
O comando que recebe as palavras.
< clientes.txt
Usa o arquivo como entrada (veja Redirecionamento).

Se algum nome tiver espaço, use xargs -d '\n' mkdir < clientes.txt, que separa só por linha.

Forma 6: pelo gerenciador de arquivos

No desktop GNOME do Debian, abra o app Arquivos e pressione Ctrl+Shift+N. Para uma ou duas pastas é tão rápido quanto o terminal. Para dez ou mais, o terminal ganha.

Pastas dentro de pastas: -p

Tente criar site/css quando a pasta site ainda não existe:

$ mkdir site/css
mkdir: cannot create directory ‘site/css’: Arquivo ou diretório inexistente

O mkdir só cria o último nível. Como site não existe, ele não acha onde pôr a css. A opção -p (de parents, "pais") cria todas as pastas que faltam no caminho:

mkdir
O programa.
-p
Cria as pastas "pais" que faltarem e não reclama se a pasta já existir.
-v
Mostra cada pasta criada.
site/css
O caminho completo que você quer.
$ mkdir -pv site/css
mkdir: foi criado o diretório 'site'
mkdir: foi criado o diretório 'site/css'

Uma estrutura inteira de uma vez

Juntando -p com chaves, você monta a estrutura de um projeto num comando só. As duas formas abaixo dão o mesmo resultado. Para ver a estrutura, o find lista tudo o que há dentro (o tree, que desenha a árvore, não vem instalado no Debian):

# forma longa: um caminho por pasta
$ mkdir -p loja/src loja/docs loja/testes/unidade loja/testes/integracao
# forma curta: com chaves
$ mkdir -p loja/{src,docs,testes/{unidade,integracao}}
$ find loja
loja
loja/testes
loja/testes/integracao
loja/testes/unidade
loja/docs
loja/src

O find mostra os itens na ordem em que estão gravados no disco, que pode variar. Você vai conhecê-lo em find e locate.

Dica para scripts

Em scripts, use sempre mkdir -p: se a pasta já existir, ele não dá erro e o script continua.

Missão: crie, com um único comando, a pasta app contendo src, docs e testes. Confira com ls app.

touch: criar arquivos vazios

touch significa "tocar". Ele "toca" no arquivo para atualizar a data de modificação. Se o arquivo não existe, ele cria um vazio. Por isso é usado para criar arquivos.

touch
O programa.
anotacoes.txt
O arquivo a criar (ou a "tocar", se já existir).
$ touch anotacoes.txt
$ ls -l anotacoes.txt
-rw-rw-r-- 1 ana ana 0 out 15 10:30 anotacoes.txt       « tamanho 0: vazio

Ele também aceita vários nomes e chaves, como o mkdir:

$ touch index.html style.css script.js
$ touch capitulo{1..3}.md
$ ls
capitulo1.md  capitulo2.md  capitulo3.md  index.html  script.js  style.css

O touch não apaga o conteúdo

Se o arquivo já existe, o touch só muda a data. O conteúdo fica intacto:

$ cat notas.txt
Comprar café
$ ls -l notas.txt
-rw-rw-r-- 1 ana ana 14 out 14 17:40 notas.txt
$ touch notas.txt
$ ls -l notas.txt
-rw-rw-r-- 1 ana ana 14 out 15 21:12 notas.txt         « só a data mudou
$ cat notas.txt
Comprar café

Escolher a data: -d

Com -d (de date) você escolhe a data que o arquivo vai ter. É útil para testar scripts que apagam arquivos antigos:

$ touch -d "2026-01-01 08:00" antigo.log
$ ls -l antigo.log
-rw-rw-r-- 1 ana ana 0 jan  1  2026 antigo.log

Outras formas de criar um arquivo

O touch cria arquivos vazios. Quando você já quer escrever algo dentro, há outros caminhos:

ComandoO que fazCuidado
touch arq.txtCria vazio ou só atualiza a dataNunca apaga conteúdo
echo "texto" > arq.txtCria com uma linha de textoApaga o conteúdo anterior
echo "texto" >> arq.txtAcrescenta uma linha no fimSeguro: não apaga nada
> arq.txtCria vazio ou esvazia o arquivoApaga o conteúdo sem perguntar
nano arq.txtAbre o editor padrão do DebianVeja nano e vim
$ echo "Lista de compras" > compras.txt
$ echo "pão" >> compras.txt
$ cat compras.txt
Lista de compras
pão
Atenção: > apaga, >> acrescenta

Um > no lugar de >> apaga tudo o que havia no arquivo, sem perguntar e sem lixeira. Na dúvida, use >>.

Missão: crie o arquivo compras.txt com três linhas: pão, leite e café. Use echo com > e >>, e confira com cat compras.txt.

Quando não funciona

"Arquivo existe" 
$ mkdir fotos
mkdir: cannot create directory ‘fotos’: Arquivo existe

O que aconteceu: já existe uma pasta, ou um arquivo, com esse nome.

Como resolver: confira com ls -ld fotos. Se a ideia era só "garantir que a pasta exista", use mkdir -p fotos, que não reclama.

"Arquivo ou diretório inexistente" no mkdir 
$ mkdir projetos/2026/janeiro
mkdir: cannot create directory ‘projetos/2026/janeiro’: Arquivo ou diretório inexistente

O que aconteceu: alguma pasta do caminho (projetos ou 2026) ainda não existe.

Como resolver: use mkdir -p projetos/2026/janeiro.

"Permissão negada" 
$ mkdir /opt/meuapp
mkdir: cannot create directory ‘/opt/meuapp’: Permissão negada
$ touch /etc/teste.conf
touch: não foi possível tocar '/etc/teste.conf': Permissão negada

O que aconteceu: fora da sua pasta pessoal, quase tudo pertence ao administrador (root).

Como resolver: antes, pense se o arquivo não deveria estar na sua pasta pessoal. Se precisa mesmo criar ali, vire root com su -, que pede a senha do root. No Debian o sudo nem vem instalado quando a instalação define uma senha de root (veja root, su e sudo).

$ su -
Senha:
#> mkdir /opt/meuapp
#> ls -ld /opt/meuapp
drwxr-xr-x 2 root root 4096 out 15 10:31 /opt/meuapp
#> exit
"Não é um diretório" 
$ mkdir -p notas.txt/x
mkdir: cannot create directory ‘notas.txt’: Não é um diretório

O que aconteceu: no caminho existe um arquivo com o nome que deveria ser de uma pasta.

Como resolver: escolha outro nome ou renomeie o arquivo com mv.

Nome com espaço virou duas pastas 
$ mkdir Meus Projetos
$ ls
Meus  Projetos

O que aconteceu: o espaço separa argumentos, e o mkdir recebeu dois nomes.

Como resolver: apague as duas com rmdir Meus Projetos e crie de novo com aspas: mkdir "Meus Projetos". Ou evite espaços: meus-projetos.

Resumo

  • mkdir nome cria uma pasta; mkdir a b c cria várias.
  • Chaves {a,b} e sequências {01..12} são expandidas pelo shell e funcionam com qualquer comando.
  • mkdir -p cria o caminho inteiro e não reclama se a pasta já existir.
  • touch cria arquivos vazios e nunca apaga conteúdo; > apaga, >> acrescenta.
  • No Debian 13, a mensagem do mkdir mistura inglês e português; leia as duas partes.
