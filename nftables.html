Debian nftables

O nftables é o firewall do Debian. Desde o Debian 10 ele é a ferramenta oficial para filtrar o tráfego de rede, e no Debian 13 o pacote já vem instalado. Mas, recém-instalado, ele não bloqueia nada: o serviço vem desligado e a configuração de exemplo deixa tudo passar. Nesta aula você vai entender o que vem pronto e escrever o seu primeiro firewall.

Você vai aprender
  • Como o Debian 13 vem de fábrica: pacote instalado, serviço desativado, regras vazias.
  • O que são tabelas, cadeias (chains) e regras, lendo o /etc/nftables.conf real.
  • Como escrever um firewall que libera SSH, HTTP e HTTPS e bloqueia o resto.
  • Como validar o arquivo com nft -c antes de aplicar, e como não ficar trancado do lado de fora.

Os exemplos acontecem na máquina fictícia servidor. Todos os comandos do nft precisam de root: no Debian, entre como root com su - (veja root, su e sudo). As linhas que começam com root@servidor:~# foram digitadas como root.

Antes do comando: quem é quem

No Linux existe um só motor de firewall, dentro do kernel, chamado netfilter. As ferramentas são formas diferentes de dar ordens a ele:

FerramentaO que éNo Debian 13 recém-instalado
nft (nftables)A ferramenta moderna e oficial. Fala direto com o netfilter.Instalada (pacote nftables 1.1.3), serviço desativado
iptablesA ferramenta antiga. No Debian atual ela é só uma "tradutora" (iptables-nft) que grava regras nftables.Não instalada
ufwUma camada simples por cima, criada pelo Ubuntu.Não instalada (veja ufw (opcional))

Note a diferença para o Ubuntu: lá o ufw já vem pronto. No Debian, o caminho padrão é escrever as regras do nftables num arquivo.

Conferindo o estado de fábrica

Três comandos mostram como o firewall está. Primeiro, o pacote e a versão:

#> nft --version
nftables v1.1.3 (Commodore Bullmoose #4)

Depois, o serviço que carrega as regras no boot:

#> systemctl status nftables
○ nftables.service - nftables
     Loaded: loaded (/usr/lib/systemd/system/nftables.service; disabled; preset: enabled)    « disabled: não liga no boot
     Active: inactive (dead)                                                                  « não está rodando agora
       Docs: man:nft(8)
             http://wiki.nftables.org

E, por fim, as regras que estão valendo agora:

#> nft list ruleset
#> echo $?
0                                    « nenhuma regra e nenhum erro: o firewall está vazio

O nft list ruleset não mostrou nada. Isso significa que nenhum pacote é filtrado: todas as portas abertas por programas estão acessíveis pela rede.

"nft: comando não encontrado" 
$ nft list ruleset
bash: nft: comando não encontrado

O que aconteceu: o nft fica em /usr/sbin, que não está no PATH do usuário comum no Debian. Mesmo chamando pelo caminho completo, sem root ele não consegue ler o firewall:

$ /usr/sbin/nft list ruleset
Operation not permitted (you must be root)
netlink: Error: cache initialization failed: Operation not permitted

Como resolver: entre como root com su - e rode de novo.

Tabelas, cadeias e regras

O nftables organiza tudo em três níveis, como pastas dentro de pastas:

NívelO que éExemplo
Tabela (table)Uma caixa que agrupa cadeias. Tem uma família: ip (IPv4), ip6 (IPv6) ou inet (os dois).table inet filter
Cadeia (chain)Uma lista de regras ligada a um ponto do caminho dos pacotes (hook).chain input (o que chega à máquina)
Regra (rule)Uma condição e uma decisão.tcp dport 22 accept

Os três hooks que você mais vai usar:

  • input: pacotes que chegam para esta máquina (alguém acessando o seu SSH).
  • output: pacotes que saem desta máquina (o seu apt update).
  • forward: pacotes que só passam por ela (quando ela é um roteador ou hospeda containers).

O arquivo que já vem no Debian

O Debian instala um /etc/nftables.conf de exemplo. Este é o conteúdo real do Debian 13:

#!/usr/sbin/nft -f

flush ruleset

table inet filter {
	chain input {
		type filter hook input priority filter;
	}
	chain forward {
		type filter hook forward priority filter;
	}
	chain output {
		type filter hook output priority filter;
	}
}

Linha por linha:

  • #!/usr/sbin/nft -f: o arquivo é um "script" do nft.
  • flush ruleset: apaga todas as regras atuais antes de carregar estas. Assim o arquivo sempre descreve o firewall inteiro.
  • table inet filter: uma tabela chamada filter que vale para IPv4 e IPv6.
  • type filter hook input priority filter;: esta cadeia filtra os pacotes de entrada.

As cadeias estão vazias e não dizem uma política (o que fazer quando nenhuma regra combina). Sem política, o padrão é aceitar. Por isso, mesmo se você ligar o serviço com este arquivo, nada é bloqueado.

Uma regra, parte por parte

Esta é a regra que libera o acesso SSH:

tcp
Só pacotes do protocolo TCP (o SSH usa TCP).
dport 22
destination port: a porta de destino é a 22, a do SSH.
accept
A decisão: deixar passar. As outras decisões comuns são drop (descartar em silêncio) e reject (recusar avisando).

Várias portas de uma vez usam chaves, chamadas de conjunto (set):

tcp dport
Porta de destino TCP…
{ 80, 443 }
…que seja 80 (HTTP) ou 443 (HTTPS).
accept
Deixar passar.

E a regra mais importante de todas, que deixa voltar as respostas das conexões que a própria máquina abriu:

ct state
connection tracking: o estado da conexão a que o pacote pertence.
established,related
Conexão já estabelecida, ou relacionada a uma (como um erro ICMP de uma conexão sua).
accept
Deixar passar.

Sem essa regra, com a entrada bloqueada, o apt update enviaria o pedido mas nunca receberia a resposta.

Um firewall completo

Este é um firewall típico de servidor: bloqueia toda entrada, exceto respostas, ping, SSH e web. Escreva primeiro numa cópia, para testar com calma:

#!/usr/sbin/nft -f

flush ruleset

table inet filter {
	chain input {
		type filter hook input priority filter; policy drop;   # o que não for liberado é descartado
		ct state established,related accept                   # respostas de conexões que eu abri
		ct state invalid drop                                  # pacotes sem pé nem cabeça
		iif "lo" accept                                        # a própria máquina falando com ela mesma
		ip protocol icmp accept                                # ping (IPv4)
		ip6 nexthdr ipv6-icmp accept                           # ICMPv6: o IPv6 não funciona sem ele
		tcp dport 22 accept                                    # SSH
		tcp dport { 80, 443 } accept                           # HTTP e HTTPS
	}
	chain forward {
		type filter hook forward priority filter; policy drop; # não é roteador: não repassa nada
	}
	chain output {
		type filter hook output priority filter; policy accept; # tudo pode sair
	}
}

O que muda em relação ao arquivo de fábrica é o policy drop; na cadeia input. Agora o padrão é descartar, e cada regra abre uma exceção.

Validar antes de aplicar: nft -c

A opção -c (de check, conferir) lê o arquivo, procura erros e não aplica nada. Use sempre antes de carregar regras num servidor remoto.

nft
O programa.
-c
Só conferir; não mexe no firewall.
-f /root/firewall.nft
Lê as regras deste arquivo (file).
#> nft -c -f /root/firewall.nft
#> echo $?
0                                    « silêncio e código 0: o arquivo está correto

Com um erro de digitação (acept em vez de accept), o nft mostra a linha, a coluna e marca onde se perdeu:

#> nft -c -f /root/firewall.nft
/root/firewall.nft:12:21-21: Error: syntax error, unexpected newline
		tcp dport 22 acept
		                  ^
#> echo $?
1

A mensagem fica em inglês: o nftables não tem tradução para o português.

Aplicar e deixar permanente

Quando o arquivo estiver validado, copie para o lugar oficial e ligue o serviço. O --now liga agora e no boot:

#> cp /root/firewall.nft /etc/nftables.conf
#> systemctl enable --now nftables
Created symlink '/etc/systemd/system/sysinit.target.wants/nftables.service' → '/usr/lib/systemd/system/nftables.service'.
#> nft list chain inet filter input
table inet filter {
	chain input {
		type filter hook input priority filter; policy drop;
		ct state established,related accept
		ct state invalid drop
		iif "lo" accept
		ip protocol icmp accept
		ip6 nexthdr ipv6-icmp accept
		tcp dport 22 accept
		tcp dport { 80, 443 } accept
	}
}

Depois de editar o arquivo de novo, recarregue com systemctl reload nftables, que roda nft -f /etc/nftables.conf.

Atenção: servidor remoto

Se você está conectado por SSH e esquecer a regra tcp dport 22 accept (ou a do ct state established), a conexão cai no instante em que as regras forem carregadas, e só o acesso físico (ou o console do provedor) resolve. Use a rede de segurança da próxima seção.

Testar sem medo: a "rede de segurança"

Antes de aplicar regras num servidor que você não alcança fisicamente, agende um "desfazer" automático para daqui a 5 minutos. Se você ficar trancado, basta esperar.

systemd-run
Roda um comando como uma tarefa temporária do systemd.
--on-active=5m
Daqui a 5 minutos.
/usr/sbin/nft flush ruleset
O comando: apagar todas as regras (tudo volta a passar).
#> systemd-run --on-active=5m /usr/sbin/nft flush ruleset
Running timer as unit: run-p10126-i10426.timer                 « guarde este nome
Will run service as unit: run-p10126-i10426.service
#> nft -f /root/firewall.nft
# abra OUTRA janela e teste: ssh root@servidor
#> systemctl stop run-p10126-i10426.timer                      « deu certo: cancele o desfazer
  1. Agende o flush para daqui a 5 minutos.
  2. Carregue as regras novas com nft -f.
  3. Abra uma segunda sessão SSH. Não feche a primeira.
  4. Se a segunda sessão entrar, cancele o timer com systemctl stop. Se não entrar, espere 5 minutos: as regras somem e você entra de novo.

Mudar regras sem editar o arquivo

Você também pode criar tabelas e regras direto pelo terminal. Isso vale até o próximo reboot (ou o próximo flush). É útil para testes rápidos:

#> nft add table inet teste
#> nft add chain inet teste entrada '{ type filter hook input priority 10; policy accept; }'
#> nft add rule inet teste entrada tcp dport 8080 counter accept
#> nft -a list table inet teste
table inet teste { # handle 4
	chain entrada { # handle 1
		type filter hook input priority filter + 10; policy accept;
		tcp dport 8080 counter packets 0 bytes 0 accept # handle 2     « handle 2: o "número" da regra
	}
}
#> nft delete table inet teste
  • counter conta quantos pacotes e bytes passaram pela regra. Ótimo para saber se ela está sendo usada.
  • -a mostra os handles, os números internos de cada regra. Para apagar uma regra só: nft delete rule inet teste entrada handle 2.
  • Nas aspas simples ficam as chaves e o ponto e vírgula, para o bash não interpretá-los.

Use um gerenciador só

ufw, firewalld e o seu nftables.conf podem apagar as regras uns dos outros (lembre do flush ruleset). Escolha um e desative os demais.

Quando não funciona

Liguei o serviço e nada é bloqueado

O que aconteceu: você ligou o serviço com o arquivo de fábrica, que não tem policy drop.

Como confirmar: nft list chain inet filter input e procure a palavra policy. Se não aparecer, o padrão é aceitar.

Como resolver: escreva as regras como em "Um firewall completo" e rode systemctl reload nftables.

Depois do reboot, minhas regras sumiram

O que aconteceu: regras criadas com nft add vivem só na memória. Ou o serviço continua disabled.

Como resolver: coloque as regras no /etc/nftables.conf e rode systemctl enable nftables. Para salvar o que está valendo agora: nft list ruleset > /root/regras-atuais.nft e revise antes de copiar (lembre de pôr flush ruleset no topo).

Instalei o Docker e meu firewall parou de funcionar

O que aconteceu: o Docker cria regras próprias para os containers. Um flush ruleset apaga as regras dele, e um systemctl restart docker recria as dele por cima das suas.

Como resolver: não use flush ruleset num servidor com Docker; apague só a sua tabela (delete table inet filter no lugar de flush ruleset). Veja Docker.

O ping funciona, mas o site não abre de fora

Como confirmar: adicione counter na regra da porta e veja se o número sobe quando alguém tenta acessar:

#> nft list chain inet filter input | grep 443
		tcp dport { 80, 443 } counter packets 0 bytes 0 accept

Se o contador fica em zero, o pacote nem chega: o bloqueio está antes (roteador, provedor de nuvem). Se sobe, o firewall está liberando, e o problema é o servidor web (veja ip, ping, ss para conferir se ele está escutando).

Resumo

  • O nftables é o firewall oficial do Debian; vem instalado, mas desativado e sem bloquear nada.
  • As regras ficam em /etc/nftables.conf, organizadas em tabelas, cadeias e regras.
  • policy drop + exceções (ct state established, lo, SSH, web) é o modelo de servidor.
  • Sempre nft -c -f antes de aplicar e uma rede de segurança com systemd-run em servidores remotos.
  • systemctl enable --now nftables torna o firewall permanente.
