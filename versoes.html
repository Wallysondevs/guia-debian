Debian Versões do Debian

O Debian não tem uma versão só: ao mesmo tempo existem a estável, que você instala no dia a dia, uma em teste, que vai virar a próxima, e uma instável, onde tudo chega primeiro. Cada uma tem um número e um nome de personagem do filme Toy Story. Entender isso evita dois sustos clássicos: instalar a versão errada e atualizar para uma versão nova sem querer.

Você vai aprender

  • Os codinomes (bookworm, trixie, forky…) e por que eles importam.

  • Quanto tempo cada versão recebe correções de segurança.
  • Como descobrir a versão e o codinome da sua máquina.

As quatro "faixas" do Debian

Pense numa linha de montagem. Os pacotes novos entram por uma ponta, são testados e, quando estão maduros, saem prontos na outra ponta:

  1. experimental: área de rascunho. Pacotes muito novos, que podem quebrar. Não é uma distribuição completa, só um complemento para testes.
  2. unstable, apelidada de sid: onde os pacotes novos chegam primeiro. Muda todo dia. Usada por desenvolvedores do Debian.
  3. testing: os pacotes passam para cá depois de alguns dias na sid sem bugs graves. É a futura versão estável sendo montada.
  4. stable: a versão lançada oficialmente. Depois do lançamento, só recebe correções de segurança e de bugs sérios. É a que este guia usa.

Atenção: "testing" não é "teste" no sentido de "mais seguro"

A testing não recebe correções de segurança com a mesma rapidez da stable. Para um computador de uso diário ou um servidor, use sempre a stable.

Codinomes: os personagens do Toy Story

Desde 1996, cada versão do Debian recebe o nome de um personagem do filme Toy Story. O nome é escolhido antes do lançamento, então a próxima versão já tem nome enquanto ainda está em testing.

Curiosidade

A unstable se chama sid para sempre, numa piada interna: o Sid é o menino que destrói os brinquedos no filme. Também se costuma dizer que "sid" significa Still In Development ("ainda em desenvolvimento").

Por que o codinome importa

O arquivo de repositórios do Debian aponta para um codinome, não para "stable". Veja o da máquina deste guia:

$ cat /etc/apt/sources.list
#deb cdrom:[Debian GNU/Linux 13.5.0 _Trixie_ - Official amd64 NETINST with firmware 20260516-10:08]/ trixie contrib main non-free-firmware

deb http://deb.debian.org/debian trixie main non-free-firmware      « "trixie", não "stable"
deb-src http://deb.debian.org/debian trixie main non-free-firmware

deb http://security.debian.org/debian-security trixie-security main non-free-firmware
deb-src http://security.debian.org/debian-security trixie-security main non-free-firmware

# trixie-updates, to get updates before a point release is made;
# see https://www.debian.org/doc/manuals/debian-reference/ch02.en.html#_updates_and_backports
deb http://deb.debian.org/debian trixie-updates main non-free-firmware
deb-src http://deb.debian.org/debian trixie-updates main non-free-firmware

# This system was installed using small removable media
# (e.g. netinst, live or single CD). The matching "deb cdrom"
# entries were disabled at the end of the installation process.
# For information about how to configure apt package sources,
# see the sources.list(5) manual.

Com trixie, a máquina continua no Debian 13 mesmo depois que o Debian 14 for lançado. Se estivesse escrito stable, no dia do lançamento do 14 o apt upgrade tentaria pular de versão sozinho, o que pode quebrar o sistema. Mudar de versão deve ser uma decisão sua: veja Atualizar a Versão do Debian.

Atualizações 13.1, 13.2… (point releases)

Depois do lançamento, a cada dois ou três meses o Debian publica uma atualização pontual (point release): um pacote de todas as correções acumuladas. O número muda de 13.0 para 13.1, 13.2 e assim por diante.

Isso não é uma versão nova: é o mesmo Debian 13 com correções. Você não precisa reinstalar nada; um apt update seguido de apt upgrade já leva sua máquina para a atualização mais recente.

A máquina deste guia foi instalada com a ISO 13.5 (veja a linha comentada do cdrom acima), mas já está na 13.7, porque o instalador baixou as atualizações:

cat
Mostra o conteúdo de um arquivo (de concatenate, "juntar").
/etc/debian_version
Arquivo que guarda só o número da versão do Debian.
$ cat /etc/debian_version
13.7                         « Debian 13, sétima atualização pontual

Quanto tempo dura o suporte

Cada versão estável passa por três fases. As duas primeiras são gratuitas:

FaseQuem cuidaDuração aproximadaO que recebe
Suporte normalEquipe de segurança do Debian~3 anos (até 1 ano depois da próxima versão)Correções de segurança e atualizações pontuais
LTS (Long Term Support)Equipe Debian LTSAté completar ~5 anosCorreções de segurança dos pacotes principais
ELTS (Extended LTS)Empresa Freexian (pago)Até ~10 anosCorreções para quem paga

O Debian lança uma versão estável nova a cada cerca de 2 anos. Na prática: com o Debian 13, você tem tempo de sobra até precisar migrar. A data exata de fim de suporte de cada versão está em wiki.debian.org/DebianReleases.

Como descobrir a versão da sua máquina

Já viu o /etc/debian_version. Estas são as outras formas, cada uma com um nível de detalhe:

ComandoMostra
cat /etc/debian_version13.7
grep VERSION_CODENAME /etc/os-releaseVERSION_CODENAME=trixie
lsb_release -cstrixie
lsb_release -aDistribuidor, descrição, número e codinome
apt-cache policyDe quais faixas (stable, stable-security…) vêm os pacotes
grep
Procura linhas que contêm um texto.
VERSION_CODENAME
O texto procurado.
/etc/os-release
O arquivo onde procurar.
$ grep VERSION_CODENAME /etc/os-release
VERSION_CODENAME=trixie
$ lsb_release -cs
trixie

O apt-cache policy mostra a "etiqueta" de cada repositório. Repare em a= (faixa) e n= (codinome):

$ apt-cache policy

Missão: nesta máquina simulada, mostre só a linha do codinome dentro de /etc/os-release. Depois veja o número exato com cat /etc/debian_version.

Qual versão eu devo usar?

SituaçãoRecomendação
Primeiro contato com Debianstable (Debian 13)
Servidorstable, sempre
Computador novo com hardware muito recentestable + kernel dos backports
Preciso de um programa mais novostable + backports ou Flatpak
Quero ajudar a testar o próximo Debiantesting, numa máquina que pode quebrar
Não misture faixas

Adicionar linhas de testing ou sid no sources.list de uma stable cria o que a comunidade chama de FrankenDebian: um sistema montado com peças incompatíveis, que quebra nas atualizações. Se precisa de algo mais novo, use os backports.

Quando não funciona

"lsb_release: comando não encontrado" 
$ lsb_release -a
bash: lsb_release: comando não encontrado

O que aconteceu: em instalações muito mínimas (contêineres, por exemplo), o pacote lsb-release pode não estar instalado.

Como resolver: use cat /etc/os-release, que sempre existe.

O apt avisa que o repositório mudou de codinome 
$ su -c 'apt update'
…
Nota: O repositório 'http://deb.debian.org/debian stable InRelease' alterou seu valor 'Codename' de 'trixie' para 'forky'

O que aconteceu: o sources.list usa stable em vez do codinome, e uma nova versão foi lançada.

Como resolver: troque stable por trixie no sources.list para continuar no Debian 13, ou planeje a migração com Atualizar a Versão do Debian.

Resumo

  • stable é a versão lançada e recomendada; testing é a próxima em montagem; sid é a instável.
  • Cada versão tem um codinome do Toy Story: 12 bookworm, 13 trixie, 14 forky.
  • Use o codinome no sources.list para não mudar de versão sem querer.
  • 13.1, 13.2… são atualizações pontuais do mesmo Debian 13.
  • Suporte: ~3 anos normais + LTS até ~5 anos; nova versão a cada ~2 anos.
